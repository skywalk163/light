    1. 对比案例一：快速排序¶

    1.1 完整代码对比¶

    Python 版本¶

    def quicksort(arr):
    """快速排序——经典实现"""
    if len(arr) <= 1:
        return arr
    pivot = arr[len(arr) // 2]
    left = [x for x in arr if x < pivot]
    mid = [x for x in arr if x == pivot]
    right = [x for x in arr if x > pivot]
    return quicksort(left) + mid + quicksort(right)


# 测试
arr = [64, 34, 25, 12, 22, 11, 90, 5, 77, 30]
print("排序前:", arr)
print("排序后:", quicksort(arr))

    光明版本¶

    # 快速排序
段落 快速排序 接收 数组：
    如果 列表长度(数组) 小于等于 1：
        返回 数组
    设 基准 为 数组[列表长度(数组) // 2]
    设 左侧 为 [x 遍历 x 之 数组 若 x 小于 基准]
    设 中间 为 [x 遍历 x 之 数组 若 x 等于 基准]
    设 右侧 为 [x 遍历 x 之 数组 若 x 大于 基准]
    设 拼接结果 为 快速排序(左侧) -> 中间 -> 快速排序(右侧)
    返回 拼接结果

# 测试
设 数组 为 [64, 34, 25, 12, 22, 11, 90, 5, 77, 30]
打印("排序前：" + 转字符串(数组))
打印("排序后：" + 转字符串(快速排序(数组)))

    1.2 分步对照¶

    语义 Python 写法 光明写法 差异说明
    函数定义 def quicksort(arr): 段落 快速排序 接收 数组： Python 用英文缩写 def，光明用中文「段落」
    条件判断 if len(arr) <= 1: 如果 列表长度(数组) 小于等于 1： Python 的函数调用 len() + 符号 <=；光明用完整中文语句
    取基准值 pivot = arr[len(arr) // 2] 设 基准 为 数组[列表长度(数组) // 2] 光明「设...为...」的语序更接近自然语言「令基准等于...」
    列表推导 [x for x in arr if x < pivot] [x 遍历 x 之 数组 若 x 小于 基准] Python 的 for...in...if 语序是英文思维；光明「遍历...之...若...」是中文思维
    列表拼接 left + mid + right 左侧 -> 中间 -> 右侧 光明用 -> 管道符，语义更清晰
    递归调用 quicksort(left) 快速排序(左侧) 中文函数名，无需思维转换
    字符串拼接 f-string / + "文本" + 转字符串(值) 光明需要显式转字符串，但语义更清晰

    1.3 思维差异分析¶

    Python 的思维路径：

    想排序 → 定义函数 def quicksort(arr) → 检查长度 len(arr) → 
取中间值 // 2 → 列表推导 [x for x in arr if ...] → 递归

    光明的思维路径：

    想排序 → 定义段落 快速排序 接收 数组 → 检查长度 列表长度(数组) →
取中间值 // 2 → 列表推导 [x 遍历 x 于 数组 若 ...] → 递归

    核心差异：

    1. 命名方式：Python 的函数名 quicksort 是英文缩写，光明直接用「快速排序」。对于中文母语者，阅读 quicksort 需要额外 0.1-0.3 秒的「解码」时间（将英文映射到概念），而「快速排序」是零延迟的直接理解。

    2. 语法结构：Python 的 def quicksort(arr): 是「关键字 + 函数名 + 参数」结构，光明的 段落 快速排序 接收 数组： 是「名词 + 动词 + 宾语」结构，与中文自然语序完全一致。

    3. 逻辑表达：Python 的列表推导 [x for x in arr if x < pivot] 虽然简洁，但 for...in...if 的语序与中文思维相反。光明的 [x 遍历 x 于 数组 若 x 小于 基准] 遵循「目标→来源→条件」的中文语序。

    1.4 学习曲线分析¶

    学习阶段 Python 的学习负担 光明的学习负担 差异
    理解递归概念 中等 中等 一致
    记忆函数定义语法 记忆 def、return 记忆「段落」「接收」「返回」 光明更直观
    记忆关键字 if/else/for/in/len/return 中文对应词 光明减少 50% 记忆量
    变量命名 需考虑英文命名规范 可直接用中文 光明零门槛
    调试与理解错误信息 英文错误信息 中文错误信息 光明更友好

    2. 对比案例二：CSV 文件处理¶

    2.1 完整代码对比¶

    场景描述：读取一个包含学生成绩的 CSV 文件，计算各科平均分，筛选出总分最高的前 3 名学生，将结果写入新的 CSV 文件。

    Python 版本¶

    import csv

def analyze_grades(input_file, output_file):
    # 读取数据
    with open(input_file, 'r', encoding='utf-8') as f:
        reader = csv.DictReader(f)
        students = list(reader)

    if not students:
        return

    # 计算各科平均分
    subjects = ['语文', '数学', '英语']
    averages = {}
    for subject in subjects:
        scores = [int(s[subject]) for s in students]
        averages[subject] = sum(scores) / len(scores)

    # 计算总分并排序
    for s in students:
        s['总分'] = sum(int(s[sub]) for sub in subjects)

    top3 = sorted(students, key=lambda s: s['总分'], reverse=True)[:3]

    # 写入结果
    fieldnames = ['姓名'] + subjects + ['总分', '排名']
    with open(output_file, 'w', encoding='utf-8', newline='') as f:
        writer = csv.DictWriter(f, fieldnames=fieldnames)
        writer.writeheader()
        for i, s in enumerate(top3, 1):
            writer.writerow({
                '姓名': s['姓名'],
                '语文': s['语文'],
                '数学': s['数学'],
                '英语': s['英语'],
                '总分': s['总分'],
                '排名': i
            })

    return averages, top3


# 使用
averages, top3 = analyze_grades('成绩.csv', '前三名.csv')
print("平均分：", averages)
print("前三名：", [s['姓名'] for s in top3])

从 文件系统 导入 文件存在

    如果 非 文件存在(输入文件)：
        打印("文件不存在：" + 输入文件)
        返回 空, []

    设 原始数据 为 解析CSV文件(输入文件)
    设 学生列表 为 转字典列表(原始数据)

    如果 列表长度(学生列表) 等于 0：
        返回 空, []

    # 计算各科平均分
    设 科目 为 ["语文", "数学", "英语"]
    设 平均分 为 {}
    遍历 科目 于 科目：
        设 分数列表 为 []
        遍历 学生 于 学生列表：
            列表追加(分数列表, 整数(学生[科目]))
        设 总分 为 0
        遍历 分数 于 分数列表：
            设 总分 为 总分 加 分数
        平均分[科目] 为 总分 除以 列表长度(分数列表)

    # 计算每个学生的总分
    遍历 学生 于 学生列表：
        设 学生总分 为 0
        遍历 科目 于 科目：
            设 学生总分 为 学生总分 加 整数(学生[科目])
        学生["总分"] 为 学生总分

    # 按总分排序取前3

        返回 学生["总分"]
    设 排序后 为 排序(学生列表, 依据 键 为 取总分, 倒序 为 真)
    设 前三名 为 排序后[0 到 3]

    # 写入结果

            "语文": 学生["语文"],
            "数学": 学生["数学"],
            "英语": 学生["英语"],
            "总分": 学生["总分"],
            "排名": 序号
        })
        设 序号 为 序号 加 1

    序列化CSV文件(输出文件, 输出数据)

    返回 平均分, 前三名

    2.2 分步对照¶

    语义 Python 写法 光明写法 差异说明
    导入模块 import csv 从 CSV 导入 解析CSV文件 光明导入的是具体函数，而非模块
    文件存在检查 需要手动 os.path.exists 文件存在(输入文件) 直接、语义化
    读取 CSV csv.DictReader(f) → list(reader) 解析CSV文件(输入文件) → 转字典列表() 光明两步更清晰
    遍历数据 for s in students: 遍历 学生 于 学生列表： 光明是完整中文句子
    整数转换 int(s[subject]) 整数(学生[科目]) 语义一致，光明的中文更直观
    排序 sorted(..., key=lambda s: s['总分'], reverse=True) 排序(..., 依据 键 为 学生 => 学生["总分"], 倒序 为 真) 光明使用命名参数，语义自明
    切片 sorted_list[:3] 排序后[0 到 3] 光明用 0 到 3 替代 :3，更直观
    写 CSV csv.DictWriter + writerow 序列化CSV文件(文件路径, 数据) 光明一行搞定
    错误处理 隐式抛异常 显式检查文件存在 光明更健壮

    2.3 思维差异分析¶

    Python 的思维路径：

    打开文件 → 创建 DictReader → 手动转换整数 → 生成器表达式求平均分 →
lambda 排序 → 切片 → 创建 DictWriter → 逐行写入

    光明的思维路径：

    解析CSV文件 → 转字典列表 → 遍历计算 → 排序（参数名自明） → 序列化写入

    核心差异：

    1. API 设计的语义化：Python 的 CSV 处理需要理解 DictReader、DictWriter、fieldnames、writeheader 等概念。光明的标准库将所有这些封装为 解析CSV文件、序列化CSV文件 等语义化函数，调用者只需关注「做什么」而非「怎么做」。

    2. 参数命名：光明的排序函数使用命名参数 依据 键 为 学生 => 学生["总分"], 倒序 为 真，参数名本身就是文档。Python 的 key=lambda 和 reverse=True 对初学者不够直观。

    3. 错误处理：光明版本显式检查文件是否存在，这是一种更符合直觉的编程习惯——在动手之前先确认条件。Python 的「先做，错了再处理」风格对初学者不太友好。

    4. 数据流向：光明代码的数据流向是线性的：读取→转换→处理→输出。Python 代码中穿插了 with 上下文管理器、生成器表达式等概念，增加了认知复杂度。

    2.4 学习曲线分析¶

    知识点 Python 学习难度 光明学习难度 说明
    CSV 读取 高（需理解 DictReader、上下文管理器） 低（解析CSV文件 一个函数） 光明封装度高
    数据转换 中（列表推导、生成器表达式） 中（显式遍历） 光明更冗长但更清晰
    排序 中（lambda 语法） 低（命名参数） 光明参数名自文档化
    文件写入 高（DictWriter、writeheader、writerow） 低（序列化CSV文件 一个函数） 光明大幅简化
    异常处理 中（需理解 try/except） 低（前置条件检查） 光明更符合直觉

    3. 对比案例三：Web 请求 + JSON 解析¶

    3.1 完整代码对比¶

    场景描述：向 GitHub API 发送请求，获取用户仓库列表，筛选出星标数超过 100 的仓库，按星标数排序后输出。

    Python 版本¶

    import requests
import json

def get_popular_repos(username, min_stars=100):
    url = f"https://api.github.com/users/{username}/repos"
    headers = {"Accept": "application/vnd.github.v3+json"}

    try:
        resp = requests.get(url, headers=headers, timeout=10)
        resp.raise_for_status()
    except requests.exceptions.RequestException as e:
        print(f"请求失败：{e}")
        return []

    repos = resp.json()

    # 筛选星标超过阈值的仓库
    popular = [r for r in repos if r['stargazers_count'] >= min_stars]

    # 按星标数排序（降序）
    popular.sort(key=lambda r: r['stargazers_count'], reverse=True)

    # 提取关键信息
    result = []
    for r in popular:
        result.append({
            'name': r['name'],
            'stars': r['stargazers_count'],
            'description': r.get('description', ''),
            'language': r.get('language', 'Unknown'),
            'url': r['html_url']
        })

    return result


# 使用
repos = get_popular_repos('skywalk163')
print(f"找到 {len(repos)} 个热门仓库：")
for r in repos:
    print(f"⭐ {r['stars']} - {r['name']} ({r['language']})")
    if r['description']:
        print(f"   {r['description']}")

    语义 Python 写法 光明写法 差异说明

    条件筛选 [r for r in repos if ...] 遍历 + 如果 + 列表追加 光明更显式
    排序 sort(key=lambda r: ..., reverse=True) 排序(..., 依据 键 为 ..., 倒序 为 真) 光明命名参数
    空值处理 r.get('description', '') 仓库["描述"] 若 ... 否则 "" 光明用三元表达式
    结果键名 英文字符串 中文字符串 光明直接中文

    3.3 思维差异分析¶

    Python 的思维路径：

    import requests → 构造 URL（f-string）→ 发送请求 → 检查异常 → 
resp.json() 解析 → 列表推导筛选 → lambda 排序 → 提取信息

    光明的思维路径：

    从 HTTP客户端 导入 → 创建客户端 → 构造 URL（拼接）→ 发送请求 → 
检查状态码 → 解析JSON → 遍历筛选 → 排序（命名参数）→ 提取信息

    核心差异：

    1. 异常处理的可读性：Python 的 resp.raise_for_status() 是一个「隐式」操作——它不直接告诉读者发生了什么。光明的 如果 响应.状态码 不等于 200：抛出 是显式的条件判断，任何读者都能理解其含义。

    2. 数据处理的显式性：光明的 遍历 + 如果 + 列表追加 虽然比 Python 的列表推导多写几行，但每一步都清晰可见。对于初学者，显式代码比隐式代码更容易理解。

    3. 命名参数的自文档化：光明的 排序(..., 依据 键 为 仓库 => 仓库["星标"], 倒序 为 真) 中的参数名 依据、键、倒序 本身就是文档。Python 的 key=lambda 和 reverse=True 需要学习者知道 key 是什么、reverse 为什么是布尔值。

    4. 空值处理的语义化：Python 的 r.get('description', '') 是一个方法调用，光明的 仓库["描述"] 若 仓库["描述"] 不等于 空 否则 "" 是一个条件表达式，语义更清楚。

    3.4 学习曲线分析¶

    知识点 Python 学习难度 光明学习难度 说明
    HTTP 请求 中（需理解 requests 库的各种概念） 中（HTTP客户端 封装） 差异不大
    异常处理 中（try/except、异常类型层级） 低（尝试/捕获） 光明关键字更直观
    JSON 解析 低（resp.json() 原生方法） 低（解析JSON 函数） 差异不大
    排序 lambda 高（lambda 语法对初学者不友好） 低（命名参数） 光明大幅降低门槛
    空值处理 中（需理解 get() 方法、默认值） 中（三元表达式） 光明更显式
    字典键名 需用英文 可用中文 光明更灵活

    4.2 光明的核心优势¶

    1. 零认知转换：中文母语者阅读光明代码无需经过「英文→中文→逻辑」的转换过程，直接理解代码含义。

    2. 语义化 API：光明标准库的函数名和参数名都是中文，解析CSV文件 比 csv.DictReader 更容易理解。

    3. 命名参数自文档化：光明的 排序(..., 依据 键 为 ..., 倒序 为 真) 参数名本身就是文档，无需查阅文档。

    4. 显式优于隐式：光明倾向于显式表达（如 如果 响应.状态码 不等于 200 而非 resp.raise_for_status()），这对初学者更友好。

    4.3 光明的折衷¶

    1. 代码更冗长：光明的显式风格导致代码行数通常比 Python 多 20-50%。这是「可读性」和「简洁性」之间的权衡。

    2. 生态依赖桥接：光明通过 Python 桥接和 C FFI 使用现有生态，而非原生支持。这意味着调用 Python 库时存在一定的性能开销。

    3. 社区规模：光明仍处于早期阶段，社区规模和第三方库数量远不及 Python。
