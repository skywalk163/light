    光明（Light）- 完整规范文档¶

    版本：v4.0
    日期：2026-08-04

    语言命名¶

    中文名称：光明
    英文名称：Light
    文件扩展名：.段 或 .light

    命名寓意： - 段：段落，词句段篇的核心代码单元 - 言：语言，编程语言 - 整体寓意：用段落书写的编程语言

    文档说明¶

    本文档整合了光明（Light）编程语言的完整设计，包括： - 第一部分：理念与核心概念 - 第二部分：设计决策（34项） - 第三部分：完整语法规范 - 第四部分：实现路线图 - 第五部分：潜在风险与缓解 - 第六部分：已知限制 - 第七部分：示例库（10个真实场景） - 第八部分：中文编程语言语法对比研究

    第一部分：理念与核心概念¶

    一、核心理念¶

    1.1 为什么不能只翻译关键字？¶

    如果只是把 if → 如果、def → 定义函数，那只是： - 输入变慢（拼音输入需要切换） - 没有本质创新 - 无法超越现有语言

    1.2 中文真正的优势¶

    语义密度：光明的核心优势——用更少的字符表达更多的含义

    英文: "Calculate the sum of two numbers and return the result"
中文: "计算两数之和并返回"

    层级组织：词、句、段、篇天然形成编程层级（光明的核心特性）

    词 → 变量、操作符
句 → 语句（自带部分数据）
段 → 函数/代码块（自带上下文）
篇 → 模块/程序（整体逻辑）

    1.3 三大核心创新¶

    1. 数据携带

    句子、段落可以自带数据，减少函数参数传递。

    传统：def fibonacci(n): return ...  # 需要传参
中文：斐波那契第十项              # 数据内嵌

    2. 上下文继承

    段落自动继承父作用域的数据。

    主程序：
  学生列表为...

统计段：
  # 自动继承"学生列表"
  返回学生列表之长度

    3. 语义密度

    用更少的代码做更多的事。

    Python（150字符）：
def find_above_average(numbers):
    avg = sum(numbers) / len(numbers)
    return [n for n in numbers if n > avg]

中文（40字符）：
列为一五十三七
求大于平均值之项

    第二部分：设计决策¶

    本文档记录光明（Light）编程语言的最终设计决策，共33项。

    决策1：光明的词句段篇边界¶

    最终决策：单行不限动词数，多行必须用段或缩进块

    规则¶

    代码形式 分类 说明
    单行代码（无分号） 句 可以包含多个动词（用逗号/并连接）
    多行代码 段或缩进块 必须用《》定义段落，或用缩进块
    若...则： 内部 缩进块 属于条件语句的一部分，不算独立段落

    示例¶

    # 单行句（不限动词数）
计算三加五并打印结果。

# 多行必须分段
《数据处理》段()：
  读取文件。
  过滤数据。
  排序数据。
  输出结果。
结束。

# 缩进块（不独立成段）
若结果大于十则：
  打印大。
  记录日志。
结束。

    理由¶

    • ✅ 用户无需记住"动词数≤3"的阈值
    • ✅ 解析简单：以换行或句号为边界
    • ✅ 符合人们日常书写习惯

    决策2：数据携带机制¶

    最终决策：默认只读继承 + 修改需显式声明 + --strict可选模式

    默认模式（适合业务专家）¶

    主程序：
  甲 = 1
  乙 = 2

  《统计》段()：
    # 默认只读继承
    总和 = 甲 + 乙              # 可以读取
    # 父.甲 = 10               # 错误：未声明继承
  结束。

  《修改》段(继承: 甲)：        # 显式声明才能修改
    父.甲 = 10
  结束。

    严格模式（适合大型项目）¶

    # 编译选项：--strict

主程序：
  甲 = 1
  乙 = 2

  《统计》段(使用: 甲, 乙)：    # 强制声明所有使用的外部变量
    总和 = 甲 + 乙
    返回总和
  结束。

  调用《统计》(使用: 甲, 乙)    # 调用处也明确传入

    理由¶

    • ✅ 默认模式保持简洁性（业务专家友好）
    • ✅ 严格模式保证清晰性（专业程序员友好）

    决策3：段的作用域¶

    最终决策：仅支持词法作用域，去掉动态继承

    规则¶

    • 段的父作用域在定义时确定
    • 不支持动态作用域（避免复杂性）
    • 如需传递上下文，显式传递上下文对象

    示例¶

    主程序：
  甲 = 1

  《修改》段(继承: 甲)：
    父.甲 = 2                  # 永远修改主程序的甲
  结束

  《执行》段(操作)：
    甲 = 100                   # 局部变量
    操作()                    # 操作的父仍是主程序
  结束

  调用《执行》(《修改》)
  打印甲                      # 输出：2（主程序的甲被修改）

    理由¶

    • ✅ 行为可预测（调试容易）
    • ✅ 简化语言核心（降低学习成本）
    • ✅ 符合主流语言实践

    决策4：标点符号规则¶

    最终决策：换行即语句结束，标点可选，支持续行

    基本规则¶

    # 方式1：换行（推荐）
设甲为三
设乙为五
打印甲加乙

# 方式2：加标点（可选）
设甲为三。
设乙为五。
打印甲加乙。

# 方式3：分号分隔（一行多句）
设甲为三；设乙为五；打印甲加乙

# 等价于（三个独立行）
设甲为三
设乙为五
打印甲加乙

    语法规则¶

    1. 分号;或；分隔多个语句
    2. 每个分号前后的语句都是独立的句
    3. 行末仍然可以加句号（可选）

    决策16：动词连接符"并"的用法¶

    最终决策："并"同时支持自然语言连接和代码块连接两种用法

    用法一：自然语言连接（句子内部）¶

    用于连接一个句子中的多个动词，表示顺序执行或并列关系。

    # 单行句中的"并"
计算三加五并打印结果。

# 等价于
计算三加五。
打印结果。

# 更复杂的例子
读取文件并解析数据并保存结果。

    用法二：代码块连接（段落之间）¶

    用于连接多个段落调用或数据结构，实现管道式处理。

    # 连接段落调用
返回《快速排序》(小列表)并等列表并《快速排序》(大列表)。

# 连接数据结构
小列表并等列表并大列表。

# 管道式处理
原始数据并《过滤》并《排序》并《去重》。

    语法规则¶

    1. 句子内部：动词1 + 宾语1 + 并 + 动词2 + 宾语2
    2. "并"作为连接词，表示动作的顺序或并列

    3. 所有动词属于同一个句子

    4. 段落之间：数据/调用1 + 并 + 数据/调用2 + 并 + 数据/调用3

    5. "并"作为操作符，连接多个数据或段落调用
    6. 形成管道式处理链

    理由¶

    • ✅ 符合中文自然语言习惯
    • ✅ 语法简洁，无需额外关键字
    • ✅ 上下文决定语义，解析器可区分两种用法

    决策17：类型注解系统¶

    最终决策：支持可选的类型注解，采用参数: 类型和-> 返回类型语法

    类型注解示例¶

    # 简单类型

    类型检查规则¶

    1. 可选性：类型注解是可选的，不加类型注解的代码完全合法
    2. 静态检查：编译时可进行类型检查（--type-check选项）
    3. 运行时忽略：类型注解不影响运行时行为
    4. 类型推断：编译器可自动推断部分类型
    # 默认：不进行类型检查
python 编译器.py main.句

# 开启类型检查
python 编译器.py --type-check main.句

    理由¶

    • ✅ 渐进式类型系统（类似Python的Type Hints）
    • ✅ 不强制要求类型注解（保持简洁）
    • ✅ 专业程序员可使用类型检查（提高可靠性）
    • ✅ 符合中文习惯（参数: 类型而非类型 参数）

## 决策19：符号双模式支持

**最终决策**：**支持中文符号和英文符号双模式，两者等价**

### 符号分类与模式

| 符号类型 | 中文符号 | 英文符号 | 是否等价 | 推荐用法 |
|---------|---------|---------|---------|---------|
| **语义标点** | 。 | . | ✅ 是 | 中文优先（有语义意义） |
| | ： | : | ✅ 是 | 中文优先（有语义意义） |
| | ； | ; | ✅ 是 | 中文优先 |
| | ， | , | ✅ 是 | 可混用 |
| | ？ | ? | ✅ 是 | 中文优先 |
| **辅助括号** | （） | () | ✅ 是 | 英文优先（输入便捷） |
| | 【】 | [] | ❌ 否 | 中文独有（篇名标记） |
| **标记符号** | 《》 | 无 | ❌ 否 | 中文独有（段落名标记） |
| **运算符** | 加减乘除 | + - * / | ❌ 否 | 汉字优先（语义密度优势） |

### 双模式语法示例

    方式1：全中文符号¶

    《计算》段（甲：数，乙：数） -> 数： 返回甲加乙。 结束。

    方式2：混合符号（推荐）¶

    《计算》段(甲: 数, 乙: 数) -> 数： 返回甲加乙。 结束。

    方式3：全英文符号¶

    《计算》段(甲: 数, 乙: 数) -> 数: 返回甲加乙. 结束.

    三种方式完全等价¶

    ### 详细规则

#### 1. 句号：`。` 与 `.` 等价
    设甲为三。 # 中文句号 设甲为三. # 英文句号（等价） 
    #### 2. 冒号：`：` 与 `:` 等价
    《计算》段(甲：数)： # 中文冒号 《计算》段(甲: 数): # 英文冒号（等价） 
    #### 3. 逗号：`，` 与 `,` 等价
    《计算》(甲，乙，丙) # 中文逗号 《计算》(甲, 乙, 丙) # 英文逗号（等价） 《计算》(甲，乙, 丙) # 混合使用（等价） 
    #### 4. 分号：`；` 与 `;` 等价

## 决策20："并"的两种用法区分

**最终决策**：**明确区分"并"和"->"的语义，避免解析歧义**

### 问题背景

"并"可以连接句子内部的动词，也可以连接段落调用/数据，可能导致歧义：
    读取文件并过滤数据并排序并输出。 
    这里存在两种可能的语义：
1. **顺序执行**：每个动词独立执行，不传递中间值
2. **管道式处理**：前一操作的结果作为下一操作的输入

### 解决方案

**明确区分两种操作符**：

| 操作符 | 语义 | 中间值传递 | 使用场景 |
|-------|------|-----------|---------|
| `并` | 顺序执行 | ❌ 无 | 句子内部动词连接 |
| `->` | 管道式处理 | ✅ 有 | 数据流转、段落调用 |

### 语法规则

#### 1. "并"用于顺序执行

    顺序执行（无中间值传递）¶

    读取文件并过滤数据并排序并输出。

    等价于：¶

    读取文件。 过滤数据。 排序。 输出。 

    **规则**：
- "并"后面的动词独立执行
- 不传递中间值
- 每个动词都是独立的语句

#### 2. "->"用于管道式处理

    管道式处理（中间值传递）¶

    数据 -> 《过滤》 -> 《排序》 -> 《输出》。

    等价于：¶

    临时1 = 《过滤》(数据) 临时2 = 《排序》(临时1) 《输出》(临时2) 

    **规则**：
- 前一操作的结果作为下一操作的输入
- 明确的数据流向
- 推荐用于段落调用链

### 示例对比

    场景1：顺序执行多个独立操作¶

    打开文件并读取内容并关闭文件。

    场景2：管道式数据处理¶

    数据 -> 《过滤》 -> 《排序》 -> 《去重》。

    场景3：混合使用¶

    读取数据。 数据 -> 《处理》 -> 《保存》。 打印完成信息并关闭程序。 

    ### 理由

- ✅ 语义明确，无歧义
- ✅ 解析器实现简单
- ✅ 符合直觉（"并"是并列关系，"->"是流向关系）
- ✅ 与函数式编程的管道操作符一致

    决策29：无空格分词支持¶

    最终决策：支持无空格分词，实现真正的中文连续书写

    问题背景¶

    当前示例中大量使用空格分隔：

    设 甲 为 三。
若 甲 大于 十 则：
  打印 甲。
结束。

    能否实现无空格书写？

    定义甲等于三。
如果甲大于十那么：
  打印甲。
结束。

    技术方案¶

    三层分词机制：

    第1层：类型切换自动分词¶

    规则：字符类型切换时自动分词

类型：
- HAN：汉字
- NUM：数字
- SYM：符号
- ENG：英文

示例：
定义甲等于三。
HAN HAN HAN HAN HAN 。
  ↑   ↑   ↑   ↑
切换 切换 切换 保持

分词：[定义] [甲] [等于] [三] [。]

    第2层：双字关键词优先匹配¶

    规则：优先匹配双字关键词，无法匹配则作为标识符

输入：定义甲等于三

解析：
1. 尝试匹配"定义甲" → 不是关键词
2. 尝试匹配"定义" → 是关键词 ✓
3. 剩余"甲" → 标识符
4. 尝试匹配"等于三" → 不是关键词
5. 尝试匹配"等于" → 是关键词 ✓
6. 剩余"三" → 数字

结果：[定义] [甲] [等于] [三]

    第3层：元数驱动参数收集¶

    输入：打印甲加乙

解析：
1. 打印 (arity=1) → 需要收集1个参数
2. 甲 → 参数的一部分
3. 加 (arity=2) → 新动词！停止收集
4. 甲加乙 → 不是参数，而是"甲" + "加" + "乙"

正确解析：打印(甲) + 加(乙, ?)
等等，这有问题！

    问题：无空格时，如何区分打印甲和打印+甲加乙？

    解决方案：引入最小吞噬原则

    原则：动词只吞噬必要的参数数量，遇到新动词立即停止

输入：打印甲加乙

解析：
1. 打印 (arity=1) → 收集1个参数
2. 甲 → 收集到1个参数，停止！
3. 加 (arity=2) → 收集2个参数
4. 乙 → 参数1
5. ？→ 参数2缺失（语法错误）

正确写法：打印甲加乙乘丙。
解析：打印(甲) + 加(乙, 乘(丙, ?))
还是不对！

最终方案：
打印甲加乙。 → 打印(加(甲, 乙))

    修正方案：右结合优先

    输入：打印甲加乙。

解析：
1. 扫描到句号 → 这是完整句子
2. 从右向左解析
3. 加 (arity=2) → 收集甲和乙
4. 打印 (arity=1) → 收集加的结果

结果：打印(加(甲, 乙))

    无空格书写规则¶

    核心规则：

    1. 双字关键词自动截断：定义甲 → [定义] [甲]
    2. 类型切换自动分词：甲加1 → [甲] [加] [1]
    3. 元数驱动参数收集：动词收集指定数量参数
    4. 句号作为语句边界：。 标记完整语句

    示例对比：

    有空格写法 无空格写法 解析结果

    打印 甲 加 乙。 打印甲加乙。 打印(加(甲, 乙))

    决策34：主谓/谓宾/定语语义区分¶

    最终决策：利用汉语语法特性区分原地操作和函数式操作

    核心概念¶

    利用汉语语法结构明确区分操作语义：

    语法结构 示例 语义 是否修改原对象
    主谓结构 列表排序 原地修改 ✅ 是
    谓宾结构 排序列表 返回新对象 ❌ 否
    定语结构 排序后的列表 生成临时数据 ❌ 否
    之字结构 列表之首 提取属性 ❌ 否

    与现有概念的关系¶

    1. 与决策32（主谓宾语序）的关系¶

    语义 管道式调用 原地修改
    分隔符 逗号, 无分隔符

    详细语法规则¶

    1. 主谓结构（原地修改）¶

    语法：[主语][动词] 或 [主语][动词][宾语]

    语义：主语接受操作，原地修改

    适用操作：

    操作 示例 等价Python
    排序 列表排序 列表.sort()
    反转 列表反转 列表.reverse()
    添加 列表添加元素 列表.append(元素)
    删除 列表删除元素 列表.remove(元素)
    清空 列表清空 列表.clear()
    去重 列表去重 列表去重实现

    定义甲等于列3 1 2。

甲添加元素4。           # 甲变为[1,2,3,4]

    2. 谓宾结构（返回新对象）¶

    语法：[动词][宾语] 或 [动词][宾语][补语]

    语义：对宾语执行操作，返回新对象

    适用操作：

    操作 示例 等价Python
    排序 排序列表 sorted(列表)
    反转 反转列表 reversed(列表)
    筛选 筛选列表条件 filter(条件, 列表)
    映射 映射列表函数 map(函数, 列表)
    求和 求和列表 sum(列表)
    求最大 求最大列表 max(列表)

    示例：

    定义甲等于列3 1 2。

定义丙等于反转甲。      # 丙=[2,1,3]，甲不变
定义丁等于求和甲。      # 丁=6

    3. 定语结构（临时生成）¶

    语法：[定语]的[名词]

    语义：生成临时数据，不修改原对象

    适用场景：

    场景 示例 等价Python
    排序 排序后的列表 sorted(列表)
    筛选 值大于0的列表 [x for x in 列表 if x>0]
    去重 去重后的列表 list(set(列表))
    反转 反转后的列表 列表[::-1]

    示例：

    定义甲等于列3 1 2。

定义乙等于排序后的甲。   # 乙=[1,2,3]，甲不变
定义丙等于值大于0的甲。  # 丙=[3,1,2]，甲不变

    4. 之字结构（提取属性）¶

    语法：[对象]之[属性]

    语义：提取对象的属性或特征

    适用场景：

    场景 示例 等价Python
    首元素 列表之首 列表[0]
    末元素 列表之末 列表[-1]
    长度 列表之长 len(列表)
    和 列表之和 sum(列表)
    最大值 列表之最大 max(列表)
    最小值 列表之最小 min(列表)

    示例：

    定义甲等于列1 2 3。

定义乙等于甲之首。       # 乙=1
定义丙等于甲之长。       # 丙=3
定义丁等于甲之和。       # 丁=6

# 第五部分：潜在风险与缓解

## 一、缩进敏感 + 中文标点 = 输入门槛

### 风险描述

虽然决策4允许用英文句号`.`代替`。`，但用户仍需要输入中文冒号`：`、逗号`，`等。对于习惯英文编程的用户，频繁切换输入法仍是痛点。

**风险等级**：中等

### 缓解措施

1. **编辑器插件**：自动转换英文标点为中文
   - 输入`:` → 自动变成`：`
   - 输入`,` → 自动变成`，`（可配置）

2. **双模式支持**：允许英文标点作为备选
   ```
   # 中文标点（推荐）
   设甲为三。

   # 英文标点（兼容）
   设甲为三.
   ```

3. **IDE提示**：悬停显示标点快捷键

---

## 二、"默认只读继承"可能导致过度依赖隐式变量

### 风险描述

业务专家虽然喜欢少打字，但当篇变大（例如超过200行），隐式变量来源会变得难以追踪。即便有`--strict`模式，但默认模式仍可能鼓励不良实践。

**风险等级**：高

### 缓解措施

1. **IDE变量来源提示**：鼠标悬停显示继承链
   ```
   《统计》段：
     返回学生列表之长度。
     # 悬停显示：学生列表 ← 继承自主程序（第15行定义）
   ```

2. **一键转换为显式依赖**：
   ```
   # 转换前
   《统计》段：
     返回学生列表之长度。

   # 转换后
   《统计》段(继承: 学生列表)：
     返回学生列表之长度。
   ```

3. **代码审查规则**：超过100行的篇默认建议使用显式依赖

## 三、与Python生态互操作时，中文变量名传递给C扩展可能出错

### 风险描述

虽然Python 3支持Unicode变量名，但某些C扩展可能假定变量名为ASCII。

**风险等级**：低

### 缓解措施

1. **记录在已知限制中**（见下文"已知限制"章节）

2. **提供别名机制**：
   ```

   学生列表为[张三, 李四]

   # 传递给C扩展时使用别名
   调用numpy.array(学生列表 别名 student_list)
   ```

3. **类型注解中标注ASCII要求**：
   ```
   《调用C库》段(数据: 列表, 名称: 串 仅ASCII) -> 列表：
     ...
   ```

## 四、错误类型定义与数据段语法重复

## 1. 中文变量名与C扩展兼容性

某些Python C扩展（如早期版本的NumPy、Pandas API）可能不支持Unicode变量名。建议：
- 传递数据给C扩展时，使用英文别名
- 或使用`.to_ascii()`方法转换（如需实现）

## 2. 缩进必须一致

混用空格和Tab会导致解析错误。建议：
- 使用编辑器配置自动转换Tab为空格
- 推荐2空格缩进（节省屏幕空间）

## 3. 字符串插值

当前版本不支持Python风格的f-string。字符串拼接使用：

    方法1：连接函数¶

    打印连接("结果是", 结果)。

    方法2：格式化函数（v1.5实现）¶

    打印格式("结果是{}"，结果)。

    方法3：字符串模板（v2.0实现）¶

    打印"结果是{结果}"。 

    ## 4. 并发/异步特性为实验性

v1.0不提供并发/异步支持，计划在v2.0实现。
