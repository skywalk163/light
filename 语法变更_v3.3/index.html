    光明语法变更 v3.3¶

    版本：v3.3 日期：2026-08-03 状态：正式版 基于：v3.2 统一语法规范

    概述¶

    本次变更围绕两个核心问题展开： 1. 代码转换时的语法不足 — Python 有而光明无的语法结构如何处理 2. 初学者友好度 — 选词是否繁琐、是否容易上手

    核心思路：光明是独立的中文语言，Python/C 代码作为"外语引用"嵌入，边界清晰，不做中文拉丁化。

    1. 嵌入块语法（新增）¶

    1.1 设计理念¶

    光明不需要为每种 Python 语法找中文对应。就像中文文本中可以嵌入数学公式和英文缩写一样，光明允许直接嵌入 Python/C 代码块。

    嵌入块是"外语引用"，不改变光明自身语法。

    1.2 语法格式¶

    嵌入 Python:
    <原始 Python 代码>
结束嵌入

嵌入 C:
    <原始 C 代码>
结束嵌入

    1.3 示例¶

    Python 嵌入块： 

    令 甲 = 10
嵌入 Python:
    甲 = 甲 * 2
    result = [x**2 for x in range(甲)]
    print(f"结果: {result}")
结束嵌入
打印 甲

    Python 嵌入块直接共享光明变量作用域，无需显式传递。

    C 嵌入块： 

    嵌入 C:
    int add(int a, int b) {
        return a + b;
    }
结束嵌入

    C 嵌入块通过 ctypes 编译执行，生成的共享库自动加载。

    1.4 实现细节¶

    • Lexer 层：在词法分析阶段检测 嵌入 关键词，捕获到 结束嵌入 的原始文本，作为单个 EMBED_BLOCK token 输出，避免光明分词器破坏嵌入代码
    • Parser 层：EmbedBlock AST 节点包含 language（语言名）和 code（原始代码）
    • Code Generator：Python 嵌入块直接输出原始代码（textwrap.dedent 处理缩进）；C 嵌入块生成 ctypes 编译加载代码

    1.5 解决的语法缺口¶

    以下 Python 语法不再需要在光明中寻找对应，直接嵌入即可： - 装饰器（@staticmethod、@property 等） - async/await - lambda 表达式 - walrus 运算符（:=） - match-case 语句 - 复杂推导式 - 任何 Python 特有语法

    2. 选词优化：段落 → 函数¶

    2.1 变更内容¶

    旧关键词 新关键词 说明
    段落 函数 更直观，初学者一目了然
    段 函数 单字别名同步更新

    2.2 向后兼容¶

    段落 和 段 作为别名保留，使用时触发 DeprecationWarning： 

    DeprecationWarning: 语法「段落 名 接收 参数」已废弃，
请改用「函数 名(参数)」。在未来的版本中将移除「接收」关键字。

    2.3 示例¶

    新语法（推荐）： 

    函数 加法(甲, 乙):
    返回 甲 + 乙

函数 阶乘(n):
    如果 n <= 1:
        返回 1
    否则:
        返回 n * 阶乘(n - 1)

    旧语法（向后兼容）： 

    段落 加法(甲, 乙):
    返回 甲 + 乙

    2.4 修饰符同步更新¶

    以下修饰符前缀也使用 函数： - 异步 函数 名(): （原 异步 段落） - 严格 函数 名(): （原 严格 段落） - 松散 函数 名(): （原 松散 段落）

    3. 多异常捕获语法（增强）¶

    3.1 新增语法¶

    在原有 捕获 (TypeA, TypeB) 括号语法基础上，新增无括号逗号分隔语法：

    尝试:
    令 甲 = 整数("abc")
捕获 ValueError, TypeError 为 错误:
    打印 错误

    3.2 支持的全部语法形式¶

    语法 说明
    捕获 错误: 无类型，仅变量
    捕获 ValueError: 仅类型
    捕获 ValueError 错误: 类型 + 变量
    捕获 ValueError, TypeError: 多类型（无括号）
    捕获 ValueError, TypeError 错误: 多类型 + 变量
    捕获 (ValueError, TypeError): 多类型（括号，向后兼容）
    捕获 (ValueError, TypeError) 错误: 多类型 + 变量（括号，向后兼容）

    3.3 生成的 Python 代码¶

    except (ValueError, TypeError) as 错误:
    print(错误)

    4. 成员访问统一（推迟）¶

    4.1 现状¶

    当前存在双重成员访问体系： - 的 — 用于光明自身对象 - . — 用于外部对象（Python import 的对象）

    4.2 推迟原因¶

    经评估，统一为 的 的影响面过大： - 48 个 .light 文件使用 . 成员访问（1556 行代码） - import 路径中的 .（如 导入 os.path）无替代方案 - TokenType.DOT 同时承担句号和成员访问两种语义，需先拆分

    4.3 分阶段计划（未来实施）¶

    1. Phase 1：拆分 TokenType.DOT 为 TokenType.PERIOD（句号）和 TokenType.DOT（点号）
    2. Phase 2：为 import 路径设计替代语法（如 导入 os/path 或 导入 os::path）
    3. Phase 3：迁移 48 个 .light 文件从 . 到 的
    4. Phase 4：移除 . 成员访问语义

    5. 迁移工具更新¶

    tools/migrate_syntax.py 新增第 4 项迁移规则：

    段落 名(参数):  →  函数 名(参数):
严格 段落 名():  →  严格 函数 名():
异步 段落 名():  →  异步 函数 名():

    用法不变： 

    python tools/migrate_syntax.py --dry-run stdlib/
python tools/migrate_syntax.py stdlib/

    • 通过：1243 项
    • 失败：35 项（全部为 pre-existing：FFI/DateTime/clang 缺失依赖）
    • 新增失败：0（零回归）

    8. v3.4 增量变更¶

    版本：v3.4 日期：2026-08-03 状态：正式版

    8.1 链式方法调用修复¶

    问题：己.history.append(内容) 在类方法中被拆成两条语句——self.history 和 append(内容)——而非 self.history.append(内容)。

    根因：_parse_self_assignment 在检测到 己.属性名 后不跟赋值运算符时，直接返回部分 MemberAccess，未继续解析后续链式调用。

    修复：回退到完整表达式解析器处理整个链式调用。

    8.2 数学运算符双轨制¶

    光明同时支持中文运算符和数学符号运算符，可自由混用：

    中文 数学符号 语义
    加 + 加法
    减 - 减法
    乘 / 乘以 * 乘法
    除 / 除以 / 除法
    整除 // 整除
    模 / 模以 / 取余 % 取余
    幂 / 幂以 ** 幂运算

    新增：**（幂）和 //（整除）数学符号运算符。

    lexer 上下文判断：// 在表达式中间（前一个 token 是数字/标识符/)/]）时识别为整除运算符，否则为行注释。

    混合运算示例： 

    令 甲 = 2 ** 3 * 乙     →  甲 = ((2 ** 3) * 乙)
令 甲 = 甲 // 乙 + 1    →  甲 = ((甲 // 乙) + 1)
令 甲 = 2 ** 3 ** 2     →  甲 = (2 ** (3 ** 2))  （右结合）

    8.3 模块路径系统（分层双轨制）¶

    光明的导入语句支持三种语言前缀，实现光明标准库与外部语言的清晰分层：

    光明标准库（默认，无前缀）： 

    导入 数学
导入 文件系统
导入 文件系统 为 fs

    Python 第三方库（Python: 前缀）： 

    导入 Python: numpy
导入 Python: numpy 为 np
导入 Python: numpy, pandas

    C 语言库（C: 前缀，通过 ctypes 加载）： 

    导入 C: stdio
导入 C: stdio 为 std

    设计理念：光明标准库用原生中文路径，无标点符号；外部语言用显式前缀声明语言边界，保持"外语引用"的清晰分隔。
