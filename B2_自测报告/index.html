    3. B2-2 验证路径评估¶

    三选一评估结果：选 b + c（附加）

    选项 评估 选/不选
    a) 装 llvmlite 最快但工具链依赖重，且不能替代 C 层验证 不选
    b) clang 直编 链路最接近真实发布形态（IR → .ll → clang → exe），本机已有 clang 选
    c) 纯 C 单测 不验证 IR 生成，但立刻给 socket/poller/TLS 层真绿 附加

    4. B2-3 poller 升级¶

    项目 旧 新
    后端 select WSAPoll（Windows）/ poll（POSIX），select 为编译期 fallback（-DDV_POLLER_FORCE_SELECT）
    上限 DV_POLLER_MAX 256 硬编码 动态扩容（初始 256，翻倍增长），select fallback 受 FD_SETSIZE 限制但在超限时明确报错
    静默丢 fd num_registered >= DV_POLLER_MAX 时返回 -1（但事件循环不检查返回值） dv_poller_register 返回 -1 + 写 g_poller_error；dv_poller_wait_n 超容量返回 -1 + 写错误文本；事件循环检查返回值并打 stderr
    事件循环 int out_fds[256] 固定栈分配 malloc(num_registered * sizeof(int)) 按注册数分配

    5. B2-4 TLS¶

    选择 Schannel（不选 OpenSSL/mbedTLS）： - 系统自带，不引入第三方依赖，与「不装库」口径一致 - 不改分发形态

    安全红线： - 证书校验默认开启（g_tls_verify_default = 1） - dv_tls_set_verify(t, 0) 关闭时往 stderr 打醒目告警 - dv_tls_add_trusted_cert_file(path) 追加显式信任锚，用「独占根」引擎（比系统根更严） - dv_tls_wrap 必须给主机名（SNI + 主机名校验都要它），拒绝无名包装

    握手挂回 IO 等待队列： - dv_tls_handshake 返回 DV_TLS_WANT_READ / DV_TLS_WANT_WRITE - dv_tls_want_event(t) 翻译为 DV_POLL_READ / DV_POLL_WRITE - 调用方直接喂给 dv_coro_await_io，不阻塞事件循环

    测试（2/2 passed）： - 正例：添加信任锚 → 握手成功 → send/recv 回显验证 - 负例：不加信任锚 → 握手必须失败（自签证书不在系统根存储中）

    7. B2-5 HTTP/1.1 决策摘要¶

    结论：不在 C 层重写 HTTP/1.1，应让 LLVM 后端补齐语言特性后直接复用 stdlib/流式.light。

    阻断级缺口（3 个）： 1. yield / 生成器：流式.light 的 read_body()、按行读取()、读分块() 全靠 yield 流式产出。LLVM codegen 零支持。 2. bytes 类型：HTTP 协议全靠 bytes（b""、b"\r\n"）。LightValue 只有 type=3 (STR)，无 bytes 类型。 3. 切片 [start:end]：头解析、体切分全用切片。_gen_typed_index_access 只处理单整数索引。

    高优先级缺口（4 个）：导入 socket、.encode()、socket 方法（recv/sendall/close）、codecs.getincrementaldecoder

    详见 docs/B2-5_HTTP决策分析.md。
