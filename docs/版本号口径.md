# 版本号口径

> 适用范围：`light` / `hive` / `lightharness` / `lightmem` / `lightplugin`。
> 校验脚本：`scripts/check_version_consistency.py`（T-0265 起支持 `--repo` 跨仓）。

## 铁规

**一个仓只有一个版本号真源，其它声明点必须跟它，不许各自拍。**

- 版本号只允许在小数点分段（`0.15.2`），需要预发布时用 `0.5.0-rc1` 这类后缀。
- 改版本号时，先改真源，再把同仓其它声明点与 `CHANGELOG` 对齐，最后打 tag。
- 真源找不到机器可校验点时（只有 tag），tag 就是真源，其它文本描述必须跟 tag 一致。
- 跨仓看到不一致，只能在本仓修；改别的仓要走那个仓自己的任务卡。

## 各仓单一真源

| 仓库 | 单一真源 | 其它必须跟它的声明点 | 为什么 |
|---|---|---|---|
| `light` | `pyproject.toml` 的 `version` | `src/version.py` 的 `VERSION`、`cli.light_unified --version`、`CHANGELOG.md` 首条、最近 tag | 打包/发布入口；脚本从 R96 起就守着它 |
| `hive` | `hive.py` 的 `VERSION` | `pyproject.toml` 的 `version`、最近 tag | `hive --version` 打印的就是它，是运行时真源 |
| `lightharness` | `CHANGELOG.md` 首条语义化版本 | 最近 tag | 无 `pyproject.toml`，CHANGELOG 是唯一人工维护的声明 |
| `lightmem` | 最近 git tag | （无其它机器可校验点） | 无 `pyproject.toml`，`go.mod` 不带版本 |
| `lightplugin` | 最近 git tag | （无其它机器可校验点） | 无 `pyproject.toml` |

## 探测点

脚本按「存在性」自动探测，不存在的点跳过并注明原因：

| 探测点 | 取值方式 |
|---|---|
| `pyproject.toml` | `^\s*version\s*=\s*"..."` |
| `src/version.py` | `^\s*VERSION\s*=\s*"..."` |
| `hive.py VERSION` | `^\s*VERSION\s*=\s*"..."` |
| `CHANGELOG.md 首条` | 跳过 `[未发布]` / `Unreleased`，取首个语义化版本 |
| `cli --version` | 存在 `cli/light_unified.py` 时实跑 `python -m cli.light_unified --version` |
| `最近 tag` | `git describe --tags --abbrev=0`（无 `.git` 则跳过） |

比较时统一去掉前导 `v` / `V`（`v0.15.2` 与 `0.15.2` 视为同一版本）；展示保留原样。

## 用法

```bash
# 默认：只校验本仓 src/version.py + pyproject.toml（行为与 R96 完全一致）
python scripts/check_version_consistency.py
python scripts/check_version_consistency.py --git      # 再加上最近 tag
python scripts/check_version_consistency.py --strict   # 不一致时 rc=1（CI 用）

# 跨仓：自动探测该仓所有版本声明点，按上面的单一真源判定
python scripts/check_version_consistency.py --repo ../hive
python scripts/check_version_consistency.py --repo .
```

退出码：

- `0`：一致，或本仓探测不到任何版本声明点（跳过）；
- `1`：跨仓模式发现不一致（会逐条写出「谁 != 谁」和「该改成什么」）；
- `2`：参数错误（`--repo` 缺值或目录不存在）。

跨仓模式始终严格（不一致即 `1`），不需要也不接受 `--strict` 来放宽。

## hive 的已知不一致与修复建议

`hive` 现在有两套版本号：`hive.py` 的 `VERSION = "0.15.2"`（运行时真源）与 `pyproject.toml` 的
`version = "0.1.0"`。`pip install` 装出来是 0.1.0，`hive --version` 打印 0.15.2，用户报 bug 时说不清版本。

修复：`hive/pyproject.toml` 的 `version` 从 `0.1.0` 改成 `0.15.2`，并在 hive 的 CI 里加一条：

```bash
python /path/to/light/scripts/check_version_consistency.py --repo .
```

（已拆给 T-0272，本卡只报告、不改 hive 的任何文件。）

## 向后兼容

`--repo` 是新增参数，默认路径（不带 `--repo`）走原有逻辑：

- 只查 `src/version.py` 与 `pyproject.toml`（`--git` 再查 tag），不跑 CLI、不读 CHANGELOG；
- 输出文案、`✅/❌` 标记、`--strict` 语义与 R96 一致；
- `--git` 取到的 tag 仍去掉前导 `v` 后再展示和比较。

`python scripts/check_version_consistency.py`（CI 与任务卡 verify 用的就是这条）行为不变。
