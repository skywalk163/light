# 语言缺陷账（Language Defect Ledger）

**用途**：逐条登记光明语言已确认的设计/实现缺陷，跟踪修复状态、根因与交付物。
**状态取值**：`待修复` / `修复中` / `已修复` / `已验证` / `不修复（带理由）`。
**更新约定**：每轮外发任务（D*）交付后，由执行方把对应条目状态改为「已修复」并补 `修复版本`/`修复日期`/`交付物`。

## 二、修复要点速记

### L-068（类方法边界）
- **类结束标记**：`类结束` / `结束类` 显式收尾类定义；词法器会把 `类结束` 贪心合并成单个标识符 token，故按单 token（IDENTIFIER/KEYWORD）优先识别，并兼容 `类 结束` / `结束 类` 双 token 写法。
- **标记后的段落归模块级**：`类结束` 被解析器消费后，其后 `段落 XXX` 正常作为模块级函数（见 `examples/test_L068.light` 场景 1）。
- **同名碰撞编译警告**：模块顶层 `段落/函数/段` 与某类成员同名时给 L-068 编译警告；**仅**针对「名字与某类成员相同」这一高危场景，正常模块级函数不误报。
- **落点纠正**：检测必须加在 `parser_core._parse_module_with_recovery`（parse 实际走的容错循环），而非 `parser_stmt._parse_module`（未被调用）。

### L-073（运行期错误翻译，仅展示层）
- 翻译表（附 `（文件:行号）`，复用 L-061 的 py→light 行映射）：
  - `'X' object has no attribute 'Y'` → `类 X 缺少方法/属性 Y（文件:行号）`
  - `'Y'`（KeyError） → `字典缺少键 'Y'（文件:行号）`
  - `list index out of range` → `列表索引越界（文件:行号）`
  - `unsupported operand type(s) for OP: 'T1' and 'T2'` → `类型错误：不能对 <T1中文> 与 <T2中文> 做 <OP中文> 运算（文件:行号）`
- **不改异常类型**，只改 `ErrorFormatter.format_error` 的展示；保留 Python 原始错误行，依赖异常类型的代码零影响。

### L-070（默认参数 `{}`/`[]` 字面量 — 方案B：每次调用重新求值）
- **决策**：选方案B（每次新建），因光明用户可能不熟悉 Python 可变默认参数陷阱，且默认参数多用于「可选配置字典」，每次新建更安全。
- **实现**：在 `_generate_paragraph` / `_generate_method` 中收集 `mutable_defaults`（DictLiteral/ListLiteral 默认值），签名写 `参数=None`，函数体首行插入 `if 参数 is None: 参数 = {}` / `[]`，确保每次调用重新求值。
- **向后兼容**：用 `空` + 方法体内判空的旧写法继续可用。
- **限制**：`code_generator_unified.py` 的 `_generate_segment`/`_generate_method` 不支持默认参数生成（只收集参数名），故 unified 后端不适用。

### L-071（`.获取()` 安全访问原语）
- **实现**：新增 `_light_get(obj, key, default=None)` helper，先试 `obj.get(key, default)`，AttributeError 时试 `obj[key]`，再失败返回 default。同时支持字典（缺键返回默认值）和列表（越界返回默认值）。
- **触发条件**：MemberAccess 分支中 `expr.member == '获取'` 且实参 1-2 个时，发射 `_light_get(obj, args)` 而非 `obj.get(args)`。
- **向后兼容**：`取可选` 继续可用；`载荷.获取`（HTTP 请求体专用）行为不变。

### L-074（`是字典`/`是列表`/`是字符串`/`是布尔`/`是函数`/`是数字` 内置化）
- **实现**：在 `builtin_map` 中登记六个类型判断函数映射到 `_light_builtin.*`；`keywords.py` 的 `VERB_ARITY` 补齐 `是布尔`/`是函数`/`是数字`（`是字典`/`是列表`/`是字符串` 已有登记）；`stdlib/builtins.py` 新增三个宿主转发函数（委托 `内置核心判型` 模块）；`stdlib/内置核心判型.light` 补充纯光明实现。
- **命名区分**：`是数字` → 检查 int/float（`_light_builtin.是数值`）；`是数字符` → 检查单个字符是否为数字（`_light_builtin.是数字`，`str.isdigit`），两者语义不同。
- **向后兼容**：`从 内置核心判型 导入 ...` 的旧写法继续可用（导入同名函数不冲突）。

### L-069（`序列化JSON` 布尔值 — JSON 合法 `true`/`false`）
- **问题范围**：仅 antlr 后端。`src/` 后端因 `真`→Python `True`（源级映射 `bootstrap_v3_gen.py:92`），`json.dumps(True)` 天然产 `"true"`，无需改。stdlib 真身 `JSON核心.light` 已在先前修复（`编码值` L40-43 bool→`"true"`/`"false"`，`解析值` L220-228 逆向 `true→真`/`false→假`/`null→空`）。
- **根因**：antlr 后端 `_builtin_stringify_json` 直接 `json.dumps(val)`，`val` 是含 `LightValue` 包装的 dict；`json.dumps` 不认识 `LightValue`，嵌套布尔无法正确序列化。
- **修复**：新增 `_json_plain` 静态方法，递归剥离 `LightValue`→`.value`、dict→递归、list→递归，返回纯 Python 值。`_builtin_stringify_json` 改为 `json.dumps(self._json_plain(val), …)`。`LightValue.value` 对布尔是 Python `True`/`False`，`json.dumps` 正确产 `true`/`false`。
- **`解析JSON` 逆向**：`_builtin_parse_json` 已在 HEAD 中正确处理 `bool`→`LightValue('布尔')`、`None`→`LightValue('空')`，无需改。
- **向后兼容**：`1`/`0` 仍产 JSON `1`/`0`（整数不变）；`true`/`false` 解析回 `真`/`假`。

### L-072（`转字符串` 方案A — 光明相输出，容器发 JSON）
- **方案A 口径**（与 `stdlib/内置核心转换.light:29` 规范真身逐字一致）：
  - `真` → `"真"`、`假` → `"假"`、`空` → `"空"`（光明字面，非 Python `True`/`False`/`None`）
  - `str` → 原样返回，**不加引号**（日志与错误消息拼接依赖此行为）
  - `dict`/`list` → JSON 文本（双引号、`ensure_ascii=False` 保中文、紧凑无缩进）
  - 其余 → `str()` 兜底
- **三后端逐一线修复**：
  1. **stdlib 真身** `内置核心转换.light`：`转字符串` 段落改写为方案A（`值 == 空`→`"空"`、`值 == 真`→`"真"`、`值 == 假`→`"假"`、dict/list→`序列化JSON`、其余→`str()`）。
  2. **bootstrap 地板** `builtins.py:390`：`转字符串` 函数体改为方案A（`is True`/`is False`/`is None` 前置，`isinstance(str)` 原样，`isinstance(dict,list)`→`json.dumps(…, ensure_ascii=False)`，`str()` 兜底）。bool 必须在 int 之前判（Python 里 `bool` 是 `int` 子类）。
  3. **antlr 后端** `light_builtins.py`：`_builtin_to_string` 改为方案A，dict/list 路径复用 L-069 的 `_json_plain` helper 剥离 `LightValue` 包装后 `json.dumps`。
  4. **src fallback** `code_generator.py:1136,1191`：`转字符串 = str` 兜底改为方案A lambda（`is True`/`is False`/`is None`/`isinstance(dict,list)`→`json.dumps`/`str()`），仅在 `.light` 真身加载失败时触发。
- **向后兼容**：`转字符串("abc")` 仍产 `abc`（不加引号）；`转字符串(25)` 仍产 `25`。
