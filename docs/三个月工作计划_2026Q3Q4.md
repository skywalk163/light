用户指出「AI 开发速度快，三个月计划可能 1-2 天完成」。基于当前 AI 辅助开发的实际能力，预估如下：

| 测试修复（已知 bug） | 2 天 | 0.5 天 | 4x |
| 桥接模块批量生成 | 5 天 | 1 天 | 5x |
| 框架库开发 | 5 天 | 2 天 | 2.5x |

| 文档编写 | 3 天 | 1 天 | 3x |

**乐观预估**: 如果 AI 辅助效率持续提升，三个月计划可能在 **15-20 个有效工作日** 内完成。

**保守预估**: 考虑调试、集成、回归测试的不可避免开销，实际需要 **25-30 个有效工作日**。

### 9.2 多代理协作策略

```
                    ┌─────────────┐
                    │  DuMate 主控  │
                    │  (协调+整合)  │
                    └──────┬──────┘
                           │
          ┌────────────────┼────────────────┐
          │                │                │
  ┌───────▼───────┐ ┌─────▼──────┐ ┌───────▼───────┐
  │ Agent A       │ │ Agent B    │ │ Agent C       │
  │ 核心编译器     │ │ 生态系统    │ │ 开发者工具     │
  │ Lexer/Parser  │ │ duanpub    │ │ VS Code/LSP   │
  │ 类型系统       │ │ 框架库     │ │ Playground    │
  └───────────────┘ └────────────┘ └───────────────┘
```

- **Agent A（编译器）**: 专注 parser/lexer/type-system，不碰 stdlib 和工具链
- **Agent B（生态）**: 专注 duanpub 桥接和框架库，不改核心编译器
- **Agent C（工具）**: 专注 VS Code 扩展和 Playground，不改编译器和 stdlib
- **DuMate（主控）**: 协调任务分发、合并冲突、质量审查、测试验证

### 9.3 质量保障红线

AI 辅助开发必须遵守的质量规则：

1. **每次变更必须跑全量测试** — 0 failures 是硬性门槛
2. **新增功能必须附带测试** — 无测试的代码不合并
3. **不允许改测试期望值来"修 bug"** — 必须修复底层逻辑
4. **不允许用 SkipTest 跳过失败** — 必须修复或标注为环境依赖
5. **每次提交前 `git status` 检查** — 不引入新的未跟踪临时文件
6. **CHANGELOG 必须同步更新** — 每个功能变更都有记录
