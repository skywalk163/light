# 迁移指南：从 v3.3 到 v4.0

光明 v4.0 是一次重大的语言版本升级，引入了五层分层架构、单字核心关键字系统、类型系统等新特性。本指南将帮助你从 v3.3 平滑迁移到 v4.0。

## 重要说明

**v4.0 完全兼容 v3.3 代码。** 所有 v3.3 的双字关键字作为别名永久保留，v3.3 代码无需任何修改即可在 v4.0 中运行。

迁移到 v4.0 新语法是**可选的**，但推荐使用新语法以获得更好的开发体验。

## 破坏性变更

虽然 v4.0 完全向后兼容，但以下变更需要注意：

### 1. 关键字简化

v4.0 引入了 L0 核心单字关键字，原有的双字关键字作为别名保留：

| v3.3 双字 | v4.0 单字 | 状态 |
|-----------|----------|------|
| `如果` `那么` `否则` | `若` `则` `否` | 别名保留 |
| `打印` | `印` | 别名保留 |
| `遍历` | `遍` | 别名保留 |
| `段落` | `段` | 别名保留 |
| `返回` | `返` | 别名保留 |
| `导入` `导出` | `引` `出` | 别名保留 |
| `尝试` `捕获` `抛出` | `试` `捕` `掷` | 别名保留 |
| `匹配` `情况` | `匹` `例` | 别名保留 |
| `跳出` `跳过` | `断` `跃` | 别名保留 |
| `新建` | `新` | 别名保留 |

### 2. 运算符变化

v4.0 推荐使用符号运算符代替中文别名：

| v3.3 | v4.0 | 说明 |
|------|------|------|
| `加` `减` `乘` `除` | `+` `-` `*` `/` | 符号运算符 |
| `大于` `小于` `等于` | `>` `<` `==` | 符号比较 |
| `并且` `或者` `不是` | `且` `或` `非` | 单字逻辑 |

### 3. 标点变化

v4.0 L2 文言体推荐使用英文标点：

| v3.3 | v4.0 (L2) | 说明 |
|------|-----------|------|
| 中文逗号：， | 英文逗号：, | L2 推荐 |
| 中文冒号：： | 英文冒号：: | L2 推荐 |
| 句号结尾 | 无句号 | L2 风格 |

## 使用迁移工具

光明 v4.0 提供了自动迁移工具，可以一键将 v3.3 代码转换为 v4.0 新语法。

### 基本用法

```bash
# 迁移单个文件
light --migrate-v3-to-v4 旧文件.light -o 新文件.light

# 迁移整个目录
light --migrate-v3-to-v4 ./旧项目/ -o ./新项目/

# 原地迁移（覆盖原文件）
light --migrate-v3-to-v4 文件.light --in-place
```

### 迁移选项

```bash
# 指定目标文体
light --migrate-v3-to-v4 文件.light --style=baihua  # 转换为 L1 白话体
light --migrate-v3-to-v4 文件.light --style=wenyan   # 转换为 L2 文言体（默认）

# 保留双字别名
light --migrate-v3-to-v4 文件.light --keep-aliases

# 预览迁移结果（不实际写入）
light --migrate-v3-to-v4 文件.light --dry-run
```

## 分步迁移示例

### 示例：将 v3.3 代码迁移到 v4.0 L2 文言体

**迁移前（v3.3）：**

```python
# v3.3 风格
打印("你好，光明！")

段落 计算(甲, 乙)：
    如果 甲 > 乙：
        返回 甲加乙
    否则：
        返回 甲减乙

设 结果 = 计算(10, 5)
打印(结果)
```

**运行迁移命令：**

```bash
light --migrate-v3-to-v4 old.light -o new.light
```

**迁移后（v4.0 L2 文言体）：**

```python
# v4.0 L2 文言体
印("你好，光明！")

段 计算(甲, 乙):
  若 甲 > 乙:
    返 甲 + 乙
  否:
    返 甲 - 乙

设 结果 = 计算(10, 5)
印(结果)
```

### 示例：迁移到 L1 白话体

```bash
light --migrate-v3-to-v4 old.light -o new.light --style=baihua
```

**迁移后（v4.0 L1 白话体）：**

```python
# v4.0 L1 白话体
打印("你好，光明！")

段 计算(甲, 乙)：
  如果 甲 > 乙：
    返回 甲 + 乙
  否则：
    返回 甲 - 乙

设 结果 = 计算(10, 5)
打印(结果)
```

## 手动迁移要点

如果选择手动迁移，以下要点值得注意：

### 1. 关键字替换对照表

| 类别 | v3.3 | v4.0 L1 白话体 | v4.0 L2 文言体 |
|------|------|----------------|---------------|
| 输出 | `打印` | `打印` | `印` |
| 条件 | `如果` `那么` `否则` | `如果` `否则` | `若` `则` `否` |
| 遍历 | `遍历` | `遍历` | `遍` |
| 函数 | `段落` `返回` | `段` `返回` | `段` `返` |
| 异常 | `尝试` `捕获` `抛出` | `尝试` `捕获` `抛出` | `试` `捕` `掷` |
| 模块 | `导入` `导出` | `导入` `导出` | `引` `出` |

### 2. 标点替换

L2 文言体推荐使用英文标点，但这不是强制要求：

```python
# v3.3（中文标点）
如果 甲 > 乙：
    打印("甲更大")

# v4.0 L2（英文标点）
若 甲 > 乙:
  印("甲更大")
```

### 3. 缩进调整

v4.0 推荐使用 2 空格缩进（v3.3 常用 4 空格），但这不是强制要求。迁移工具会自动调整缩进。

## 常见迁移陷阱

### 陷阱 1：忘记迁移工具不会影响功能

迁移工具只改变语法风格，不会改变代码的逻辑和行为。迁移前后程序的输出和行为完全一致。

### 陷阱 2：认为必须迁移

v4.0 完全兼容 v3.3，现有代码不需要任何修改。如果团队还没准备好切换风格，可以继续使用 v3.3 语法。

### 陷阱 3：混用新旧风格导致混乱

虽然 v4.0 支持新旧关键字混用，但建议整个项目保持一致的风格：

```python
# 不推荐：混用新旧风格
如果 甲 > 乙:     # v3.3 风格
  印("甲更大")    # v4.0 风格

# 推荐：统一风格
若 甲 > 乙:       # v4.0 L2 风格
  印("甲更大")
```

### 陷阱 4：忽略文体声明

迁移后建议在文件首行添加文体声明：

```python
# 文体: 白话  → L1 白话体
# 文体: 文言  → L2 文言体
```

## 常见问题

### Q: 迁移后代码变短了，正常吗？

正常。L2 文言体使用单字关键字和英文标点，代码量会比 v3.3 减少约 20-30%。

### Q: 迁移工具会修改注释吗？

不会。迁移工具只处理代码中的关键字、运算符和标点，注释内容保持不变。

### Q: 迁移后还能用 v3.3 的双字关键字吗？

可以。v4.0 永久保留 v3.3 双字关键字作为别名，新旧关键字可以混用。

### Q: 如果迁移工具报错怎么办？

检查源文件是否有语法错误。迁移工具要求源文件在 v3.3 下是合法的。如果遇到问题，可以在 GitHub 提交 Issue 报告。
