# 门禁机初始化清单 · 0.88（FreeBSD）

> **定位**：0.88 是 Light 的**唯一权威判绿机**（0.82 / 0.86 已关机下线）。
> 本清单是**换机 / 重装 / 新建干净树**后必须逐项核对的最小集合。任一项没做，会出现「同一 commit 本机绿、0.88 红」的假红。
>
> **R164-D 起，「人肉三步」收敛成一条命令**：
>
> ```bash
> cd <主测试树> && <venv>/bin/python scripts/门禁机自检.py --check
> # 退出码 0 = 全 PASS；1 = 有 FAIL（②LH 副本 / ③LOCKED 依赖）
> ```
>
> 该命令已**挂进真门禁**：`.git/hooks/pre-push` 在推送前调用
> `scripts/门禁机自检.py --check --allow-dirty`（跳过「①工作树干净」——推送时工作树常含
> 未提交/未跟踪物，闸门只该看固化项），②③④ 任一 FAIL 即**拦截推送**。模板在
> `tools/ci/hooks/pre-push`，安装：`cp tools/ci/hooks/pre-push .git/hooks/pre-push && chmod +x .git/hooks/pre-push`。
>
> 依赖版本的**唯一权威**是 `scripts/ensure_venv.py` 的 `LOCKED` / `WATCH` 常量，本文件只做清单指引，不重复维护版本号。

## 2. 目录树（**两个都要**）

1. **主测试树**：git 工作树（如 `~/r164clean`、`~/r164t4`），`git fetch` 后 ff 到本轮目标 commit。
   要求：跑测试前确认 `git rev-parse --short HEAD` 等于本轮基线。**判绿要干净检出**：
   `git status --porcelain` 干净（未提交 / 未跟踪物会让「同 commit」不成立）。
2. **lightharness 树**：`~/lightharness`。
   ⚠️ **它不是 git 仓库，只是同步过去的拷贝**，是 0.88 门禁机**最脆的一环**（R161-E / R164-T2 各坏过一次）。
   `tests/unit/test_builtins_drift.py` 通过 `scripts/sync_builtins.py` 的 `LH_PATH`（= 主树同级 `lightharness/stdlib/...`）读它。
   树一陈旧或被**裸拷贝覆盖**，`test_lh_name_diff_only_lh_only` / `test_lh_public_body_hash_equals_main` 就假红。

   刷新方式（幂等，`newline="\n"` 写盘，不会带出 CRLF，且自带反例自检）：
   ```bash
   cd <主测试树> && <venv>/bin/python scripts/sync_builtins.py    # 验收：结尾打印「[自检] 全部通过 / 同步完成，exit 0」
   ```
   验收：`pytest tests/unit/test_builtins_drift.py -n 0 -p no:randomly -q` 全绿。

当前 `LOCKED`（缺了会真红，故必须锁）：

| 包 | 锁版本 | 缺失后果 |
|---|---|---|
| `lunardate` | 0.3.0 | `tests/test_datetime.py` 农历 8 条红 |
| `requests` | 2.34.2 | `tests/lightpub/test_lightpub_bridge.py` 6 errors |

超时不要慌，也不要换源强装；装完用 `pip show cryptography requests` 核对版本。

⚠️ **禁止**用 `LIGHT_ALLOW_SKIP_TLS_TEST=1` 之类环境变量把 TLS 用例放行——那是藏红，不是修复。

## 4. 初始化后的一次性自检（**「跑一条命令」**）

```bash
cd <主测试树>
git status --porcelain                                   # 期望空（判绿树）
<venv>/bin/python scripts/门禁机自检.py --check --venv <venv>   # 期望「结果：全 PASS」，exit 0
<venv>/bin/python -m pytest \
  tests/unit/test_builtins_drift.py tests/test_tls_light.py \
  tests/lightpub/test_lightpub_bridge.py tests/test_async_io_light.py \
  -n 0 -p no:randomly -q                                 # 期望 0 failed / 0 error
```

`门禁机自检.py --check` 四步：①git 树（HEAD / 工作树干净 / 非 shallow）②lightharness 副本（口径复用 `sync_builtins.py`）
③`ensure_venv.py` 的 `LOCKED` 逐项版本核对 ④baseline 收集数（`tests/ci_baseline_failures.txt` 快照 collected 与
`pytest --collect-only` 实际门收集数偏差 ≤ ±10%，R165 补；防基线虚高、分辨力归零）。**推送场景**用 `--allow-dirty` 只核②③④（见文首）。

> ④ 的口径：collect-only 只读不执行（秒级），本机实测基线 9399 vs 实际收集 9348，偏差 0.54% PASS。
> 若实际收集骤降（大面积 skip / 收集失败），偏差超 ±10% 即 FAIL——那是门本身坏了，不是「变绿」。

## 5. 假红速查（同一 commit 本机绿、0.88 红时先查这里）

| 现象 | 真因 | 处置 |
|---|---|---|
| builtins drift 报一批「LH 副本缺 N 项」/「LH 独有函数」不符 | `~/lightharness` 树陈旧或被裸拷贝覆盖 | 跑 `sync_builtins.py`（§2） |
| `test_tls_light.py` 只剩 1 条红 / lightpub 6 errors / TLS 异步读腿 3 errors | venv 缺 `cryptography` / `requests` | `ensure_venv.py`（§3） |
| pytest **根本起不来**（`unrecognized arguments: --timeout=60`，exit 4） | venv 缺 `pytest-timeout` | `ensure_venv.py`（§3，已入 LOCKED） |
| 断言「不是纯 CRLF」「锚点缺失」这类行尾红 | 测试判据硬编码 `\r\n`；git 索引 LF，Windows autocrlf 检出 CRLF，FreeBSD 检出 LF | 判据必须行尾无关：读取后 `replace(b'\r\n', b'\n')` 再比（R161-E 已修 #5 / #8：`test_C1_骨架文件存在且为纯CRLF` 判「行尾统一」，`test_源码级_病灶depth感知锚点存在` 走 `_read_rt_norm()`） |
| 全量门出现「协程恢复 / 心跳协程 SIGSEGV」类 | 真实产品缺陷，不是环境 | 按实记红，禁止改判据掩盖 |
| ④baseline 偏差 FAIL（collected 骤降 / 与基线脱节） | 大面积 skip、收集失败，或基线陈旧 | 先修收集问题；确认门正常后用 `check_ci_baseline.py --write-baseline` 重建基线 |

## 6. 维护规则

- 新增 `LOCKED` 项必须附「**缺了会红**」的用例证据（哪几条、红成什么样），否则只进 `WATCH`。
- 改 `ensure_venv.py` 的 `LOCKED` 后，在 0.88 跑一次 §3 的 `--check` + §4 自检（含 `门禁机自检.py --check`），
  把原始输出贴进当轮交付报告。
- 本清单与 `scripts/ensure_venv.py`、`pyproject.toml` 的 `[dev]` 组三处需同步；版本号只写在本脚本里。
- `门禁机自检.py` 的口径（`LH_ONLY` / `block_hash`）**不另写一份**，直接 import `sync_builtins`，两处口径迟早分叉。
