### Task 0 — `vscode_extension_completions` + `native_leg_capability` 测试隔离（26 个 ERROR/fail，全量专属）

**文件**：`tests/test_vscode_extension_completions.py`（18）、`tests/unit/test_native_leg_capability.py`（8）
**现象**：这两文件**单独跑（含 `-n 8`）都 29 passed**，但在**全量**里仍失败：
- vscode：`AssertionError: 扩展文件不存在: /home/workbuddy/light_verify/vscode-extension/extension.js`（路径是绝对路径、文件确实存在、事后 `os.path.exists` 也返回 True）
- native_leg：`能力清单 JSON 不见了: tests/unit/../../docs/原生腿能力清单.json`（**相对路径**，依赖 cwd）
**根因**：**测试顺序污染全局状态**——全量里排在它们之前的某个测试改了 cwd 或泄漏了 monkeypatch，使后续用例的（相对）路径解析失败 / `os.path` 行为异常。原生腿用相对路径所以对 cwd 敏感；vscode 用绝对路径仍挂，说明还有更全局的泄漏（cwd 或 `os.path` 被 mock）。
**修复指引**：
1. `tests/unit/test_native_leg_capability.py` 的 `_加载清单`：把 `tests/unit/../../docs/原生腿能力清单.json` 改成基于 `__file__` 的**绝对路径**（`os.path.join(os.path.dirname(__file__), '..', '..', 'docs', '原生腿能力清单.json')`），消除 cwd 依赖。
2. 定位污染源：在 0.88 上跑 `python3 -m pytest tests/ -n 0 -p no:cacheprovider -q`（单进程、确定性），然后二分/逐个目录加入 vscode+native_leg 重跑，找出**哪个测试**让 cwd 变脏或未还原 monkeypatch（重点嫌疑：`tests/` 下多个文件在 import 时 `os.chdir(..)` 到仓库根，以及 `test_v4_1_integration.py`/`test_module_system*.py`/`test_missing_stdlib.py` 里 `os.chdir` 到临时目录的用例——确认其 restore 在所有异常路径上都执行）。修法：用 `monkeypatch.chdir` 或 fixture 的 `yield`+`finally` 严格还原，不要依赖模块级 `os.chdir`。
3. 验收：0.88 全量里这两文件不再出现（从 FAIL/ERROR 变为 pass）。
**注意**：这是"全量才暴露"的隔离 bug，不要当代码逻辑 bug 硬改业务逻辑；核心是让测试不依赖全局 cwd 且不泄漏状态。

### Task 1 — `数学.light` 命名/特性对齐（5 个 ImportError）
**文件**：`tests/test_stdlib_complete.py`
**失败**：`from 数学 import 排列, 复数实部, 黄金比例, 双曲正弦, 反正弦` → `cannot import name`
**现实**：`stdlib/数学.light` 当前导出 `绝对值/最大值/最小值/幂/平方根/立方根/正弦/余弦/正切/对数/自然对数/.../pi/pow/sqrt/sin/cos/tan/floor/ceil/round/random`，**无上述 5 个**。
**修复指引**：
- `双曲正弦`→ 应实现为 `sinh(x)`（或别名）；`反正弦`→ `arcsin(x)`；`黄金比例`→ 常量 φ；`复数实部`→ 复数类型的实部取值；`排列`→ 排列组合函数。
- 若复刻规范里这 5 个本不属于数学模块范畴，则改测试 import 到正确模块。
**验收**：`tests/test_stdlib_complete.py` 在该类 import 处全绿。

### Task 2 — `数据结构.light` 命名对齐（6 个 ImportError）

### Task 4 — `日期` 模块 LunarDate snake/camel 命名（8 个 AttributeError）

### Task 5 — `phase4` 对象式 API 契约（~17 个 AttributeError）
**文件**：`tests/test_stdlib_phase4.py`
**失败示例**：`'dict' object has no attribute '是否有效'`、`'bool' object has no attribute '是否有效'`、`'dict' object has no attribute '设置'/'获取'/'验证'/'_总数'`、`'bool' object has no attribute 'get'`。
**根因**：测试把 stdlib 返回的对象当成**带方法的对象**（如 `结果.是否有效()`、`状态.设置(...)`），但 stdlib 实际返回**普通 dict / bool**，方法以函数式提供（如 `是否有效(结果)`、`设置当前(状态, 值)`）。
**修复指引**：二选一，按复刻规范统一——
- (A) 改测试：把 `X.方法(...)` 改成函数式 `方法(X, ...)`（风险低，推荐先试）；
- (B) 改 stdlib：让这些构造返回带方法的类（改动大，需确认是否目标设计）。
- 涉及模块：`数据验证`(验证结果)、`进度条`(状态)、`缓存管理器`(见下) 等。
**验收**：`tests/test_stdlib_phase4.py` 的 AttributeError 全消除（该文件还剩 bytes/str、ord、kwarg 等见 Task 8）。

### Task 6 — `phase13`/comprehensive/pure_light_hook 的 NameError（~17 个）
**文件**：`tests/test_stdlib_phase13.py`、`tests/test_stdlib_comprehensive.py`、`tests/test_pure_light_hook.py`
**失败示例**：`name '列表' is not defined`(×7)、`name '无' is not defined`(×3)、`name 'split'/'去除空格'/'replace'/'find' is not defined`。
**根因**：测试用了一批**解释器未定义的标识符**——`列表`(应用 `新建列表` 或 `[]`)、`无`(None，light 里可能是 `空`)、`split/replace/find/去除空格`(字符串方法，误当作裸全局名，应为 `文本.分割()` 等方法式或对应 builtin)。属于测试方言/写法与 light 解释器不符。
**修复指引**：按 light 实际 builtin/方法替换这些名字；`split/replace/find` 改为 `文本.分割(分隔符)` 等（查 `src/keywords.py` 注册表确认正确写法）；`列表`→`新建列表()`；`无`→`空`。逐文件修完让 NameError 消失。
**验收**：上述三文件 NameError 全消除。

### Task 7 — 原生腿能力边界：函数值传递（~13 个 RuntimeError/Exception）
**文件**：`tests/test_stdlib_phase3.py`（时间管理：`倒计时`/`定时器`/`多次计时`/`计时函数` 报 `原生腿不可用：回调需函数值动态调用`）、`tests/test_stdlib_phase9.py`（`断言失败`/`断言可调用`/`断言满足条件`/`链式断言器` 报 `能力边界：原生腿函数值不可调用…降级 stub`）
**根因**：这些是**已知语言限制**——原生腿（native backend）暂不支持把函数作为值传递/动态调用。测试在验证解释器这一能力，当前必败。
**修复指引**：**不要当 bug 硬修代码**，改为在测试上标注预期失败，让 CI 不红但保留追踪：
```python
@pytest.mark.xfail(strict=False, reason="原生腿暂不支持函数值作为值传递（见原生腿能力边界.md）")
```
或整文件/整类加 `pytest.mark.xfail`。待原生腿支持函数值后再摘掉标记。
**验收**：这些用例从 FAILED 变为 XFAIL（不计失败），全量 summary 不再出现它们。

### Task 8 — 具体真 bug（bytes/str/ord/kwarg + R13C + llvm_c3_expr，~12 个）
**文件**：`tests/test_stdlib_phase4.py`、`tests/unit/test_原生腿_R13C_对拍扩展.py`、`tests/test_llvm_c3_expr.py`
**失败与定位**：
- **bytes/str**：`AssertionError: 'hello' != b'hello'`、`'68656c6c6f' is not an instance of <class 'bytes'>`、`IndexError: string index out of range`、`TypeError: ord() expected string of length 1, but int found` → 编码/字节处理（`编码解码`/`字节转字符串`/`字符串转字节`）返回 str 而测试期望 bytes；某处把字符当 int 传 `ord()`。
- **缓存管理器 kwarg**：`TypeError: 缓存管理器() got an unexpected keyword argument '最大容量'` → 调用用了 `最大容量=` 但定义形参是 `最大`（查 `stdlib` 缓存模块）。
- **R13C URL 编码**：`实际=['a%20b%26c%3D1',...,'path/to?q=光明'] 期望=[...,'path/to?q=奥楥']` → URL 编码对 `光明` 两字结果不一致（编码实现差异，疑似字符集/引号 bug）；另 `实际=['1','0.571429','1','0'] 期望=[1.0,1.0,1.0,0.0]` → 数值被转成 str。
- **llvm_c3_expr**：`Failed: DID NOT RAISE <class 'NotImplementedError'>`、数值差（`+ 1.33333`）、`Use -v to get more diff` → 原生腿表达式求值（异常传播 / 除法精度）错误。
**修复指引**：逐条定位 stdlib/编译器代码修：
- 字节函数明确返回 `bytes`；`ord()` 调用前确认传入是长度为 1 的 str。
- `缓存管理器` 形参对齐（`最大容量` 或调用方改 `最大`）。
- R13C 的 URL 编码对非 ASCII 字符（`光明`）需要按规范（UTF-8 percent-encoding）实现；数值型断言确认类型。
- llvm_c3_expr 的 `NotImplementedError` 应在对应未实现分支抛出；除法精度对齐 Python 语义。
**验收**：对应用例在 0.88 转绿。
