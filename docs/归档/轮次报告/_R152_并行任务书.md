## 二、关键发现（R152 起草前本机复验结论，各线动笔前必读）

### 2.1 集合工具 5 缺口是「带方法/属性的对象」需求，超出补函数范畴

`stdlib/集合工具.light`（带魔数、无同名 `.py`——**`集合工具.py` 已删**）现返回普通 dict/list，
phase13 测试要求（`tests/test_stdlib_phase13.py:655` 起 `测试集合工具模块` 类）：

| 测试 | 要求的 API | 现状 | 可行性初判 |
|---|---|---|---|
| `test_双端队列` | `dq.右入队/右出队/左入队/左出队` | 返 dict 包装 | ✅ **可纯光明类化**（光明类支持字段+`己.`+方法，见 `stdlib/HTTP服务端.light:63`） |
| `test_计数器最常见` | `c.最常见(2)` 返 [(elem,count)...] | 返普通 dict | ✅ **可纯光明类化** |
| `test_命名元组` | `点(3,4)` 后 `p.x`/`p.y`（**动态字段名**） | 返字段名 list | ❓ 需调查：光明类字段是静态声明，动态属性访问疑似不支持 → D 线 |
| `test_默认字典`/`test_默认字典列表` | `d['缺失键']` 触发工厂、`d[k] += 1` | 返普通 dict（工厂只存不用） | ❓ 需调查：需「缺失键读拦截」对象模型支持 → D 线 |

**本机复验（两种姿势，都已跑）**：
- 直跑 `pytest tests/test_stdlib_phase13.py -k 测试集合工具模块` → **8 条全 `ModuleNotFoundError`**
  （钩子没装：`stdlib/_light_import_hook.py` 只由「跑过光明产物」的测试顺带安装，本机单文件跑无人装）。
- 先 `install([stdlib])` 再跑 → **3 过 5 红，与 0.82 完全一致**（双端队列/命名元组/计数器最常见/默认字典/默认字典列表）。
- ⇒ 5 缺口是**通用缺口**（不是环境分叉，不能照抄 `_原生腿环境分叉_XFAIL` 先例）；
  本机直跑全红是**钩子安装时序依赖**，属测试装置问题（C 线）。

### 2.2 护栏盲区：魔数-only 模块不在扫描面

`tests/unit/test_R150_魔数接管对等.py` 的 `扫描缺口()` 只查「**含魔数 + 有同名 `.py`**」的组合。
`集合工具.py` 已删 ⇒ `集合工具.light` 即便语义缺一大截也**永不过护栏**——这正是 5 条红能活到
R152 的原因。同类模块还有 `统计.light`、`数学统计.light`（后者头注释仍写「对齐 stdlib/数学统计.py」
但该 `.py` 已不存在，oracle 悬空）。**E 线必须补这个盲区。**

### 2.3 `test_展开用户目录` 根因方向（B 线现场定案）

0.82 junit 原文：`'test'.startswith('/home/ai')` 假——光明腿返回了 **`'test'`**（只剩尾巴）。
`stdlib/文件系统.light:273` 的实现：`USERPROFILE` 空 → `HOME` 空 → `返回 路径`（应是 `'~/test'`）；
实际返回 `'test'` 说明走了 `连接路径(家, 尾)` 且 **`家` 为空/null**——即 `是空(家)` 没拦住。
两个嫌疑：① 原生腿子进程 **env 未传播**（HOME/USERPROFILE 读不到）；② `环境变量()` 读缺省变量时
返 null 而非 `""`，`是空(null)` 为假。注意 `test_展开环境变量`（同文件、同 fixture）在 0.82 是过的——
B 线复现时留意两测试的 env 读取路径差异，别被表面现象带偏。

### 2.4 `test_获取文件所有者` 口径分歧

测试（`tests/unit/test_R148_文件系统补齐.py:55`）断言 `got["用户"] == str(got["uid"])`——
意图是**两腿都字符串化 uid**（Windows 无 pwd/grp 时的统一口径）。0.82 上 `.py` 参考腿走了
`pwd.getpwuid` 返回真名 `'ai'`，光明腿返 `'1002'`。**裁定方向：改 `.py` oracle 去掉 pwd/grp 真名查询、
统一字符串化**（与测试注释声明的口径一致），而不是让光明腿去调 pwd（Windows 腿做不到，会制造新的环境分叉）。

### A 线 · 集合工具能力债（零 `src/`，动 `stdlib/集合工具.light`）

- **目标**：`测试集合工具模块` 8 条中，本线负责**双端队列 + 计数器最常见 2 条转绿**（类化实现），
  其余 2 类（命名元组/默认字典）先出**可行性调查报告**（半天内可出的轻量活），结论移交 D 线定案。
- **类化做法**（照 `stdlib/HTTP服务端.light` 的类语法）：
  - `双端队列(可迭代对象, 最大长度)` 返 `类 双端队列类` 实例：字段 `队列`（list）+ `最大长度`；
    方法 `右入队(项)/左入队(项)/右出队()/左出队()`（`列表追加`/`列表弹出` 或索引操作实现；
    最大长度非空时超长截断——**注意两腿陷阱①：`列 + [项]` native 返 0 长，用 `列.追加(项)`**）。
  - `计数器(可迭代对象)` 返 `类 计数器类` 实例：字段 `映射`（dict）+ 方法 `最常见(n)`
    （按键值降序取前 n，返 `[(elem, count), ...]` 列表；并列顺序按 Python `Counter.most_common`
    语义——**插入序稳定**，与 A 线 R151 随机族对拍同源的严谨度要求）。
  - 兼容性：现有 3 条过的测试（`test_计数器` 用 `c['a']`、`test_有序字典`、`test_统计频率`）**不许回归**——
    计数器类化后 `c['a']` 是否还工作？若类不支持下标读取，需在类里保留 dict 兼容路径或调整——
    **这是 A 线第一个要验证的点**（先探针再动手，探针避开 `排序/反转/写/读` 等被内置截胡的方法名）。
- **交付**：本机（钩子装好后）8 条中 6 条绿（+类化 2、原 3 不回归、调查移交 1 类……按实际裁定）；
  `stdlib/集合工具.light` 顶部「原生腿能力边界」注释块同步更新（边界条目逐条消）。
- **禁令**：不许改 `tests/test_stdlib_phase13.py` 的期望值来凑绿（改测试是 D 线裁定+E 线登记的事）。
