## 5. 删影子决策：**不删 `stdlib/文件系统.py`**

按 SKILL §6.1 删影子协议 + 任务书"不设部分覆盖也删的例外"铁律：

**保留 .py 的两个硬理由：**

1. **未全覆盖**：38/115 函数 runtime 无原语，纯光明实现无法替代。删 .py 会让这 38 个函数直接消失。
2. **两处已验证的语义分歧**（删了会炸积木库 / 改语义超 scope）：
   - py 的 `文件列表` / `遍历目录` 真实语义是「只文件 + 完整路径」；现有 `.light` 段落转发 `_light_builtin.列出目录` 返回裸文件名，且积木库 `工具/列目录文件.light` 依赖裸名行为（R129 CI 闸门曾因此红过）。修它会破坏积木库，超出 C 线边界。

**结论**：登记留 R146——待 TRUNK 补齐归档/磁盘/权限/符号链接/seek/监控等原语，并处理 `文件列表/遍历目录` 语义分歧与积木库迁移后，再走"115/115 全覆盖 + 三腿对拍一致 + 删后三断点"删影子流程。

## 6. Native 腿边界（TRUNK 差距，非 C 线缺陷）

在 0.82 用 `cli/light.py run --backend native` 编译对拍驱动时，native（C/LLVM）codegen 报：
- `未定义的段落：扩展名`（全局原语未注入 native）
- 改为 `_light_builtin.分割扩展名` 后：`未定义的模块点访问：分割扩展名`

**结论**：native codegen 既未注入全局 `扩展名()/目录名()` 路径原语，也未暴露 `_light_builtin.分割扩展名/分割路径` 的 C 绑定。这是 TRUNK 地板层 native codegen 的原语覆盖缺口。C 线不删影子，native 腿对 `文件系统` 模块 fallback 到 `.py`，不阻塞交付。src / unified（转译）腿已全绿。
