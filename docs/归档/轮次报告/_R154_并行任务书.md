## 一、现状账（四条线的出处与起草时核实结论）

### 1.1 L-213 · `环境变量()` 两腿口径分歧 —— 比缺陷账记录的更深（已查实两点深化）

缺陷账/空值规范 §9 只记了“缺 key：src 返 None / 原生返 `""`”。本轮起草时查实**还有一层未记录的 arity 分歧**：

| 场景 | src 腿（`stdlib/builtins.py:308`） | 原生腿（现状） |
|---|---|---|
| 缺 key，1 参 `环境变量(名)` | `None`（null） | `""` |
| 缺 key，2 参 `环境变量(名, 默认)` | `默认` | **`""`——默认参数被静默丢弃** |
| key 存在 | 变量值 | 变量值（对齐） |

**查实点（派单前已验证，A 线可直接引用）**：
1. `src/llvm/codegen_typed.py:2646-2656` 的 `环境变量` 分支**只传 `args[0]`** 给 `dv_getenv`，`args[1]`（默认值）从未到达 C 侧。
2. `src/llvm/runtime_typed.c:3755` `dv_getenv(const char* name)` **只有 1 参**，缺 key 返 `dv_strdup("")`；0 参调用在 codegen 侧返 `""` 常量。
3. **连带损伤（本轮新发现）**：`stdlib/os.light:30-35` 的 `getenv(名, 默认 等于 "")` 写的是
   `设 值 为 环境变量(名)` + `如果 值 == 空: 返回 默认`——原生腿缺 key 返 `""` 而非 null，
   `"" == 空` 为假 ⇒ **非空默认值在原生腿永远丢失**（src 腿因返 None 而正常）。这是 L-213 的第三个病灶。
4. **调用方清单（.light，共 5 文件）**：`stdlib/os.light:32`、`stdlib/内置核心系统.light:13/15`（`主目录`，已用 `是空` 守）、
   `stdlib/分布式/节点网络.light:242`、`stdlib/文件系统.light:277/282/837/843/849`（均传 `""` 默认，行为不变）。
5. **修复的波及面**：`主目录` 在 USERPROFILE/HOME **双缺**时，原生腿返回值将从 `""` 变 null——
   R153 后调用方都用 `是空` 守得住，但 A 线必须 grep `主目录` 全部调用方逐一确认。

**修法方向**（空值规范 §9 建议 + 本轮补全）：原生腿向 src 对齐——**补齐 arity + 缺 key 且无默认时返 null**。
设计要点（A 线现场可调整，但此坑必须先想清楚）：**不能靠返回值字符串区分“缺 key”与“空值变量”**
（`""` 是合法值）⇒ C 侧必须用 NULL 指针（或 out 参数）表达“缺失”，codegen 侧据此选择
`_create_null_dv()`（已存在于 `codegen_typed.py:1075`）或包装默认值/变量值。
