### 5.2 #2 `test_light_import_hook_stdlib.py::test_find_spec_does_not_intercept_stdlib_pure_shadow` —— **测试隔离缺陷（未修，登记）**

**签名**：`assert hook.find_spec('inspect') is None` → 实得 `ModuleSpec(name='inspect', loader=<LightLoader>)`。

**取证**：

| 场景 | 结果 |
|---|---|
| 整文件隔离跑 | **5 passed in 4.02s** |
| 全量门内（9398 例同一进程） | **1 failed** |
| 组合复现 ①`test_distributed_eval_light.py` + 本文件 | 61 passed（不复现） |
| 组合复现 ②`test_pure_light_hook.py` + 本文件 | 74 passed / 1 skipped（不复现） |

**代码级机制**（`stdlib/_light_import_hook.py`，逐行核对）：

```python
# 252-256：守卫用 any(search_dirs) —— 只要【任一】搜索目录里有 inspect.py 就放行
if not is_submodule and fullname == realname and realname in _STDLIB_MODULES:
    if _COMPILE_DEPTH > 0: return None
    if not any(_exists_exact(b, realname + '.py') for b in search_dirs): return None
# 257-275：加载却是【逐 base】判定 —— 命中 stdlib/inspect.light 的那个 base 并没有 inspect.py，
#           且不是子模块 ⇒ 落到 274 行直接返回 spec（没有任何再确认）
```

**两处判定口径不对齐**：守卫是「全局 any」，加载是「单目录」。因此只要 `LightFinder.search_paths` 里
**累积**进任何一个含 `inspect.py` 的目录（`install()` 只 extend 不清理，`_current_finder()` 复用同一 finder），
`stdlib/inspect.light` 就会被编译——正是该守卫本来要防的**循环导入**（gitea run 161）。
本用例 `hook` fixture 拿到的正是 conftest 那个**全局 finder**，所以它在长会话里会看到被前面用例污染过的 `search_paths`。

**定性**：**非产品功能回归**（真机 `.light` 运行路径不受影响：正常进程里 `search_paths` 是 `[stdlib, contrib, 项目根]`，无 `inspect.py`）；
**是本轮唯一未清的 new_red**，属「钩子守卫设计 + 测试隔离」双重问题。
**建议修法**（交下轮，本线不改 `src/`/`stdlib/` 产品代码）：
1. 守卫改为「对**每个** base 单独判定」——`stdlib` 名只在「该 base 同时有 `.py` 且 `.light` 为纯光明」时才接管；
   或干脆对 `_STDLIB_MODULES` 的**直接 import 一律 return None**（别名 `_light_*` 不受限），语义更简单且无副作用；
2. 用例侧把 fixture 改为「`uninstall()` → `install([STDLIB_DIR])`」以拿干净 finder（同 `test_lpd_009` 的做法），
   让判据不再依赖会话历史。

## 七、联合 E2E「worker 领任务热路径」复评 = **通**

判据逐项对齐任务书「worker 注册 → 领任务 → 心跳 → 完成」：

| 环节 | 用例 | 实测 |
|---|---|---|
| 注册 + 分发 | `test_分发与结果汇聚`（1 master + 3 worker **真子进程**、1200 条） | ✅ 3 节点各处理 >0、三者之和 == 总数、无重复任务 ID、无静默丢条 |
| 心跳（独立协程） | `test_心跳独立于执行_长任务期间不被标失联` | ✅ 长任务执行期间不被标失联、结果被接受 |
| 心跳（失联判定）+ 重派 | `test_重派与心跳_杀节点后重派且无静默丢条` | ✅ 被杀节点标失联（身份级）、已领未完成条目重派、只计一次分 |
| 完成 + 幂等 | `test_幂等_同任务重复上报只计一次` | ✅ 进程内真 RPC 重复上报只计一次 |
| 背压 / 限流 | `test_背压_满后生产者被挡住` | ✅ 有界队列满后生产者被挡 |

**结论：R159 起「联合 E2E 被阻断 / 递延」这笔账销账**。注：本线 E2E 走的是**光明的 stdlib 分布式集群**
