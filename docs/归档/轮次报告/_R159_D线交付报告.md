## 三、关键实证：任务书病灶分析**漏掉了列表路径**（本线核心发现）

### 3.1 病灶的**完整**图景

任务书 §一1.4 只让改 `runtime_typed.c:743` 的 `case 5`（`dv_to_string_depth`），理由是
`depth` 天然区分标量/容器元素。**这是对的，但只覆盖字典路径**。

实测发现 `转字符串` 在 native 有**两条**容器路径：

| 容器形态 | 走哪个函数 | 修前是否走 depth≥1 |
|---|---|---|
| **字典**（type 7） | `dv_container_to_string`（`runtime_typed.c:612`）→ `dv_elem_to_string` → `dv_to_string_depth(e, depth+1)` | ✅ depth≥1，`case 5` 单独改即生效 |
| **列表**（type 4） | **`dv_list_join`**（`codegen_typed.py:3349`）——**不经** `dv_container_to_string` | ❌ **depth=0**，`case 5` 单独改**不生效** |

证据链：

```
src/llvm/codegen_typed.py:3331-3363
  if name in ('转文本', 'to_string', '转字符串', ...):
      ...
      # R12C（R11A-09）：runtime dv_to_string 对列表（type 4）读 str
      # 字段恒得 "[]"。运行时按 DV 类型分派：列表 → dv_list_join
      is_list = icmp eq i32 type_reg, 4
      → list_lab: 'dv_list_join'(args[0], ", ")   # ← 列表走这里
      → def_lab:  'dv_value_to_string'             # ← 标量/字典走这里
```

而 `dv_list_join`（`runtime_typed.c:3822`）内部**两处**调用的是 `dv_to_string(e)`（depth=0），
不是 `dv_to_string_depth(e, 1)`。**这就是为什么只改 `case 5` 无法让主判据
`转字符串([真, 假]) == [true, false]` 收敛。**

## 四、连带影响：`连接字符串([真, 假])`（登记不修）

`dv_list_join` 被**两个**内置共用：

1. `转字符串(列表)`（`codegen_typed.py:3349`）—— 本线目标路径；
2. `连接字符串` / `join` / `str_join` / `implode`（`codegen_typed.py:3793`）—— **连带受影响**。

实测连带变化：`连接字符串([真, 假], ",")` native 从 `真,假` 变 `true,false`。

**为何这不构成回归**：

- **src 腿对布尔抛 TypeError**：`stdlib/字符串工具轻量.light:82` 明写
  `如果 isinstance(元素, str) == 假: 抛出 类型错误("sequence item " ... ": expected str instance, ...")`。
  实测 src 腿 `连接字符串([真, 假], ",")` → `rc=1`，stderr
  `[运行错误] sequence item 0: expected str instance, bool found`。
- **这是 `str.join` 语义（收严）的另一条已存在分歧**：native 静默拼接 vs src 抛 TypeError，
  与「容器 repr」**根因不同**、**归属不同**（属 `连接字符串` 的判型语义，非 `dv_to_string` 的 repr）。
- **原生腿的 `.light` 实现不走这个 C 函数**：stdlib 的 `连接字符串` 在原生腿走的是
  `.light` 层 `isinstance` 判型路径（`stdlib/字符串工具轻量.light`），不调用 `dv_list_join`；
  `dv_list_join` 只服务**内置名** `转字符串` / `连接字符串`（codegen 内联路径），
  而后者对布尔**本来就该抛**。
- 受影响面：`tests/unit/test_地板搬迁_连接字符串_S2.py`（265 passed）——
  但这是 Python 腿测试，不经过 `runtime_typed.c`，**不受影响**；
  `tests/unit/test_runtime_builtin_O0.py::test_连接字符串_对拍Python` 只测 `a/b/空/中文` 元素，
  **无布尔元素**，**不受影响**（已实跑绿）。

**结论**：本线**不修**这条（超出 E-3 范围），**登记交主 agent**：
`连接字符串` 两腿对**布尔元素**的口径分歧（src 抛 TypeError / native 静默拼接）
需另立号（建议从 **L-219** 起，先 `grep L-219` 确认未用）——**非本轮 repr 收敛范围**。
