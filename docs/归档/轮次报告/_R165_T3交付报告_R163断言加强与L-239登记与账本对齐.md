## 三、§4.2 · L-194 PY 腿对齐 → 独立编号 L-239 + 五段式登记

### 3.1 结论一句话

任务书所指的「L-194 PY 腿」症状，在**当前树**是本轮新暴露的**一条 PY 转译腿独有腿不对称**：**`异步 运行 X()` 中 `X` 为非异步（同步）段落时，PY 腿崩、原生腿静默通过**。已按任务书 §4.2「不能修就五段式登记」**独立编号 L-239**，**本轮不落地 `src/` 修复**。

### 3.2 触发条件（最小等价复现，本机 PY 腿）

唯一触发条件：**被导入模块**顶层写 `异步 运行 启动()。`，且目标 `启动` 是**非异步（同步）段落**。

```
① 触发（同步段目标）
   m_sync.light:
     段落 启动():
         打印("模块顶层异步启动")
     异步 运行 启动()。
   main_sync.light:  从 m_sync 导入 启动 / 打印("主控段")
   python light6.py run main_sync.light  ⇒  rc=1
     [运行错误] a coroutine was expected, got None
     （stdlib/_light_import_hook.py:188 exec(compile(...)) → 产物 m_sync.light:290
       asyncio.run(启动()) → ValueError）

② 对照（异步段目标，正确）
   m_async.light:     异步 段落 启动(): ...（同形态）
   python light6.py run main_async.light  ⇒  rc=0
     stdout: 模块顶层异步启动 / 主控段

③ 机读佐证（light6.py compile）
   m_sync  → def 启动():            + 顶层 asyncio.run(启动())      （无 async）
   m_async → async def 启动():      + 顶层 asyncio.run(启动())

④ 原生腿：本轮未在本机重跑（§0 资源纪律 + 需 clang/MSVC 全流程）
   数据引自 0.88 `_R164_T1交付报告_L198命名截胡收口.md` §4.1 M2：rc=0
   （先执行 启动() 的同步副作用，再继续主控段）
```

### 3.3 根因（代码级）

- PY 腿**无条件**把 `异步 运行 X()` 编成 `asyncio.run(<X 求值>)`，**不检查 X 是否真返回协程**：`src/code_generator.py:2136-2140`（`RunAsyncStmt` 分支：`self._needs_asyncio = True; call = self._generate_expr(stmt.call); self._add_line(f"asyncio.run({call})")`）。
- 对照**模块顶层裸 `ParagraphCall`** 分支（`src/code_generator.py:1935-1943`）**会先判** `stmt.name in self.async_paragraphs` 才包 `asyncio.run` —— `RunAsyncStmt` 这条路径**缺同样判型**。
- 被调 `启动` 是同步段 ⇒ PY 生成 `def 启动()`（`src/code_generator.py:2654-2657` 仅在 `异步` 修饰符命中时才 `async def` + 登记 `async_paragraphs`），`启动()` 返回 `None` ⇒ `asyncio.run(None)` ⇒ `ValueError`。
- 对照原生腿：`src/llvm/codegen_typed.py:9250` `_gen_typed_run_async` 求值 `X()` 后 `_extract_ptr_from_dv` 取协程句柄、`call void @dv_coro_run_to_completion(ptr …)`；`X` 为同步段时 `X()` 已执行（副作用已发生），取到的非协程值被 runtime 容忍 ⇒ **rc=0**。

### 3.4 影响面

仅在**畸形/无意义写法**下触发——`异步 运行 X()` 的语义前提是 `X` 为 `异步 段落`。全仓真实 `异步 运行` 站点（`stdlib/分布式/主控.light:13,22`、`stdlib/分布式/节点.light:12,19`、`examples/harness/M2_流式对话.light:62,80`、`examples/harness/评测驱动.light:338,588,661,663`）目标**均为 `异步 段落`**，PY 腿全部正常 ⇒ **无合法程序被本缺陷破坏**；受损的是「两腿对 malformed 程序的容忍度不一致」这一可观察的腿不对称。

### 3.5 修法方向（≥2 条，待裁定，本轮不实施）

| 方案 | 内容 | 风险 / 代价 |
|---|---|---|
| **1 · 运行时对齐（容忍派）** | `RunAsyncStmt` 发射前加判型：目标为本地已知同步段落则降级裸调用，或产物加 `asyncio.iscoroutine` 守卫 | 改 `src/code_generator.py` 影响**所有**被编译程序 ⇒ 须 9000 例全量门；把原生腿「同步段可被 `异步 运行` 并执行副作用」的意外行为固化为语义 |
| **2 · 编译期明确报错（诊断派）** | `异步 运行 X()` 的 `X` 非异步段落时编译期报错 | 静默变响亮、零 ABI 风险；但与原生腿仍不对称（原生腿继续容忍） |
| **3 · 原生腿对齐 PY 腿（拒收派）** | 令原生腿同口径拒收/报错 | 动 `src/llvm`（T-1 独占区） |
| 备选最小改（已评估） | 另建「本模块已声明的非异步段落」集合，仅命中才降级裸调用 | `_user_defined_functions`（`src/code_generator.py:158`，`generate()` 时 `:1272` 重置）混装导入别名 / embed 导出（`:943-949`、`:964`），误判会把跨模块异步目标降级 ⇒ 协程静默不被驱动（真回归）⇒ **须独立集合才安全** |

### 3.7 附带观察（不新开编号，待主 agent 裁定是否立项）

本线取证 L-239 时顺带发现两条相邻 PY 腿不对称，均以 `python light6.py compile/run` 机读证实：
