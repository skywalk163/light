# R167 收口后裁定 · 形态③「协程体内 `异步 运行 f()`」语义 —— **编译期拒收**，独立立项

- 裁定事项：`_R167_收口报告.md` §5.2-3 / `_R167_并行任务书.md` §8 —— 协程体内（`异步 段落` 段体内）写
  `异步 运行 f()` 的语义取向：**编译期拒收** vs **定义成「调度到当前 loop」**。
- 裁定人 / 日期：业主（段言），2026-10-26（R167 收口后）。
- 关联：`docs/功能对标/语言缺陷账.md` §二十四·三（L-239 同族形态③，R167-T4 登记）；
  `_R167_T4交付报告_L239同族形态排查.md` §2.3 / §6-4。
- **结论：采用「编译期拒收」（诊断派）；独立立项交下一轮实施**（不在 R167 这种「只改测试门」的轮次内改语义）。

---

## 一、待裁定的问题

形态③ = 在**协程体内**（`异步 段落` 段体里）写 `异步 运行 f()`，`f` 为函数值变量 / 任意表达式。

R167-T4 实测（0.88）已确认：这不是「两腿对拍口径下的**腿不对称**」，而是**原生腿整体未实现该形态**、
**PY 腿该路径又无稳定自洽语义**——即一条**语法层待裁定项**。其核心分歧是：

| 取向 | 含义 | 代价 |
|---|---|---|
| **A · 编译期拒收**（诊断派） | 把「协程体内 `异步 运行`」定为**非法写法**，编译期明确报错 | 极小（补上下文判型 + 措辞订正）；语义不变 |
| **B · 调度到当前 loop** | 把它**重新定义**为「在当前事件循环里调度 `f`」 | 大：同一关键字顶层 / 协程内**双语义** + 需动 `src/llvm` 协程 codegen/runtime |

---

## 二、裁定结论

**取 A —— 编译期拒收。** 协程体内 `异步 运行` 判为非法形态，编译期报错；**独立立项**，交下一轮实施。

---

## 三、理由（逐条附证据）

1. **语义自洽性：`异步 运行` 在运行中的 loop 内不是「未实现」，而是「不可能成立」。**
   `异步 运行` 的定义 = 求值 `X()` 得到一个**协程句柄**，起一个**新事件循环**并阻塞驱动至完成：
   原生腿 `dv_coro_run_to_completion`（`src/llvm/codegen_typed.py:9250-9270`，其注释 :9261-9262 已自陈
   「与 Python `asyncio.run` 不能写在 async 函数内同口径」）、PY 腿 `asyncio.run(...)`（`src/code_generator.py:2219`）。
   在**已运行**的事件循环内，`asyncio.run()` 嵌套必抛——0.88 实测 `f3b`（直接 `异步 运行 异步干活()`）
   = `(1, '', "asyncio.run() cannot be called from a running event loop")`。故选项 B 之外**不存在**「正确实现」，
   选项 A 才是对现状最如实的定性。

2. **选项 B 会引入「同语法双语义」，与项目已收口的判型纪律相悖。**
   顶层 `异步 运行 X` = 新 loop；协程内 = 当前 loop——同一关键字按位置改变含义是 context-overloading。
   项目在 R166 / R167 已确立「**只对可确证的落点动手、宁可不对齐也不误伤**」的判型纪律
   （R166：名字不可解析 ⇒ 不扩大改动面；R167：跨模块 / 导入名判不出 ⇒ 维持原样）。
   选项 B 与之一致性最差，且原生腿实现「协程内启动子协程 / 调度」= 触 `src/llvm` 协程 codegen/runtime
   （与 L-227 / L-228 / L-232 同区深水），属**全量门级**改动，绝不能塞进「只改测试门」的收口轮。

3. **语言已有正确替代 ⇒ 拒收不损失任何表达力。**
   协程体内驱动 / 并发已有三个一等原语：`等待`（`src/code_generator.py:2196-2202`，R167 已打通同步/异步判型）、
   `异步 作用域`（结构化并发，PY 腿 `asyncio.gather`，`src/code_generator.py:3732`）、`创建任务`（`stdlib/协程.light` 导出）。
   `异步 运行` 在协程内属**语义冗余**——拒收只会把畸形写法**变响亮**，与 `_require_async_context`
   （`src/code_generator.py:3710-3730`）「让用户看懂自己该改哪里」的既有取向一致。

4. **两腿现状决定的「最小改动」方向就是 A。**
   原生腿**已经拒收**：`src/llvm/codegen_typed.py:9264-9266` `if self._in_coroutine: self._reject_unsupported_stmt('RunAsyncStmt(協程内)', stmt)`；
   PY 腿 `RunAsyncStmt` 分支（`src/code_generator.py:2203-2221`）**缺对应上下文判型** ⇒ 这正是形态③
   「腿不对称」的唯一落点。选 A = 把 PY 腿补上原生腿已有的上下文判型，**方向就是「两腿对齐」**、改动面最小；
   选 B = 反向拆除原生腿已有的拒收并新增实现，改动面最大。

5. **真实程序零影响（grep 实测）。**
   全仓 `stdlib` / `examples` 中 `异步 运行` 的**真实站点**全部在**模块层**（含顶层 `如果/否则` 分支，
   仍非协程体内）：`examples/harness/评测驱动.light:661,663`、`examples/harness/M2_流式对话.light:80`、
   `stdlib/分布式/主控.light:22`、`stdlib/分布式/节点.light:19`（其余命中均为注释 / 字符串）。
   协程体内的 `异步 运行` 仅见于 R167 探针 `_scratch_r167t4/f3*.light` 与历轮 scratch 树。
   拒收判据是「语句是否位于 `异步 段落` 体内」，故上述真实站点**逐字不受影响**。

## 四、立项范围（交下一轮，独立于收口轮）

**必做（最小，两腿对齐）：**

1. `src/code_generator.py`：`RunAsyncStmt` 分支（`:2203`）补「**不得位于 `异步 段落` 体内**」判型，
   镜像原生腿 `_in_coroutine`。PY 侧现成状态位 `self._in_async_function`（`:193`，由 `_generate_paragraph`
   `:2769` 按 `'异步' in stmt.modifiers` 置位、`:2815` 还原；异步方法路径 `:4026`/`:4101` 另行维护）。
   命中即抛编译期 `CodeGenError`，措辞指路协程内替代（`等待` / `异步 作用域` / `创建任务`）。
2. `src/llvm/codegen_typed.py:9265`：把 `_reject_unsupported_stmt('RunAsyncStmt(協程内)')` 的**措辞**由
   「原生后端暂不支持…请用转译后端」（`_FALLBACK_HINT`，`:6801-6806`）改为**语言级语义错误**——
   两腿既已都拒收，原「请用转译后端」指引已**失真**（转译后端同样拒收）。
   ⚠️ 动 `src/llvm/**` ⇒ **9000 例全量门级**，须与第 1 条**同轮**跑门。

**用例改写（`tests/unit/test_R167_L239_同族形态.py` 形态③ 三例，裁定生效的产物、非回归）：**

| 用例 | 现状（R167-T4） | 裁定后应改为 |
