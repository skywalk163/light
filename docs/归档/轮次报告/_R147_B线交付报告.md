## 一、根因

### L-207（.light/.py 在 Python 层语义不等价）
`stdlib/__init__.py` 的 57 处相对 star-import（`from .XXX import *`）走标准导入机制，只认 `.py`。即使同名 `.light` 首两行含「纯光明实现」魔数，相对导入仍加载 `.py` 影子，`.light` 的纯光明实现被无视。根因：`_light_import_hook.LightFinder.find_spec` 对子模块名（`'.' in fullname`）一律 `return None` 让位给 PathFinder。

---

## 二、做了什么

### B1：顶层 import hook 通用化（治 L-207）

**改动文件（2 个）：**

1. **`stdlib/_light_import_hook.py`**：`LightFinder.find_spec` 改造
   - 旧逻辑：`if '.' in fullname: return None`（子模块一律让位）
   - 新逻辑：对子模块名，从父包 `__path__`（`path` 参数）查找 `.light`；仅当 `.light` 含魔数时才接管（`.py` 存在时要求魔数；`.py` 不存在时也要求魔数——空壳门面不让接管，保持修改前 ImportError 被吞的行为）
   - 标准库保护逻辑保留，对子模块跳过（Python 标准库无同名子模块冲突）

2. **`stdlib/__init__.py`**：在所有 star-import 之前自动 install hook
   - 用 `importlib.util.spec_from_file_location` 动态加载 `_light_import_hook.py`（不依赖 sys.path）
   - 调用 `install([stdlib_dir])` 注册 LightFinder 到 `sys.meta_path`
   - 失败静默 pass（不影响正常 import）

**验证探针（本机 src 腿）：**
