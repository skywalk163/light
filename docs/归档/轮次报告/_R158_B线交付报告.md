## 二、旧 / 新定位方式对照

### 2.1 病根复述（R157-E9）

旧判据（`floor_bootstrap.py` 原文）：

```python
窗口 = 2
起 = max(0, 行号 - 1 - 窗口); 止 = min(len(lines), 行号 + 窗口)
命中 = [i + 1 for i in range(起, 止)
        if RE_DECL.search(lines[i]) and 名字 in lines[i]]   # 「行里含名字」= 子串匹配
if not 命中: 判红
```

两个脆弱点：

1. **窗口只有 ±2 行**：`段落 X(` 上方增删任何一行都会把定义行推出窗口 —— R153 往每个
   `段落` 上方增厚「对齐 `stdlib/builtins.py:xxxx`」注释，9 条判型内置证据行集体失配，
   自举率被误算成 59/96。
2. **`名字 in 行` 是子串匹配**：`是空` 是 `是空白` 的前缀，`段落 是空白(字符)` 会冒充
   `段落 是空(值)`；注释行里出现名字也会被当成定义行。

### 2.2 新定位方式（R158-B 落地）

新增三个纯函数 + 一条正则，判定改为**两步**：

| 步 | 做什么 | 关键实现 |
|---|---|---|
| ① 语法级定位 | 按**声明名**找定义行，不靠行号猜 | `RE_DECL_NAME = ^\s*(?:段落\|类\|函数)\s+(?P<name>[^\s(（:：]+)`；`声明行表()` 收「行首关键字 + 紧跟声明名」的行；`定位定义行()` 取**声明名精确相等**的候选 |
| ② 漂移上界 | 断「证据行号与定义行的距离 ≤ 一个**段落块长**」 | `段落块()` 返回 `[前置注释/空行块首行, 下一处同级声明行 − 1]`，块长由文件**现算** |

**为什么这样就顶得住 R153 那类注释增厚**：增删行只会**平移**定义行；段落块本身随声明一起
平移，块长不变，于是平移量被「一个块长」的容差吸收。判据真正 key 的是「这个文件里有没有
名叫 `X` 的语法级定义行」，而不是那个会漂的数字。**两种方式都不靠猜行号**。

**为什么段落块上界取「下一处同级声明 − 1」而不是「定义体末行」**：
- 取定义体末行会把块长压到只有函数体那几行，稍一增删就出界（旧 ±2 的同型病，只是宽一点）；
- 取「下一处声明 − 1」既给出足够容差，又天然被同级/更外层声明框住，不会跨段落乱认。
- 这条也**兼容既有回归**：`tests/unit/test_ci_gates_round9.py::test_证据必须落在定义行的窗口内`
  要求「定义在第 4 行、证据行写第 6 行（空白行）仍绿」—— 段落块 `[1,6]` 恰好覆盖它。

**为什么段落块下界要含「前置注释块」**：R153 的病灶正是往 `段落` 上方增厚注释，证据行会落进
注释块里；不把注释块算进段落，等于把病灶继续留在判据里。
