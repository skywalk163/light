建议订正时一并修名。

### 新发现 2 · 「高精度」是**假高精度** —— 风险形态比「没有」更危险

R151 落地的 `dv_decimal_*` 是**降级实现**：

- 内部 static `dv_decimal_add_str/sub_str/mul_str/div_str`（`runtime_typed.c:9034/9042/9049/9056`）
  **用 `atof` 转 double 计算，再 `snprintf("%.10f")` 输出**；
- 源码注释自认：_「简单实现：用 double 计算后转字符串（**生产环境应实现纯字符串算术**）」_、
  _「精度：**固定 10 位小数**」_。

⇒ 缺陷账 §十 原设想的「新 dv 类型 + C 绑定 + 序列化 + repr + 全链路」**未被采纳**，
走了更省的字符串级路径，**代价是精度不达标**。

**为什么比「没有」更危险**：没有功能时调用方会自己想办法；有功能但精度不达标且**静默**时，
调用方看到 `高精加法("0.1","0.2")` 的返回值会**误以为拿到了 Decimal 精度**，实际误差与 double 无异。
这与 `docs/编程注意事项.md` 坑 04「缺失 ≠ 空值」同族——**用降级实现冒充完整特性**。

**建议（需业主裁定，二选一，代价差 2 倍以上）**：
① 补纯字符串算术（~2 人日，只改内部实现，接口不变）；
② 在 `docs/api/builtins.md` 显式标注精度上限（~0.2 人日），避免误用。
