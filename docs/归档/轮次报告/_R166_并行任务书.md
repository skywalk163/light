## 2. T-1 · P4/P5 判据鲁棒化

### 2.1 问题定性（R165 已取证）

- `_跑()` 按 2s 采样 12s 窗口 RSS，`增长MB = 末样本 − 首样本`。
- P4/P5（JSON / 心跳同构混合）**容器所有权不在 L-217 scope**（浅拷契约），本就不归零；
  实测 修后 1169.5 / 反跑 1164.1（**反向**）、修后 1192.9 / 反跑 1159.1（反向 2.9%）。
- 即：**该断言的信噪比不足**（机制贡献 5~33MB 被容器分配 ~1.1GB 淹没），
  序关系在两个方向都出现过 ⇒ 判据本身不可重复，不是产品波动。

### 2.2 要做

1. 判据改为**带噪声容差的有序关系**：`反跑增长 ≥ 修后增长 × 0.90`
   （10% 容差 = 实测最大反向 2.9% 的 3.4 倍余量），保留「修后不得显著更差」的单侧哨兵语义。
2. docstring 写清：P4/P5 对机制的**判别力有限**（容器分配淹没），
   「机制有牙」由 P1'/P3'（修后 ≤2MB vs 反跑 ≥20MB，10 倍信号）承担；P4/P5 只做「不倒退 + 有界」哨兵。
3. **反跑有牙**：把容差改成负数（模拟「修后显著更差」）⇒ 用例必须转红。
4. 连跑 5 次不得再抖红（本机不跑 pytest ⇒ 0.88 上验）。

### 2.3 判据

```
$ pytest tests/unit/test_R16x_L217_所有权收敛.py -n 0 -p no:randomly -q   # 连跑 5 次
  期望：5/5 全绿（修前 4 轮全量门抖 2 次）
```

## 4. T-3 · L-239 修复（PY 腿 `异步 运行 X()`，X 非异步段落）

### 4.1 根因（缺陷账 §二十四）

`src/code_generator.py:2136-2140` 的 `RunAsyncStmt` 分支**无条件** `asyncio.run(call)` +
`_needs_asyncio = True`；而同文件 `:1935-1943` 的模块级 `ParagraphCall` 分支有
`name in self.async_paragraphs` 判型。被调段落是同步段落时，`call` 求值为 `None`
⇒ `asyncio.run(None)` ⇒ `ValueError: a coroutine was expected, got None`。
原生腿（`src/llvm`）对同写法容忍（`dv_coro_run_to_completion` 收到非协程句柄时直接跑完）。

### 4.2 要做

1. `RunAsyncStmt` 分支补判型：被调名**在** `async_paragraphs` ⇒ 维持 `asyncio.run(...)`；
   **不在**（明确是同步段落）⇒ 直接同步调用（与原生腿对齐）。
   名字不可解析（函数值调用等）时维持原行为（`asyncio.run`），不扩大改动面。
2. 新增 `tests/unit/test_R166_L239_异步运行非异步段落.py`：
   - PY 腿（`light6.py run` 或 `cli.light_unified run`）跑 `异步 运行 同步段落()。` ⇒ **rc=0 且输出正确**；
   - 双腿对拍一致（原生腿同源输出相同）；
   - 负对照：`异步 运行 异步段落()` 仍走 `asyncio.run`（IR/生成码佐证，不是字符串 `in`）。
3. **反跑有牙**：临时回退判型（改回无条件 `asyncio.run`）⇒ PY 腿用例转红。

### 4.3 判据

```
$ pytest tests/unit/test_R166_L239_异步运行非异步段落.py -n 0 -p no:randomly -q
  期望：3 passed / 0 skipped
```
