## 一、结论速览

| 项 | 结论 |
|---|---|
| **推荐方案** | **三层组合：「字面量全局常量共享（先导）→ 语句级 arena + 逃逸拷贝（主体）→ 逃逸规则由编译期所有权分级提供（发射规则）」**。候选方案 5 个全部评估，**明确不选** per-temp refcount 与周期清扫 GC（理由见 §五） |
| **一句话理由** | 字符串在原生 runtime 已实证**值不可变**（§2.5 论证）⇒ 字面量/临时串可以零成本共享或集中回收；而 refcount 要与「struct 浅拷共享 str 指针」的既有契约正面相撞，GC 则根本没有 root 枚举能力 |
| **对 L-217 坐实泄漏源（字符串字面量求值）** | 先导步骤即可**归零**（字面量不再分配） |
| **对同族未隔离路径（`dv_deref_value` / `dv_clone` / 拼接 / 序列化）** | 主体步骤（arena + 逃逸拷贝 + 收尾清理）统一覆盖 |
| **跨协程 suspend/resume 约束** | 正面回答见 **§七专节**：挂起即 C 帧销毁、临时值全部死亡、arena 在 suspend 点重置到帧入口 mark；跨 await 活值只存在于 coro 帧（既有 Duff 设计事实），与 arena 所有权分离 |
| **收敛判据** | 沿用 R158/R159 预置：同口径压测 537 点拟合斜率落在 **±0.001 MB/s** 带内（§十） |
| **落地形态** | 深水区（排序标准③：触及 runtime 值所有权 + codegen 核心）⇒ **必须独立立项轮**，本文即该轮的输入 |

## 二、现状一手画像：runtime 值模型

设计必须建立在「当前到底怎么分配、怎么拷、怎么放」的准确画像上。本节全部一手核实。

### 2.1 LightValue 与所有权相关字段

`runtime_typed.c:81-95`：`struct LightValue` = `type`（0 NULL / 1 INT / 2 FLOAT / 3 STR / 4 LIST / 5 BOOL / 6 OBJ / 7 DICT / 8 REF / 23 TUPLE / 25 FUNCTION）+ `i64` + `f64` + `char* str` + `boolean` + `list_size/list_capacity/list_data`。

- **STR**：`str` 指向 `malloc(len+1)` 的 NUL 结尾缓冲（`dv_strdup`，`:181-187`；`dv_str`，`:380-386`）。
- **LIST/DICT/TUPLE**：`list_data` 是 `LightValue**` 数组，**每个元素独立 malloc**（`dv_list_append`，`:1939-1974`）。
- **REF（type=8）**：`str` 字段复用为「指向容器内元素的 `LightValue*`」（`:97-98`），不是堆字符串。
- **FUNCTION（type=25）**：`str` 为 `DvClosure*`（`:103-111`），含 `fn_ptr` + 捕获环境 `env`。
- **OBJ（type=3 + `OBJ_PREFIX` 前缀串）**：类实例以**序列化字段串**承载，**可原地 free+realloc**（`dv_class_set_member`，`:4744-4770`）——与普通 STR 的不可变性不同，见 §2.5。

**结构体本身没有所有权/引用计数字段**——这是全部问题的起点。

### 2.2 值的五个居住地与生命周期

| # | 居住地 | 载体 | 生命周期 | 现状释放 |
|---|---|---|---|---|
| V1 | **临时槽位池** | 函数入口单个 `alloca [N x LightValue]`（`_begin_temp_slot_pool`/`_emit_temp_slot_pool`，codegen_typed.py:936-968），`_new_dv_slot` 单调发号（:970-1005） | 随 C 帧；协程挂起时帧销毁 | **无 free** |
| V2 | **具名变量槽** | 每变量一个 `alloca LightValue`（`alloca_local`，:190-205） | 随 C 帧 | **无 free**（覆盖写即丢旧指针） |
| V3 | **协程帧** | `coro->args/locals/result`（runtime :5738-5742），codegen 经 `dv_coro_get_local/get_arg` 取指针跨 await 物化（codegen:8310/8319） | 协程对象生命周期 | **有**：`dv_coro_free`（:6126-6144）逐项 `dv_free` |
| V4 | **容器元素** | list/dict 内 `malloc` 的 `LightValue*` | 容器生命周期 | **有**：`dv_free` 递归 + removal 路径（:2584-2585、:2612） |
| V5 | **Future/生成器** | `f->result`（:5754）/ 生成器 `g->slots`（:6938） | future/生成器生命周期 | **有**：`dv_future_unref`（:6112-6124）/ 生成器释放（:6938-6962） |

**关键事实：codegen 全程不发射任何 `dv_free`**（grep `call void @dv_free` 在 `src/llvm` 零命中；codegen_typed.py 仅 :1586 一条注释提及）。运行时的 `dv_free` 调用方**全是 runtime 内部生命周期管理者**（协程帧 / future / 生成器 / 容器内部 / 运行时自己的 C 局部临时）。缺陷账 L-217 所述「dv_free 仅覆盖具名槽位」的准确表述是：**被管理的只有 runtime 自己持有的具名结构，codegen 发射出来的值一个都没有释放点**。

### 2.3 拷贝/释放契约现状

| 操作 | 位置 | 语义 |
|---|---|---|
| struct 赋值（`store` 进槽 / `*result = *v`） | codegen 各处 | **浅拷：`str` 指针共享**。两个槽位可指向同一缓冲 |
| `dv_clone` | runtime:447-509 | STR→`dv_strdup`（深）；LIST→深；FUNCTION→闭包+env 深；**DICT→浅（共享 list_data，L-204 刻意契约，R146-A 回退教训）**；REF→浅指针 |
| `dv_deep_clone` | runtime:514+ | 仅 dict 插入用（L-204）：LIST/DICT 递归深，STR `dv_strdup` |
| `dv_deref_value` | runtime:1898-1910 | 非 REF：`*result=*v` 后 **STR 额外 `dv_strdup`**；REF：`dv_clone`。codegen 对**所有只读内置**实参统一发射（`_deref_value`，codegen:1066-1083） |
| `dv_free` | runtime:400-445 | type=3 `free(str)`；LIST/DICT 递归；FUNCTION 释放闭包+env；**REF 仅清指针不释放目标** |

### 2.4 分配路径全集（L-217 家族的准确边界）

| # | 路径 | 分配点（一手核实） | 每调用分配量 | 现状 free | 与 L-217 的关系 |
|---|---|---|---|---|---|
| P1 | **字符串字面量求值** | codegen:1391-1393（`StringLiteral→_create_str_dv`）→ `dv_str`（runtime:380-386）→ `dv_strdup`（:181-187） | `len+1` | 无 | **R159-C 坐实的泄漏源**（对照实验唯一性） |
| P2 | **只读内置实参解引用** | codegen:1066-1083 → `dv_deref_value`（runtime:1898-1910） | `len+1`（仅 STR 实参） | 无 | **同族未隔离**：每次只读内置调用 × 每个字符串实参都分配一次 |
| P3 | `dv_clone` 深拷贝 | runtime:462 | `len+1` | 依赖目标（容器/协程帧/future 有管；槽位没有） | 同族 |

**诚实边界（重要）**：R159-C 的对照实验（纯整数循环 RSS 平坦 2.71MB）证明了「泄漏与类型相关、且随字符串字面量求值率线性（C1≡C4 同斜率）」，从而**坐实 P1**；但该对照**不能排除 P2-P5 也在贡献**——整数循环同样没有内置调用、拼接与 JSON。因此设计必须覆盖 P1-P6 全谱，验证计划必须能**测残留**而不是假设归零（§十 P1-P5 分路径探针）。

### 2.5 两个决定性事实（设计的地基）

**事实 A：普通字符串值不可变（一手论证）。** grep 全部 `strcpy/strcat/sprintf/memcpy(…->str)/realloc` 目标：均写向**新建缓冲**（`dv_str_replace` 的 `out` :1483-1505、`dv_str_repeat` 的 `out` :1533-1545、`dv_class_set_member` 的 `new_str` :4744-4770 等）；对既有 `LightValue.str` 的写操作只有 `free`（`dv_free` :409、`dv_obj_release_slot` :4457、`dv_class_set_member` :4750/4768 的 free+替换），**没有任何原地改字符的路径**。⇒ 同一字符串内容被多个槽位/容器共享是安全的；`gen_string_constant`（core.py:244-249 / `_emit_string` :38-59）本就为每个字面量生成 `private unnamed_addr constant` 模块级常量并去重——**字面量的正确形态本来就是零分配共享**，P1 的 `dv_strdup` 是纯防御性冗余。

**事实 B：仓内已有成功先例——OBJ 缓冲的「唯一所有权 + 深拷贝」协议**（runtime:4440-4469，一手核实）。类实例是可原地变的序列化串，无法共享，runtime 为此建立了完整协议并已被 codegen 集成：

- `dv_obj_deepcopy_self`：prologue / 赋值 / 方法调用 `己` 时深拷（codegen:7556、8812、7498 配套 `dv_obj_release_slot`）；
- `dv_obj_release_slot`：覆盖写前释放旧缓冲（codegen:7554-7559，消除 per-`set_member` 增长）；
- `dv_value_disown`：writeback 移动后清空槽位，防双重释放（codegen:7504）。

其头注（:4449-4450）自述：「对象缓冲是普通 malloc 字符串，由 dv_free 的 type-3 分支统一 free……**本仓代码生成器不在局部槽位出口 emit dv_free，属既有模型**」——即**当前全仓缺的正是「普通字符串 + 容器 + 临时值」的同款协议**。本设计 = 把该协议推广到全值类型，并利用事实 A 让不可变串走更便宜的共享/arena 路线。

## 五、候选方案对比（5 个；明确推荐，不给「都行」）

| 维度 | 甲 · per-temp refcount | **乙 · 语句级 arena + 逃逸拷贝（推荐主体）** | **丙 · 字面量常量共享（推荐先导）** | 丁 · 周期清扫 GC | 戊 · 编译期逃逸分析分级 |
|---|---|---|---|---|---|
| **改哪** | LightValue 或缓冲头加 count；**每一次槽位 store/覆盖/拷贝**都要 ±1（codegen 全路径 + runtime 全 builtin） | runtime 加 thread-local bump arena + mark/reset；分配入口切换；codegen 在**语句边界**与**逃逸点**发射 | codegen 字面量分支 + runtime `dv_str_immortal` + `dv_free` 守卫 | runtime 加周期清扫；需要 root 枚举 | codegen 侧静态分级（owns/borrow 标注），作为乙的**发射规则**存在，不独立 |
| **free 归谁** | 最后一个持有者（计数归零） | arena：语句边界 wholesale reset；逃逸值：目标结构（槽位 epilogue / 容器 / 协程帧） | 无人——模块常量随程序生命周期 | 清扫器（问题：判不准） | 编译期定夺，运行期无计数 |
| **对每轮分配量的影响** | malloc 次数**不变**（照旧每次分配），只是配对了 free；无收益于速率 | 字面量/临时串从 malloc 堆搬进 bump（**每轮 malloc 次数降一个数量级**）；逃逸拷贝保留 malloc | 字面量求值**零分配**（直接砍掉坐实源） | 分配照旧 + 清扫开销 | 决定乙的发射精度 |
| **迁移爆炸半径** | **最大**：动每一个值生产路径；IR 每槽 ±1 指令膨胀；与 C5 浅拷契约正面相撞（浅拷 = 隐式 +1，漏一处就双重释放/泄漏） | 中大：新增代码路径可整体开关（feature flag），旧路径原样保留 | **最小**：单分支 + 单函数 + 单守卫，可当小时级改动 | 中大且**不可行**（见右） | 中：纯 codegen 规则 |
| **协程交互风险** | **最高**：帧跨 suspend 存活、C 栈临时随帧死，计数配对极易错（R119-B 的 future refcount 已是前车之鉴：waiting_for 还有 timer/io 伪装 future 不走计数的坑，:6105-6106） | **低**：suspend 点统一 reset 到帧入口 mark（§7.2），与帧生命周期对齐，无跨帧计数 | **无**：常量无生命周期问题 | 高：协程帧是 root，清扫器必须感知调度器 | 低（同乙） |
| **异常/try 交互风险** | 长跳转跳过 ±1 ⇒ 计数漂移累积 | mark 栈 + catch 入口 reset-to-try-mark 可解（§八） | 无 | 高 | 低 |
| **结论** | **不选**：与 C5 结构性冲突，且已被仓内 R119-B 证明在此代码库很脆 | **选为主体** | **选为先导** | **不选**：C 栈上的临时 LightValue 无法枚举 root，必然误释放（会崩）或保守不回收（等于没做） | **选为乙的发射规则** |

**推荐方案明确陈述：丙（先导）→ 乙+戊（主体）。** 核心理由：

1. **丙先砍掉已坐实的 100% 泄漏源且零语义风险**——事实 A 保证共享安全，`_emit_string` 的去重常量本就存在，`dv_strdup` 是冗余防御；
2. **乙用「分配器分离」替代「引用计数」**——所有权由「缓冲从哪个分配器来」隐式决定（arena 区间 / 常量区 / owned malloc），不需要给每次浅拷配平计数，从而绕开甲与 C5 的结构性冲突；
3. **戊给乙提供精度**——哪些 SSA 值逃逸是编译期已知的（存储目标是否为具名变量/实参/容器/协程帧/返回值），不需要运行期跟踪；
4. **丁直接判死**：没有 root 枚举能力（C 栈帧、调度器队列、线程栈都是 root，但无法从 C 侧枚举），任何「周期清扫」在此架构下要么漏 root 误释放（SIGSEGV），要么全保守（零回收）。

## 六、推荐方案展开：三层所有权 + 逃逸规则

### 6.1 三态定义（tag 打在缓冲头，不动 LightValue 布局）

每个堆缓冲前加 8 字节头 `DvBufHeader { uint32 tag; uint32 gen; }`，`str` 指针照旧指向数据区：

| 态 | tag | 生产路径 | 释放责任 |
|---|---|---|---|
| **IMMORTAL** | 1 | 丙：字面量常量（直接指向模块 `@.str.N`，无需分配，tag 由范围/显式设定表达） | 无人；`dv_free` 见 tag 跳过 |
| **ARENA** | 2 | 乙：一切临时值分配入口（`dv_str` 非字面量路径、`dv_deref_value`、`dv_clone` 的临时结果、拼接/repr/JSON 的临时结果） | 语句边界 / suspend 点 **wholesale reset**（bump 指针回退，不逐块 free） |
| **OWNED** | 3 | 逃逸拷贝（`dv_own`）：具名变量存储、函数实参、协程帧、容器插入、future 结果、生成器槽、异常对象 | 目标结构的既有管理者（V2 epilogue / V3 `dv_coro_free` / V4 removal / V5 unref） |

**不变量**：

- I1 任一缓冲**恰属一态**；tag 在分配时定死，运行期不改；
- I2 ARENA 缓冲的指针**不得**在 reset 之后被任何结构持有（由逃逸规则保证：所有跨语句/跨帧持有点都先 `dv_own`）；
- I3 OWNED 缓冲的释放点唯一且现存（复用 §2.2 的 V2-V5 管理者，只补 V2 的 epilogue）；
- I4 OBJ 缓冲（C6）**永远 OWNED**，沿用 §2.5 事实 B 的既有协议，禁入 arena。

### 6.2 逃逸点全集（编译期可判定，戊的产出）

|---|---|---|

| E2 函数调用实参 | codegen:2153-2210（args_arr 组装） | 每实参 `dv_own`（被调方帧比调用方语句活得更久） |
| E3 协程创建实参 | `dv_coro_create`（runtime:5787；args 现为 **memcpy 浅拷**，:5801-5808） | **补深拷**（见 §7.3 与 §十三 R1 的语义裁定项） |

**非逃逸（留 ARENA）**：只读内置实参解引用结果（P2，`dv_deref_value` 的 strdup 结果只活一条内置调用）、比较/查找的中间串、打印临时——这些全部在语句内死亡。

### 6.3 语句边界 mark/reset 规则

- 每条**顶层语句**入口：`m = dv_arena_mark()`；出口：`dv_arena_reset(m)`。
- 循环体：循环语句本身是一条语句，**每轮迭代**在迭代入口重新 mark/reset（心跳轮 16KB 的来源正是循环内字面量，reset 后当轮回收）。
- 槽位池单调发号（§2.2 V1）意味着**同一语句内的多个临时值同时存活**——mark/reset 以语句为粒度正好覆盖；跨语句的临时读若存在（见 §十三 R2），由 E1-E8 之外的「编译期证明不存在」或按逃逸处理。

### 6.4 协程 suspend 规则（与 C2 对齐）

- **suspend 点（await 的 `ret void` 前）**：`dv_arena_reset(帧入口 mark)`——该 resume slice 的全部临时值随 C 帧一起死亡，与现状语义一致（现状它们本来就已被丢弃，只是没回收）；
- **resume 时**：从帧入口 mark 重新开始 bump；跨 await 活值只从 `coro->locals/args` 取（C2），不经过 arena；
- 该规则使 arena 与协程帧**所有权完全分离**：arena 管「一帧一片的临时」，coro 帧管「跨片的活值」，两者无共享缓冲（E3 深拷保证）。

### 6.5 保守论证：为什么 reset 不会 double-free / 不会 UAF

- **不重**：`dv_free` 只对 OWNED/IMMORTAL 操作；ARENA 缓冲由 reset 整体回收，任何结构持有它都违反 I2（被逃逸规则阻止）；同一缓冲不可能既在 arena 又被某管理者 free。
- **不漏**：每个分配不是 ARENA（被某次 reset 回收）就是 OWNED（有唯一释放点）；IMMORTAL 无需释放。残留泄漏只可能来自「释放点管理者本身漏」（V2 epilogue 未覆盖的变量形态），由 §十 的分路径探针测量。

## 七、与协程回收的协作（专节 · 正面回答跨 suspend/resume）

> 任务书要求：「挂起后临时值归谁、resume 后如何取回、不重不漏」+ 「与协程回收 `dv_coro_*` 的协作单列一节」。

### 7.1 挂起后临时值归谁

**全部死亡，由 arena 在 suspend 点统一回收。** 依据（一手核实）：`dv_coro_resume`（:5846-5862）调 `coro->func(...)`，协程函数挂起时执行 `ret void` 把 C 栈帧还给调度器——临时槽位池（V1）是**该帧的 alloca**，帧毁则槽毁；槽里的 `str` 指针（arena 缓冲）随之悬空。现状下这些悬空指针只是「再也没人读」（泄漏但不崩）；arena 化后在 suspend 点 reset，**把泄漏变回收，语义零变化**。

### 7.2 resume 后如何取回

跨 await 需要活的值，**在 await 之前就已物化进 coro 帧**（Duff 装置既有设计）：codegen 在协程状态机函数里对跨挂起点变量经 `dv_coro_get_local/get_arg`（codegen:8310/8319）拿 `coro->locals/args` 的指针读写（runtime:6038-6053）。这些缓冲归 coro 帧管理者（`dv_coro_free`，:6126-6144），与 arena 无关。⇒ **取回路径完全不经过 arena，天然不重不漏。**

### 7.3 与 `dv_coro_*` 家族的逐项协作

| 函数（runtime 行号） | 现状 | 本设计下的动作 |
|---|---|---|
| `dv_coro_create` :5787 | args **memcpy 浅拷**（:5801-5808）——协程帧与调用方帧**共享** `str`/`list_data` 指针 | **E3 改深拷**（`dv_clone` 逐参）。这是本设计对协程家族**唯一的行为变更**，语义影响见 §十三 R1 需业主裁定 |
| `dv_coro_resume` :5846 / `await` :5917 / `run_to_completion` :5990 / `sleep` :6750 / `await_io` :6708 | 调度与挂起 | 无改；suspend 点按 §6.4 加 arena reset（codegen 侧发射） |
| `get_result` :6030 / `get_local` :6038 / `get_arg` :6048 / `get_await_result` :6056 | 读取（get_await_result 已 `dv_clone`） | 无改；返回值语义不变 |

### 7.4 与 A 线 L-219 的接口边界（C7 落地）

本设计**不假设 L-219 的任何修法**，只依赖两条既有事实：① 跨 await 活值物化进 coro 帧（§7.2）；② `己`/self 绑定属 A 线修复范围，与本设计的所有权分层无共用代码。**冲突面为零**；唯一时序要求：本设计的实施轮应在 L-219 修复之后（或同轮 A 先交付），以便用修好的协程路径做 §十 的协程探针验证。

## 八、异常 / try / setjmp 交互（C3 落地）

- **问题**：`_gen_typed_try` 内联 setjmp（codegen:5156 区）；`抛出` 经 longjmp 跳过 try 体内语句的 reset ⇒ 该语句入口到抛出点之间的 arena 分配被「孤儿化」——bump 指针停在中途，后续语句的 reset 只能回到自己的 mark，**孤儿块永久不会被回收**（缓慢泄漏，非 UAF）。
- **规则**：mark/reset 改为**显式 mark 栈**（每层语句 push/pop）；`捕获` 子句入口发射 `dv_arena_reset(本 try 语句入口 mark)`——长跳转丢弃的正是 try 体内的全部临时值，与正常路径语义一致（异常传播时 try 体局部值本就不再可见）。
- **与 R159-A 结论的关系**：R159-A 已定「跨挂起点 `抛出` 可被 `捕获` 接住、兜底拒绝非必要」——本规则不改该结论，只补异常路径的 arena 卫生；`_gen_typed_try` 不大改（任务书禁令延续）。
- **异常对象**（E7）本身走 OWNED，runtime 异常机现有 `dv_free` 不变。

## 九、线程与生成器（C4 / C6 周边）

- **线程**：`dv_thread_spawn`（runtime:7565+）在独立线程跑段函数 ⇒ arena 必须 **thread-local**（`_Thread`-local / TLS），每线程独立 bump 段与 mark 栈；线程入口/出口各自 reset。`g_dv_threads` 无锁登记的既有边界不动。
- **生成器**（`生成`）：`g->slots` 是堆数组、退出时统一 `dv_free`（runtime:6938-6962）⇒ 生成器槽是 OWNED 逃逸点（E6）；yield 值经 future/结果路径已是 `dv_clone`。
- **OBJ 缓冲**：永远 OWNED（I4），`dv_obj_release_slot/deepcopy_self/value_disown` 协议原样保留；`dv_free` 的 type-3 分支加 tag 判断后对 OBJ 行为不变。
