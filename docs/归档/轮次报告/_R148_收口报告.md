## 二、核心修复根因

### A 线：原生腿 JSON 级联（真 bug）
原生腿不认识 `解析JSON`/`序列化JSON`/`美化JSON`（走 `builtins.py → import JSON → JSON核心.light` 的 Python 级联， `_gen_typed_builtin` 无分支也不走 `_light_builtin` 回退）→ 报「未定义的段落：解析JSON」。改为 C 层三个原语 + codegen 暴露，零改动业务语义。

### C 线：`统计.light` 众数/多众数/频率分布（真 bug，src 腿）
`内置核心字典.light:27` 的 `字典设置(映射,键,值)` 是**原地修改、返回 None**。原写法 `设 频次 为 字典设置(...)` 把累加器重赋为 `None`，下一轮 `字典获取(频次,...)` 崩 `TypeError: 'NoneType' object is not subscriptable`。改为直接调用（原地改、不重赋值）。此前该模块从未被三腿对拍覆盖，缺陷长期潜伏。

### C 线：JSON核心.light CRLF 字面损坏
R148-C 追加段中 `如果 ... == k:` 行的 `\r\n` 被错写为**字面 ASCII `/r/n`**（0x2F 正斜杠），解析器把下一行拼到同行 → 语法错误。替换为真 CRLF（`0d 0a`），并复验 `bareLF=0`。

### D 线：凭证夹具不留痕（本轮收口新增）
D 线反跑测试原本在**源文件内**留字面合成 token（`ghp_...`/`AKIA...`），导致 `pre-push` 真门扫描推送范围时会拦截本文件自身。**不削弱门禁**，改为运行时动态拼接前缀（`"gh"+"p_"`），仓库内零字面密钥形态；原「靠命中自身夹具证明有牙」的断言改为独立的 `test_scanner_still_has_teeth`（临时文件合成 token 必被检出）。结果：全仓 `--root` 与全历史 `--history` 扫描**双双 RC=0**。
