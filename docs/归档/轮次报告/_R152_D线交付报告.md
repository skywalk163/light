## 一、D1 · 命名元组 / 默认字典：**实现落地**（不是边界裁定）

任务书给的裁定标准是「能 containment 实现就实现，否则登记边界」。实测结论：**能**，
且改动面比预估更小——**只需在 `src/code_generator.py` 的 `method_name_map` 补 3 个表项**，
`.light` 侧纯光明表达，零 runtime / 零 codegen_typed 改动。

### 1.1 调查题答复（任务书 D1 三问）

**① 光明类是否支持动态字段（`设 己.[变量名] 为 值` / `p.[变量名]` 读）？**

❌ **不支持，且不必支持**。`src/code_generator.py:4525` 属性访问恒发射
`_light_attr_get(_o, {expr.member!r})`——`member` 是**字面量字符串**，变量无从代入。
→ 路径 A（动态属性赋值）**否决**。

**② 原生腿对象模型加「动态属性对象」新价值类型的成本？**

不需要评估——**找到了更省的第三条路**：CPython 已有 `__getattr__` 兜底钩子，
光明侧只要能把「中文方法名」映射成这个特殊方法名即可，无需新价值类型、无需改 runtime。
→ 路径 B **不必走**。

**③ 默认字典能否只在 dict 读路径加「工厂槽」特例？**

任务书点名的「最省候选」其实**对 src 腿无效**：phase13 走的是 `_light_import_hook`
编译出的 **Python（src 腿）**，`d['缺失键']` 是直接 CPython `dict.__getitem__`，
C 层 `runtime_typed.c` 的 dict 读根本不在这条路径上。
→ 改用 **CPython 的 `__missing__`**：dict 子类缺键读时 `dict.__getitem__` 会回调它——
这正是官方 `collections.defaultdict` 的实现方式，比拦截 `__getitem__` 更省更稳。

### 1.2 实现（containment 三处，src 只动一个 dict）

**`src/code_generator.py`** —— `method_name_map` 补 3 项（定义侧 `_method_def_name_map`
由它派生，故**一处改动两处生效**）：

| 光明方法名 | Python 特殊方法 | 用途 |
|---|---|---|
| `缺失` | `__missing__` | dict 子类缺键读回调（默认字典） |
| `取属性` | `__getattr__` | 属性查找失败兜底（命名元组动态字段） |
| `调用` | `__call__` | 让类实例本身可调用（命名元组工厂） |

冲突复核（动手前全仓扫描）：`.调用(` / `.缺失(` / `.取属性(` 调用 **0 处**，
`段落 调用/缺失/取属性` 定义 **0 处**（`调用函数` / `调用AI` / `调用处理器` 是不同键，
不受影响）⇒ **零既有语义迁移**。

**`stdlib/集合工具.light`** —— 纯光明新增 3 个类：

* `类 默认字典类 继承 dict:` + `段落 缺失(键)`（读 `"默认工厂"` 槽 → 调工厂 → 写回 → 返回）；
* `类 命名元组类:` + `段落 取属性(名)`（按 `己.映射` 返回字段值，缺字段抛 `属性错误`）；
* `类 命名元组工厂 继承 list:` + `段落 调用(*值们)`（造 `命名元组类` 实例并填字段）。
  **继承 list 是刻意的**：自带字段名副本 ⇒ `长(命名元组(...))` 仍是字段个数，
  原生腿 T5C 冒烟的 `长(名)==2` 期望不受影响（实测 rc=0 out=`2`）。

**边界注记**同步进 `stdlib/集合工具.light` 头部「原生腿能力边界」条目 1 / 2。

### 1.3 实证（探针留底 `_r152d_scratch/`）

| 探针 | 结果 |
|---|---|
| `探针特殊方法.light` 编译前 | `def 缺失/调用/取属性`（中文名，未映射） |

## 二、D1 附带发现与修复（A 线类化的实例化语法错误）

详见 `_R152_A线交付报告.md` §六。摘要：

- **根因**：光明类实例化语法是 `新 类名(...)`，不是 `类名(...)`；后者被解析成段落调用，
  原生腿报「未定义的段落」，把 `test_原生腿_T5C_集合随机.py` 从绿打成红。
- **修法**：`集合工具.light` 全部实例化改 `新 X(...)`；队列类改 `继承 dict` 且内部队列存
  `"队列"` 键；`抛出 键错误` 降级为 `抛出 运行时错误`（`键错误` 未登记于原生腿异常白名单）。
- **教训（建议进 §5 两腿陷阱）**：**任何在「会被原生腿直接编译」的 `.light`（带魔数纯光明模块）
  里写的类，实例化必须走 `新 X(...)`**；且**改返回值形态前先查原生腿冒烟是否用 dict 形状观测它**。
