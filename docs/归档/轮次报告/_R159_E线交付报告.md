## 4. 门禁设计要点

### 4.1 机制（复用 R157-B，扩展为全套）

- **动态枚举**：`glob tests/test_*.py`，无手抄清单；新增文件自动入增量集（"新增文件"检测）。
- **真跑**：子进程 `pytest --runxfail`（xfail 标记全部失效按普通用例真跑）——判定必须动态，不许只扫不跑。
- **两种模式**：
  - `full`（`R159E_FULL=1`）：156 文件全量，**无论红绿先落基线**（红态基线 = 欠账登记输入 + D 线对照表）；
  - `incremental`（**日常默认**）：只跑「基线中红文件 + 基线后新增文件」。
- **无基线且未声明 full** → 主用例 **skip 并打印武装指引**（pytest 显式报 SKIPPED，不静默通过）。0.82/CI 不同步 `_r159_scratch/`（gitignored），门禁在那里自动退化为「静态层 + 跳过真跑」，**不拖慢全量门**；需要时同步 scratch 或以 `R159E_BASELINE=<路径>` 指过去即武装。

### 4.2 失败三分类（写码前实证的两个口径）

1. **import 类** = 缺**仓库内**模块 / `cannot import name` / 收集错且缺的是仓库内模块 ⇒ **门禁红，无常规欠账通道**（本门要堵的洞）；
2. **环境类** = 缺的全是第三方包（某台机没装 aiohttp 之类）⇒ 合法存量欠账（`_已知欠账`）；
3. **语义类** = 断言/行为/平台分叉 ⇒ 合法存量欠账。

> 仓库内判定用候选路径解析（`src/`/`stdlib/`（含中文子目录）`.py`/`.light`、`tests/`、顶层同名模块），`test_分类器有牙`/`test_仓库内模块判定有牙` 反跑有牙。

### 4.3 两个写码前探针实证驱动的设计

- **`--continue-on-collection-errors`**：pytest 默认遇收集错**中断整场**（探针实证 rc=2 + `Interrupted: 1 error during collection`，其余用例不跑）⇒ 子命令必须带此flag，否则「一个坏文件掩盖其余 155 个结论」。
- **`--runxfail` 下命令式 `pytest.xfail()` 呈现为「通过」**（junit 无 skipped 子元素、终端计 passed）⇒ 见 §12 新发现 L-219；本门不重复建设 R157-B 静态吞点层，但 junit 解析对 `skipped type=pytest.xfail`` 形态做了防御性欠账要求（当前 pytest 版本不产出该形态，两条路都堵。

### 4.4 子进程跑法（Windows 嵌套约束）

子命令继承 pyproject addopts 并显式追加 `--timeout=300`（后置覆盖全局 60，R152-C2 逐例提限不动全局）+ `--continue-on-collection-errors`；**必须走 xdist**（本机 Windows 沙箱：父进程嵌套串行 pytest 子进程会 SIGTERM，R157-B 实证），默认 `-n 1`（R157-B 收口修复同款考虑），`R159E_CHILD_WORKERS=<n>` 可覆盖。主用例 `@pytest.mark.timeout(2700)`。

### 4.5 已知局限（诚实声明）

1. **增量模式不复跑基线中绿的文件**——其中的新断言回归抓不到；唯一补法是定期 `R159E_FULL=1` 重新武装（E-4「只做增量/失败重跑」口径的固有代价）。
2. **命令式 xfail 假绿**（L-219，见 §12）。
3. **`_存量import欠账` 窄通道当前为空**——首跑双平台 0 个 import 类红，未启用。

## 12. 新发现（立号素材；账本写入属收口统一动作）

### L-219（建议立号，已 grep 确认未用）—— `--runxfail` 下命令式 `pytest.xfail()` 假绿

- **现象**：pytest `--runxfail` 只让 **marker-xfail** 真跑；**命令式 `pytest.xfail()` 仍执行且被计为「通过」**（junit 无 skipped 子元素，2026-10-17 探针实证：`2 failed, 3 passed` 中命令式 xfail 计 passed）。
- **影响**：非 except 型的命令式 xfail 会让用例「看起来绿」——R157-B 静态吞点层只覆盖「except 吞并型」这一子集，本洞**无任何门禁覆盖**。
- **建议**：后续轮扩展 R157-B 静态层（AST 扫全部命令式 `pytest.xfail()` 调用点，不论是否在 except 内）或在本门加交叉核对；修法由业主裁。

### L-220（建议立号，已 grep 确认未用）—— D9 对抗用例跨日/跨权限结果波动

- **现象**：`test_path_guard_light.py::Test对抗用例_D9::test_链接指向沙箱外时经过链接的子路径也被拒_附变异反跑` 在 **2026-10-16（R157-B）本机记录为失败**（`assert True is False`），**2026-10-17（R159-E 首跑）本机通过**、0.86 通过；机器、代码（path_guard 未被动过）均未变。
- **疑因**：Windows symlink/junction 创建权限（管理员/开发者模式）差异导致用例内条件式 xfail 触发路径不同，或该用例本身 flaky（内含变异反跑）。
