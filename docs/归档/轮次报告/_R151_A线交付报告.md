## 三、做了什么

### 3.1 文件级改动（唯一改动文件）

`stdlib/数学.light`：`+497 / -4`（`git diff --numstat`）。
4 处删除全部是**被替换的等价行**：
① 文件头注释「随机3导出归 T5C」段改写为 R151 说明；
② `从 列表工具 导入 求和` → 删除（改为本地段落，理由见 3.3-①）。

### 3.2 段落实现要点

| 项 | 关键手法 |
|---|---|
| `奇偶判定` | 原生腿 `%` 是 **C 式截断**（`-3 % 2 == -1`），src 腿是 Python 式（`+1`）。统一写 `_light_builtin.绝对值(n) % 2 == 1`，两腿同解 |
| `弧度转度分秒` | 返回三元组 `(度, 分, 秒)`；`整数()` 截断两腿一致 |
| `最大公约数` | 循环 `当 b > 0` 形式，避免 `当 乙:` 的真值依赖 |
| `线性回归` | 返回字典 `{'斜率','截距','相关系数'}`，对齐 oracle 契约；除零分支显式给默认值 |
| `复数*` | 一律 `是列表` 分派（原生腿复数为 `[实部,虚部]`；src 腿既有 CPython complex 也有列表） |
| 随机族 | 复刻 CPython `_randbelow_with_getrandbits`（`数学随机下限`），故 `随机整数` 与 CPython **位级一致** |
| `正态随机` | CPython `normalvariate` 的 Kinderman-Monahan 比值法（oracle 用 normalvariate 而非 gauss） |
| `指数随机` | `-ln(1-random()) / λ` |
| `泊松随机` | Knuth 乘法法（**oracle 该项必崩**，见 §六） |

### 3.3 三处非显然的必要决策

**① `求和` 从「导入转发」改为「本模块段落」。**
原先 `数学.light` 写 `从 列表工具 导入 求和` 并 `导出 求和`——运行期名字**可达**，
但**护栏只统计 `^段落` 行**，故它仍被记为缺口（56 项之一）。
改为本地段落既消账，又保持导出语义不变（对拍 507 项含 `求和`）。

**② 私有段落加 `数学` 前缀（`数学随机下限`/`数学随机位长`）。**
原生腿跨模块段落名**不共享**，但 `随机.light` 已有 `随机下限`/`随机位长`；
即便实证跨模块同名词段不冲突（§五-③），仍按最小惊讶原则加前缀隔离。

**③ `正态随机` 参数名遮蔽规避（本轮最重要发现，详见 §四）。**

### 3.4 未做（有意）

- **不改 `数学.py`**：任务书指定它为 golden oracle；其实测有 2 处自带缺陷（§六），
  A 线处置口径是「`.light` 给正确语义 + 登记缺陷」，不反向改 oracle。
- **不改护栏 `已知缺口` 清单**：任务书 §一明示「清单删减统一交 F 线收口时一次性完成」。

## 四、本轮发现的 codegen 缺陷（A 线只规避、不改 `src/`，登记交 D 线）

### 缺陷：参数名与同模块段落名 + 内置映射名三重撞名时，参数被编译成函数调用

**最小复现**（`_r151a_scratch/probe_x.light` / `probe_y.light`）：

```light
段落 标准差():
  返回 99.0

段落 甲(标准差):
  返回 标准差 * 2.0        # ← 生成的 Python：return (标准差() * 2.0)
```

实测矩阵（`src/code_generator.py` 编译产物核对）：

| 场景 | 参数名 | 同模块有同名段落 | 该名在 `builtin_map` | 生成 | 结论 |
|---|---|---|---|---|---|
| A | 标准差 | 有（零参） | 有（`_light_builtin.标准差`） | `标准差()` | ❌ **误编译** |
| B | 无参 | 有（零参） | 无 | `无参` | ✅ 正常 |
| C | 标准差 | 有（带参） | 有 | `标准差()` | ❌ **误编译** |
| D | 标准差 | **无** | 有 | `标准差` | ✅ 正常 |
| E | 阿尔法 | 有 | 无 | `阿尔法` | ✅ 正常 |

**触发条件**：参数名 **同时**满足「本模块存在同名段落」且「该名是 `builtin_map` 的键」，
且在表达式位置裸用（`设 X 为 参数 加 0.0` 这类先落局部变量也不免疫）。

**影响面（全 stdlib 扫描）**：`_r151a_scratch/param_scan.txt` 命中 7 处，
但其中 6 处（`幂(底数, 指数)`、`pow(底数, 指数)`、`随机整数(最小值, 最大值)`、
`随机范围(最小值, 最大值)`）**实际未被误编译**——因为 `指数/最小值/最大值` 虽有段落，
但未进 `builtin_map` 的**裸名**判据组合；唯一真正中招的是**新写的** `正态随机(…, 标准差)`。
用 AST 复核生成产物：修前「参数被编译成调用」的段落 **1 个**，修后 **0 个**。

**A 线处置**：`正态随机` 首行 `设 西格玛 为 标准差 加 0.0` 归一到局部变量后再参与运算，
保留 oracle 的参数名（`标准差`）以便调用方按名传参。
（注意：这个规避只在**先落局部变量**时有效；`设 结果 为 标准差 * 2.0` 仍会误编译。）

### 4.1 根因定位到符号级 + 已验证的修复（补丁就绪，未落 `src/`）

**根因（一行）**：`src/code_generator.py` 的 `_shadows_builtin()`（`:1098-1105`）把
「已在 `_user_defined_functions` 里」的名字一律判为**不遮蔽**——
**但段落名本身就在 `_user_defined_functions` 里**（`:2638` `self._user_defined_functions.add(stmt.name)`）。
所以「段落参数撞同名段落」这条路径**必然失效**。

插桩实测（`_shadows_builtin` 加 trace）：

```
('name=标准差', 'shadowed=False', 'in_locals=True', 'in_userfuncs=True')
```
→ 参数已进 `_local_variables`，却被 `and name not in self._user_defined_functions` 否决。

**修复（+11 / −1 行，6 处）**：新增「当前函数形参」集合，让它压过该排除项。

| # | 位置 | 改动 |
|---|---|---|
| 1 | `__init__`（`:177` 后） | 新增字段 `self._current_params: set = set()` |
| 2 | `_shadows_builtin`（`:1105`） | `and (name not in self._user_defined_functions or name in self._current_params)` |
| 3 | `_generate_paragraph` 参数绑定（`:2652` 前） | `saved_params = self._current_params` / `self._current_params = set(raw_param_names)` |
| 4 | `_generate_paragraph` 收尾（`:2710` 后） | `self._current_params = saved_params` |
| 5 | 类方法参数绑定（`:3906` 前） | 同上（取 `_current_method_params`） |
| 6 | 类方法收尾（`:3998` 后） | `self._current_params = saved_params` |

补丁文件：**`_r151a_scratch/param_shadow_fix.patch`**（**+14 / −1 行，8 处 hunk**，带 3 行上下文，可直接 `git apply`）。

**覆盖三处函数边界**（初版只盖了段落一处，实测类方法与嵌套段落同样中招，已补齐）：

## 六、oracle（`数学.py`）自带缺陷 2 处（只登记，不复制）

| 项 | `数学.py` 实现 | 实际结果 | 应为 | A 线处置 |
|---|---|---|---|---|
| `欧拉常数` | `return math.gamma(1)` | **`1.0`**（Γ(1)=1=0!） | γ ≈ 0.5772156649（docstring 自己写的是「γ ≈ 0.5772」） | `.light` 返回真值 γ；**不改 oracle** |
| `泊松随机` | `_random.poissonvariate(均值)` | **`AttributeError`**（该属性在 CPython 全版本不存在） | 如 Knuth 法 | `.light` 给可用语义（Knuth 乘法法）；**不改 oracle** |

⇒ 这两项**不做逐值对拍**（oracle 自身无正确参照），改以「语义正确性 + 统计口径」验证：
`欧拉常数` 与真值比对；`泊松随机` 用大样本均值收敛（λ=4.0 时 20000 样本均值 ≈ 4.0）。
⚠️ 建议后续轮次把这两处同步修回 `数学.py`，否则「oracle」名不副实。

## 九、踩坑与修正记录（过程留档）

| 坑 | 现象 | 修正 |
|---|---|---|
| **对拍 harness 自身缺陷** | 随机族一次跑出 70 条「失败」，看数值分布完全随机 | light 侧与 CPython 侧**共用同一全局 random 流**、互相推进导致错位 → 改为**每次比较前两侧各自同种子重播**，160 项全通过 |
| **`正态随机` 参数遮蔽** | src 腿 `TypeError: 'float' object is not callable` | 定位到 §四 的 codegen 缺陷 → 首行归一到局部变量规避；并用 AST 全量复核「受影响段落 1 → 0」 |
| **`随机样本` 去重口径** | 初版按**值**去重，遇重复元素（`[1,1,1]` 抽 2 个）会永久拒绝采样 → 死循环 | 改按**索引**去重；`k >= n` 直接整表打乱返回 |
| **并行线同工作区作业** | 为隔离 D 线 `runtime_typed.c` 做 `git stash` 时，`stdlib/builtins.py` 的 stash/pop 把 `数学.light` 行尾带成 CRLF | 停止对非 A 线文件的一切 stash；`数学.light` 行尾重新归一为 LF（已核 `CRLF=0`）。D 线隔离改用**目录副本**（`_r151a_scratch/src_head/`），零触碰他线文件 |
| **`随机范围` 语义歧义** | `随机.light` 的 `随机范围` 是 randrange，`数学.py` 的是 uniform | 按 **oracle（`数学.py`）** 实现为 uniform 区间随机；不导入 `随机.随机范围` 以避免语义串台 |
