## 1. 缺陷与根因

**现象**（R158-C 实测）：带 `import` 的多模块程序里，`异步 段` 全部被当普通函数生成，
`创建任务(f())` 的实参立即求值、`异步 运行` 直接跑完，分布式 worker 领任务循环
永不可达（领任务 = 0 / 12874 请求）。

**根因**：单模块路径 `TypedLLVMCodeGen.generate()` 里有

```python
modifiers = self._segment_modifiers.get(reg_key, [])
self._gen_typed_segment(..., modifiers, ...)
```

而多模块路径 `compile_modules_typed()` 的循环体**没取也没传** `modifiers`，
`_gen_typed_segment` 的 `modifiers` 形参取默认 `None` → `is_async` 恒假。
`modifiers` 是 `is_async` 的**唯一真源**（任务书禁令：不许改成"猜"）。

## 4. 连带面①：`_count_await_in_node` 漏计穷举（逐类表）

### 4.1 为什么它是"静默截断"而不是编译错误

`num_await` 是**发射前预扫**结果，决定 `switch` 有几个 `case` 臂。
**欠计** ⇒ 挂起点写入的 `resume_point` 不在 `switch` 范围内 ⇒ 落 `default` ⇒ 直接跳到
`coro_switch_end` ⇒ 函数 `ret void`，**协程后半段被静默跳过**（rc=0，无报错）。
**多计** ⇒ `switch` 引用从未发射的恢复标签 ⇒ `clang: use of undefined value`。

### 4.2 逐类表（探针 `_r159_scratch/a_collateral_matrix.py`）

判定口径：同一程序在 HEAD 与修复后各跑一次，比对 stdout 真值（不看测试绿不绿）。

| 形态 | HEAD(修复前) | 修复后 | 说明 |
|------|-------------|--------|------|
| `如果` 体内挂起 | OK `前\|if后\|done` | OK 同左 | 旧实现已覆盖 |
| `当` 体内挂起 | OK `i0\|i1\|done` | OK 同左 | 旧实现已覆盖 |
| `遍历` 体内挂起 | **COMPILE_FAIL**（dominance） | **OK** `a\|b\|done` | 连带面#3 |
| `尝试` 体内挂起 | **TRUNC** `try前` | **OK** `try前\|try后\|done` | 旧实现不递归 `TryStatement` |
| `捕获` 体内挂起 | **TRUNC** `catch前` | **OK** `catch前\|catch后\|done` | 见 §4.3 双计陷阱 |
| `匹配` 分支内挂起 | **TRUNC** `done\|one` | **TRUNC** `done\|one` | **不是本缺陷**，见 L-220 |
| 双挂起点顺序 | OK `s1\|s2\|done` | OK 同左 | — |
| `否则` 分支挂起 | OK `else前\|else后\|done` | OK 同左 | — |
| 嵌套段定义（外层挂起） | **COMPILE_FAIL**（`use of undefined value`） | **OK** | 见 §4.4 |

### 4.3 关键：`catch_body` 双计（本次实测新抓）

第一版通用递归把 `捕获` 体**算两遍** → `resume__coro_f1_2_3` 未定义 → 编译失败。
根因在 `src/compiler.py:_convert_try_stmt`：v3 解析器把 catch 体**同时**填进
`catch_clauses` 与向后兼容字段 `catch_body`，且两次 `_to_list_stmts` 各建一份**新节点对象**
（内容相同、身份不同）——所以按 `id()` 去重无效，必须按字段语义去重。

修法：与同文件既有 `_iter_ast_children`（R118 收口）**同一条口径**——

```python
if 字段.name == 'catch_body' and getattr(node, 'catch_clauses', None):
    continue
```

### 4.4 例外二：嵌套 `段落` 定义不计入外层

`段落 内(): 睡眠(5)` 在语句层是 no-op（`_gen_statement` 直接 return，实体另成函数）。
通用递归会把它的 body 算进外层 ⇒ 多计 ⇒ `clang: use of undefined value`。
故 `SegmentDefinition` 显式 `return count`，不下探。

### 4.5 结论

`_count_await_in_node` 从"逐类 isinstance 穷举"改为"按 dataclass 字段通用递归 + 2 条显式例外"
（`SegmentDefinition` 不下探、`TryStatement.catch_body` 在有 `catch_clauses` 时跳过）。
**新语句类型不再需要来这里补分支**——这是本线对连带面的根本性收口，而非打补丁。

## 5. 连带面②：`_gen_typed_try` × 协程 评估结论

探针：`_r159_scratch/a_try_coro_probe.py`（单模块路径，协程早已开启，可直接观测组合行为）。

| 用例 | HEAD(修复前) | 修复后 |
|------|-------------|--------|
| T1 `尝试` 内 `睡眠`，无异常 | **`try-前`（截断）** | `try-前 \| try-后 \| done` |
| T2 `尝试` 内 `等待 任务` | **（空，一句都没输出）** | `got \| done` |
| T3 `尝试` 内 `睡眠` 后 `抛出` | **`try-前`（catch 与 done 全丢）** | `try-前 \| catch \| done` |
| T4 `尝试` 内仅同步体（无挂起） | `done` | `done` |

| 用例 | HEAD `switch` 臂数 | 修复后 `switch` 臂数 |
|------|:---:|:---:|
| T1 | **1**（只有 resume 0） | **2** |
| T3 | **1** | **2** |

**结论（任务书要求的 (i)/(ii)/(iii) 择一）**：

- 任务书设想的是"try × 协程不兼容，需编译期响亮拒绝"。**实测否定了这个前提**：
  修复 `_count_await_in_node` 后，`尝试`/`捕获` 内挂起、以及**跨挂起点的异常捕获**
  （T3：`睡眠` 后 `抛出`，catch 正常接住）**都能正确工作**，`setjmp/longjmp`
  与协程恢复块并不冲突。
- 因此**不需要**"编译期拒绝"这条兜底（(ii) 不成立为必要项）；(i)"修好"已经达成，
  且由 §4.2 的行为矩阵与 §6 的反跑双重背书。
- **唯一保留的边界**：`_gen_typed_try` 的**全面改造**（如 finally × 挂起、跨协程传播）
  不在本线 scope（任务书明令"只做评估 + 兜底拒绝"）。已评估部分无静默错误。

|------|------|--------|
| `匹配` 后接语句 | `after` → `one`（**顺序反了**） | `after` → `one` |
| `如果` 后接语句（对照） | `one` → `after`（正确） | `one` → `after` |

与协程/挂起无关（无 `睡眠` 也复现），是原生腿 `匹配` 语句的发射顺序缺陷；
`docs/原生腿能力边界.md` 承诺"按源码顺序逐条比较，命中即跳出"，与此不符。
影响面：`匹配` 之后还有逻辑的分支代码会**先跑后续逻辑再跑命中分支**。

### 9.3 L-221（建议立号）：顶层单条 `异步 运行 <同步段落>()。` 被发射两次

复现（`_r159_scratch/a_zero/v_d.light`）：

```
段落 主():
  输出("Z")
  输出("W")

异步 运行 主()。
```

| 写法 | `_seg_f1` 调用点 | 输出 |
|------|:---:|------|
| `异步 运行 主()。`（单条顶层语句） | **2**（`__light_init` + `main`） | `Z W Z W`（**跑两遍**） |
| `主()。`（直接调用） | 1 | `Z W` |
| 两条顶层 `异步 运行`（`主2.light`） | 2（**都只在 `__light_init`**） | 各一次 |

`main` 里 `call @__light_init()` 之后又 `call @_seg_f1`，故段体执行两遍。
目标为**异步段**时不复现（A3/A1b 断言精确输出仍绿）。HEAD 同样复现。
