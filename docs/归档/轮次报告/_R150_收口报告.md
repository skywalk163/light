## 一、交付内容

### A 线 · TRUNK：原生腿补 2 个文件系统原语（四处齐全）

| 段落 | C 符号 | POSIX | Windows |
|---|---|---|---|
| `文件锁定(路径, 共享)` | `dv_fs_lock` | `flock(LOCK_EX\|LOCK_NB / LOCK_SH\|LOCK_NB)` | `LockFileEx(LOCKFILE_FAIL_IMMEDIATELY\|...)` |
| `文件解锁(路径)` | `dv_fs_unlock` | `flock(LOCK_UN)` | `UnlockFileEx` |

四处：`src/llvm/runtime_typed.c`（含**进程内 static 锁表** `path→fd`，解锁靠它查回 fd）
→ `src/llvm/codegen_typed.py` `declare`+`_gen_typed_builtin` 分派（含中英别名）
→ `src/code_generator.py` `builtin_map` 裸名条目 → `stdlib/builtins.py` src 腿地板实体。

**踩到的坑（都已修）**：
1. Windows 分支缺 `#include <fcntl.h>` → `_O_RDWR/_O_CREAT` undeclared；
2. MSVC 上关句柄叫 `_close` 不是 `close` → 加 `_dv_lock_close` 宏；
3. `sys/file.h`（flock 常量）必须显式 include，否则 FreeBSD/clang 腿整条崩；
4. **重复锁定语义**：Windows msvcrt 对同一 fd 同一区间重复 locking 会失败 →
   两腿统一取「本进程已持有即返回真」的幂等口径（不再「重开 fd 再锁」）。

### B 线 · BRIDGE：`.light` 补 2 段 + 4 处语义漂移

`stdlib/文件系统.light`：补 `文件锁定`/`文件解锁` 两个门面段（更新导出清单）；
修 6 处语义漂移，全部以 `stdlib/文件系统.py` 为黄金 oracle：

| 段落 | 原来 | 现在 | 判据 |
|---|---|---|---|
| `计算文件哈希` | 抛 `运行时错误` | 抛 `值错误` | 测试期望 `ValueError` |
| `MIME类型检测` | 抛 `运行时错误` | 抛 `值错误` | 同上（两处抛点） |
| `备份文件` | 抛 `运行时错误` | 抛 `文件错误` | 测试期望 `FileNotFoundError` |
| `是否为有效路径名` | 只判 `" "` 单个空格 | `去除空白(路径) == ""` 判全空白 | `.py:875` 用 `path.strip()` |
| `展开用户目录` | 先取 HOME；尾巴带前导 `/` | 先取 USERPROFILE；剥前导 `/` | Git-Bash 的 HOME 是 MSYS 形态；`os.path.join("C:\\Users\\x","/test")` → `C:/test` |
| `文件树` | 只列顶层 | `_文件树行` 递归展开目录 | 测试断言 `"nested.txt" in 树` |
