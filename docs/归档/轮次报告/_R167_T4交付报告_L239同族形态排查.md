## 二、三形态排查结果（双腿原始数据·0.88）

对拍口径：PY 腿 = `python -m cli.light_unified run <f>`；原生腿 = `compile_light_typed(optimize_level=0)` 编译后执行。记录 `(rc, stdout, stderr末行)`。

### 2.1 形态① `等待 X()` 而 X 是同步段落 —— **腿不对称，本轮已修**

| 探针 | 原生腿 | PY 腿（修前） | PY 腿（修后） |
|---|---|---|---|
| **A** 同步段落定义在**调用点之前**（`f1a`） | `(0, "同步干活跑了 \| 主结束", "")` | `(1, "同步干活跑了", "object NoneType can't be used in 'await' expression")` | `(0, "同步干活跑了 \| 主结束", "")` |
| **A'** 同步段落定义在**调用点之后**（`f1c`） | 未单独跑原生腿（同形，见注） | `(1, 同 A 的 TypeError)` | `(0, "干活跑了 \| 主结束", "")` |
| **负对照** 等待**异步**段落（`f1b`） | `(0, "异步干活跑了 \| 主结束", "")` | `(0, 同左)` | `(0, 同左)`（`await` 保留，恰好 1 处） |

**根因（代码级）**：`src/code_generator.py` 的 `AwaitExpr` 分支（语句侧 `:2187`、表达式侧 `:4884`）无条件发 `await <inner>`。被等待者 `同步干活()` 是普通函数调用、求值即执行并返回 `None` ⇒ `await None` ⇒ `TypeError`。原生腿 `dv_coro_run_to_completion` 遇非协程句柄一律容忍、正常跑完 ⇒ rc=0。

**修法（与 R166 同风格：补判型、不扩大改动面、断言值不改）**：

1. `_resolve_await_callable_kind()`：只对「名字可解析为**本模块同步段落**」返回 `'sync_paragraph'`；异步段落 / 函数值 / 表达式 / 导入名一律 `'other'`（维持原样发 `await`）。**只有能确证是同步段落时才动手**。
2. `AwaitExpr`（语句 + 表达式两处）按判型结果决定发不发 `await`。
3. `_prescan_async_paragraphs()`：把段落分表（`async_paragraphs` / 新增 `sync_paragraphs`）提前到**发射前**统一收集——原实现只在发射到该段落时才登记，**判型会依赖「被调段落写在调用点前面还是后面」**，A' 探针就是钉这一条。`generate()` 里两表按次重置，防跨调用污染。
4. `_generate_paragraph` 里同步段落也登记 `sync_paragraphs`（覆盖「预扫描没覆盖到」的路径，双保险）。

**为什么不顺手把 `异步 运行`（R166 那段）也改用新判型**：R166 的分支按任务书 §5 表格属于「已修且已收口」，本轮无缺陷证据，不动——避免把两个已收口的判型口径搅在一起。两处判型目前是**两条独立分支、同一判据来源**（都是 `async_paragraphs`）。

### 2.2 形态② `异步 遍历 x 之 同步可迭代` —— **预判成立，无缺陷，锁结论**

| 探针 | 原生腿 | PY 腿 |
|---|---|---|
| 普通列表内 `合计 为 合计 + x`（`f2d`） | `(0, "3", "")` | `(0, "3", "")` |
| `追加(...)` 形态（`f2b`） | `(0, "3", "")` | `(0, "3", "")` |
| 同步生成器作可迭代（`f2e`） | 编译期 `NotImplementedError: 原生后端暂不支持语句类型「YieldStmt」`（**本探针里原生腿不支持生成器段落，与本形态无关**） | `(0, "3", "")` |

复核 `src/code_generator.py:2525-2531` 与 `:1710-1731`：`异步 遍历` 一律经 `_light_async_iter(...)` 包装，辅助函数运行时探测 `__aiter__`、普通 list 回退为逐个 `yield`。结论与任务书预判一致。

**排查中顺带排掉一个假线索（如实记录）**：我第一版探针把自增写成 `计数 加等 1`，PY 腿报 `object int can't be used in 'await' expression`，一度被当成「形态② 缺陷」。实为 `加等` 不是合法关键字、被解析成前缀 `等待`（`(计数 + 等待(1))`），**与 `异步 遍历` 无关**——同一写法在**普通同步 `遍历`** 里同样崩（`f2c`）。规范写法是 `加等于` / `计数 为 计数 + 1`。**这是写错语法，不是腿缺陷，未登记缺陷账。**

### 2.3 形态③ `异步 运行 f()` 而 f 是函数值变量 —— **原生腿未实现，登记为语言级限制，本轮不修**

| 探针 | 原生腿 | PY 腿 |
|---|---|---|
| f 绑定**异步段落**（`f3a`） | 编译期 `NotImplementedError: 原生后端暂不支持语句类型「RunAsyncStmt(協程内)」（…请用转译后端）` | `(0, "主结束", "RuntimeWarning: … never awaited")` |
| f 绑定**同步段落**（`f3c`） | 同上，`NotImplementedError` | `(0, "同步干活跑了 \| 主结束", "")` |
| 直接 `异步 运行 异步干活()`（`f3b`，对照） | 同上，`NotImplementedError` | `(1, "", "asyncio.run() cannot be called from a running event loop")` |

**裁定**：腿内（协程体内）的 `异步 运行` **原生腿整体未实现**，无从双腿对拍；这不是「腿不对称」，而是**原生腿缺该形态**。按任务书 §5「若某形态原生腿也崩/也错 ⇒ 不是腿不对称，登记为语言级限制，不修」处理。

**顺带把 PY 腿侧的真实语义写清楚（供后续轮立项，不在本线修）**：

- `异步 运行` 的语义是「在事件循环里再起一个循环」，在**协程体内**用本身就是矛盾的：`asyncio.run()` 在运行中的 loop 里必抛（`f3b`）。
- `f` 为函数值时，R166 判型「名字不可解析 ⇒ 按同步段落」把它编成裸 `f()`：同步段落值能跑完，但**异步段落值的那种又静默丢弃协程**（Never awaited 警告）。也就是说，`异步 运行 f()` 这条路上 PY 腿**自己没有稳定语义**。
- 结论：**该形态属语法层待裁定项**（要么编译期拒收、要么定义成「放到当前 loop 里调度」），不适合在 R167 这种「只改测试门」的轮次里改语义。

## 三、改动清单（`git diff src/code_generator.py`，+75/−2）

| 位置 | 改动 |

**影响面自评**：
- 只有「`等待 X()` 且 `X` 是本模块顶层同步段落」这一种落点会改变生成码；其余全部逐字不变。
- `async_paragraphs` 从「发射到才登记」变为「发射前已全量登记」，会让**模块顶层裸调用异步段落**的既有判型在「异步段落定义在后」时也能命中——这是**同方向的修正**（少一处同族不对称），已在 `f1c` 之外由 87 项异步族回归覆盖。
- 跨模块 / stdlib 导入名不在本模块段落表里，判不出 ⇒ 维持原样（**宁可不对齐也不误伤**）。这一点是刻意的：把导入的同名异步段落误判成同步即会「协程静默不被驱动」，比现状更坏。
