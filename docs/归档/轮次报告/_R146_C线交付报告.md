## 6. 第 4 步（选做）—— 本轮**未做**，理由

按任务书「只挑 Tier 1 里最简单、最有把握的**活名**」的要求：

- 数学族 **活名 = 0** → 无对象可实现。
- 数学族 **活名 = 0** → 无对象可实现。
- JSON 族 **活名 = 2**（`JSON转CSV` 强 / `CSV转JSON` 弱），且经 §9 复核**均未被真正覆盖**。理论上这正是第 4 步该动手的对象。

**但仍判定不实现**，三条理由：

1. **落点不合适**：本轮文件域只有 `stdlib/数学.light` 与 `stdlib/JSON核心.light`。CSV↔JSON 转换放 `JSON核心.light` 语义不搭（该文件头明示只做「解析/序列化/序列化缩进/写入文件」，且有严格的「与 `builtins.py` 逐字符等价」契约，见其第 3-20 行）。放错地方比不补更糟 —— 任务书明令「不要为了凑数改坏现有 .light」。
2. **口径需先对齐**：`JSON.py:480` 的实现有两条隐含约定（值为字符串时 `,`→`、`、`\n`→空格`；空数据返回 `''`），且 `输出文件` 非 None 时写盘并 `返回 None`。落到 `.light` 前需主 agent 确认是否逐字对齐，否则删影子时测试会红。
3. **优先级**：§9 暴露的 28 个桩文件 / 731 个空导出名是更严重的问题，本轮把余量留给「把结论写实」而非「补 2 个函数」。

→ **判定：只登记，不实现。** 建议下一轮单独开一条「JSON转CSV/CSV转JSON 落点裁定 + 语义对拍 + 迁移」子线。

**未跑**：`cli/light.py run --backend src` / `--backend native` 双腿对拍 —— 无实现对象，无需对拍。
