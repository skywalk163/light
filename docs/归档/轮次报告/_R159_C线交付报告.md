## 3. diff 定位证据链（分配打点）

### 3.1 判据修正：**「每轮 KB」会把速度差混进来，必须以「每秒 + IR」为准**

早期打点用每轮 KB，结果各变体差 40 倍以上（P 0.077 vs B 3.718 KB/轮）——但那是因为
**迭代速度差 40 倍**（1.2M vs 0.03M 轮/s），不是每轮泄漏差 40 倍。改用「MB/s + 迭代数
归约」后，所有含字符串操作的变体斜率收敛到同一量级（115–117 MB/s），泄漏的真变量是
**「每迭代做了多少次字符串字面量求值」**。

### 3.4 IR 级根因（不看行为看指令）

编译三个最小程序 dump `.ll`（HEAD 编译器，同一入口 `compile_light_typed`）：

1. **`裸循环` 循环体零分配**：`miniloop.ll` 的 `while_body` 只有 `dv_int`/`add`/`store`/
   `getelementptr`，**没有任何 call 到分配函数**（值全部落在 alloca 帧槽里）。
2. **每比较一次字面量 = 一次 `dv_str`**：`strcmp_loop.ll` 的 `while_body` 内
   `call void @dv_str(ptr %27, ptr %26)` + `%30 = call i32 @dv_eq(...)`——
   **字面量常量被 `dv_strdup` 成堆副本再比较**，循环每转一次就多一个永不释放的副本。
3. **运行时实现**（`src/llvm/runtime_typed.c`）：
   `dv_str` → `result->str = dv_strdup(s)` → `malloc(len+1)`；`dv_concat` → `malloc(len_a+len_b+1)`
   再 `dv_strdup` 一份。`dv_free`/`dv_obj_release_slot` 只覆盖「具名槽位」，**临时值无释放路径**。
4. **探针主循环实测 IR**（`c_driver_stage1.ll` 之外的 `r159_probe_ir.ll`）：主循环体内
   **17 次 `dv_str` / 15 次 `dv_eq` / 2 次 `dv_concat`**，与 §3.2 R 变体
   「103.7 B/轮 ÷ 14 个字面量 ≈ **7.4 B/次字面量求值**（FreeBSD jemalloc 8B 粒度）」自洽。
   心跳轮 16.37 KB ÷ 7.4 B ≈ **2200 次字面量求值/轮**——一次 JSON-RPC 心跳（序列化 +
   头拼接 + `收全部` 逐块拼接 + `解析响应` 逐行 split/切取）量级吻合。

### 3.5 定量交叉验证（固定迭代 × 变字面量次数）：**探针失效，形态证据已足**

设计 `_r159_scratch/c_run_fixed_k.py` + `c_probe_alloc/fixed_K{0,1,2,4,8}.light`：固定迭代数、
只改每轮字面量比较次数 K，测峰值 RSS 对 K 的线性度（消除速度混淆）。
**结果：0.86 上探针失效**——`c_fixed_k_result_086.json` 显示 K=0/1/2/4 的初值/峰值全为
null（程序在首个采样点前就跑完 1e7 迭代），K=8 的 start=peak=end=884.46 MB（平台基线即此值，
无增量可测）。0.82 上补跑受 W1 独占纪律约束，窗口期内未做；**窗口结束后亦未补跑**——机制已由
§3.3 以更干净的方式证明（见 §7.2），且 0.82 为多线排队共用机，不占无谓资源。
（若 R160 立项后需要 FreeBSD 粒度下的定量表，该探针可直接复跑，无需改码。）

**判定：不补证**。因为「每轮量 ∝ 字面量求值次数/秒」的唯一性已由 §3.3 对照组以更干净的
方式证明——C0（无字符串）零增长排除一切其它分配源；C1≡C4（1 次 vs 4 次比较同斜率，
因迭代速度同比变化）证明速率绑定的是**每秒字面量求值次数**而非代码形态；
C5（C 语言 malloc(2) 死循环）证明纯 malloc 即可复现同形态斜率。固定 K 只是同一结论的
重复表述，且探针在该迭代量级下取不到有效初值（1e7 迭代 ~17 s，快于 20 s 采样间隔）。

## 4. 处置裁决：三分支第二支（登记不修，转独立立项）

**裁决依据**：证据链（§3）+ 任务书 §四 C 线三分支对比——

| 分支 | 判据 | 本线实测 | 结论 |
|---|---|---|---|
| ① 定位到行 + stdlib 内可最小修 | 泄漏点落在 `节点网络.请求`/`确保连接`/`收全部` 之一且可局部回收修正 | 泄漏**不落在** `节点网络.light` 任何一段：纯探针（无任何网络代码）同样线性涨，`序列化`/`编码值` 热点否证（§3.2 B/H vs R 只差 2%） | **不适用** |
| ② 定位到行 + 根因落 runtime 值所有权 | 根因是「临时值无释放路径」而非某 stdlib 函数 | IR 级坐实（§3.4）：`StringLiteral` → `dv_str` → `dv_strdup` → `malloc`，循环每转一次泄漏一份，临时值无 free | **落本支** |
| ③ 斜率收敛 ±0.001 MB/s 带内 | 斜率入带 | 0.01952 MB/s（复跑；原始 0.01951），**远在带外** | **不适用** |

### 4.1 定位到行（两条腿都给出行号，HEAD sha `3845a5121`）

**发射腿**（codegen，对所有原生腿程序统一生效）：

- `src/llvm/codegen_typed.py:1392-1393` —— `isinstance(expr, ast.StringLiteral)` 分支：
  `s_reg = self.gen_string_constant(expr.value)` → `return self._create_str_dv(s_reg), 'dv'`；
  即**每个字符串字面量表达式**都被物化成一个堆上 `LightValue`。
- `src/llvm/codegen_typed.py:1094` —— `_create_str_dv`：`call void @dv_str(ptr {slot}, ptr {ptr_val})`。
- 同类发射点另有 6626/6649（`匹配` 键字面量）、501/524 等（合计全仓 10+ 处 emit），
  但**共同必经之路是 1094**，故 1392 是唯一需要改的语义点。

**运行时腿**（`src/llvm/runtime_typed.c`）：

- `:181-188` `dv_strdup`：`d = (char*)malloc(len + 1)`。
- `:380-387` `dv_str`：`result->str = dv_strdup(s ? s : "")`。
- `:400` 起 `dv_free` / `dv_obj_release_slot`：只覆盖**具名槽位**（变量重赋值/对象释放时），
  **表达式临时值没有任何释放路径**——`dv_eq`、`dv_concat` 的两个操作数副本、`序列化`
  内部拼接产生的中间副本，函数返回即失联。

### 4.2 五段式登记（移交主 agent，按任务书 §四 C 线「登记五段式，转独立立项」）

| 段 | 内容 |
|---|---|
| **① 现象** | L-217：每次心跳轮确定性缓泄 ~16.36 KB（段①复跑；原始跑 16.37 KB，R158-C 三次 16–16.65 KB，三方交叉吻合）；斜率 +0.01952 MB/s，r²=0.999998，前后半程一致；FD ≤7；6 GB 外推 82.3 h。**非分配器噪声**（纯整数循环 RSS 全程平坦 2.71 MB） |
| **② 定位** | `codegen_typed.py:1392-1393`（StringLiteral→`dv_str`）+ `runtime_typed.c:181-188/380-387`（`dv_strdup` malloc）。**不含 `stdlib/分布式/节点网络.light` 任一行** |
| **③ 根因** | runtime **值所有权**缺失：原生腿没有临时值生命周期管理。每个字符串字面量求值 = 1 次 `malloc(len+1)`，无对应 free；`dv_concat`/`dv_eq` 操作数副本同因。泄漏速率只由「**每秒字符串字面量求值次数**」决定（C1≡C4 同斜率、C0 平坦证明唯一性） |
| **④ 影响面** | **不限网络库**：任何含字符串字面量的原生腿循环都漏（探针/心跳/纯比较皆复现）。定量：FreeBSD ~**7.4 B/次字面量求值**；心跳轮 ~16.4 KB ÷ 7.4 ≈ **2 200 次/轮**（序列化+头拼接+逐块拼接+逐行解析的量级，自洽）。长时常驻进程全数命中 |
| **⑤ 建议处置** | **不硬修**：修法是运行时所有权体系（Arena/引用计数/临时值帧内复用），影响全部 stdlib 与既有测试，远超 R159 scope。**建议 R160 独立立项**，先做小样评审（三选一：临时值帧级 arena 随语句释放 / LightValue 内联小串 + 引用计数 / 编译期常量折叠消去只读字面量副本），再定方案。**本线不动 `src/**`，不碰 `节点网络.light`** |

### 4.3 为什么不是「修 `节点网络.请求` 回收路径」

`节点网络.light` 的 `请求`/`收全部`/`解析响应` 都**只是泄漏的放大器而非来源**：它们每轮做几千次
字符串字面量求值，所以把 base 速率放大了 ~2 200 次/轮。即便就地补回收，也只治标——探针
（纯循环 + 1 个字面量比较，零网络代码）斜率同为 130 MB/s 量级即证。且该文件是 B 线主文件，
按任务书 §五 协议 C 线**未获得写入授权**。
