## D1：链式方法调用

### 背景

原始三大阻塞点之一。`_parse_postfix` 的 while 循环已能处理 `obj.method().chain2()`，但 LPAREN 分支拒绝非 Identifier 的调用目标，导致 `func()()` 失败。

### 实现

#### 新增 AST 节点

`src/ast_nodes_v3.py` 新增 `FunctionCallExpr`：

```python
class FunctionCallExpr(ASTNode):
    __slots__ = ('callee', 'args')
```

#### Parser 修改

`src/parser_expr.py` LPAREN 分支：
- 原：`return self._error("不支持在复杂表达式后进行括号调用")`
- 新：收集参数 → 创建 `FunctionCallExpr(expr, args)` → `continue`

`src/parser_stmt.py` `_parse_assignment_stmt`：
- 原：单级属性赋值 `obj.attr = value`
- 新：while 循环构建链式 `MemberAccess` 目标，支持 `b.a.x = 42`

#### Code Generator 修改

`src/code_generator.py` 新增 `FunctionCallExpr` 生成分支，输出 `callee(args)` 形式。

### 支持的场景

```段言
# 字符串链式调用
令 r = s.upper().lower()

# 函数返回值立即调用
令 r = f()()

# 对象方法链
c.add(5).add(3)

# 链式属性赋值
b.a.x = 42
```

### 排除

`令 b.a = A()` 这种用 `令` 对成员表达式赋值不支持（`令` 只接受简单标识符），这不是本轮目标。

|-------------|---------|------|
| `match-case` | `匹配/情况` | 已支持 |
| `async def` | `异步 函数` | 已支持 |
| `async for` | `异步 遍历` | 已支持 |
| `async with` | `异步 使用` | 已支持 |
| `await expr` | `等待 <expr>` | 已支持 |
| `@staticmethod` | `静态 函数` | 已支持 |

## D3：端到端教程重写

### 背景

`docs/端到端实战教程.md` 使用旧 v3.4 前语法（`设 X 为 Y`、`加上`、`段落`、`那么`、`结束。`），需重写。

### 实现

全面重写为 v3.4 推荐风格：

| 旧风格 | 新风格 |
|--------|--------|

## D4：TokenType.DOT 拆分

### 背景

v3.3 推迟的技术债。TokenType.DOT 同时承担句号和成员访问两种语义，lexer 层面已拆为 `.`→DOT、`。`→PERIOD，但 parser 层仍混用。

### 实现

`src/parser_expr.py`：
- 9 处 `_is_expr_terminator` 终止符列表：`(DOT, COMMA, ...)` → `(DOT, PERIOD, COMMA, ...)`
- lambda 后可选句号：`TokenType.DOT` → `TokenType.PERIOD`
- 移除运行时 `if tok.value == '.':` 检查（DOT 已在 lexer 层拆分，始终是英文点号）

`src/parser_core.py`：
- token 描述拆分：`'DOT': '句号「。」或点号「.」'` → `'DOT': '点号「.」'` + `'PERIOD': '句号「。」'`

### 效果

句号「。」和点号「.」各司其职，不再互相干扰。句号可选化的基础更加稳固。
