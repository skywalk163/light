## 〇、先说清楚「自举」的定义（省掉后来者每一轮的重新纠结）

> **「自举」在本项目里的定义是「不经 stdlib 的 Python 封装、不写 `引 Python` 块」，
> 不是「脱离 CPython 运行时」。**
>
> 纯光明模块照样 `导入 socket` / `导入 ssl` / `导入 json` / `导入 re` /
> `导入 subprocess` / `导入 codecs` —— 这是既定口径，不是妥协。
> 真正的边界是「不在光明层包一层 Python 函数再转调 CPython」，而是用光明语法
> 直接表达算法/协议/数据结构。因此 C 扩展（ssl/hashlib/psutil/msvcrt/fcntl）
> 与三方包（lunardate/cryptography）是天花板，不是偷懒。

## 一、唯一口径（§2.3）

| 项 | 定义 |
|---|---|
| `code` | 非空且不以 `#` 开头的行 |
| `decl` | 行首为「段落 / 类 / 函数」**定义**的行（`^\s*(段落|类|函数)\b`，不含「调用 函数甲()」这类纯调用行） |
| 有真实现 | `decl ≥ 1` |
| **主报维度** | **文件维度**：有真实现的 `.light` 文件数 / 顶层 `.light` 总数 |
| 行维度 | `decl / code`，**虚高，明确标注不许引用**（见下） |

**为什么行维度不许引用**：一个 `.light` 文件哪怕只有一行真定义、其余全是注释，
行维度也会很高；文件维度才反映「有多少模块真正自举了」。第二轮曾因混用口径
闹出 0/134、8/63、16/68 三个数字，本轮统一到文件维度。

### 3.2 明确放弃、写进永久 Python 边界

| # | 模块（行数） | 不可自举的根因 |
|---|---|---|
| 8 | `stdlib/日期时间.py`（1616） | 时区 + ISO 解析 + 农历（三方 `lunardate`，缺包时直接 `RuntimeError`，即门禁里那 8 条红）；对齐成本极高 |
| 9 | `stdlib/文件系统.py`（1522） | 体量最大，文件锁走 `msvcrt`/`fcntl` 两套 C 扩展 |
| 10 | `stdlib/哈希.py`（153）/ `stdlib/加密.py`（634） | 依赖 OpenSSL / `cryptography` / PyCryptodome；**自己实现密码学原语不该做也做不动** |
| 11 | `stdlib/系统接口.py`（437）/ `stdlib/环境.py`（215） | 全靠 `psutil`（三方 C 扩展）读平台内核接口，无替代路径 |

> 结论回到本节开头那句：「自举」= 不经 stdlib 的 Python 封装、不写 `引 Python` 块，
> 不是脱离 CPython 运行时。第 8–11 类是 C 扩展 / 三方包硬边界，属永久 Python 边界，
> 不再投入自举；第 1–7 类是可继续推进的目标，但第 3、5、6、7 类会受 `ssl`/`threading`/
> `multiprocessing`/`re` 的 C 依赖制约，只能做到「协议/算法层自举、系统层借 C」。
