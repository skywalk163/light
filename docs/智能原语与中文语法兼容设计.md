> 版本：v1（最小可行原型，2026-11-15）
> 定位：**L1 前端可选适配层 + 编译期只读轨迹**，不是新语法、不是新关键字。
> 权威约束：`docs/language/l0-core.md`（L0 冻结字表）、`docs/syntax.md`（30 字永久冻结承诺）。

## 0. 一句话结论

智能原语**不是关键字**，而是「L1 双字标准形式（普通标识符） + L0 组合惯用法（冻结字） + 前端弹性映射（可关闭）」。
因此它既不会挤进 L0 关键字池，也不会和中文自然词法抢词；中文越丰富，映射表越厚，标准形式与 L0 组合骨架反而越稳定——这是两者共同进步的机理，见 §8。

### 验收对照

| 验收项 | 落地方式 | 证据 |
|---|---|---|
| L0 核心字零改动、零新增 | 不碰字表文档、`keywords.py`、lexer/parser/codegen | §4「没改什么」+ diff |
| 现有测试**失败集合不新增** | 弹性层**默认关闭**，关闭路径源码对象原样返回；main 基线本身有 278 failed / 1 error（既有环境类红），故验收口径为「失败集合逐条不新增、总数不增加」 | §5.2 逐条比对 |

## 1. 只读盘点结论（实现前的事实基础）

### 1.1 L0 口径校准（重要）

- 「**30 字永久冻结**」是规范文案：`docs/language/levels.md:12`、`docs/syntax.md:5`、
  `docs/architecture.md:26`、`docs/L2_文言体语法规范_v4.0.md:11` 均如此表述。
- 但 `docs/language/l0-core.md` **实列 44 字**（该文件第 3 行自述 44）。`src/keywords.py:17-35`
  记录了缘由：曾有一个自称「冻结 30 字」的 `KEYWORDS_L0_CORE` frozenset，2026-08-20 因
  「零生产消费者 + 与文档是两个不同集合 + 留着是第二事实源」被删除。**字表在代码里已无实体，
  权威只在文档；「冻结」是规范承诺，不是代码里的一张表。**
- 本轮**不修正 30/44 口径**（属于改规范，超出最小原型范围），只在 §7 风险清单登记。
  无论按 30 还是 44 口径，本方案都不动字表，硬约束天然满足。

### 1.2 「段言弹性语法兼容层」先例：`src/elastic_syntax.py`

现成的「口语 → 标准关键字」文本替换层，但：

- **零接入**：全仓只有它自己 + `tests/e2e/test_e2e_chain.py:73` 一句注释提及，注释原话
  「未接入主管线的 `src/elastic_syntax.py`」。
- 四个导致它不能作为生产前端的缺陷：
  1. `_apply_elastic_map()` 用 `\b` 词边界。Python 的 `\w` 涵盖汉字，`\b对于\b` 在中文上下文
     几乎匹配不上——正是一条 e2e 排除用例的根因。
  2. `_normalize_whitespace()` 对每行 `strip()`，会抹掉**缩进敏感**语法的缩进。
  3. 无字符串 / 注释 / L4 嵌入块保护，会改到字面量与说明文字。
  4. 无开关、无外部配置、无冲突诊断；类级 add/remove 无法整体关闭。

→ 因此**新建独立模块，原文件一字不动**。本层也不复用它的实现，避免继承缺陷。

### 1.3 contrib / stdlib 盘点

先纠偏：任务里提到的「Agent 循环、事件总线」**不在 contrib/**，实际是
`stdlib/代理循环.light`、`stdlib/事件总线.light`。contrib/ 有 49 个 `.light`，但都是
「每行 `# ` 开头的注释化接口清单 + 末尾 `导出 …`」，**不是可执行 Light 代码**，目录内无 README/索引。

| 适合升为 L1 智能惯用模式（纯控制流骨架） | 应留在库层（真实运行时） |
|---|---|
| `stdlib/事件总线.light`：遍历→匹配→调用→中止传播→错误隔离 | `stdlib/代理循环.light`：SSE 网络 + 线程并行 + token 预算 |
| `contrib/工作流引擎`：DAG 拓扑排序 / 状态迁移 | `contrib/Actor模型`：真线程 + Queue + 监督重启 |
| `contrib/消息队列` 的 `发布订阅` 类 | `contrib/任务队列调度器`：定时/重试状态机 + 工作线程 |
| `contrib/插件系统`：注册扩展点→触发扩展点 | `contrib/分布式锁`：类级全局字典 + 续期线程 |
| `contrib/上下文管理器`：进入→执行→退出时提交/回滚 | `contrib/审计日志`：文件持久化 + 时间戳 + 哈希 |

现成骨架参照：`stdlib/代理循环.light:539-587` 的 `运行()` 主循环
（`当 轮 < 最大轮数` → 单轮请求 → `完成原因` 判分支 → 分发工具 → `继续`）。

**判据**：能用 `段 / 设 / 当 / 若 / 返回 / 断` 加列表/字典表达、且不需要线程/网络/持久化的，
才上 L1；其余保持库，通过 L4 `引 Python:` 或 `导入` 调用。

### 1.4 L4 评估结论

`引 Python: / 引 C: / 引 Go: / 引 MoonBit:` 已落地于 `src/code_generator.py:6255+`。
**本轮不把「智能体」做成 L4 引用目标**：L4 是跨语言 FFI 层，智能体是控制流形状，混层会制造
「`引 智能体:` 到底是引外部库还是定义一个原语」的歧义。将来若要接外部 agent runtime，
直接 `引 Python:` 导入即可，零新增语法。此项列入 §7 风险，本轮不实现。

## 2. 设计：分层隔离 + 弹性适配 + L0 组合惯用法

### 2.1 为什么不和中文冲突（核心论证）

冲突的前提是「两个东西抢同一个语法位置」。这里没有抢：

| 层 | 占据的语法位置 | 本方案是否占用 |
|---|---|---|
| L0 冻结字 | 关键字 token（`段/设/当/若/…`） | **完全不碰** |
| L1/L2 别名关键字 | 关键字 token（`段落/如果/…`） | **完全不碰** |
| 用户标识符 | 普通标识符 token | 智能原语只占这里，且是**用户自己起的段落名** |

`观察 / 规划 / 决策 / 执行 / 记忆` 五个双字词**都不在 `keywords.ALL_KEYWORDS` 里**
（实测 123 个关键字中零命中）。它们和 `甲`、`分数`、`我的列表` 是完全同一类东西。
所以：

- 编译器不需要认识它们 → 词法器零改动；
- 用户写 `段 规划(信号):` 与写 `段 算分(信号):` 在语法上无任何区别 → 语法器零改动；
- 「智能」体现在**组合形状**（观察→规划→决策→执行→记忆 的调用序列 + `当` 循环 + `若` 分支），
  而这个形状是 L0 冻结字拼出来的 → 编译器只需**只读扫描形状**即可打轨迹，不必新增语义；
- **弹性层只做风格归一化，绝不是代码能跑的前提**：口语示例里每个变体在定义处与调用处
  保持一致，关掉弹性层仍是一份合法的纯 Light 程序（`test_口语示例在弹性层关闭时仍可独立运行`
  守这条约束）。混写不同的同义变体（定义「计划」、调用「安排」）才需要开启弹性层来合一。

中文口语多样性带来的问题（「计划」「安排」「筹谋」都指同一件事）也不是语法问题，
而是**命名一致性**问题，所以放到前端做**标识符重命名**，而不是改核心语法。

### 2.2 L1 白话体：标准双字形式

| 标准形式 | 单义 | `kind` | 常见口语变体（默认表） |
|---|---|---|---|
| `观察` | 取环境/输入 | `observe` | 看看、瞧瞧、感知、打量、读取环境 |
| `规划` | 由状态推动作 | `plan` | **计划、安排、筹谋**、盘算、打算 |
| `决策` | 判断是否中止 | `decide` | 拿主意、定夺、拍板、决断 |
| `执行` | 产生副作用 | `act` | 动手、实施、落实、干活、去办 |
| `记忆` | 记录状态 | `memory` | 记下、记住、存档、留个底 |

约定：**双字、单义、不与现有关键字/内置名同形**。用户只需记这 5 个日常词，且忘了也能用
任意口语说法（由弹性层吸收）。标准形式是「可读性基线」，不是必须遵守的语法。

### 2.3 L0 组合惯用法

不新增任何字，只用冻结字拼装。`段` 定义、`设` 赋值、`当` 循环、`若` 分支、`断` 跳出、`返回` 返回：

```light
段 观察(环境):
    返回 环境["信号"]

段 规划(信号, 轮):
    若 轮 >= 3:
        返回 "停"
    返回 信号

段 主():
    设 环境 为 ["信号": "走"]
    设 轮 为 0
    当 轮 < 4:
        设 信号 为 观察(环境)
        设 动作 为 规划(信号, 轮)
        若 动作 == "停":
            断
        执行(动作)
        设 轮 为 轮 + 1
主()
```

完整可运行版见 `examples/智能原语/观察_规划_执行.light`。
**编译器可优化点（本轮未实现，仅登记）**：`当` + `观察/规划/执行` 三段固定序列可识别为
`observe_plan_act` 惯用模式，未来可做循环不变量外提或工具调用批处理；本轮只做可观测性打标。

### 2.4 弹性语法兼容层：映射表结构

唯一事实源：`src/smart_primitives_map.json`（不内嵌第二份表）。

```json
{
  "schema": "light.smart-elastic-map/v1",
  "version": 1,
  "enabled": false,
  "scope": "identifier",
  "on_conflict": "diagnose",
  "primitives": {
    "规划": { "kind": "plan", "variants": ["计划", "安排", "筹谋", "盘算", "打算"] }
  }
}
```

| 字段 | 含义 |
|---|---|
| `schema` / `version` | 表结构版本，便于将来演进 |
| `enabled` | 默认 `false` —— **兼容性的硬保证** |
| `scope` | 固定 `identifier`：只改标识符位置，不改关键字、不改语法 |
| `on_conflict` | 只作用于**冲突类**诊断（001/002/003）：`diagnose` 原样输出 / `warn` 降级为警告 / `keep` 不输出。**配置类**（004/005）不受此开关影响，永不被吞——否则用户会误以为自定义表已生效 |
| `primitives` | 标准双字形式 → `{kind, variants[]}` |

**替换规则**（`src/smart_primitives.py`）：

1. 按变体长度降序编译，长词优先（`计划书` 先于 `计划`）；规则按映射表内容缓存，返回副本。
2. 中文边界用 `(?<!\w)变体(?!\w)`，**不用 `\b`**——这是相对旧弹性层最关键的修正。
3. 逐字符构造「可编辑掩码」，保护区口径**与 `lexer.py` 对齐**：
   英文引号 `"…"` / `'…'`（含反斜杠转义）、**三引号 `"""` / `'''` 跨行**、
   **中文引号 `「…」` / `『…』`**（`lexer.py:469-472` 的字符串定界符）、`#` 行注释（含行尾注释）；
   L3/L4 嵌入块整块原样透传，起止标记覆盖 `引`/`嵌入` × `结束引`/`结束嵌入` 四种组合，
   并支持**缩进回归闭合**与 EOF 闭合（`lexer.py:2044-2184`）。
4. **绝不 `strip()` 任何一行**，只在可编辑片段内替换，缩进与行尾（含 CRLF）逐字符保留。
5. 关闭时返回**原始字符串对象**，不做任何拷贝或规范化。
6. 掩码在轨迹扫描中复用：字符串与注释里的「规划(测试)」不会产生假 `tool_call` 事件。

### 2.5 配置、关闭与诊断

| 通道 | 写法 | 优先级 |
|---|---|---|
| 文件头指令 | `# @智能弹性 开` / `# @智能弹性 关`（前 30 行内） | 最高（逐文件覆盖） |
| 总开关 | `LIGHT_SMART_ELASTIC=1|0` | 中 |
| 映射表 | `LIGHT_SMART_ELASTIC_MAP=/path/to/map.json` | 中 |
| 轨迹开关 | `LIGHT_SMART_ELASTIC_TRACE=1|0`（默认跟随总开关） | 中 |
| 冲突处置 | `LIGHT_SMART_ELASTIC_ON_CONFLICT=diagnose|warn|keep` | 中 |
| 映射表内 `enabled` | JSON 字段 | 最低 |

**诊断码**（输出到 stderr，并写进轨迹的 `diagnostics`；字段为
`code / severity / line / column / source / target / origin`。
源码级诊断（002）带真实行列；配置级诊断（000/001/003/004/005）指规则或配置文件，
`line=0` 表示「不指向某一行源码」，`origin` 给出来源表路径）：

| 码 | 级别 | 触发 | 处置 |
|---|---|---|---|
| `L-SMART-001` | error | 变体或标准词撞 `keywords.ALL_KEYWORDS` 或高频内置名 | 该规则不加载，编译继续 |
| `L-SMART-002` | warning | 同一源码里口语变体与标准双字形式混用（归一化后会合并两个名字）。**边界**：只覆盖「变体与标准词同现」；若用户原有标识符恰好叫「计划」而文件中无「规划」，文本级替换无法与口语用法区分，见 R13 | 提示确认是否预期 |
| `L-SMART-003` | error | 变体非法 / 重复映射到不同标准词 / 标准词也是另一条的变体（链式替换） | 该规则不加载 |
| `L-SMART-004` | error | 自定义表加载失败：路径不存在 / JSON 损坏 / schema 不匹配 / `scope` 非法 / 某条 `spec` 不是对象 / `variants` 不是列表 | 回退内置兜底表，编译继续 |
| `L-SMART-005` | warning | `on_conflict` 取值不在 `diagnose/warn/keep` 内 | 按 `diagnose` 处理 |
| `L-SMART-000` | warning | 无法加载 `ALL_KEYWORDS`，保留字检查降级 | 不影响替换 |

保留字**从 `keywords.ALL_KEYWORDS` 动态读取**，不另造一份字表——项目曾因「第二事实源」删掉
`KEYWORDS_L0_CORE`，本设计刻意不重蹈覆辙。

### 2.6 可观测性：结构化轨迹

编译期**只读扫描**归一化后的源码，输出 sidecar `<源文件>.smart-trace.json`（已加入
`.gitignore`，是运行产物不入库）。不改 AST、不改生成代码、不注入运行时钩子，因此零运行时开销。

```json
{
  "schema": "light.smart-trace/v1",
  "pattern": "observe_plan_act",
  "primitives": {"观察": "observe", "规划": "plan", "执行": "act"},
  "duration_ms": 0.42,
  "rewrites": [{"line": 39, "from": "安排", "to": "规划", "column": 16}],
  "events": [
    {"type": "primitive_def",  "line": 21, "primitive": "规划", "kind": "plan", "l0_form": "段"},
    {"type": "decision_point", "line": 22, "primitive": "规划", "condition": "轮 >= 3", "l0_form": "若"},
    {"type": "tool_call",      "line": 39, "primitive": "规划", "callee": "规划", "scope": "主流程"},
    {"type": "side_effect",    "line": 32, "primitive": "执行", "kind": "print"},
    {"type": "duration",       "line": 36, "phase": "loop", "metric": "iterations",
     "static_bound": 4, "condition": "轮 < 4", "l0_form": "当"}
  ],
  "diagnostics": []
}
```

`pattern` 判定要求**两个条件同时满足**：源码出现「观察 / 规划 / 执行」三段，且至少存在一处
L0 循环骨架（`当`，即 `duration` 事件）。只有三个散点调用、没有循环的，判为 `custom`——
否则「乱序三连」会被误报成惯用模式。
`duration` 事件的 `static_bound` 是编译期可静态推断的循环上界（`< 数字`）；真实运行耗时
属于运行时采样，本轮不做，见 §7。

### 2.7 四层关系一览

| 层 | 本方案的角色 | 是否改动 |
|---|---|---|
| **L0** 冻结核心字 | 提供 `段/设/当/若/断/返回` 等组合骨架 | **零改动** |
| **L1** 白话体 | 承载 5 个标准双字形式（普通标识符）与口语变体 | 只加前端适配，不改文体规范 |
| **L2** 文言体 | 单字别名可自由混用，弹性层不干预 | 零改动 |
| **L3** 领域嵌入 | `引 SQL:` / `引 模式:` 整块原样透传 | 零改动 |
| **L4** 外语引用 | 评估后本轮**不**新增「智能体」引用目标 | 零改动 |

## 3. 用户写法示例

### 3.1 标准写法（零配置，直接跑）

```bash
python3 -m cli.light run examples/智能原语/观察_规划_执行.light
```

输出 3 轮 `执行动作: 走` / `记下: 走` + `完成`。全文没有任何新关键字。

### 3.2 口语写法（文件头逐文件开启）

`examples/智能原语/观察_规划_执行_口语变体.light` 首行是 `# @智能弹性 开`，因此：

```bash
python3 -m cli.light run examples/智能原语/观察_规划_执行_口语变体.light
```

同一份逻辑里：`看看→观察`、`计划→规划`、`拍板→决策`、`动手→执行`、`记下→记忆`。
字符串 `"计划已定: "` 里的「计划」**不被替换**（输出仍是「计划已定」），这是保护规则的直观验证。

示例本身每个口语词在定义与调用处保持一致，所以**关掉弹性层也照常能跑**——弹性层是风格
归一化，不是运行前提。若要演示「多对一」，可把主流程里的 `设 动作 为 计划(信号, 轮)`
改成 `设 动作 为 安排(信号, 轮)`，开启弹性层后两个词都会归一成 `规划`（由
`test_混写口语变体时弹性层使其自洽` 端到端验证）。

## 6. 迁移与禁用弹性层

**完全不需要迁移**：现有 `.light` 代码一个字都不用改。标准双字写法本来就是合法 Light 代码；
只有想用口语变体的**新代码**才需要开启。

**禁用方式（任选其一，效果等同）**：

1. 什么都不做 —— 默认关闭（`smart_primitives_map.json` 的 `enabled: false`）。
2. 显式环境变量：`LIGHT_SMART_ELASTIC=0`。
   **注意**：若文件头写了 `# @智能弹性 开`，文件头优先级更高，会覆盖这个 0；
   想真正关掉带指令的文件，得同时把指令改成「关」（或删掉）。同理，`LIGHT_SMART_ELASTIC_TRACE=0`
   只关轨迹，不影响归一化。
3. 单文件强制关闭：文件头写 `# @智能弹性 关`（优先级最高，覆盖环境变量）。
4. 只要映射不要轨迹：`LIGHT_SMART_ELASTIC_TRACE=0`。
5. CI 里彻底移除钩子：把 `cli/light.py::_read_source()` 恢复成原来的三行即可——
   `text = path.read_text(encoding='utf-8')` 之后直接 `return text`，
   并删掉 `_SMART_DIRECTIVE_RE` / `_SMART_TRUTHY` / `_smart_elastic_maybe_on` 三个定义
   （约 20 行）。**不要只删 `try` 块**：那样 `_read_source` 会因缺少 `return` 而返回 `None`。
   删除后 `src/smart_primitives.py` 不会被任何路径隐式加载，可整文件移走。

**从口语版回退到标准版**：把 `LIGHT_SMART_ELASTIC=1 python3 -m cli.light compile X.light`
的产物读一遍归一化结果即可——`preprocess()` 是纯函数，返回的就是标准写法源码，
可直接另存为 `.light` 提交。轨迹里的 `rewrites` 数组也逐条列出了改了哪个词、在哪一行。

## 8. 为什么智能原语和中文能「共同进步」

**不冲突的原因**（§2.1）：两者根本不在同一层抢位置。L0 冻结字占关键字位；智能原语只占
用户标识符位，且靠 L0 的组合形状获得语义。中文越口语化，变化只发生在**前端映射表**；
核心语法一个字不动。

**共同进步的机理**是三条单向、可独立关闭的通道：

1. **中文滋养原语**：用户把「计划 / 安排 / 筹谋 / 盘算」都写进映射表，原语的可达性变高，
   但标准形式仍是那 5 个双字词——口语多样性被吸收成容错，而不是被固化成语法负担。
2. **原语反哺中文**：为了能被识别为惯用模式，写法自然收敛到「双字、单义、L0 组合骨架」，
   这给中文技术写作提供了一套稳定的表达范式；`observe_plan_act` 这类结构化轨迹又把
   模糊的自然语言流程变成可观测、可优化的工程对象。
3. **两者都不被锁死**：映射表可配置可关闭，L0 永久冻结，L1/L2 别名保持兼容。任何一方演进
   都不要求另一方改代码——中文加词只改 JSON，编译器加优化只识别组合形状，都不碰对方。

一句话：**冻结的是骨架，生长的是说法，可观测的是形状。**
