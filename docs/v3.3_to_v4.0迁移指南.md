# v3.3 → v4.0 分层语法迁移指南

**版本**：v3.3（双字关键字统一语法）→ v4.0（分层语法 / L0 30字核心字）  
**发布时间**：2026-08-04  
**兼容性**：✅ **零破坏** — 所有 v3.3 代码在 v4.0 解析器下**不报错**。  
**迁移方式**：**自愿增量迁移**，不需一次性改完全部代码。

---

## 1. 为什么改？

光明 v3.3 采用了"决策27：所有核心关键字统一为双字"的设计，在实践中遇到瓶颈：
- 关键字太长，教学中孩子敲代码费力
- 语法形态单一，难以同时支撑"青少年快速上手"和"大型商用项目"两种场景
- 缺少"自修复"机制：关键字反复变更（段落→函数→段…），用户心智负担大

v4.0 引入**分层语法架构**，借鉴中文的智慧：
- 中文只有 3000 常用字，却能支撑所有学科
- 白话文/文言文共享同一套汉字，只是文体不同
- 数学公式/化学方程式直接嵌入中文文章，不需要翻译

v4.0 核心思路：
```
L0 核心字表（30字冻结，永不变化）
├── L1 白话体（青少年/教学：无类型、因果链语法、极简）
├── L2 文言体（商用/工程：类型注解、类、模块、缩进）
├── L3 领域嵌入（SQL/正则/数学/JSON 直接融入表达式）
└── L4 外语引用（Python/C/Go 用 引 块引用，数据级互操作）
```

详细设计见 [分层语法设计_v4.0.md](./分层语法设计_v4.0.md)。

---

## 2. 零破坏承诺

**v3.3 所有合法语法 → v4.0 下 100% 通过，不报错。**

所有 v3.3 的双字关键字全部保留为**向后兼容别名**。
解析器内部分两层：
- **关键字识别层**：既识别 L0 单字，也识别 v3.3 双字
- **语法推荐层**：新写代码时文档推荐 L0 单字（但不强制）

**你可以选择不迁移**：v3.3 双字写法永久保留，没有 Deprecation 计划。

## 3. 关键字映射速查表

### 3.1 L0 30字核心字 ←→ v3.3 双字别名

下表左列是 v4.0 推荐写法（L0），右列是仍然支持的 v3.3 兼容写法（以及其它历史别名）。

**控制流（7字）**

| L0 单字 | v3.3 写法 / 别名 | 语义 |
|--------|-----------------|------|
| 若 | 如果 | 条件开头 |
| 否 | 否则 | 否则分支 |
| 当 | 当 | while 循环（不变） |
| 遍 | 遍历 / 对 | for 循环 |
| 跳 | 跳出 | break（跳出循环） |
| 过 | 跳过 | continue（跳过本次） |
| 返 | 返回 | return（从函数返回） |

**定义与类型（6字）**

| L0 单字 | v3.3 写法 / 别名 | 语义 |
|--------|-----------------|------|
| 设 | 设 / 定义 / 常量 | 赋值 / 声明变量 |
| 段 | 段 / 段落 / 函数 | 函数定义 |
| 类 | 类 | class（不变） |
| 承 | 继承 | extends（类继承） |
| 接 | 接口 | interface（接口定义） |
| 配 | 匹配 | match（模式匹配） |

**异常（4字）**

| L0 单字 | v3.3 写法 / 别名 | 语义 |
|--------|-----------------|------|
| 试 | 尝试 | try |
| 捕 | 捕获 | catch |
| 抛 | 抛出 | throw |
| 终 | 最终 | finally（v3.3 已有，新增单字别名） |

**自指与连接（5字）**

| L0 单字 | v3.3 写法 / 别名 | 语义 |
|--------|-----------------|------|
| 自 | 己 / 自我 / self | 指向自身（类方法中） |
| 之 | 之 / 的 | 属性提取（甲之属性 = 甲.属性） |
| 并 | 并 / ，/ ， / -> | 管道/并列 |
| 从 | 从 | 来源（导入语句中） |
| 是 | （新）/ 等于 | 判断相等 / 类型判断（后续细化） |

**逻辑与值（6字，全部与 v3.3 一致）**

| L0 单字 | v3.3 写法 / 别名 | 语义 |
|--------|-----------------|------|
| 且 | 且 / 与 | and（不变） |
| 或 | 或 | or（不变） |
| 非 | 非 | not（不变） |
| 真 | 真 | true（不变） |
| 假 | 假 | false（不变） |
| 空 | 空 | None/null（不变） |

**组织（2字）**

| L0 单字 | v3.3 写法 / 别名 | 语义 |
|--------|-----------------|------|
| 导 | 导入 | import |
| 出 | 导出 | export |

### 3.2 算术运算符：符号为主，中文别名保留

v4.0 算术运算符**以符号为主形式**，中文写法保留为别名（L1 白话体教学中可用）。

| v4.0 主形式（符号） | v3.3 中文别名（保留） | 语义 |
|--------------------|---------------------|------|
| `+` | 加 / 加上 | 加法 / 加等于 |
| `-` | 减 / 减去 | 减法 / 减等于 |
| `*` | 乘 / 乘以 | 乘法 / 乘等于 |
| `/` | 除 / 除以 | 除法 / 除等于 |
| `%` | 模 / 模以 / 取余 | 取模 / 模等于 |
| `**` / `^` | 幂 / 幂以 | 幂运算 / 幂等于（`**` 新增 Python 风格） |
| `整除` 双字保留 | 整除 | 整数除法（对应 Python `//`，避免与行注释 `//` 冲突） |

### 3.3 比较运算符

| v4.0 主形式（符号） | v3.3 中文别名 | 语义 |
|--------------------|--------------|------|
| `==` | 等于 / 是 | 相等判断 |
| `!=` | 不等于 | 不等判断 |
| `>` | 大于 | 大于 |
| `<` | 小于 | 小于 |
| `>=` | 大于等于 / 不小于 | 大等于 |
| `<=` | 小于等于 / 不大于 | 小等于 |

---

### 3.4 L4 外语引用块：`嵌入` → `引`

v4.0 引入"引用"语义，将外部语言代码视为中文引经据典。

| v3.3 写法 | v4.0 推荐写法 | 语义 |
|-----------|-------------|------|
| `嵌入 Python:` | `引 Python:` | 开始引用 Python 代码 |
| `嵌入 C:` | `引 C:` | 开始引用 C 代码 |
| `结束嵌入` | `结束引` | 结束引用块 |

**四种组合全部兼容**（可以混写，解析器都认）：

```
√ 嵌入 Python:  ... 结束嵌入   （v3.3 原写法）
√ 引   Python:  ... 结束引     （v4.0 推荐）
√ 引   Python:  ... 结束嵌入   （容错，混写也过）
√ 嵌入 Python:  ... 结束引     （容错，混写也过）
```

## 4. 迁移步骤（自愿增量，不用一次性）

### 第 1 步：什么都不改（推荐第一天）

先不修改任何现有代码，直接在 v4.0 解析器下跑通一遍：
```
pytest tests/unit/test_lexer.py tests/unit/test_parser.py tests/unit/test_light_examples_run.py
```
如果全部通过 → 零破坏成立，继续用原有写法。

### 第 2 步：新写代码用 L0 单字（推荐）

新写的函数、新文件从今天起就用 L0 单字，不影响老文件。

**对比示例（同一个函数）：**

```light
# v3.3 原写法（仍然支持，不需改）
函数 加法 接收 甲, 乙:
    尝试:
        返回 甲 加 乙
    捕获 错:
        抛出 错
    最终:
        打印 "结束"

# v4.0 新写法（推荐，更简洁）
段 加法(甲: 数, 乙: 数) -> 数:
    试:
        返 甲 + 乙
    捕 错:
        抛 错
    终:
        打印 "结束"
```

### 第 3 步：大块代码可选批量替换（脚本待实现）

未来提供 `python tools/migrate_syntax.py --from v3.3 --to v4.0` 一键替换关键字。
建议在单独的 commit 里做，避免和业务修改混在一起。

### 第 4 步：选文体（L1 白话体 / L2 文言体）

- **教学脚本/快速原型** → 用 L1 白话体（无类型、因果链语法、单行优先）
- **大型项目/库开发/团队协作** → 用 L2 文言体（类型注解 + 缩进 + 模块系统）

文体声明（可选，写在文件头）：
```
# 文体: 白话      → L1 教学/脚本风格，解析器更宽容
# 文体: 文言      → L2 工程风格，严格缩进/类型
```

## 5. 文体选择指南

### 选择 L1 白话体，如果你写的是：

- 教学课件、编程启蒙教程（给青少年用）
- 100 行以内的脚本（一次性任务、数据处理）
- 快速原型、Demo、验证想法

特点：
- 无类型负担，变量不用声明类型
- 因果链语法 `温度大于30,开风扇`，像说话一样写
- 中文标点句号`。`可选，冒号`：`也可用`:`

### 选择 L2 文言体，如果你写的是：

- 长期维护的项目、团队协作代码
- 标准库、第三方库、SDK
- 需要类型安全和重构友好的代码

特点：
- 类型注解：`段 加法(甲: 数, 乙: 数) -> 数`
- 类系统：`承`（继承）、`接`（接口）、`自`（self）
- 模块系统：`导`（import）、`出`（export）
- 模式匹配：`配 值: 情况 1: 打印 "一"`

## 6. 语法变更速查表（1 分钟版）

这张表贴在桌面，写代码时瞄一眼。

| 想写什么 | v3.3 原写法（仍然 OK） | v4.0 L0 推荐写法 |
|---------|-----------------------|----------------|
| 如果 | 如果甲>5那么… | 若甲>5:… |
| 否则 | 否则:… | 否:… |
| 循环遍历 | 遍历列表之为i:… | 遍列表之为i:… |
| 跳出循环 | 跳出 | 跳 |
| 跳过循环 | 跳过 | 过 |
| 返回函数 | 返回 值 | 返 值 |
| 定义函数 | 函数 名 接收 参数: | 段 名(参数: 类型) -> 返回: |
| 定义类 | 类 名 继承 父类: | 类 名 承 父类: |
| 定义接口 | 接口 名: | 接 名: |
| Try块 | 尝试:…捕获:…最终:… | 试:…捕:…终:… |
| self | 己 / 自我 | 自 |
| 导入 | 导入 模块 | 导 模块 |
| 导出 | 导出 名 | 出 名 |
| 模式匹配 | 匹配 值: 情况 1: | 配 值: 情况 1: |
| 嵌入外语 | 嵌入 Python:…结束嵌入 | 引 Python:…结束引 |
| 算术 | 甲 加 乙 乘 丙 | 甲 + 乙 * 丙 |
| 复合赋值 | 甲 加上 1 | 甲 += 1 |

## 7. 常见问题 FAQ

**Q1：v3.3 的双字关键字未来会不会不支持？**

不会。双字关键字永久作为别名保留在解析器关键字表中。没有 Deprecation 计划，没有删除时间表。

**Q2：L0 30字真的够用吗？是不是太少了？**

中文只有 3000 常用字，却能支撑所有学科。光明 L0 是"偏旁部首"，不是全部词汇：更多语义用**组合**表达（`承`=继承、`接`=接口，和类组合），用**函数名**表达（排序、反转、打印不是关键字，是内置函数名）。30 字是经过 8 种主流语言对比后确定的合理值（对比：Lua 22、Go 25、Python 35、Rust 58）。

**Q3：L1 和 L2 能在同一个项目里混用吗？**

可以。两者共享 L0 核心字，互相调用函数没有区别。推荐约定：
- `src/educational/`、`examples/` 用 L1 白话体
- `src/core/`、`src/lib/` 用 L2 文言体
- 文件头 `# 文体: 白话` / `# 文体: 文言` 明确声明

**Q4：`是` 关键字怎么用？什么时候支持 isinstance？**

目前 v4.0 A 阶段，`是` 作为 `等于` 的别名，用于相等判断。
类型判断语义（`甲是数` = isinstance(甲, 数) / `甲是空` = `甲 is None`）在 v4.1 B/C 阶段实现。

**Q5：为什么 `//` 整除不用？和注释冲突怎么办？**

`//` 在 ANTLR .g4 中已被 `LINE_COMMENT_SLASH`（`//` 行注释）抢占。避免与注释的歧义，v4.0 保留「整除」双字关键字作为复合运算符。后续如需要可在 lexer 层做上下文识别（数字后面的 `//` 视为整除）。

**Q6：`引 Python:` 能调用光明变量吗？**

当前阶段通过**数据级互操作**（不是作用域共享）：先在 `引 Python:` 中定义函数，然后在光明中用 `Python.函数名(参数)` 调用，参数和返回值自动进行类型映射。详细设计见 [分层语法设计_v4.0.md 第 8 节 L4](./分层语法设计_v4.0.md#八l4外语引用层)。
