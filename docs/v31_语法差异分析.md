# v3.1 语法规范与当前实现差异分析

**日期**：2026-07-04
**规范版本**：统一语法规范 v3.1
**分析范围**：Light v3 解析器（lexer.py、parser_stmt.py、parser_expr.py、keywords.py、ast_nodes_v3.py）

---

## 概述

本报告全面审查了 Light v3 解析器与《统一语法规范 v3.1》之间的差异，按严重程度分为 **严重**、**中等**、**轻微** 三个等级，并给出修复优先级建议。

---

## 🔴 严重差异（影响核心语法一致性）

### 1. `跳出` 和 `跳过` 语句强制要求句号

**规范描述**：v3.1 明确指出句号是可选的（第 42-49 行）。

**实际实现**：`跳出` 和 `跳过` 语句**强制要求**句号，缺少句号会导致解析失败。

**代码位置**：
- `src/parser_stmt.py:103-105` — `跳出` 语句
  ```python
  if tok.type == TokenType.KEYWORD and tok.value == '跳出':
      self._consume(TokenType.KEYWORD, '跳出')
      self._consume(TokenType.DOT)  # 强制消耗句号
      return BreakStmt()
  ```
- `src/parser_stmt.py:108-111` — `跳过` 语句

**影响**：用户写 `跳出` 或 `跳过` 而不加句号会报语法错误，与"句号可选"的核心设计原则矛盾。

**修复建议**：将句号改为可选，与其他语句保持一致。

---

## 🟡 中等差异（功能基本可用，但与规范有偏差）

### 2. 遍历循环缺少 `于` 关键字支持

**规范描述**：v3.1 列出了两种遍历语法（第 282-286 行）：
- `遍历 项 之 列表：`
- `遍历 项 于 列表：`

**实际实现**：仅支持 `在`、`之`、`中的` 三种连接词，**不支持 `于`**。

**代码位置**：
- `src/parser_stmt.py` — `_parse_foreach_stmt` 方法

**影响**：用户使用 `遍历 甲 于 列表：` 语法会报错。

**修复建议**：在遍历循环的连接词判断中添加 `于` 支持。

---

### 3. 遍历循环和当循环的冒号是强制的（非可选）

**规范描述**：v3.1 中冒号用于开始块，但未明确说明是否可选。

**实际实现**：
- 遍历循环：冒号**强制**
- 当循环：冒号**强制**
- 条件语句：冒号**可选**

**影响**：不同语句块对冒号的要求不一致。条件语句可以省略冒号（用句号或换行缩进代替），但遍历和当循环必须写冒号。

**修复建议**：统一策略——或将冒号都设为可选，或明确规范中哪些语句强制冒号。

---

### 4. 变量声明与赋值的 AST 节点类型不区分

**规范描述**：v3.1 中 `设 甲 为 10` 是变量声明，`甲 = 20` 是赋值语句。

**实际实现**：`_parse_assignment_stmt`（`甲 = 值` / `甲 等于 值` / `甲 为 值`）也返回 `VarDecl` 节点。

**代码位置**：
- `src/parser_stmt.py` — `_parse_assignment_stmt` 返回 `VarDecl(name, value)`

**影响**：从 AST 角度无法区分"变量声明"和"赋值语句"，语义分析器可能需要额外处理。虽然对运行无影响，但与 AST 设计原则有偏差。

## 🟢 轻微差异（向后兼容或细节偏差，不影响主要功能）

### 5. 仍保留「结束」关键字（向后兼容）

**规范描述**：v3.1 明确移除「结束」关键字，采用纯缩进式语法（第 14 行）。但第 754 行也提到"如果需要可以通过配置开启（默认关闭）"。

**实际实现**：「结束」关键字是**可选**的，解析器会自动消耗它，不影响纯缩进语法的使用。

**评估**：这是合理的向后兼容设计，不影响 v3.1 纯缩进语法的使用。

---

### 6. 条件语句支持多种块开始方式（冒号是可选的）

**规范描述**：v3.1 标准形式是 `如果 条件：`（第 250 行）。

**实际实现**：条件语句的冒号是**可选**的，支持多种形式：
- `如果 条件。` + 缩进块
- `如果 条件 那么` + 缩进块
- `如果 条件 那么：` + 缩进块
- `如果 条件：` + 缩进块
- 单行形式：`如果 条件 那么 语句`

**评估**：这是更灵活的设计，虽然与"标准形式"略有差异，但完全兼容规范语法。

---

### 7. 段落定义支持多种旧语法形式

**规范描述**：v3.1 标准形式是 `段落 名 接收 参数：`（第 305 行）。

**实际实现**：支持的形式远多于规范：
- `段落/函数/段 段名 参数/接收/输入 参数名`（三种关键字组合）
- `段落/函数/段 段名(参数1, 参数2)`（括号形式）
- 冒号是可选的
- 泛型参数 `[T, U]` 支持

**评估**：这是向后兼容的设计，标准形式 `段落 名 接收 参数：` 完全支持。

---

### 8. 导入导出语法比规范更丰富

**规范描述**：v3.1 列出的语法（第 372-378 行）：
```
导入 模块
导入 模块1, 模块2
从 模块 导入 函数1, 函数2
导出 符号1, 符号2
导出 全部
```

**实际实现**：除上述外还支持：
- 书名号语法：`导入《模块名》`、`从《模块》导入《符号》`
- 别名语法：`导入 模块 为 别名`、`从 模块 导入 符号 为 别名`

**评估**：功能超集，完全兼容规范语法。

---

### 9. 中文无空格分词已实现，且有保护机制

**规范描述**：v3.1 说"中文关键字和标识符之间不需要空格"（第 51-56 行）。

**实际实现**：词法分析器实现了三层分词机制，支持无空格分词。同时设有：
- 常见复合词保护列表（`COMMON_COMPOUND_WORDS`），避免误拆分
- 用户定义标识符预扫描，避免将用户定义的函数名误拆分为关键字

**评估**：实现完善，比规范描述的更智能。

---

### 10. 赋值语句支持三种形式

**规范描述**：v3.1 列出三种赋值形式（第 222-225 行）：
```
甲 = 20
甲 等于 30
甲 为 40
```

**实际实现**：三种形式均已支持。

**评估**：✅ 完全符合规范。

---

### 11. 异步语法（v3.1 未涵盖，新增特性）

**实际实现**：已实现以下异步语法：
- `异步 段落 段名()` — 定义异步段落
- `异步作用域 ... 结束` — 结构化并发块
- `等待 异步操作` — await 表达式

**评估**：这是 Level 10 新增功能，超出 v3.1 规范范围。建议后续版本更新规范文档时加入异步语法章节。

## 🎯 修复优先级建议

### 🔴 最高优先级（核心一致性）

1. **修复 `跳出` 和 `跳过` 语句的句号强制问题**
   - 文件：`src/parser_stmt.py`
   - 修改：将 `self._consume(TokenType.DOT)` 改为可选消耗
   - 理由：与"句号可选"核心设计原则矛盾

### 🟡 高优先级（功能完整性）

2. **添加遍历循环的 `于` 关键字支持**
   - 文件：`src/parser_stmt.py` 的 `_parse_foreach_stmt`
   - 修改：在连接词判断中添加 `于` 支持
   - 理由：v3.1 规范明确列出，用户可能自然使用

### 🟡 中优先级（一致性改进）

3. **统一遍历/当循环与条件语句的冒号策略**
   - 方案 A：都改为可选（更灵活）
   - 方案 B：都改为强制（更规范）
   - 理由：当前行为不一致可能造成用户困惑

4. **区分变量声明与赋值的 AST 节点**
   - 将 `_parse_assignment_stmt` 返回 `Assignment` 而非 `VarDecl`
   - 理由：语义清晰，便于后续类型检查和优化

### 🟢 低优先级（文档与规范同步）

5. **在 v3.1 规范中添加异步语法章节**
   - 理由：异步语法已实现，规范应同步更新

6. **添加配置开关控制「结束」关键字**
   - 理由：v3.1 提到"通过配置开启（默认关闭）"，当前实现是默认开启

## 💡 用户书写体验评估

### 优点
1. **中文无空格**：支持 `如果甲大于十那么打印甲`，书写自然流畅
2. **句号可选**：大部分语句句号可选，减少标点负担
3. **多种语法兼容**：新旧语法混用都能解析，迁移成本低
4. **动词调用灵活**：支持无括号调用 `打印 "你好"` 和有括号调用 `打印("你好")`

### 待改进
1. **`跳出`/`跳过` 必须加句号**：与其他语句不一致，容易忘
2. **遍历/当循环必须加冒号**：条件语句可以省略，循环却不行，容易混淆
3. **遍历缺少 `于`**：`遍历 甲 于 列表` 是很自然的中文表达
4. **缩进敏感但无明确错误提示**：缩进错误时可能产生难以理解的解析错误
