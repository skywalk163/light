## 0. 认知框架：空的二相性与转化律

> 这一节不是文学修辞，是**后面所有口径的推导前提**。跳过它，本文的规则就是死记硬背；
> 读懂它，所有规则都成为必然。

中文一个「空」字承担着两个截然不同的相。编程里踩的每一个空值坑，
追到最后都是**把二相当成了一相**，或**忽视了相互转化**。

### 0.1 二相

| 相 | 光明里的形态 | 本质 | 能力 |
|---|---|---|---|
| **无相** | `空`（`type == 0`） | **什么都没有**——不存在 | 不可寻址、不可遍历、不可增长 |
| **器相** | `""` `[]` `{}` `b""` | **有器无物**——存在但无内容 | 可寻址、可遍历（零次）、**可增长** |

「空既可以是什么都没有，也可以是任何东西的容器」——这句话就是二相性本身。

### 0.2 转化律（空 ⇄ 不空）

```
无相 ──设 x 为 ""──→ 器相 ──列.追加(项)──→ 非空（空中生色）
 ▲                                                   │
 └──────────── 置 null ──────────────────────────────┘
```

- **空即是色**：空容器一旦 `追加` / 赋值就有了内容。空不是终点，是起点。
- **色即是空**：`设 字典[键] 为 空` 把**值**（色）转成了空，但**键**（器）还在，
  `字典包含键(字典, 键)` 仍为真。形态空了，存在性未灭。
  ⇒ 这就是「置空软删除」陷阱的哲学根源（见 §5 编年「集合工具」条）：
  **误把「色已空」当成「器已灭」**。

### 0.3 由框架直接推出的三条口径

1. **判空必须分相**：问「存在吗」用严格 null 判定；问「有内容吗」用 `长(x) == 0`；
   问「键在吗」用 `字典包含键`——**不能靠值判**，因为值可空（转化律）。
2. **`是空` 收编空串、不收编空容器的理由**：字符串在光明里**既是标量也是容器**
   （str 是 char 的容器），横跨二相，实用主义必须收编；列表/字典是纯粹器相，
   有专门原语 `长(x) == 0`。这个不对称是**设计选择，不是疏漏**——
   后人不必再问「为什么 `""` 算空 `[]` 不算」。
3. **每个 API 返回「空」时必须声明返回哪一相**。R152/R153 的病根正是
   `环境变量()` 缺 key 返 `""`（器相），而 `是空` 当时只认无相——
   **拿无相的尺子量器相**，尺子说「不空」，HOME 兜底被跳过。
   这不是 bug，是**相判错了**（未决项见 §9 L-213）。

## 1. 速查卡（TL;DR）

| 我想判断… | 用这个 | **不要**用 |
|---|---|---|
| 值是 null **或** 空串 | `是空(x)` | `x == 空`（被 `__eq__` 恒真对象骗过） |
| 值是 null（严格） | `类型(x) == 类型(空)` | `是空(x)`（空串也会为真） |
| 字符串是纯空白（空格/制表/全角空格） | `是空白(x)` | `长(去空白(x)) == 0`（绕） |
| 字符串长度为 0 | `长(x) == 0` | `是空(x)`（null 也会为真） |
| 列表/字典没有任何元素 | `长(x) == 0` | `是空(x)`（容器永不为空） |
| 字典里有没有这个键 | `字典包含键(d, k)` | `是空(字典获取(d, k))`（置空软删除仍为真！） |
| if 条件想按「真假值」分支 | 直接 `如果 x:` | `是空(x)`（口径窄得多） |

**一句话**：`是空` 只管 **null 和 ""**，别的空（空白、空容器、空字节串）都不归它管。

## 2. 唯一权威口径（R153 业主裁定，2026-10-16 生效）

```
是空(x)  :=  x 是 null   或   x 是空字符串 ""
```

### 2.1 判真 / 判假矩阵（src 腿与原生腿实测一致）

| 输入 | `是空` | `是空白` | `长` | `如果 x:`（真值） |
|---|---|---|---|---|
| `空`（None/null） | **真** | 抛 TypeError | — | 假 |
| `""`（空串） | **真** | 假 | 0 | 假 |
| `" "` / `"\t"` / `"\u3000"` | 假 | **真** | ≥1 | 假 |
| `"abc"` | 假 | 假 | 3 | 真 |
| `[]`（空列表） | 假 | 抛 TypeError | 0 | 假 |
| `{}`（空字典） | 假 | 抛 TypeError | 0 | 假 |
| `b""`（空字节串） | **假**（只认 str） | 抛 TypeError | 0 | 假 |
| `0` / `0.0` / `假` | 假 | 抛 TypeError | — | 假 |

> `是空白` / `是字母` / `是数字` 对非字符串入参抛 `TypeError`，这是**有意的错误口径**
> （对齐 Python `str.isspace(1)`，调用方 `捕获` 才接得住）。**不要**把它们"修"成返回假。

### 2.2 明确**不**跟着扩的三个近亲

| 原语 | 口径 | 为什么不能跟着扩 |
|---|---|---|
| `断言为无(x)` / `断言不为无(x)` | 严格 `x is None` | 契约是「为无」。扩了会把 `断言不为无("")` 从「失败」变成「通过」，测试静默变弱。 |
| `is_null` / `null?`（原生腿别名） | 严格 `type == 0` | 名字叫 is_null 就该只判 null。R153 起与 `是空` **名实分家**（`dv_is_null` vs `dv_is_empty`）。 |
| `如果 x:`（真值判断） | Python falsy：`""`/`[]`/`{}`/`0`/`0.0`/`假`/`空` 均假 | 这是**条件表达式**语义，不是判空函数。见 `docs/L1_白话体语法规范_v4.0.md` §四。 |

## 4. 判空决策树

```
要判断一个值「是不是空的」
│
├─ 我知道它一定是个字符串吗？
│  ├─ 是 → 想知道「长度为 0」？      → 长(x) == 0
│  │        想知道「全是空白」？    → 是空白(x)
│  │        想知道「既没内容也不是空白」？ → 长(x) == 0
│  └─ 否 ↓
│
├─ 它可能是 null 吗？
│  ├─ 是 → 用 是空(x)      ← 覆盖 null + ""
│  └─ 否（我保证非 null）→ 按真实类型走上面的分支
│
├─ 它是容器（列表/字典）吗？
│  └─ 是 → 长(x) == 0      ← 是空(x) 对容器恒为假！
│
└─ 我是想判断「字典里这个键存不存在」吗？
   └─ 字典包含键(d, k)      ← 置空软删除后键仍在，判值会误判
```

### 4.1 为什么 `是空` 不能顺手扩到「空容器」

三个理由，任一都足以否掉：

1. **业主明令**：R153 裁定原文「纯空白/空格是否算空，需项目规范另行明确，不默认纳入」，
   容器同理不纳入。
2. **`b""` 都不算**：只认 str 的 `""`，否则 bytes/str 双轨口径又要分叉。
3. **会破坏 `断言为无` 的近亲隔离**：见 §2.2。

| 缺 key，2 参 `环境变量(名, 默认)` | `默认` | `""`（**默认值被静默丢弃**） | `默认` |
| key 存在 | 变量值 | 变量值 | 变量值 |
| key 存在但值为 `""` | `""` | `""` | `""`（**真·空值，不是缺失**） |

- **第三条病灶（本轮新发现）**：`stdlib/os.light:getenv(名, 默认 等于 "")` 写的是
  `值 == 空` 判缺 key；原生腿缺 key 返 `""` 而非 null ⇒ `"" == 空` 为假
  ⇒ **非空默认值在原生腿永远丢失**（src 腿因返 None 而正常）。
- **根因**：① `src/llvm/codegen_typed.py` 的 `环境变量` 分支只传 `args[0]`，
  `args[1]`（默认值）从未到达 C 侧；② `dv_getenv` **用返回串表达“缺失”**，
  而 `""` 是合法环境变量值（`export X=`），调用方无从分辨 ⇒ 三态必然塌成两态。
- **修法**：C 侧 `dv_getenv` 缺 key 返 **NULL 指针**（不再用空串哨兵）；
  codegen 侧据 `icmp ne ptr out, null` 显式 br 分流三态
  （命中 → 变量值 / 缺失且有默认值 → 实参默认值 / 缺失且无默认值 → `dv_null`）。
- **⚠️ `stdlib/os.light` 的 `值 == 空` 刻意不改**：探针证伪了“改成 `是空(值)`”
  这个候选修法 —— 那会把“存在但值为空串”也吞进默认分支，与 src 腿
  （真 Python `os.getenv` 返 `""`）产生**新分叉**（实测：src `<empty>` vs native `DEF2`）。
  真正的病灶在 `dv_getenv` 返回值；修好后 `值 == 空` 本就正确。详见
  `stdlib/os.light` 段内注记与 `_R154_A线交付报告.md` §2.3。
- **验证**：`tests/unit/test_R154_L213_环境变量口径.py`（15 条，三态两腿逐行对拍 +
  源码级守 + 反跑有牙）；双 gen `--check` RC=0；波及面测试 41 条全绿。
- **已知边界（未对齐，刻意保留）**：0 参调用 `环境变量()` —— src 腿 TypeError
  （缺必填实参），原生腿返空串（选择“不崩”而非“同崩”）。已在 `docs/api/builtins.md` 登记。
- **指针**：`_R154_A线交付报告.md`（销账五段式 + 波及面 + 反跑证据）。

### L-213 候选 · `环境变量()` 缺 key 两腿口径分歧（活缺陷）

| 腿 | 缺 key 返回 | 位置 |
|---|---|---|
| src 腿 | `None`（null） | `stdlib/builtins.py:321` `os.environ.get(name, None)` |
| 原生腿 | `""`（空串） | `src/llvm/runtime_typed.c:3755` `dv_getenv` → `dv_strdup("")` |

- **为什么 R152/R153 都没根治**：R152 明确裁定「零 `src/`、不动全局语义」做局部绕开；
  R153 broaden `是空` 后 `是空("")` 也为真，`文件系统.light` 那条路径两腿都能拦住，
  症状被掩盖，但**分歧本身仍在**，别的调用点仍会中招。
- **建议修法**（需业主裁定 + 全量兜底）：让原生腿 `dv_getenv` 缺 key 返回 **null**
  （`LightValue{type=0}`）而非空串，与 src 腿对齐；或反向把 src 腿也改成返 `""`。
  前者更符合「缺 key = 无值」的直觉，但会改变所有 `环境变量()` 调用点的行为，
  必须重跑 0.82 全量门。
- **临时规避**：调用 `环境变量()` 后一律用 `是空(x)` 判（R153 后两腿都拦得住），
  不要用 `长(x)==0` 或 `x == ""`。

### L-214 候选 · **双轨 `是空`：加一行 import 就换一套口径**（活缺陷，2026-10-16 实测）

仓里有两个**都叫 `是空`** 的真实实现，口径不同，**取决于文件头部有没有 import**：

| 轨 | 定义位置 | 口径 | 触发条件 |
|---|---|---|---|
| 地板内置（**权威**） | `stdlib/内置核心判型.light:55` | `null 或 ""` | 不导入，直接写 `是空(x)` |
| lightpub 桥接 | `stdlib/lightpub/类型工具.py:65` | `null` / `""` / `[]` / `{}` / `()` / `set()` 全算空 | 写了 `从 类型工具 导入 是空` |

实测证据（`docs/归档/R154_scratch归档/R153_双轨是空探针/探针_双轨是空.light`，rc=0；R154-D 已把原 `_r153d_scratch/` 探针归档）：

| 输入 | 不导入（权威） | 导入后 |
|---|---|---|
| `空` | 真 | 真 |
| `""` | 真 | 真 |
| `" "` | 假 | 假 |
| `[]` | **假** | **真** |
| `{}` | **假** | **真** |

- **为什么比 L-213 更危险**：`从 类型工具 导入 是空` 是**看起来完全无害的常规 import**，
  任何人为了「用一下类型工具」都会顺手写；而语义分叉**没有任何编译期或运行期提示**。
  R152/R153 只关注了地板内置那一轨，这条一直没人看过。
- **建议修法**（需业主裁定）：把 lightpub 的 `是空` 改名为 `皆空`（或 `为空或空容器`），
  与地板内置彻底分名；或直接删除该导出，让调用方用地板内置 + `长(x)==0`。
  前者改动小、不破坏既有 import，推荐。
- **临时规避**：**判空不要 `从 类型工具 导入 是空`**。已在该模块的 API 文档
  （`docs/api/类型工具.md`）顶部加了醒目分歧对照表。
