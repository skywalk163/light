# 编号登记表（历史编号唯一归宿）

> 建立：R154 C 线（2026-10-16）。总账 §4.2 第 4 条“T/L 双体系并存”的本轮收口。
>
> **定位**：本文只回答一个问题——**“我在旧文档里看到一个 T-xxx / KI-Rxx 编号，它是什么、去哪查”**。
> 细节一律留在权威载体，本文只做索引与定性，不做第二份细节账（防漂移铁律，同总账 §5.1）。

## 一、立规（自本轮起生效）

1. **新问题一律 L-2xx 顺延**，进 `docs/功能对标/语言缺陷账.md`（缺陷）或对应权威载体（见总账 §3 载体地图）。
2. **T 族与 KI 族编号自此不再新增**——T 是历史任务编号（随任务体系终止而冻结），KI-Rxx 见 §四。
3. 本文由**当轮 C 线/收口 agent** 在发现新历史编号引用时更新；日常开发不需要动它。
4. 编号是**不可再生资源**：已定性条目不删除，只追加（L-201 教训同款纪律）。

## 一·五、T 编号引用带轮次前缀（R157 C 线立规）

> R154 裁定「T/KI 系编号后续逐步落实轮次前缀」，本轮将惯例落纸（**不返工改历史引用**，
> 新引用自本轮起执行）。

**惯例**：正文引用 T 族（及 KI-Rxx）编号时，一律带**轮次前缀**，形态为 R{轮次}-{编号}，
例如引用 R10 期任务编号 T12 写作 **R10-T12**、R131 探针标签 T3B 写作 **R131-T3B**。

- **示范**（正确）：R97-T12、R10-T5B、R131-T3B。
- **反例**（新引用禁止）：裸 T12、裸 T5B、裸 KI-R131-01 不带轮次。
- **例外**：本表 §三/§四 的登记行本身是「号码 ↔ 真身」索引，可裸写编号（这是查表入口本身）。
- **逐步落实**：存量旧文档中的裸引用本轮不动，后续轮次修订到哪篇顺带补哪篇。

## 二、编号体系总览（三族）

| 体系 | 形态 | 性质 | 权威载体 | 状态 |
|---|---|---|---|---|
| **L 族** | L-xxx | 语言/编译器**缺陷**编号 | `docs/功能对标/语言缺陷账.md` | **在用**（唯一活跃编号，新问题 L-2xx 顺延） |
| **T 族** | T-数字[字母][-子号] | 历史**任务/工作项**编号（不是缺陷编号） | 见 §三（按亚族分载体） | **冻结**（R154 起不再新增） |
| **LH 族** | LH-xx | **lighthive 侧**问题编号（外部来源，不是本仓编号） | 缺陷账 §二十五（`LH → L 号` 对照） | **冻结**（22 条已全部并入缺陷账，2026-10-29） |

> 少数以 `#L-T5B-n` 等形态挂在 `docs/known_issues.md` 对应章节内。查缺陷永远从缺陷账或 known_issues 入手，不直接引用 T 号。

## 四、KI 族裁定（不并号，维持现状）

`docs/known-issues/` 的 KI-Rxx-xx（KI-R94-01/02、KI-R94-W13、KI-R95-01 等，全仓 28 处引用/10 文件）
**不并入 L/T 体系**，理由：

1. 它有**自洽的三态生命周期**（`open` / `accepted-risk` / `closed+证据`），比缺陷账的静态状态更适合工程侧 known issue；
2. 有独立看板与责任人约定（`docs/known-issues/README.md`），体系完整；
3. 职责边界清晰：工程侧（CI/门禁/测试稳定性）归 KI，语言/编译器本体归 L——两个目录头部互有指针。

**裁定**：维持现状；本文 §二总览建指针；KI 编号同样**不再新增**（新工程侧问题优先走 L 编号 + 权威载体，除非业主明确恢复 KI 看板制）。
