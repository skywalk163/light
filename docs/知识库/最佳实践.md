# 光明最佳实践

## 1. 文体选择

### 何时使用 L1 白话体
- K12 教学和初学者入门
- 快速原型开发
- 团队中有编程新手
- 教学材料编写

### 何时使用 L2 文言体
- 商业项目开发
- 大型代码库
- 需要类型注解的场合
- 熟练开发者团队

### 文体混合使用
光明支持在同一项目中混合使用 L1 和 L2：
- 教学模块用 L1
- 核心模块用 L2
- 通过 `导`/`从` 互相调用

## 2. 代码组织

### 2.1 单文件 vs 多模块
- **小项目**（< 200 行）：单个 `.light` 文件即可
- **中项目**（200-1000 行）：按功能拆分为 2-3 个模块
- **大项目**（> 1000 行）：使用完整模块系统 + `package.toml`

### 2.2 模块拆分原则
- 按功能领域拆分（用户管理、数据处理、报表生成）
- 每个模块不超过 300 行
- 模块间通过导入/导出通信
- 避免循环依赖

## 3. 错误处理

### 3.1 基本错误处理
```light
# 不要这样做
段 读取文件(路径):
    返回 打开(路径, "r") 的 读取  # 可能崩溃

# 应该这样做
段 安全读取(路径):
    试:
        设 f = 打开(路径, "r")
        设 内容 = f 的 读取
        f 的 关闭
        返回 内容
    捕 错误:
        打印 "读取失败：", 错误
        返回 空
```

### 3.2 错误处理策略
- **用户输入**：总是验证并捕获异常
- **文件操作**：使用 `试/捕/终` 确保资源释放
- **网络请求**：设置超时并处理连接失败
- **类型转换**：验证输入格式后再转换

## 4. 数据处理

### 4.1 列表操作
```light
# 创建列表
设 列表 = [1, 2, 3, 4, 5]

# 遍历
遍 列表 为 元素:
    处理(元素)

# 筛选（手动）
设 结果 = []
遍 列表 为 元素:
    如果 元素 > 3:
        结果的 添加 元素
```

### 4.2 字典操作
```light
# 创建字典
设 字典 = {"键1": 值1, "键2": 值2}

# 安全取值
如果 字典 包含 "键1":
    设 值 = 字典["键1"]

# 遍历
遍 字典 的项 为 项:
    打印 项[0], ":", 项[1]
```

## 5. 函数设计

### 5.1 函数设计原则
- **单一职责**：一个函数只做一件事
- **参数适量**：不超过 3-4 个参数
- **命名清晰**：函数名说明其功能
- **返回值一致**：返回类型保持一致

### 5.2 函数示例
```light
# 好的设计
段 计算学生平均分(成绩列表):
    如果 成绩列表的长度 等于 0:
        返回 0
    设 总分 = 0
    遍 成绩列表 为 分:
        总分 = 总分 + 分
    返回 总分 / 成绩列表的长度

# 避免这样做
段 处理数据(数据, 类型, 排序, 过滤, 限制):
    # 太多参数，功能不单一
    返回 数据
```

## 6. 文件管理

### 6.1 文件操作最佳实践
```light
# 使用试/捕确保文件关闭
试:
    设 f = 打开("文件.txt", "r")
    设 内容 = f 的 读取
捕 错误:
    打印 "文件操作失败：", 错误
终:
    如果 f 不等于 空:
        f 的 关闭
```

### 6.2 路径处理
- 使用相对路径（相对于项目根目录）
- 避免硬编码绝对路径
- 使用 `配置` 模块管理路径

## 7. 性能建议

### 7.1 性能优化原则
1. 先保证正确性，再优化性能
2. 使用分析工具找出瓶颈
3. 优化热点代码（执行最频繁的部分）

### 7.2 常见优化
- 减少不必要的列表遍历
- 避免在循环中执行文件操作
- 大数据量时考虑分批处理
- 使用编译模式获得最佳性能

## 8. 安全性

### 8.1 输入验证
```light
# 用户输入必须验证
段 安全获取数字(提示):
    设 输入 = 读取(提示)
    试:
        返回 整数(输入)
    捕:
        打印 "请输入有效的数字！"
        返回 安全获取数字(提示)
```

### 8.2 文件安全
- 验证文件路径，防止路径遍历
- 文件操作使用异常处理
- 敏感数据避免明文存储
