# 光明报错数据集（T-0319）

> 把开发中暴露的每个 Light 报错自动归档，去重、脱敏后导出成 SFT 样本，定期增量微调
> `light-translator`，让它专门避开 Light 的已知暗坑，而不是泛泛做语言翻译。
>
> 本文只描述**库与格式**。命令行接线在 T-0326，且必须可关闭；本模块自身不在
> `light ai check` 主流程里默认写盘。

实现：`tools/ai_copilot/error_corpus.py`（纯标准库，不联网、不上传、不发遥测）。
测试：`tests/test_error_corpus.py`。

---

## 1. 存储布局

默认根目录 `~/.light/error_corpus`，可用环境变量 `LIGHT_ERROR_CORPUS_DIR` 覆盖
（只读取这一个环境变量），也可在每个 API 上显式传 `root=`。

```
<root>/
  YYYY-MM.jsonl     # 按月追加，一行一条 JSON
  index.json        # sidecar 索引：去重计数与 last_seen
  .lock             # 跨进程写锁
```

- JSONL **只追加**：同一 `(code, source_hash)` 重复出现时不再写行，只更新索引。
- `index.json` 是导出/统计的唯一数据源，避免每次去重都扫描全量 JSONL。
  JSONL 行里的 `hits` 是该错误**首次**归档时的快照（固定为 1），累计次数以索引为准。
- 月文件按记录时间（本地时区）切分，跨月自动新建。

## 2. 记录字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `ts` | str | 首次归档时间，ISO 8601 带时区 |
| `last_seen` | str | 最近一次命中时间 |
| `code` | str | 错误码（T-0316 码表），缺失时为 `UNKNOWN` |
| `message` | str | 编译器原始报错文本（已脱敏） |
| `hint` | str | 错误码对应的通用原因说明（已脱敏） |
| `fixes` | list[str] | 人类可读修复建议（已脱敏） |
| `source_snippet` | str | 出错行 ±2 行，超出 2000 字符截断 |
| `source_hash` | str | 源文件 sha256 前 16 位，仅用于去重 |
| `lang_level` | str/null | 由调用方经 `context` 传入 |
| `backend` | str/null | `src` / `llvm` 等，由调用方传入 |
| `light_version` | str/null | 由调用方传入 |
| `hits` | int | 该错误累计出现次数 |

去重键固定为 `(code, source_hash)`。`source_hash` 对源文件全文计算，仅保存前 16 位，
不保存原文；同一段代码在不同位置重复报同一个错只累计 `hits`。

> `summary()` 的输出字段固定为 `{code, hits, last_seen}`，T-0320 依赖这三个键，
> 不要改名或删字段。

---

## 3. 隐私边界

归档内容**只用于改进编译器与翻译模型**，因此：

1. **只存片段，不存整文件**：`source_snippet` 最多出错行上下各 2 行。
2. **绝对路径只留 basename**：`/Users/alice/project/main.light` → `main.light`；
   Windows 盘符路径、`~/...` 同样处理。
3. **疑似 token 打码**：连续 32 位以上的 `[A-Za-z0-9_-]` 替换为 `***`。
4. **不采集标识信息**：不读取环境变量（除 `LIGHT_ERROR_CORPUS_DIR`）、不取主机名、
   不取用户名；报错文本里的用户名只可能通过路径出现，已被第 2 条去掉。
5. 脱敏在**落盘前**完成，`message` / `hint` / `fixes` / `source_snippet` 都会过一遍
   `sanitize()`；产物里不应出现原始绝对路径或长 token。

## 4. 清理

```python
from error_corpus import purge

purge()                                   # 默认：只报告 90 天前的条目，不落盘
purge(before="2026-01-01", dry_run=False) # 真正删除并重写月文件
```

- `before` 支持 `datetime` 或 ISO 字符串；缺省为 90 天前。
- `dry_run=True` 只返回将被清理的 `{code, source_hash, hits, last_seen}` 列表。
- 真正清理时同步删除 `index.json` 中的条目，并重写受影响的月文件（原子替换）；
  某个月文件清空后直接删除。
- 索引写失败只 `warnings.warn`，不抛出——已经落盘的 JSONL 不会因此丢行。

## 5. 导出与喂给训练脚本

`export_pairs(min_hits=1)` 返回 SFT 风格样本：

```json
{
  "prompt": "报错代码: E1001\n报错信息: 未知关键字 'models'\n代码片段:\ndefine main() {\n    models x = 1\n}",
  "completion": "修复步骤:\n1. 把 models 改成 define models\n提示: Light 用 define 声明变量"
}
```

`min_hits` 用来过滤偶发错误，例如只导出复现 3 次以上的暗坑：

```python
import json
from error_corpus import export_pairs

pairs = export_pairs(min_hits=3)
with open("error_corpus_sft.jsonl", "w", encoding="utf-8") as fh:
    for pair in pairs:
        fh.write(json.dumps(pair, ensure_ascii=False) + "\n")
```

导出的 JSONL 与 `tools/ai_copilot/sft_dataset.jsonl` 的 SFT 字段（`instruction` /
`input` / `output`）不同构，接入训练前需要做一次字段映射：

- `prompt` → `instruction`（或 `input`，视训练脚本模板而定）
- `completion` → `output`
- 建议 `category` 固定为 `light_error_fix`，便于在混训时控制采样比例

现有脚本 `tools/ai_copilot/merge_corpus_into_sft.py` 采用「schema 保留式追加」，
可以直接把映射后的行并入 `sft_dataset.jsonl`；训练入口见
`tools/ai_copilot/train_sft.ipynb`。

## 6. 并发与失败语义

- 追加写使用 `open(..., "a", encoding="utf-8")` **单行一次写入**，不会产生半行。
- 索引读改写由 `.lock`（POSIX `flock` / Windows `msvcrt.locking`）串行化；
  拿不到锁时降级为无锁执行并 `warnings.warn`，不阻断归档。
- 索引写失败只告警：JSONL 数据行优先保留，最坏情况是下次同一错误再多写一行。
- 同一进程内多线程、多个进程同时归档同一目录都是安全的。

## 7. 不做什么

- 不联网、不上传、不发遥测。
- 不在 `light ai check` 主流程里默认写盘（T-0326 接线，且必须可关闭）。
- 不收集环境变量、主机名、用户名等标识信息。
- 不引入第三方依赖（无 pandas / pydantic）。
