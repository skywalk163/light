风险分析与应急方案

R1: FFI 函数实现复杂度超预期 高

30 个缺失函数中部分涉及底层内存操作（取地址、指针解引用），实现难度可能超出 2 天预算。
应急: 先实现测试直接引用的 15 个核心函数，剩余标记为 NotImplemented 并跳过对应测试，W2 补齐。

R2: duanpub P1 桥接遇到运行时依赖 高

HTTP客户端/Socket 依赖 Python 标准库 socket/urllib，桥接层可能遇到异步 IO 兼容问题。
应急: 降级为同步实现 + W3 补充异步支持；若 socket 过于复杂，先只做 SQLite 桥接。

R3: 转译器修复与 DuMate 并行冲突 中

T08/T09 由 Trae 负责，若与 DuMate 修改的文件存在交集可能导致 merge 冲突。
应急: 文件隔离: Trae 只动 tools/ai_copilot/，DuMate 不碰该目录。冲突时以 DuMate 为主。

R4: 文档统一工作量超预期 中

57 个 .md 文件逐一审查+更新可能超过 2 天。
应急: 用 migrate_syntax.py 的 --md 模式批量扫描过时语法；优先修核心 10 个文档，剩余标为 "v1.x 参考"。

R5: CLI 打包遇到依赖问题 中

pip 打包可能遇到 entry_point 配置、数据文件包含（.duan 模板/语法文件）等打包问题。
应急: 先做 zipapp (python -m zipapp) 一键打包，W4 再做正式 PyPI 发布。

R6: 性能基准结果不理想 低

段言通过 Python AST 转译执行，性能必然低于原生 Python，对比数据可能不好看。
应急: 定位为"功能完整性优先于性能"，基准数据仅作内部参考，不对外发布。记录优化方向留待 v4.1。

R7: Web Playground 部署环境限制 低

本地 Playground 需要后端运行 Python，公开部署需要服务器资源。
应急: W3 做本地版（localhost），公开版留待后续。可考虑 WASM 编译路线。
