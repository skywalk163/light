## 1. 讨论分类与标签

### 1.1 分类定义

段言社区的 GitHub Discussions 使用以下分类体系：

| 分类 | 图标 | 标签 | 说明 | 适用场景 |
|------|------|------|------|----------|
| **一般讨论** | 💡 | `general` | 关于段言的一般性讨论、想法交流或社区互动 | 社区公告、语言设计讨论、技术交流 |
| **问题求助** | ❓ | `help` | 在使用段言过程中遇到问题，寻求社区帮助 | 安装问题、编译错误、使用困惑 |
| **功能建议** | 🚀 | `ideas` | 为段言提出新的功能建议或改进想法 | 新语法特性、标准库扩展、工具改进 |
| **展示分享** | 🎨 | `showcase` | 分享您用段言构建的项目、工具或创意作品 | 项目展示、代码片段、创意作品 |
| **问答** | ✅ | `qna` | 有明确答案的问答式讨论 | 技术问题、最佳实践、解决方案 |
| **公告** | 📢 | `announcements` | 官方发布的重要公告（仅限维护者） | 版本发布、社区活动、重要通知 |

### 1.2 标签体系

除分类标签外，建议为讨论添加以下补充标签：

| 标签 | 颜色 | 说明 |
|------|------|------|
| `beginner-friendly` | 🟢 绿色 | 适合新用户参与的问题 |
| `discussion` | 🔵 蓝色 | 需要社区讨论的话题 |
| `tutorial` | 🟣 紫色 | 教程或学习资源相关 |
| `bug` | 🔴 红色 | 用户报告的疑似 Bug（应转为 Issue） |
| `duplicate` | ⚫ 灰色 | 重复的讨论 |
| `pinned` | ⭐ 金色 | 置顶的重要讨论 |
| `resolved` | 🟢 绿色 | 问题已解决 |
| `wontfix` | ⚫ 灰色 | 不计划采纳的建议 |
| `under-review` | 🟡 黄色 | 维护者正在评估中 |

### 1.3 标签使用规范

#### 维护者标签行为

1. **新讨论默认无标签**，维护者应在 48 小时内完成初步分类
2. **`bug` 标签**的讨论应在 1 周内转为 GitHub Issue
3. **`duplicate` 标签**应附带指向原讨论的链接
4. **`pinned` 标签**仅用于不超过 3 个置顶讨论
5. **`resolved` 标签**由提问者或维护者在问题解决后添加

#### 社区成员标签行为

- 社区成员可以建议标签，但最终由维护者决定
- 请勿滥用标签，一个讨论最多使用 3 个标签

## 3. 常见问题 FAQ

### 3.1 安装与入门

#### Q: 如何安装段言？
```bash
pip install duan
```
安装完成后运行 `duan --version` 验证。

#### Q: 段言需要 Python 环境吗？
是的，段言编译器基于 Python 实现，需要 Python 3.10 或更高版本。

#### Q: 段言支持哪些操作系统？
段言支持 Windows、macOS 和 Linux 三大主流操作系统。

#### Q: 如何运行一个段言程序？
```bash
duan run hello.duan
```
或编译为可执行文件：
```bash
duan compile hello.duan --backend llvm-typed
```

### 3.2 语言特性

#### Q: 段言和 Python 的关系是什么？
段言的编译器使用 Python 实现，但段言本身是一门独立的编程语言，拥有自己的语法、类型系统和标准库。

#### Q: 段言支持面向对象编程吗？
是的，段言支持类、继承、接口、多态等面向对象特性。

#### Q: 段言的性能如何？
段言支持 LLVM 原生编译，性能接近 C 语言。解释执行模式适合开发和调试。

#### Q: 段言支持中文关键字，那英文关键字还支持吗？
段言同时支持中文和英文关键字，`打印` 和 `print` 等价，`如果` 和 `if` 等价。

### 3.3 开发与贡献

#### Q: 如何参与段言开发？
请参考[贡献指南](../CONTRIBUTING.md)和[开发指南](../DEVELOPMENT_GUIDE.md)。

#### Q: 段言使用什么许可证？
段言使用 MIT 许可证，完全开源免费。

#### Q: 如何报告 Bug？
请在 GitHub Issues 中提交 Bug 报告，使用 [Bug 报告模板](https://github.com/skywalk163/duan/issues/new?template=bug_report.md)。

#### Q: 段言有包管理器吗？
有的，段言内置了 `duan pkg` 包管理命令和 duanpub 包注册中心。

### 3.4 社区与支持

#### Q: 段言社区在哪里？
- **GitHub Discussions**：技术讨论和问题求助
- **GitHub Issues**：Bug 报告和功能请求
- **文档站**：https://skywalk163.github.io/duan/

#### Q: 如何获取帮助？
1. 先在 FAQ 和已有讨论中搜索
2. 在 GitHub Discussions 的「问题求助」分类提问
3. 提供完整的环境信息和复现步骤

#### Q: 段言有官方文档吗？
有的，请访问 [文档站](https://skywalk163.github.io/duan/)。

## 4. 审核指南

### 4.1 审核原则

1. **尊重与包容**：所有讨论都应遵循社区行为准则
2. **最小干预**：只在必要时进行干预
3. **透明公正**：审核操作应附带说明
4. **一致性**：同类情况使用相同的审核标准

### 4.2 审核操作指南

#### 正常审核流程

| 场景 | 操作 | 说明 |
|------|------|------|
| 新讨论发布 | 分类 + 添加标签 | 48 小时内完成初步分类 |
| 问题已解决 | 标记为 `resolved` | 确认问题已解决后关闭 |
| 重复内容 | 标记为 `duplicate` + 链接 | 指向原讨论 |
| 违反行为准则 | 隐藏 + 通知 | 严重违规直接删除 |

#### 需要警惕的行为

- **广告垃圾**：与段言无关的商业推广
- **人身攻击**：针对个人的侮辱性言论
- **重复发布**：相同内容多次发布
- **偏离主题**：与段言无关的讨论
- **恶意行为**：蓄意破坏社区氛围

### 4.3 升级处理

当遇到以下情况时，应升级给核心维护团队处理：

1. 涉及法律问题的内容
2. 严重违反行为准则的事件
3. 需要项目层面决策的重大讨论
4. 社区成员之间的严重冲突

### 4.4 维护者责任

- **定期检查**：每周至少检查 3 次 Discussions
- **及时响应**：问题求助类讨论应在 48 小时内回复
- **引导讨论**：帮助偏离主题的讨论回到正轨
- **鼓励参与**：欢迎新成员，鼓励有价值的贡献
- **记录归档**：定期整理有价值的讨论到 Wiki 或文档

### 4.5 讨论转 Issue 的规则

以下情况应将 Discussion 转为 Issue：

| 条件 | 操作 |
|------|------|
| 确认是 Bug | 创建 Bug Issue，链接原 Discussion |
| 确认是功能需求 | 创建 Feature Request Issue，链接原 Discussion |
| 需要代码审查 | 引导用户提交 PR |
| 讨论已成熟 | 总结讨论结果，创建 Issue 跟踪实施 |

## 5. 与 CODE_OF_CONDUCT 的关联

### 5.1 行为准则概述

段言社区遵循 [CODE_OF_CONDUCT.md](../../CODE_OF_CONDUCT.md) 中定义的行为准则。所有 Discussions 参与者（包括提问者、回答者、浏览者）都应遵守：

1. **尊重他人**：尊重所有社区成员，无论其技术水平、背景和经验
2. **包容开放**：欢迎所有水平的开发者，从新手到专家
3. **建设性沟通**：提供建设性的反馈，关注问题本身
4. **协作精神**：乐于分享知识，帮助他人成长
5. **禁止骚扰**：不欢迎任何形式的骚扰、歧视或人身攻击

### 5.2 违规处理流程

| 级别 | 违规行为 | 处理方式 |
|------|----------|----------|
| 轻微 | 不友善言论、轻微偏离主题 | 提醒 + 编辑或删除违规内容 |
| 中等 | 重复违规、人身攻击 | 警告 + 临时禁言（7 天） |
| 严重 | 恶意骚扰、歧视性言论、威胁 | 永久封禁 + 报告 GitHub 支持 |

### 5.3 举报渠道

如果发现违反行为准则的行为，请通过以下方式举报：

1. **私信维护者**：在 GitHub 上 @ 项目维护者
2. **发送邮件**：项目维护者邮箱（见项目主页）
3. **提交 Issue**：在 Issues 中创建「社区报告」Issue（仅维护者可见）

举报时请提供：
- 涉事讨论的链接
- 违规内容的具体描述
- 你认为违反了哪条准则
- 任何相关的截图或证据

### 5.4 行为准则的持续改进

- 行为准则本身也是社区讨论的议题
- 欢迎在「一般讨论」分类中提出改进建议
- 重大变更需要经过社区讨论和核心维护团队批准
