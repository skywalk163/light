# 命令可用性说明（R96 校正）

> 本文档直面「文档承诺与真实可用性」的落差，逐条说明 `light` CLI 命令的真实状态。
> 凡标「✅」为实测可用；标「⛔」为默认关闭 / 已知缺陷。

## 一、可用命令（实测通过，2026-09-25）

| 命令 | 说明 | 备注 |
|---|---|---|
| `light run` | 解释执行 | 默认 SRC 后端，无需额外依赖 |
| `light compile` | 编译为 Python | `-o 输出` |
| `light ast` / `tokens` | 显示 AST / Token 流 | 调试用 |
| `light check` | 语法 + 类型检查 | ✅ **安全，只体检不改写文件**，首选 |
| `light type-check` | 独立类型检查 | |
| `light init` | 初始化项目 | |
| `light pkg` | 包管理（init/build/run/native/search/info/list） | ✅ 可用 |
| `light test` | 跑测试 | |
| `light harness` | deepseek-harness MVP | examples/harness |
| `light py2light` | Python → 光明 转译 | |
| `light repl` / `tutorial` | 交互式 / 教程 | |
| `light feedback` | 反馈收集 | |
| `light doc` | 生成文档 | ✅ R97 将验收对真实工程的可用性 |
| `light profile` | 性能分析 | ✅ 同上 |
| `light install` / `publish` | 安装 / 发布包 | ✅ 已能执行（缺 package.toml 时给出清晰错误，非 traceback） |
| `light pkg update` / `pkg publish` | 更新 / 发布包 | ✅ 同上 |

## 二、默认关闭 / 已知缺陷

| 命令 | 状态 | 原因 | 替代 |
|---|---|---|---|
| `light fmt` | ⛔ 默认关闭（需 `--force`） | **R96-KI-01 语义破坏缺陷**：现有 formatter 会把合法代码改写成不可解析形式（重排缩进＋错误补冒号） | `light check`（安全体检）；R97 T9 修复后开放 |
| `light fmt --force` | ⚠️ 知情风险执行 | 同上，仅确认风险后使用 | 同上 |

## 三、承诺兑现率（指标）

- R96 起点：7 条被文档当"可用"的格式化/工具命令中，6 条实测可用，仅 `fmt` 因缺陷关闭；
- 目标：R97 末，所有文档中标注可用的命令「零意外失败」。

## 四、给文档维护者的要求

任何在 README / `docs/user_guide.md` / 教程中出现的 `light xxx` 命令，**必须先在真实环境跑一遍**再写入；
对 `fmt` 类未稳定命令，标注「⛔ 默认关闭（R96-KI-01）」。
