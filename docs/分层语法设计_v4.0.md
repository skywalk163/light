**版本**：v5.0.0

---

## 概述

本设计文档提出光明语法的**分层架构**,作为突破当前语法瓶颈的根本方案。

核心立意:**借鉴中文"一套字 + 多种文体 + 自然吸收专业符号"的智慧**,让光明既能让青少年快速上手,又能让高手用它做商用大型项目。

---

## 第一部分:问题诊断

### 1.1 当前瓶颈的根本原因

光明当前陷入瓶颈,表面看是"语法让人迷糊",根因是**"统一语法"的执念错了**。

试图用**一套语法**同时满足"青少年易学"和"商用大型项目",结果两边都不讨好:
- 青少年面对 `段落/函数/段`、`为/等于`、`加上/+` 等多种等价形式,无所适从
- 工程师面对无类型注解、无模块可见性、无性能优化空间,不敢用于商用项目

### 1.2 双模式泛滥

当前光明积累了过多双模式,每多一个双模式,学习成本×2,解析器复杂度×2,文档篇幅×2:

| 双模式类型 | 现状 |
|-----------|------|
| 中英文符号 | `。`/`.`、`：`/`:`、`，`/`,` 全等价 |
| 有空格/无空格 | `设 甲 为 10` = `设甲为10` |
| 显式结束/缩进 | `结束。` 可选 |
| 有括号/无括号 | `《排序》(列表)` = `《排序》列表` |
| 段落/函数 | `段落`/`函数`/`段` 三个关键字并存 |
| 中文运算符/符号 | `加上`/`+`、`乘以`/`*` 并存 |
| 主谓/谓宾 | `列表排序` vs `排序列表` |
| 显式模式/简洁模式 | 元数驱动的双调用语法 |

### 1.3 v3.3 嵌入块的"投降"

v3.3 引入 `嵌入 Python:`/`嵌入 C:` 块,本质是**投降**——承认光明语法不够用,得借外文。这违背了"中文编程"的初衷,且给学习者传递了"光明做不到的事就嵌入外文"的负面信号。

### 1.4 关键字反复变更

从 v1.4 到 v3.3,关键字反复变更:
- `段` → `段落` → `函数`
- `设` → `定义` → `设`
- `若` → `如果` → `若`
- `为` → `等于` → `为`

每次变更都导致迁移成本和文档维护成本,**字不稳定,语言就无法积累生态**。

## 第二部分:中文的真正启示

### 2.1 类比的正确解读

3000常用字处理所有学科,这一现象的**正确启示**不是"字少",而是"分层+共享":

| 中文现象 | 启示 |
|---------|------|
| 3000字稳定不变,组合出百万词 | **字是稳定的,组合是灵活的** |
| 数学用 `3+5=8`,化学用 `H₂O`,音乐用 `1 2 3` | **不翻译专业符号,直接吸收** |
| 白话文、文言文、公文、诗歌共存 | **不同文体适应不同场景,共享同一套字** |
| 同一篇文章可混合白话+文言+公式 | **文体可混用,靠语境消歧** |
| "打"字有20+含义,但读者从不困惑 | **语境消歧,而非语法消歧** |

### 2.2 光明当前违背的原则

- 试图用**一套语法**包打天下(没有文体之分)
- 试图**翻译一切**(`加上`代替`+`、`嵌入 Python:`代替直接写)
- 双模式制造歧义,而非用语境消歧
- 关键字反复变更,字不稳定

## 第三部分:分层架构总览

### 3.1 五层架构

```
┌─────────────────────────────────────────┐
│  L4 外语引用层  (Python/C/Go/MoonBit)   │  ← 引语言:块,数据级互操作
├─────────────────────────────────────────┤
│  L3 领域嵌入层  (SQL/正则/数学/JSON)    │  ← 融入表达式,无需引块
├─────────────────────────────────────────┤
│  L2 文言体      (商用/工程/大型项目)    │  ← 类型+模块+类
├─────────────────────────────────────────┤
│  L1 白话体      (青少年/教学/脚本)      │  ← 无类型,简洁
├─────────────────────────────────────────┤
│  L0 核心字表    (约25个单字,永不变化)   │  ← 光明的"汉字"
└─────────────────────────────────────────┘
```

### 3.2 设计原则

1. **字稳定(L0)**:核心字表永不变化,这是光明的"汉字",所有文体共享
2. **体分层(L1/L2)**:不同场景用不同文体,各自优化,不强求统一
3. **域吸收(L3)**:领域 DSL(SQL/正则/数学)直接融入表达式,无需标记
4. **语引用(L4)**:完整编程语言(Python/C/Go)用 `引 语言:` 块,数据级互操作
5. **可混用**:同一项目可混合L1/L2/L3/L4,靠文体声明和语境消歧
6. **冻结关键字**:停止反复变更,L0核心字确定后不再修改

### 3.3 L3 与 L4 的本质区别

虽然 L3 和 L4 都涉及"非光明原生"的语法,但二者本质不同,必须分层:

| 维度 | L3 领域嵌入(吸收型) | L4 外语引用(引用型) |
|------|-------------------|-------------------|
| 性质 | 表达特定领域问题的符号系统 | 表达任意计算的通用语言 |
| 中文对应 | 数学公式、化学方程式、五线谱 | 英语、日语、法语(外语) |
| 与光明关系 | **补充**(光明不擅长的领域) | **平级**(另一种通用语言) |
| 嵌入目的 | 表达领域逻辑 | 复用生态/性能/平台 |
| 作用域 | 表达式级别,返回值 | 完整程序单元,可定义函数/类/模块 |
| 边界 | 无缝融入,无需标记 | 需要明确引用边界(`引 语言:`) |
| 互操作 | 数据进出,表达式求值 | 数据级:参数传入/返回值传出 |
| 实现机制 | 词法扩展/解析器识别 | FFI/解释器嵌入/编译加载 |

**分层准则**:本质不同就分层。内部双模式是妥协,分层是原则。

## 第四部分:L0 核心字表

### 4.1 核心字表(30字)

这是光明的"偏旁部首",**永不变化**。

**重要原则**:L0 是**全集合**(L1∪L2),L1 白话体只使用其中子集,L2 文言体使用全集。`类/承/接/配` 等字在 L0 中,但 L1 不使用——这不矛盾,L0 定义的是"光明所有可用字",而非"每个文体必须用的字"。

#### 控制流(7字)
| 字 | 用途 | 示例 |
|----|------|------|
| `若` | if | `若甲>5:打印甲` |
| `否` | else | `否:打印"小"`;`否若`组合=elif |
| `当` | while/for | `当甲<10:甲+=1` |
| `遍` | foreach | `遍列表之为i:打印i` |
| `跳` | break | `跳` |
| `过` | continue | `过` |
| `返` | return | `返甲+乙` |

#### 定义与类型(6字)
| 字 | 用途 | 示例 | L1 |
|----|------|------|----|
| `设` | let/var | `设甲=10` | ✓ |
| `段` | fn/def | `段加法(甲,乙)` | ✓ |
| `类` | class/type | `类学生:` | ✗ |
| `承` | extends | `类大学生承学生:` | ✗ |
| `接` | interface/trait | `接可打印:` | ✗ |
| `配` | match | `配甲之于:1:...否:...` | ✗ |

#### 异常(4字)
| 字 | 用途 | 示例 | L1 |
|----|------|------|----|
| `试` | try | `试:...` | ✓ |
| `捕` | catch | `捕错误:...` | ✓ |
| `抛` | throw | `抛"无效输入"` | ✓ |
| `终` | finally | `终:清理()` | ✓ |

#### 自指与连接(5字)
| 字 | 用途 | 示例 | L1 |
|----|------|------|----|
| `自` | self/this | `自.姓名` | ✗(L1无类) |
| `之` | 属性访问/所属 | `列表之首` | ✓ |
| `并` | 管道/并列 | `数据并过滤并排序` | ✓ |
| `从` | 来源/导入 | `从数学导入sqrt` | ✓ |
| `是` | 相等/类型判断 | `甲是10`;`甲是学生` | ✓ |

#### 逻辑与值(6字)
| 字 | 用途 | 示例 |
|----|------|------|
| `且` | and | `甲>0且乙>0` |
| `或` | or | `甲>10或乙>10` |
| `非` | not | `非甲` |
| `真` | true | - |
| `假` | false | - |
| `空` | null/none | - |

#### 组织(2字)
| 字 | 用途 | 示例 | L1 |
|----|------|------|----|
| `导` | import | `导数学` | ✓(仅内置模块) |
| `出` | export | `出加法` | ✗ |

### 4.2 字表设计依据

**对比主流语言**(详见 [关键字对比研究报告](#)):

| 语言 | 关键字数 | 光明 L0 定位 |
|------|---------|-------------|
| Lua | 22 | 光明多 8(有异常关键字族,Lua 用函数) |
| Go | 25 | 光明多 5(有 try/catch/finally,Go 用 defer) |
| Python | 35 | 光明少 5(单字紧凑,无类型关键字) |
| Rust | 58 | 光明少 28(无所有权/生命周期/unsafe) |

**30 字的合理性**:光明 L0 是 L1+L2 的并集,要同时覆盖"青少年教学"和"商用工程",注定比 Go 的 25 多(异常关键字),比 Python 少(单字紧凑)。这是分层架构的必然结果。

### 4.3 与旧版字表的变更说明

| 操作 | 字 | 原因 |
|------|---|------|
| 删除 | `则` | 用冒号/换行替代,非独立必需 |
| 删除 | `为` | 与 `设` 重叠(`设甲为10`→`设甲=10`) |
| 删除 | `有` | 与 `是`/`之` 组合可表达 |
| 删除 | `的` | 与 `之` 语义重叠 |
| 删除 | `入` | `导` 已含导入义,`入`是凑数辅助字 |
| 新增 | `终` | finally,异常三件套补全 |
| 新增 | `自` | self/this,类方法必需(旧示例已用未列入) |
| 新增 | `承` | 继承,OOP 必需(旧示例已用未列入) |
| 新增 | `接` | 接口/协议,L2 工程必需 |
| 新增 | `配` | 模式匹配,现代语言标配 |

净变化:-5+5=0,仍为 30 字。**修复了旧字表"示例用字未列入"和"类与L1矛盾"两个 bug**。

### 4.4 双字别名(可选,不强制)

双字形式作为**可选别名**存在,供习惯者使用,但**不是主形式**:

| 主形式(单字) | 别名(双字) |
|-------------|-----------|
| `若` | `如果` |
| `设` | `定义` |
| `返` | `返回` |
| `段` | `函数`/`段落` |
| `试` | `尝试` |
| `捕` | `捕获` |
| `抛` | `抛出` |
| `终` | `最终` |
| `自` | `自己` |
| `承` | `继承` |
| `接` | `接口` |
| `配` | `匹配` |
| `导` | `导入` |
| `出` | `导出` |

### 4.5 冻结承诺

**L0 核心字表自 v4.0 起冻结,永不变化**。

- 不再进行 `段落→函数` 这类变更
- 新增概念时,优先用核心字的组合,而非新增字
- 如确需新增核心字,需经过社区讨论和版本升级

这是中文3000字稳定不变的对应物。**字稳定,语言才能积累生态**。

## 第五部分:L1 白话体

### 5.1 定位

- **适用场景**:青少年教学、个人脚本、快速原型、少儿编程
- **特点**:无类型、无模块、无类、无空格、中文标点、单行优先
- **对应中文文体**:白话文

### 5.2 语法特征

| 特征 | L1 白话体 |
|------|----------|
| 标点 | 中文标点(`。：，；`) |
| 空格 | 可选,鼓励无空格 |
| 句号 | 可选 |
| 类型注解 | 不支持 |
| 模块系统 | 不支持 |
| 类定义 | 不支持 |
| 算术运算符 | 中文(`加减乘除`)+ 符号(`+ - * /`)均可 |
| 函数定义 | `段名(参数):` |
| 块结构 | 缩进 OR 单行 |
| 文件头 | `# 文体: 白话` |

### 5.3 示例

**示例1:Hello World**
```light
# 文体: 白话
打印"你好,世界!"
```

**示例2:条件判断**
```light
设甲=10
若甲大于5:打印"大"否:打印"小"
```

**示例3:遍历求和**
```light
设成绩=[85,92,78,63,95]
设总分=0
遍成绩之为s:
    若s大于60:总分+=s
打印"总分:"并总分
```

**示例4:函数定义**
```light
段阶乘(n):
    若n<=1:返1
    返n*阶乘(n-1)
打印阶乘(5)
```

**示例5:因果链语法(白话体特色)**
```light
温度大于30,开风扇
温度大于30且湿度大于60,开风扇、开空调
```

### 5.4 L1 设计哲学

- **单行优先**:能用一行表达就一行
- **因果链**:`条件,动作` 的自然表达
- **主谓宾语序**:`列表,排序,打印` 管道式
- **无类型负担**:不要求类型注解,运行时动态
- **容错性强**:句号、空格、冒号都可选

## 第六部分:L2 文言体

### 6.1 定位

- **适用场景**:商用项目、库开发、团队协作、性能关键代码、大型工程
- **特点**:类型注解、模块系统、类、缩进、英文符号(可选中文)
- **对应中文文体**:文言文/公文

### 6.2 语法特征

| 特征 | L2 文言体 |
|------|----------|
| 标点 | 英文标点(`. : , ;`),可选中文 |
| 空格 | 必须有空格(关键字与标识符之间) |
| 句号 | 可选 |
| 类型注解 | 强烈推荐,可选强制 |
| 模块系统 | 完整支持 |
| 类定义 | 完整支持 |
| 算术运算符 | 符号(`+ - * / %`)为主 |
| 函数定义 | `段 名(参数: 类型) -> 类型:` |
| 块结构 | 缩进(强制) |
| 文件头 | `# 文体: 文言` |

### 6.3 示例

**示例1:类型化函数**
```light
# 文体: 文言
段 加法(甲: 数, 乙: 数) -> 数:
    返 甲 + 乙
```

**示例2:类与继承**
```light
# 文体: 文言
类 学生:
    设 姓名: 串
    设 年龄: 数
    设 成绩: 列[数]
    
    段 平均分(自) -> 数:
        若 长度(自.成绩) == 0:
            返 0
        返 和(自.成绩) / 长度(自.成绩)

类 大学生 承 学生:
    设 专业: 串
    
    段 简介(自) -> 串:
        返 自.姓名 + "," + 串(自.年龄) + "岁," + 自.专业
```

**示例3:模块导出**
```light
# 文体: 文言
# 文件: 数学工具.light
出 加法, 乘法

段 加法(甲: 数, 乙: 数) -> 数:
    返 甲 + 乙

段 乘法(甲: 数, 乙: 数) -> 数:
    返 甲 * 乙
```

**示例4:模块导入**
```light
# 文体: 文言
从 数学工具 导 加法, 乘法

设 结果 = 加法(3, 5) + 乘法(2, 4)
打印 结果
```

**示例5:异常处理(含终)**
```light
# 文体: 文言
段 除法(甲: 数, 乙: 数) -> 数:
    若 乙 == 0:
        抛 ValueError("除数不能为零")
    返 甲 / 乙

试:
    设 结果 = 除法(10, 0)
捕 ValueError 是 e:
    打印 "错误:", e
终:
    打印 "计算结束"
```

**示例6:模式匹配(配)**
```light
# 文体: 文言
段 评级(分数: 数) -> 串:
    配 真:
        情况 分数 >= 90: 返 "优"
        情况 分数 >= 60: 返 "及格"
        其他: 返 "不及格"

设 等级 = 评级(85)
```

> 口径（v7 单 J 裁定）:分支词只有 `情况`,默认分支写 `其他`（`否`/`否则` 同义）,
> `配` 后面不跟 `之`。`若` 只能作守卫（`情况 模式 若 条件:`）,不能当分支词。
> 早期文档的 `配 X 之: / 若 分支` 写法从未被 parser 支持,照那样写会 ParseError。


### 6.4 L2 设计哲学

- **显式优于隐式**:类型、参数、返回值都明确
- **符号优于文字**:算术用 `+ - * /`,这是国际通用,中文文章里也这样写
- **缩进强制**:块结构清晰,适合大文件
- **静态检查**:支持类型检查器,IDE 友好
- **工程化**:模块、可见性、错误处理完善

## 第七部分:L3 领域嵌入层

### 7.1 核心理念:吸收,而非翻译

L3 层的领域 DSL(领域特定语言)**直接融入光明表达式**,像中文文章里写"3+5=8"一样自然,无需任何嵌入标记。

中文文章里出现 `H₂O`、`3+5=8`、`SELECT * FROM users` 都不需要特殊标记,光明也应该如此。

### 7.2 支持的领域 DSL

#### 7.2.1 数学公式

```light
# 数学符号直接写,作为光明表达式
设 甲 = 3 + 5 × √2
设 面积 = π × r²
设 解 = (-b ± √(b² - 4ac)) / (2a)
```

#### 7.2.2 正则表达式

```light
设 模式 = /\d{4}-\d{2}-\d{2}/
若 日期 匹配 模式:
    打印 "合法日期"
```

#### 7.2.3 SQL(中文结构化,直接作为表达式)

```light
# 中文结构 SQL,无需引块
设 结果 = 从 users 选择 * 当 age > 18 排序 by name
设 计数 = 从 users 计数(*) 当 status == "active"
```

#### 7.2.4 JSON/字典字面量

```light
设 配置 = {
    "host": "localhost",
    "port": 8080,
    "debug": 真
}
```

### 7.3 L3 的实现机制

- **词法层**:识别特定模式的 token(如 `/.../ ` 为正则,`{...}` 为 JSON)
- **语法层**:扩展表达式语法,支持领域 DSL 作为子表达式
- **求值层**:调用对应的领域引擎(SQL 引擎、正则引擎、数学库)

### 7.4 L3 的边界

L3 **只处理表达式级别的领域 DSL**。如果需要嵌入完整的编程语言(定义函数、类、模块),那属于 L4 外语引用层的范畴。

## 第八部分:L4 外语引用层

### 8.1 核心理念:引用,而非投降

L4 层用于引用 Python/C/Go/MoonBit 等**完整编程语言**。语义是"像引用古文/外语一样引用外部代码"。

**光明引用外语,不是因为光明做不到,而是因为复用现有生态更高效**——就像中文文章引用英文文献不是因为中文表达不了,而是直接引用更准确。

### 8.2 `引` vs `嵌入` 的语义差异

| 关键字 | 语义 | 心理暗示 |
|--------|------|---------|
| `嵌入` | 光明做不到,塞进去 | 投降 |
| `引` | 像引用古文/外语一样引用 | 自然 |

`引` 是中文本来就有的概念(引经据典、引用),语义更准确,不会给学习者传递"光明不够用"的负面信号。

### 8.3 支持范围(分阶段)

| 阶段 | 语言 | 互操作方式 | 典型场景 |
|------|------|-----------|---------|
| **v4.0 优先** | Python | 解释器嵌入 | 生态复用(numpy/pandas等) |
| **v4.0 优先** | C | FFI 编译加载 | 性能关键、系统调用 |
| 后续 | Go | cgo / RPC | 并发、云原生生态 |
| 后续 | MoonBit | 编译到 WASM/原生 | 性能、类型安全、WASM |
| 后续 | Rust | FFI | 性能、内存安全 |

### 8.4 语法:`引 语言:` 块

```light
引 语言名:
    <该语言的原始代码>
```

### 8.5 数据级互操作机制

**核心原则**:不共享作用域,通过"定义 + 调用"实现数据级互操作。

**两步模式**:
1. `引 语言:` 块**定义**该语言的函数/代码
2. 光明通过 `语言名.函数名(参数)` **调用**,参数传入,返回值传出

```light
# 步骤1:定义 Python 函数
引 Python:
    import numpy as np
    def 求均值(数据):
        arr = np.array(数据)
        return float(arr.mean())

# 步骤2:光明调用,数据级互操作
设 数据 = [1, 2, 3, 4, 5]
设 结果 = Python.求均值(数据)
打印 结果   # 输出: 3.0
```

```light
# 步骤1:定义 C 函数
引 C:
    int 快速求和(int* arr, int n) {
        int s = 0;
        for (int i = 0; i < n; i++) s += arr[i];
        return s;
    }

# 步骤2:光明调用
设 数组 = [1, 2, 3, 4, 5]
设 总和 = C.快速求和(数组, 长度(数组))
打印 总和   # 输出: 15
```

### 8.6 单步模式(表达式级引用)

对于简单的"一次性"引用,支持 `引 语言:` 作为表达式,块内最后一行作为返回值:

```light
# Python 单步引用
设 结果 = 引 Python:
    import numpy as np
    arr = np.array([1, 2, 3, 4, 5])
    arr.mean()   # 最后一行作为返回值
打印 结果   # 3.0

# C 单步引用(需绑定入口)
设 总和 = 引 C:
    int sum(int* arr, int n) {
        int s = 0;
        for (int i = 0; i < n; i++) s += arr[i];
        return s;
    }
    sum({1,2,3,4,5}, 5)   # 最后一行作为返回值
打印 总和   # 15
```

### 8.7 互操作的数据类型映射

光明与引用语言之间的数据转换自动处理:

| 光明类型 | Python | C | Go | MoonBit |
|---------|--------|---|----|--------|
| 数 | int/float | int/double | int64/float64 | Int/Double |
| 串 | str | char* | string | String |
| 列 | list | 数组指针 | []T | Array[T] |
| 典 | dict | struct* | map[K]V | Map[K,V] |
| 真/假 | True/False | int(1/0) | bool | Bool |

复杂类型(自定义类、闭包)不自动转换,需在引用块内序列化或用 FFI 手动绑定。

### 8.8 引用块的作用域与生命周期

- `引 语言:` 定义的全局函数在整个文件可见
- 定义在 `段` 内的引用函数,生命周期与段一致
- **不共享光明作用域**:引用块内不能直接读写光明变量,只能通过参数传入/返回值传出
- 避免了"作用域共享"带来的调试困难和语义歧义

### 8.9 L4 的战略定位

L4 让光明成为**中文编程生态的枢纽**:

- 青少年学 L1 → 入门
- 工程师用 L2 → 商用
- 需要性能 → `引 C:` 或 `引 MoonBit:`
- 需要生态 → `引 Python:`
- 需要并发 → `引 Go:`(后续)

**光明不必在性能/生态上重复造轮子**,专注做好"中文表达 + 分层架构 + 外语枢纽"。这是光明区别于其它中文编程语言的**杀手锏**。

## 第十一部分:迁移路径

### 11.1 短期(不破坏现有代码)

#### 11.1.1 冻结关键字表

- 停止 `段落→函数` 这类变更
- `段`/`函数`/`段落` 三个别名永远共存
- v4.0 文档明确声明:L0 核心字冻结

#### 11.1.2 单字关键字回归

- 将 `若`、`设`、`返`、`段`、`试`、`捕`、`抛` 设为主形式
- 双字形式保留为别名,不报错
- 更新文档和示例,推荐用单字

#### 11.1.3 算术符号化

- 将 `+ - * / % ** //` 设为主形式
- `加上/减去/乘以/除以` 降级为可选别名
- 现有代码不报错,继续工作

**以上改动不破坏任何现有 .light 文件**。

### 11.2 中期(架构调整)

#### 11.2.1 引入文体声明

- 解析器识别 `# 文体: 白话` / `# 文体: 文言`
- 按文体采用不同默认规则(标点、空格、句号)
- 无声明时默认白话体

#### 11.2.2 嵌入→引用(L4)

- `嵌入 Python:` 改为 `引 Python:`(两步模式:定义 + `Python.函数()` 调用)
- `嵌入 C:` 改为 `引 C:`(FFI 编译加载 + `C.函数()` 调用)
- 互操作改为**数据级**(参数传入/返回值传出,不共享作用域)
- 旧语法保留为别名,触发 deprecation warning
- Go/MoonBit/Rust 作为后续扩展,初期不实现
- 文档更新

#### 11.2.3 领域DSL一等公民(L3 吸收型)

- SQL、正则、数学公式作为内置 DSL
- 不需要 `引` 块,直接写
- 解析器识别特定模式

### 11.3 长期(生态建设)

#### 11.3.1 L1教学版编译器

- 独立的极简解析器,只支持L1白话体
- 错误信息更友好(面向青少年)
- 内置教学示例和练习

#### 11.3.2 L2工程版编译器

- 完整版,支持所有特性
- 类型检查器
- 性能优化(LLVM后端)

#### 11.3.3 两版共享L0

- 两个版本共享 L0 核心字表
- 像简体中文和繁体中文共享汉字
- L1 代码可被 L2 项目导入,L2 库可被 L1 脚本调用

### 12.1 同一问题的不同文体表达

**问题**:计算列表中大于平均值的元素之和

#### L1 白话体
```light
# 文体: 白话
设数据=[3,1,4,1,5,9,2,6]
设平均=数据和/数据长
设结果=0
遍数据之为x:
    若x大于平均:结果+=x
打印结果
```

#### L2 文言体
```light
# 文体: 文言
段 大于平均之和(数据: 列[数]) -> 数:
    设 均值: 数 = 和(数据) / 长度(数据)
    设 结果: 数 = 0
    遍 数据 之为 x:
        若 x > 均值:
            结果 += x
    返 结果

设 数据 = [3, 1, 4, 1, 5, 9, 2, 6]
打印 大于平均之和(数据)
```

#### L4 引用型(Python 生态复用)
```light
# 文体: 文言
引 Python:
    import numpy as np
    def 大于平均之和(数据):
        arr = np.array(数据)
        均值 = arr.mean()
        return int(arr[arr > 均值].sum())

设 数据 = [3, 1, 4, 1, 5, 9, 2, 6]
设 结果 = Python.大于平均之和(数据)
打印 结果
```

类 学生:

## 第十三部分:设计原则总结

### 13.1 六大原则

1. **字稳定原则**:L0 核心字表永不变化,这是中文3000字的对应物
2. **体分层原则**:不同场景用不同文体,各自优化,不强求统一
3. **域吸收原则**:L3 专业符号直接吸收,不翻译,不嵌入
4. **语引用原则**:L4 完整编程语言用 `引` 块引用,数据级互操作
5. **语境消歧原则**:同一字在不同文体有不同表现,靠文体声明消歧
6. **渐进迁移原则**:不破坏现有代码,新旧并存,逐步引导

### 13.2 与中文的对应

| 中文 | 光明 |
|------|------|
| 3000常用字 | L0 核心字表(约25字) |
| 白话文 | L1 白话体 |
| 文言文/公文 | L2 文言体 |
| 数学公式/化学方程式 | L3 领域嵌入 |
| 英语/日语(外语) | L4 外语引用 |
| 字稳定不变 | 核心字冻结承诺 |
| 字组合成词 | 核心字组合成关键字 |
| 不同文体共享字 | L1/L2 共享 L0 |
| 文章可混用文体 | 项目可混用文体 |
| 引经据典 | `引 语言:` 引用块 |

## 第十四部分:开放问题

### 14.1 待讨论

1. **L1 是否支持类?** 当前设计不支持,但教学场景可能需要简化版
2. **L2 的类型系统强度?** 推荐还是强制?是否支持泛型?
3. **L3 吸收型的 DSL 范围?** SQL/正则/数学之外,是否支持 HTML/CSS 等?
4. **L4 引用型的语言范围?** Python+C 优先,Go/MoonBit/Rust 何时跟进?
5. **文体声明位置?** 文件头注释 vs package.toml vs 文件扩展名(`.light` vs `.light-lite`)?
6. **L1 和 L2 的互操作?** L1 脚本调用 L2 库时,类型如何处理?
7. **L4 引用型的错误处理?** 引用块内的 Python/C 异常如何传播到光明?
8. **L4 引用型的并发安全?** 多个 `引 Python:` 块并发调用时,解释器状态如何隔离?

### 14.2 已决策(v4.0 确认)

- ✅ 五层架构:L0/L1/L2/L3/L4 彻底分层
- ✅ L3(吸收型)与 L4(引用型)分开,不混层
- ✅ L4 引用型优先支持 Python + C,Go/MoonBit/Rust 后续
- ✅ L4 引用型采用数据级互操作(参数传入/返回值传出,不共享作用域)
- ✅ `引` 取代 `嵌入` 作为 L4 关键字

## 结语

光明的破局之道,不在于"一套语法更简单"或"一套语法更强大",而在于**像中文一样**:

- **字**(L0核心字)极少且稳定
- **文体**(L1白话/L2文言)分层但不分裂,共享字
- **领域**(L3数学/SQL/正则)直接吸收,不翻译,不嵌入
- **外语**(L4 Python/C/Go)用 `引` 块引用,数据级互操作

这是中文3000字处理所有学科的真正智慧。光明 v4.0 将这一智慧落地为可工程化的语言设计。
