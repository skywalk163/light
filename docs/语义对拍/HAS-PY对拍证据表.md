## 1. 口径

### 1.1 候选定义

HAS-PY = stdlib 里「**同名 `.light` 与 `.py` 同时存在**」的模块，且 `.light` **无魔数**
（首两行不含「纯光明实现」）。魔数判定 `_是纯光明` 与 `tools/ci/bootstrap_rate.py:338`
及 `stdlib/_light_import_hook.py::_is_pure_light` 同口径（读 `fh.readline()+fh.readline()`）。

### 1.2 递归口径（含子目录）

R122 原脚本用 `os.listdir` 只扫顶层，漏了 `stdlib/分布式/` 子目录。R122 修订版与
本表均用 `os.walk` 递归扫 `stdlib/`（排除 `__pycache__`）。**38 = 顶层 37 + 分布式 1（节点网络）**。

### 1.3 四类证据

1. **实现体存在性**：`.light` 是否有顶层 `段落`/`类` 定义（区分「真实现」与「纯导出清单」）；
2. **导出面差异**：`.light` 的 `导出 X Y Z。` 清单 vs `.py` 顶层公开符号（优先 `__all__`）；
3. **规模比**：两侧行数；
4. **行为对拍**：把 `.light` 复制到**临时目录**（临时目录里没有同名 `.py`）→ 钩子**必然加载
   那一份 `.light`，再与 `import <名>`（读 `.py`）逐用例双跑对比。**每次对拍在独立子进程**
   （避免 `sys.modules` 污染），输出归一化 JSON。

### 1.4 分类判定

| 术语 | 判定 |
|---|---|
| 真实现 | `.light` 有顶层 `段落`/`类`（段落数 + 类数 > 0） |
| 纯清单 | `.light` 无实现体（0 段落 0 类） |
| 导出面一致 | `.light` 导出集合 == `.py` 公开符号集合 |
| 行为等价 | 双跑逐用例 `(状态, 值)` 全等（随机/时间类用例**已按可复现口径**归一化：播种同种子、`时间戳` 只比类型不比绝对值） |
| 差异属于 | **设计边界**（`.light` 简化了语义）/ **真实缺陷**（两边都不对）/ **未定** |

## 3. 9 个真实现模块逐条分析（本轮复跑）

> 本轮复跑（2026-10-08）与 R122 相比，**`节点网络` 的 15 项用例全部对齐**（见 §3.1），
> 其余 8 个仍有行为差异。差异**根因高度集中**：8 个里 6 个崩在同一个
> **Python 腿内建缺陷族 —— `追加` 语义冲突**（`method_name_map['追加']='append'` vs
> `'追加': '_light_builtin.追加'`，后者是 `stdlib/builtins.py` 的**文件打开标志常量**
> （`def 追加() -> int` 返回 `os.O_APPEND`，零参）。`.light` 把 `追加(结果, 当前)` 当
> **列表追加**调用，而 codegen 却把它当**文件打开标志**发射 ⇒ 两实参 → `TypeError`。
> 这是 **R122 §2.4 注** 已定位的缺陷，**R123/R124 未修**（R123 只修了 `节点网络` 的 `截取`
> 族与跨腿内建名，R124 修了原生腿 `dv_isinstance`）——**登记不改**，留后续正确性轮。

## 4. 白名单 = ∅ 的结论

### 4.1 结论原文

**HAS-PY 语义等价白名单 = ∅（空集）**：38 个「非魔数 + 有同名 `.py`」模块，**无一语义等价**。
**翻面（= 让简化 `.light` 顶掉 `.py`）会把原生腿红带进在线路径**，与 R123 §9.2 第 2 条一致
（R123 §9.2 第 2 条原文：「不主张 B1 让 `节点网络` 可翻面了」—— `节点网络` HAS-PY（有同名 `.py`）
+ `.light` 无魔数 ⇒ 翻面 = 让简化传输层顶掉 `.py`，会把原生腿红带进在线路径）。

### 4.2 分层理由

| 层 | 数量 | 为什么不能翻 |
|---|---|---|
| **纯清单（stub）** | **29** | `.light` 0 段落 0 类，**翻面 = 100% 破坏 Python 腿**（导出名全部取不到，实现在 `.py`）。与 `stdlib/_light_import_hook.py` 文件头自述一致：「`.py` 优先……`.light` 在那种情况下只是清单，不是实现」。 |
| **真实现 · 行为仍不等价** | **8** | `对象池缓存`/`时间管理`/`网络请求`/`身份证校验`/`随机`/`集合`/`集合工具`/`集合操作` 仍有差异（见 §3.2–§3.9），其中 6 个崩于同一个未修的 Python 腿 `追加` 缺陷族。翻面 = 把这批差异**直接带进在线路径**。 |
| **真实现 · 本轮已对齐** | **1** | `节点网络`（§3.1）本轮复跑 15/15 对齐。但仅**Python 腿**对齐，**原生腿**该模块的语义等价性尚未对拍；且 `.light` 在原生腿可编，翻面会替换原生腿的在线实现。**仍不主张翻面**。 |

### 4.3 交叉校验（防成员/总数不自洽）

```
38 = 真实现 9 + 纯清单 29              ← 按「有无实现体」分组
38 = 导出面一致 30 + 导出面不同 8       ← 按「导出面」分组
9  = 一致 4 + 不同 5                   ← 真实现内细分
29 = 一致 26 + 不同 3                  ← 纯清单内细分
可安全翻面 = 0                          ← 结论
```
