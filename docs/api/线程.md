> 模块路径：`stdlib/线程.py`（门面 `stdlib/线程.light`）
> 导入方式：`从 线程 导入 互斥锁, 可重入锁, 创建线程` 或 `导入 线程`

**本文 2026-10-29 整篇重写。** 原文档描述的是一套**函数式 API**——
`创建互斥锁()` / `互斥锁锁定(锁)` / `分离线程(线程)` / `创建信号量(初始值)` / `条件变量阻塞(...)`
—— **这些函数在 `stdlib/线程.py` 里一个都不存在**，照着写必然 `ImportError`。

## 互斥锁 / 可重入锁

```
从 线程 导入 互斥锁, 可重入锁

设 锁 为 互斥锁()
锁.加锁()
锁.释放()

设 递归锁 为 可重入锁()      # 等价于 互斥锁(可重入 = 真)
递归锁.加锁()
递归锁.加锁()                # 同一线程可重复加锁
递归锁.释放()
递归锁.释放()
```

| 成员 | 说明 |
|---|---|
| `互斥锁(可重入 = 假)` | 构造；`可重入=真` 时底层用 `RLock` |
| `加锁(阻塞 = 真, 超时 = -1)` | 加锁；`超时` 单位秒，`-1` 表示无限等 |
| `释放()` / `解锁()` | 释放（`解锁` 是别名） |
| `已锁定()` | 是否处于锁定状态 |

### ⚠️ LH-24：不可重入锁重复加锁**会立即报错**

> **这是 2026-10-29 的行为变更。** 在此之前，同一线程对 `互斥锁()` 二次加锁会
> **永久阻塞、无异常、无日志** —— 写「每个公开方法都加锁、方法之间互相调用」这种
> 最常见写法时必然踩到，排查成本极高（进程挂起，什么都看不到）。

现在的行为：

```
从 线程 导入 互斥锁
设 锁 为 互斥锁()
锁.加锁()
锁.加锁()      # RuntimeError: 互斥锁：同一线程重复加锁会永久卡死（这是不可重入锁）。
               #              要么把加锁/释放配成对，要么改用可重入锁：`互斥锁(可重入=真)` 或 `可重入锁()`
```

**迁移建议**：方法之间会互调的类，锁一律用 `可重入锁()`；
确实需要「非本线程等待」的互斥语义才用 `互斥锁()`。

## 线程

```
从 线程 导入 创建线程

段落 干活(名字):
  打印 名字

设 t 为 创建线程(干活, "甲", 名称 = "工一", 守护线程 = 假)
t.开始()
t.等待(2.0)              # 有超时；超时返回 假
打印 转字符串(t.是否完成())
```

| 成员 | 说明 |
|---|---|
| `创建线程(函数, *参数, 名称=空, 守护线程=假)` | 创建（不自动启动） |
| `开始()` | 启动 |
| `等待(超时=空)` / `join(超时=空)` | 等结束，返回是否在超时内结束 |
| `是否存活()` / `是否完成()` | 状态 |
| `获取结果(超时=空)` | 取目标函数返回值 |
| `获取异常()` | 取目标函数抛出的异常（没有则 `空`） |

## 事件 / 信号量 / 队列 / 线程池

```
从 线程 导入 事件, 信号量, 线程安全队列, 线程池

设 e 为 事件()
e.设置()          # 也有 是否已设置()（同 是否设置()）/ 清除() / 等待(超时)

设 s 为 信号量(2)  # 构造参数是初始计数
s.获取()
s.释放()

设 q 为 线程安全队列()
q.入队("甲")
打印 q.出队()

设 p 为 线程池()   # 线程池(最大线程数) 可选
p.启动()
p.提交(干活, "乙")
p.等待完成()
p.关闭()
```

## 并发执行

```
从 线程 导入 并发执行, 并发执行带参数

设 结果 为 并发执行([甲, 乙, 丙])                 # 三个无参函数并行
设 结果2 为 并发执行带参数(干活, [["甲"], ["乙"]])  # 同一函数、不同参数
```

返回顺序与入参顺序一致（不是完成顺序）。

## 已知缺口

- **没有条件变量**（`Condition`）：原文档里的 `创建条件变量` / `条件变量阻塞` / `条件变量通知`
  从未实现。需要「等某个条件成立」时用 `事件` + 轮询，或直接用 `导入 threading` 走 FFI。
- **没有 `分离线程` / `获取线程号` / `线程让出`**：分别用 `守护线程 = 真`、
  `当前线程标识()`、`线程休眠(0)` 代替。
