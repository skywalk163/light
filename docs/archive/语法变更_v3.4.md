# 段言语法变更 v3.4

**版本**：v3.4
**日期**：2026-08-04
**状态**：正式版
**基于**：v3.3 统一语法规范

---

## 概述

本次变更围绕"降低繁琐感"展开，聚焦三个初学者痛点：

1. **P0：句号可选化** — 消除语句末尾强制句号的最大单点摩擦
2. **P1：教程主推 `令 x = 值`** — 推广简洁赋值写法，降低入门门槛
3. **P2：运算符符号写法推广** — `a + b` 与 `a 加上 b` 等价，教程中主推符号写法

核心思路：语法骨架已成型不需大改，真正阻塞使用体验的是具体摩擦点——句号强制、赋值冗余、运算符冗余。

## 1. 句号可选化（P0）

### 1.1 背景

段言要求每条语句末尾加中文句号「。」，这对初学者是最大的单点摩擦——写每行代码都要想着加句号，遗漏则报错。

### 1.2 变更内容

句号「。」在语句末尾变为**可选**，不再强制要求：

```
# 以下两种写法等价
令 x = 1。
令 y = 2

# 混合使用也合法
令 a = 10。
令 b = 20
打印 a
```

### 1.3 实现细节

句号在 parser 层面已经是条件性消耗（所有 `PERIOD` token 消耗都是 `if ... == TokenType.PERIOD` 判断）。本次修复的是两个实际阻塞点：

**属性赋值修复**：

`obj.attr = value` 之前报错"赋值需要使用「设」关键字"。根因是 `_parse_assignment_stmt` 在消耗标识符后未处理 `TokenType.DOT` 分支。

修复：在 `parser_stmt.py` 的 `_parse_assignment_stmt` 方法中新增 `TokenType.DOT` 分支，构建 `MemberAccess(Identifier(name), attr_name)` 作为 `Assignment` 目标，支持三种写法：
- `obj.attr = value`
- `obj.attr 等于 value`
- `obj.attr 为 value`

**错误消息修复**：

| 位置 | 旧消息 | 新消息 |
|------|--------|--------|
| `parser_core.py` `_generate_hint` | "请检查是否缺少语句结尾的句号" | "句号「。」是可选的，不需要每句末尾都加" |
| `parser_stmt.py` 裸 `=` 报错 | "赋值需要使用「设」关键字" | "赋值需要使用「设」或「令」关键字" |

### 1.4 向后兼容

已有句号写法完全兼容，不产生废弃警告。句号从"强制"变为"可选"，旧代码无需任何迁移。

## 2. 教程主推 `令 x = 值`（P1）

### 2.1 背景

段言有两种赋值写法：
- `设 X 为 Y` — 中文风格，语义清晰但较冗长
- `令 x = 值` — 简洁风格，接近主流语言习惯

教程此前以 `设 X 为 Y` 为主，初学者需要多写一个词。

### 2.2 变更内容

`docs/30分钟入门段言.md` 全面更新，主推 `令 x = 值` 简洁写法：

**第 2 章（变量与赋值）**：
- 主推 `令 x = 值`，保留 `设 X 为 Y` 作为中文风格对照
- 新增"句号可选"说明

**第 6 章（函数）**：
- 主推 `函数 name(params):` C 风格定义
- `段落` 作为中文风格对照保留

**第 4-12 章**：
- 所有示例从 `设 X 为 Y` 改为 `令 X = Y`
- `print` 统一为 `打印`

### 2.3 示例对比

**旧教程风格**：
```
设 甲 为 10。
设 乙 为 20。
打印 甲 加 乙。
```

**新教程风格**：
```
令 甲 = 10
令 乙 = 20
打印 甲 + 乙
```

### 2.4 向后兼容

`设 X 为 Y` 语法完全保留，不做废弃处理。教程中作为"中文风格对照"出现，用户可自由选择。

## 3. 运算符符号写法推广（P2）

### 3.1 背景

v3.3 已在 lexer/parser 层面实现符号运算符（`+ - * / % ** // == != < > <= >=`），但教程中仍以中文运算符为主，初学者不知道符号写法可用。

### 3.2 变更内容

教程中运算符示例全部改为**符号写法为主**，中文写法作为等价对照：

**第 3 章（运算符）**：

| 运算 | 符号写法（主推） | 中文写法（等价） |
|------|------------------|------------------|
| 加法 | `a + b` | `a 加 b` |
| 减法 | `a - b` | `a 减 b` |
| 乘法 | `a * b` | `a 乘 b` |
| 除法 | `a / b` | `a 除以 b` |
| 整除 | `a // b` | `a 整除 b` |
| 取余 | `a % b` | `a 模 b` |
| 幂运算 | `a ** b` | `a 幂 b` |
| 等于 | `a == b` | `a 等于 b` |
| 不等 | `a != b` | `a 不等于 b` |
| 小于 | `a < b` | `a 小于 b` |
| 大于 | `a > b` | `a 大于 b` |
| 小于等于 | `a <= b` | `a 小于等于 b` |
| 大于等于 | `a >= b` | `a 大于等于 b` |

### 3.3 混合运算

符号与中文运算符可自由混用：

```
令 a = 3 + 5
如果 a 大于 5:
    打印 "yes"
```

### 3.4 额外修复：一元负号

代码生成器中一元负号的输出格式从 `(- 5)` 修正为 `(-5)`：

```python
# 修复前
return f"({op} {operand})"    # → (- 5)

# 修复后
return f"({op}{operand})"     # → (-5)
```

## 6. 设计决策记录

### 6.1 为什么不做"句号废弃"

句号在长程序中有可读性价值——它像中文的自然断句。因此选择"可选"而非"废弃"，让用户按偏好选择。

### 6.2 为什么主推 `令` 而非 `设`

`令 x = 值` 更接近主流编程语言的 `x = value` 习惯，降低从 Python/JavaScript 迁移的认知成本。`设 X 为 Y` 保留给偏好中文自然语序的用户。

### 6.3 为什么教程主推符号运算符

符号运算符（`+ - * /`）是跨语言通用约定，初学者在数学课中已熟悉。中文运算符（`加 减 乘 除`）作为等价对照保留，但不作为主推——减少初学者需要记忆的关键词数量。
