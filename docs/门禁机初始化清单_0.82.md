## 2. 目录树（**两个都要**）

1. **主测试树**：git 工作树（如 `/home/ai/r161clean`），`git fetch` 后 ff 到本轮目标 commit。

2. **lightharness 树**：`/home/ai/lightharness`。
   ⚠️ **它不是 git 仓库，只是同步过去的拷贝**。`tests/unit/test_builtins_drift.py` 通过
   `scripts/sync_builtins.py` 的 `LH_PATH`（= 主树同级 `lightharness/stdlib/...`）读它。
   树一陈旧，`test_lh_name_diff_only_lh_only` / `test_lh_public_body_hash_equals_main` 就假红
   （R161 实测：陈旧树报 26 项「缺口」，实际仓库侧早已齐全）。

   刷新方式（幂等，`newline="\n"` 写盘，不会带出 CRLF）：
   ```bash
   cd <主测试树> && /home/ai/lm082_venv/bin/python scripts/sync_builtins.py
   ```
   验收：`pytest tests/unit/test_builtins_drift.py -n 0 -p no:randomly -q` 全绿。

## 3. venv 依赖（**换机必做**）

```bash
# 只体检，不改环境；有未就位的固化项时打印提示
/home/ai/lm082_venv/bin/python <主测试树>/scripts/ensure_venv.py \
    --venv /home/ai/lm082_venv --check

# 就位（幂等；已装且版本匹配则跳过）
/home/ai/lm082_venv/bin/python <主测试树>/scripts/ensure_venv.py \
    --venv /home/ai/lm082_venv
```

当前 `LOCKED`（缺了会真红，故必须锁）：

| 包 | 锁版本 | 缺失后果 |
|---|---|---|
| `lunardate` | 0.3.0 | `tests/test_datetime.py` 农历 8 条红 |
| `requests` | 2.34.2 | `tests/lightpub/test_lightpub_bridge.py` 6 errors |
| `cryptography` | 50.0.2 | `tests/test_tls_light.py` 整文件降级为 1 条红 + `tests/test_async_io_light.py` TLS 异步读腿 3 errors（R161-E） |

⚠️ FreeBSD 上 `cryptography` 无现成 wheel，pip 会**本地编译**（需 cffi/pycparser，约 2~3 分钟）。
超时不要慌，也不要换源强装；装完用 `pip show cryptography requests` 核对版本。

⚠️ **禁止**用 `LIGHT_ALLOW_SKIP_TLS_TEST=1` 之类环境变量把 TLS 用例放行——那是藏红，不是修复。

## 5. 假红速查（同一 commit 本机绿、0.82 红时先查这里）

| 现象 | 真因 | 处置 |
|---|---|---|
| builtins drift 报一批「LH 副本缺 N 项」 | `/home/ai/lightharness` 树陈旧 | 跑 `sync_builtins.py`（§2） |
| `test_tls_light.py` 只剩 1 条红 / lightpub 6 errors / TLS 异步读腿 3 errors | venv 缺 `cryptography` / `requests` | `ensure_venv.py`（§3） |
| 断言「不是纯 CRLF」「锚点缺失」这类行尾红 | 测试判据硬编码 `\r\n`；git 索引 LF，Windows autocrlf 检出 CRLF，FreeBSD 检出 LF | 判据必须行尾无关：读取后 `replace(b'\r\n', b'\n')` 再比（R161 已修 #5 / #8） |
| 全量门出现「协程恢复 / 心跳协程 SIGSEGV」类 | 真实产品缺陷，不是环境 | 按实记红，禁止改判据掩盖 |

## 6. 维护规则

- 新增 `LOCKED` 项必须附「**缺了会红**」的用例证据（哪几条、红成什么样），否则只进 `WATCH`。
