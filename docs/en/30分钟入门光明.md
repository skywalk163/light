# Learn LightLang in 30 Minutes

> **Version:** v7.0
> LightLang is a Chinese programming language — keywords are written in Chinese, and it supports both Chinese and symbolic operators, so even complete beginners can pick up programming quickly.
>
> This tutorial is designed for **Chinese-speaking users who have never written code before**. Follow it to the end and you'll be able to write simple programs on your own.

## 🔰 Part 1: Environment Setup (5 min)

### 1.1 Install Python — why does LightLang need it?

LightLang itself is written in Python, so it needs a Python environment to run. Think of Python as the "soil" of the language — the LightLang "tree" grows on Python soil.

**Why not write the compiler in C++ or Rust?** Python's ecosystem is mature and cross-platform friendly, and LightLang's target users are Chinese beginners, so lowering the install barrier matters more than chasing peak performance.

**Steps:**

1. Visit [python.org](https://www.python.org/downloads/) and download the latest Python (3.10 or higher)
2. Run the installer, and **make sure to tick** "Add Python to PATH"
   > Why tick this? It tells the system where the `python` command lives; otherwise typing `python` gives "command not found"
3. Click "Next" all the way to finish

**Verify:** open a terminal (Windows: press `Win+R`, type `cmd`, Enter) and enter:

```bash
python --version
```

Seeing something like `Python 3.12.x` means success.

---

### 1.2 Install LightLang

In the terminal:

```bash
pip install light
```

**Why `pip`?** pip is Python's package manager — like an app store on your phone. You type `pip install package-name` and it downloads and installs the software from PyPI (the Python Package Index) automatically.

**Verify:**

```bash
light --version
```

Seeing `光明编译器 v6.x.x` means install succeeded.

---

### 1.3 Your first LightLang program

Create a file `hello.light` with:

```light
打印 "你好，光明！"
```

**Why the `.light` extension?** The extension tells the computer "this is a LightLang source file", just like `.docx` means a Word document.

Run it:

```bash
light run hello.light
```

Seeing `你好，光明！` printed — congratulations, you've run your first LightLang program!

> **Why doesn't `打印` need parentheses?** In LightLang, `打印` is a built-in command; adding parentheses also works (`打印("你好")`) — the two forms are equivalent. This lets beginners memorize one fewer rule.

## 🚀 Part 2: Your First Complete Program (5 min)

### 2.1 Variables — why do we need "boxes"?

Variables are like storage boxes in a kitchen — you put different things in different boxes and open them when needed. Computers use variables to "remember" data.

```light
设 名字 为 "张三"
设 年龄 为 25
设 身高 为 1.75

打印 名字
打印 年龄
打印 身高
```

**Syntax breakdown:**
- `设` → tells LightLang "I want to create a variable"
- `名字` → label the box (variable name)
- `为` → put the value on the right into it
- `"张三"` → text in quotes is a string; numbers without quotes are numbers

**Why `设` instead of `var` or `let`?** LightLang aims to let native Chinese speakers think in their mother tongue. "设" means "set a variable" in Chinese — no need to translate to English first.

---

### 2.2 String interpolation — embed variables in text

To embed a variable into a piece of text, use an `f`-prefixed string (f-string):

```light
设 名字 为 "光明"
设 版本 为 1.11

打印(f"语言：{名字}，版本：{版本}")
```

**Why "f-string"?** The `f` stands for "format". `{名字}` acts like a placeholder, replaced at runtime by the variable's actual value. Output:

```
语言：光明，版本：1.11
```

---

### 2.3 Comments — notes to your future self

Lines starting with `#` are comments — the program skips them and never executes them. Comments are for **humans**:

```light
# compute age
设 当前年份 为 2026
设 出生年份 为 2000
设 年龄 为 当前年份 - 出生年份  # result: 26
打印 年龄
```

**Why comments?** When you write code you're clear-headed, but a month later you may not remember why you wrote it that way. Comments are notes left for your "future self".

---

### 2.4 Interactive input — let the program talk to you

Use the `输入` function to make the program wait for user input:

```light
设 名字 为 输入("请输入你的名字：")
打印(f"你好，{名字}！欢迎学习光明！")
```

**Why `输入`?** Without it, the program can only output fixed content. With it, the program can respond differently based on user input — that's real "interaction".

---

### 2.5 The period is optional

The period "。" at the end of a LightLang statement is **optional** — adding it doesn't affect execution, and omitting it is perfectly fine. This tutorial's examples omit periods to stay concise.

**Why make it optional?** The original intent of Chinese programming is to lower the barrier. Forcing a period would add one more "forgot the period" error, which goes against LightLang's design philosophy.

## 💻 Part 3: REPL — learn by typing (5 min)

### 3.1 What is a REPL?

REPL stands for **Read-Eval-Print Loop**. Simply put, it's an interactive environment where you "type a line, run a line".

**Why a REPL?** Want to test whether some syntax is correct? No need to create a file, save it, or run `light run` — just type it in and see the result. This is the fastest way to learn a new language.

Start the REPL:

```bash
light repl
```

You'll see a prompt like:

```
光明 REPL v7.0
>>> 
```

### 3.2 Basic REPL operations

Try typing these after `>>>`:

```text
>>> 打印 "你好，REPL！"
你好，REPL！

>>> 设 甲 为 10
>>> 设 乙 为 20
>>> 甲 + 乙
30

>>> 10 * 3 + 5
35
```

**Why does the last one print without `打印`?** In the REPL, when you enter an expression it automatically evaluates and shows the result. This lets you verify ideas quickly.

### 3.3 Multi-line code in the REPL

When a complex statement needs multiple lines, the REPL recognizes it automatically:

```text
>>> 如果 10 > 5：
...     打印 "10 大于 5"
... 否则：
...     打印 "这个不会被执行"
...
10 大于 5
```

The `...` prompt means the REPL is waiting for you to continue.

### 3.4 REPL tips

```text
>>> # quick calculation
>>> 1024 * 768
786432

>>> # string operations
>>> "光明" + "真棒"
光明真棒

>>> # view help
>>> 帮助(打印)
打印(value) → 输出内容到屏幕
```

Exit the REPL with `Ctrl+Z` then Enter (Windows) or `Ctrl+D` (Mac/Linux), or type `退出()`.

## 🔢 Part 4: Basic Operations & Conditionals (5 min)

### 4.1 Arithmetic — why two ways to write it?

LightLang supports **symbolic operators** and **Chinese operators**, fully equivalent:

```light
设 甲 为 10
设 乙 为 3

打印(甲 + 乙)       # add → 13     same as: 甲 加 乙
打印(甲 - 乙)       # subtract → 7      same as: 甲 减 乙
打印(甲 * 乙)       # multiply → 30     same as: 甲 乘 乙
打印(甲 / 乙)       # divide → 3.333   same as: 甲 除 乙
打印(甲 // 乙)      # floor divide → 3      same as: 甲 整除 乙
打印(甲 % 乙)       # modulo → 1      same as: 甲 取余 乙
打印(甲 ** 乙)      # power → 1000     same as: 甲 幂 乙
```

**Why two ways?** Beginners may not remember that `//` means floor divide and `%` means modulo — but "整除" (floor divide) and "取余" (modulo) are self-explanatory. The symbolic form is kept so experienced programmers can get started fast. **Symbolic form is recommended** — more concise and universal.

> 💡 **Tip:** `%` modulo is very common in real programming — checking parity (`数 % 2 == 0`), cycling through values, etc.

---

### 4.2 Comparison

Comparison results are `真` (true) or `假` (false):

```light
设 甲 为 10
设 乙 为 5

打印(甲 > 乙)        # true     same as: 甲 大于 乙
打印(甲 < 乙)        # false     same as: 甲 小于 乙
打印(甲 == 乙)       # false     same as: 甲 等于 乙
打印(甲 != 乙)       # true     same as: 甲 不等于 乙
打印(甲 >= 乙)       # true     same as: 甲 大于等于 乙
```

**Note:** `==` means "check equality", `=` means "assign". This is one of the most common beginner mistakes — covered in detail in "Learn from errors" later.

---

### 4.3 Logical operations — combine conditions

Use `且` (both must hold), `或` (either one holds), `非` (negate) to connect conditions:

```light
设 年龄 为 20
设 有身份证 为 真

如果 年龄 >= 18 且 有身份证：
    打印 "可以上网"
```

---

### 4.4 Conditionals — let the program make decisions

```light
设 分数 为 85

如果 分数 >= 90：
    打印 "优秀"
否则如果 分数 >= 60：
    打印 "及格"
否则：
    打印 "不及格"
```

**Why colons and indentation?** The colon (`:`) tells LightLang "the code to run when the condition holds comes next", and indentation (2 or 4 spaces) marks which lines belong to this condition. This is the shared style of Python and LightLang — **forced indentation makes structure obvious at a glance**.

---

### 4.5 Ternary expression — one line for either/or

```light
设 数 为 10
设 结果 为 "偶数" 如果 数 % 2 == 0 否则 "奇数"
打印 结果    # output: 偶数
```

**Why "ternary"?** Because it has three parts: the condition (`数 % 2 == 0`), the value when true (`"偶数"`), and the value when false (`"奇数"`).

---

### 4.6 Loops — let the computer do repetition

The computer's greatest strength is doing tedious repetition without complaint.

**While loop — "keep doing as long as the condition holds":**

```light
设 计数 为 1
当 计数 <= 5：
    打印(f"第{计数}次")
    计数 = 计数 + 1
```

**Why "当"?** Reading it aloud is "when the count is ≤ 5, run the code in the braces" — exactly like everyday speech.

**For loop — "do once for each element":**

```light
遍历 项 在 1 到 5：
    打印 项
```

**Iterate over a list:**

```light
设 水果 为 ["苹果", "香蕉", "橘子"]
遍历 水果 为 果：
    打印 果
```

**Loop control:**

- `跳出`: end the whole loop immediately (like break)
- `跳过`: skip this round, go to the next (like continue)

```light
遍历 项 在 1 到 10：
    如果 项 % 2 == 0：
        跳过           # skip even
    如果 项 > 7：
        跳出           # stop past 7
    打印 项            # output: 1, 3, 5, 7
```

## ⚡ Part 5: 段落 (Functions) — package your code (3 min)

### 5.1 Define and call — why "段落"?

Imagine writing this every day:

```light
打印 "你好，张三！"
# ... 50 lines ...
打印 "你好，张三！"
```

Too repetitive! A function "packages" this code under a name; call the name when needed:

```light
段落 问好 接收 名字：
    打印(f"你好，{名字}！")

问好("张三")   # output: 你好，张三！
问好("李四")   # output: 你好，李四！
```

**Why "段落"?** An article is made of paragraphs; a program is made of "paragraphs" too. Each paragraph does one thing; combined they form a complete program.

**Syntax breakdown:**
- `段落` → keyword, tells LightLang "I'm defining a function"
- `问好` → function name, you choose it
- `接收 名字` → parameter list, data passed in by the caller
- `：` → indented code after it is this "paragraph"'s body
- `返回` → "throw" the result back to the caller

### 5.2 Return value

```light
段落 加法 接收 a, b：
    返回 a + b

设 结果 为 加法(3, 5)
打印 结果    # output: 8
```

**Why `返回`?** Without `返回`, the function computes `a + b` but the result is only "digested" inside; the outside can't get it. `返回` passes the result out.

### 5.3 Default parameters — a "fallback value"

```light
段落 问候 接收 名字 = "世界"：
    打印(f"你好，{名字}！")

问候("张三")    # 你好，张三！
问候()          # 你好，世界！
```

**Why default parameters?** Some parameters use the same value most of the time, changed only in rare cases. Defaults let you write less code.

### 5.4 Recursion — a function calling itself

```light
段落 阶乘 接收 n：
    如果 n <= 1：
        返回 1
    返回 n * 阶乘(n - 1)

打印 阶乘(5)    # output: 120
```

**How recursion works:** `阶乘(5)` calls `阶乘(4)`, which calls `阶乘(3)`… until `阶乘(1)` returns 1 directly, then the result is passed back layer by layer:

```
阶乘(5) = 5 * 阶乘(4)
        = 5 * 4 * 阶乘(3)
        = 5 * 4 * 3 * 阶乘(2)
        = 5 * 4 * 3 * 2 * 阶乘(1)
        = 5 * 4 * 3 * 2 * 1
        = 120
```

**⚠️ Recursion must have an "exit"**: the `n <= 1` branch returns directly, otherwise it loops forever.

## 📦 Part 6: Lists, Strings & Dictionaries (3 min)

### 6.1 Lists — put several things together

```light
设 水果 为 ["苹果", "香蕉", "橘子"]
打印 水果[0]    # output: 苹果 (why start at 0? explained below)
水果.追加("葡萄")
打印 长度(水果)  # output: 4
```

**Why index from 0?** Internally, a list is a contiguous block of memory addresses. `[0]` means "the position of the first element", offset 0 units. `[1]` means offset 1 unit. Although beginners feel starting at 1 is more natural, almost all programming languages start at 0 — it's the universal convention.

### 6.2 List comprehension — generate a list in one line

```light
设 平方数 为 [x * x 遍历 x 之 范围(1, 6)]
打印 平方数    # output: [1, 4, 9, 16, 25]
```

**Read it as:** "x times x, for x in the range 1 to 5" — exactly the Chinese word order.

With a filter:

```light
设 偶数 为 [x 遍历 x 之 范围(1, 11) 若 x % 2 == 0]
打印 偶数  # [2, 4, 6, 8, 10]
```

### 6.3 String operations

```light
设 名字 为 "光明"
打印 长度(名字)  # output: 2
打印 名字[0]    # output: 段
打印 名字 + "真棒"  # output: 光明真棒
```

### 6.4 Dictionaries — key-value mapping

```light
设 学生 为 {"名字": "张三", "年龄": 25, "成绩": 95}
打印 学生["名字"]    # output: 张三
打印(f"{学生['名字']}的年龄是{学生['年龄']}")
```

**Why dictionaries?** Lists use numeric indices (0, 1, 2…), but numbers aren't intuitive. Dictionaries let you look up by text like "名字" — just like looking up a word in a dictionary.

## 🏗️ Part 7: Classes & Objects (3 min)

### 7.1 Object-oriented — why classes and objects?

When writing programs we often need to represent "real-world things" — e.g. a student has a name, age, and grades, and can compute an average. You could do it with the variables you've learned, but it gets messy:

```light
设 张三的名字 为 "张三"
设 张三的年龄 为 20
设 张三的成绩 为 [85, 92, 78]
# ... with 10 students that's 30 variables, too messy!
```

A **class** is the "blueprint"; an **object** is the "real thing" built from the blueprint:

```light
类 学生：
    属性 名字
    属性 年龄
    属性 成绩

    构造 接收 名字, 年龄：
        己.名字 为 名字
        己.年龄 为 年龄
        己.成绩 为 []

    段落 添加成绩 接收 分数：
        己.成绩.追加(分数)

    段落 平均分 接收：
        如果 长度(己.成绩) == 0：
            返回 0
        设 总和 为 0
        遍历 己.成绩 为 分：
            设 总和 为 总和 + 分
        返回 总和 / 长度(己.成绩)

# create an object — build the "real thing" from the "blueprint"
设 张三 为 学生("张三", 20)
张三.添加成绩(85)
张三.添加成绩(92)
打印(f"{张三.名字}的平均分是{张三.平均分()}")
```

**Why `己`?** `己` is like `this` / `self` in other languages, meaning "the current object itself". `己.名字` means "this student's own name".

### 7.2 Inheritance — reduce duplicated code

When two classes share a lot, let one "inherit" the other's capabilities:

```light
类 动物：
    属性 名字

    构造 接收 名字：
        己.名字 为 名字

    段落 介绍 接收：
        打印(f"我叫{己.名字}")

类 狗 继承 动物：
    段落 叫 接收：
        打印 "汪汪！"

设 小狗 为 狗("旺财")
小狗.介绍()    # 我叫旺财 (inherited from 动物)
小狗.叫()      # 汪汪！ (its own method)
```

**Why "inherit"?** Like a child inheriting parents' genes — `狗` automatically has all of `动物`'s attributes and methods, no need to rewrite them.

### 7.3 Static methods — callable without an object

```light
类 数学工具：
    静态 段落 平方 接收 x：
        返回 x * x

打印 数学工具.平方(5)    # output: 25
```

**Why static methods?** Some utility functions work without creating an object — `数学工具.平方(5)` calls directly, no need to first `设 工具 为 数学工具()`.

## 🛡️ Part 8: Exception Handling & File Operations (3 min)

### 8.1 Exception handling — what if the program errors?

There are always surprises at runtime — e.g. the user enters invalid data, or a file to read doesn't exist. `尝试/捕获` puts a "bulletproof vest" on the program:

```light
尝试：
    设 结果 为 10 / 0
    打印 结果
捕获 错误：
    打印("出错了：" + 转字符串(错误))
最终：
    打印("无论是否异常都会执行")
```

**Why `最终`?** Some operations must run whether success or failure — e.g. closing a file, releasing resources. `最终` guarantees this.

### 8.2 Raise exceptions actively

```light
段落 检查年龄 接收 年龄：
    如果 年龄 < 0：
        抛出 "年龄不能为负数"
    打印(f"年龄是{年龄}")

尝试：
    检查年龄(-5)
捕获 e：
    打印("捕获到异常：" + 转字符串(e))
```

### 8.3 File operations

```light
# write a file
写入文件("note.txt", "你好，光明！")
打印("文件已写入")

# read a file
设 内容 为 读取文件("note.txt")
打印(内容)

# check if a file exists
如果 文件存在("note.txt")：
    打印("文件存在")
否则：
    打印("文件不存在")
```

**Why `写入文件/读取文件` instead of `open/write/close`?** LightLang wraps common file operations into intuitive Chinese functions — beginners don't need to understand low-level concepts like "file handles" or "buffers".

## 🔍 Part 10: Debugging — find the bug (extra 3 min)

### 10.1 Why a debugger?

Rarely does code run perfectly the first time. A debugger lets you **execute line by line**, watching how variables change after each line, to find the problem.

### 10.2 Use `light debug`

LightLang has a built-in debugger, just use the `light debug` command:

```bash
light debug hello.light
```

**Common debugger commands:**

| Command | Action | Why this one? |
|---------|--------|---------------|
| `b 5` | set a breakpoint at line 5 | pause the program at a given line to observe |
| `d 5` | delete the breakpoint at line 5 | clear when no longer needed |
| `c` | continue to the next breakpoint | skip code you don't need to inspect |
| `n` | step over (don't enter functions) | if a function is trusted, skip it |
| `s` | step into (enter functions) | see what happens inside a function |
| `p var` | print a variable's current value | check if a variable is as expected |
| `w` | show the call stack | see which function called which |
| `l` | show current source | confirm which line is executing |
| `vars` | show all variables | overview all variable states |
| `q` | quit the debugger | end debugging |

### 10.3 Real debugging example

Suppose a program `bug.light`:

```light
段落 阶乘 接收 n：
    如果 n <= 1：
        返回 1
    返回 n * 阶乘(n - 1)

设 结果 为 阶乘(5)
打印(f"5! = {结果}")
```

Run the debugger:

```bash
light debug bug.light
```

```

[断点已设置] 第5行

> c                      # start executing

> p n                    # view n

> c                      # continue, breakpoint triggers repeatedly
[断点触发] 第5行: 返回 n * 阶乘(n - 1)
> p n
n = 4

> c
[断点触发] 第5行: 返回 n * 阶乘(n - 1)
> p n
n = 3

> c
[断点触发] 第5行: 返回 n * 阶乘(n - 1)
> p n

> c
[断点触发] 第5行: 返回 n * 阶乘(n - 1)
```

Then load a file inside the debugger to debug it.

## 🚢 Part 11: Compile & Ship — turn your program into an EXE (extra 3 min)

### 11.1 Why compile?

Your `.light` file needs the LightLang environment to run — others must install LightLang first. After compiling to `.exe`, any Windows user (even without Python and LightLang installed) can run it directly.

### 11.2 Compile to Python code

```bash
light compile hello.light -o hello.py
```

**Why compile to Python first?** The LightLang interpreter itself is written in Python; compiling to Python lets you further package it into an EXE using the Python ecosystem.

### 11.3 Compile to a standalone EXE

```bash
# install PyInstaller first (once)
pip install pyinstaller

# compile to exe
light compile hello.light -o hello.exe
```

**How it works:** `light compile` first translates LightLang into Python, then PyInstaller packages the Python into a standalone `.exe`. This file contains everything needed to run, **with no environment required**.

### 11.4 LLVM native compilation — faster, smaller

```bash
light build hello.light -o hello.exe
```

**Why `light build` instead of `light compile`?** `light build` uses the LLVM backend — it compiles LightLang directly into machine code, producing a native executable that **starts faster and is smaller**, with no Python runtime needed.

**`light build` vs `light compile`:**

| Command | Backend | Output | Needs Python? | Startup |
|---------|---------|--------|--------------|---------|
| `light compile` | SRC/ANTLR | .py or .exe | not after packaging | medium |
| `light build` | LLVM | native .exe | no | fastest |

> **Note:** if your code uses advanced features like classes (`class`), you need the LLVM backend to compile correctly. Use `light ai check` to detect code/backend compatibility.

## 🧠 Part 12: Learn from Errors — common beginner mistakes

Errors are the best teacher in programming. Below are the most common LightLang beginner mistakes; check against them when you hit a problem.

### Mistake 1: forgot `为`

```text
# ❌ wrong
设 名字 "张三"
```

```light
# ✅ correct
设 名字 为 "张三"
```

**Why?** `设 X 为 Y` is a fixed structure; `为` is a required keyword, omitting it raises a syntax error.

### Mistake 2: confusing `=` and `==`

```text
# ❌ wrong: this is assignment, not comparison
如果 分数 = 100：
    打印 "满分"
```

```light
# ✅ correct: == is comparison
如果 分数 == 100：
    打印 "满分"
```

**Why?** `=` means "put the right value into the left", `==` means "check if left and right are equal". Almost every beginner makes this mistake — **even experienced programmers slip up occasionally**.

### Mistake 3: forgot the colon `：`

```text
# ❌ wrong
如果 年龄 >= 18
    打印 "成年"
```

```light
# ✅ correct
如果 年龄 >= 18：
    打印 "成年"
```

**Why?** The colon tells LightLang "the condition is done, the code block to execute follows". In LightLang, `如果`, `否则`, `遍历`, `当`, `段落`, `类` all need a colon after them.

### Mistake 4: inconsistent indentation

```light
# ❌ wrong: messy indentation
如果 真：
    打印 "第一行"
  打印 "第二行"  # wrong indent

# ✅ correct: uniform indentation
如果 真：
    打印 "第一行"
    打印 "第二行"
```

**Why?** LightLang uses indentation (spaces or Tab) to mark which block a line belongs to. Inconsistent indentation makes it impossible for LightLang to tell — **use 4 spaces uniformly**.

### Mistake 5: variable-name collision

```light
# ❌ wrong: using a built-in function name as a variable name
设 打印 为 123
打印(打印)  # error: 打印 is no longer a function

# ✅ correct: avoid keywords
设 打印值 为 123
打印(打印值)
```

**Why?** `打印`, `输入`, `长度`, `转字符串` etc. are LightLang built-ins; using them as variable names overrides the built-ins.

### Mistake 6: index out of range

```light
# ❌ wrong
设 列表 为 [1, 2, 3]
打印 列表[5]  # list has only 3 elements, index 5 doesn't exist

# ✅ correct: check length first
设 列表 为 [1, 2, 3]
如果 长度(列表) > 5：
    打印 列表[5]
否则：
    打印(f"列表只有{长度(列表)}个元素，索引5不存在")
```

**Why?** List indices start at 0; a list of length 3 has valid indices 0, 1, 2.

### Mistake 7: mismatched string quotes

```text
# ❌ wrong
设 消息 为 "你好'
```

```light
# ✅ correct: quotes come in pairs
设 消息 为 "你好"
设 消息2 为 '你好'
```

**Why?** Strings must be wrapped in matching quotes. `"` starts and must end with `"`; `'` starts and must end with `'`.

### Mistake 8: using `设` to modify a list

```light
# ❌ wrong: use 「设」 to create a variable, use 「=」 to modify a list element
设 列表 为 [1, 2, 3]
设 列表[0] 为 10  # not supported on SRC backend

# ✅ correct: assign directly
设 列表 为 [1, 2, 3]
列表[0] = 10
```

## 🎯 Part 13: Capstone — Number Guessing Game

String everything together into a complete number-guessing game:

```light
导入 数学

# generate a random number from 1 to 100
设 目标 为 数学.随机整数(1, 100)
设 尝试次数 为 0
设 猜中 为 假

打印 "=== 猜数字游戏 ==="
打印 "我已经想好了一个 1 到 100 之间的数字"
打印 "你能猜出来吗？"

当 非 猜中：
    设 猜测 为 转整数(输入("请猜一个数字："))
    尝试次数 = 尝试次数 + 1

    如果 猜测 == 目标：
        打印(f"🎉 恭喜！你猜中了！用了{尝试次数}次")
        猜中 = 真
    否则如果 猜测 < 目标：
        打印("太小了，再试试")
    否则：
        打印("太大了，再试试")

打印 "游戏结束！"
```

**Run:**

```bash
light run guess.light
```

**What this program uses:**

| Concept | Corresponding code |
|---------|-------------------|
| Module import | `导入 数学` |
| Variable | `设 目标 为 ...` |
| Loop | `当 非 猜中：` |
| Conditional | `如果/否则如果/否则` |
| Boolean | `真/假` |
| User input | `输入(...)` |
| Type conversion | `转整数(...)` |
| String interpolation | `f"用了{尝试次数}次"` |
