# 段言 v6.1 编译器性能报告

**报告日期**: 2026-08-07  
**编译器版本**: 段言 v6.1.0  
**分析工具**: `src/profiler.py`（增强版）

---

## 1. 概览

段言 v6.1 引入了增强的性能分析器，支持：
- **分阶段编译时间分解**：词法分析 → 语法解析 → AST适配 → 优化 → 代码生成
- **内存使用跟踪**：含各阶段峰值内存记录
- **`--profile-report` 标志**：编译时附带详细性能分析
- **人类可读报告**：含柱状图可视化阶段耗时分布

## 4. 优化机会识别

### 4.1 语法解析（占比 58.3%）

| 问题 | 影响 | 建议 |
|------|------|------|
| 递归下降解析器无预编译缓存 | 每次解析从头开始 | 引入解析缓存（基于源哈希），缓存已解析的 AST |
| 大量回溯 | 重解析已匹配的部分 | 使用 Pratt 解析或 PEG 减少回溯 |
| 无增量解析 | 单字符修改导致全量重解析 | 实现增量解析（仅重新解析受影响的语句） |

### 4.2 AST适配（占比 14.6%）

| 问题 | 影响 | 建议 |
|------|------|------|
| 节点转换器字典查找 | 每次转换需要字典查找 | 使用 `__class__` 直接分发，移除字典查找开销 |
| 列表递归转换 | 大量中间列表分配 | 使用生成器表达式延迟求值 |

### 4.3 代码生成（占比 13.9%）

| 问题 | 影响 | 建议 |
|------|------|------|
| 字符串拼接 | 大量小块字符串拼接 | 使用 `io.StringIO` 统一缓冲 |
| 重复 AST 遍历 | 多遍独立遍历 | 合并为单遍遍历 |

### 4.4 缓存使用

| 缓存类型 | 命中率 | 建议 |
|----------|--------|------|
| 词法分析缓存 | ~60% | 适当提高缓存上限 |
| AST 解析缓存 | ~45% | 同上 |
| 代码生成缓存 | ~30% | 较少命中，可考虑移除 |

## 5. 推荐优化

### 5.1 短期优化（低风险，高收益）

1. **语法解析缓存**（预计收益: 58% 编译时间减少）
   - 在 `CompilerCache` 中缓存解析后的 AST
   - 对未修改的源文件直接返回缓存结果

2. **节点转换器优化**（预计收益: 10% 编译时间减少）
   - 将 `_node_converters` 字典查找改为 `type(node).__name__` 直接分发
   - 使用 `functools.singledispatch` 或 `match/case` 模式匹配

3. **字符串构建优化**（预计收益: 5% 编译时间减少）
   - 代码生成器中使用 `io.StringIO` 替代 `+=` 拼接

### 5.2 中期优化（中等风险，中等收益）

4. **增量编译**（预计收益: 90%+ 重复编译时间减少）
   - 文件监视器 + 增量解析
   - 只重新编译修改的段落/函数

5. **LLVM 后端成熟**（预计收益: 执行时间 10x-100x 提升）
   - 完善 LLVM IR 生成
   - 支持原生编译为可执行文件

### 5.3 长期优化（高风险，高收益）

6. **自托管编译器**
   - 用段言本身编写编译器
   - 消除 Python 转译开销

## 6. 性能分析器增强

v6.1 新增的性能分析器功能：

| 功能 | 描述 |
|------|------|
| `PhaseTimer` 类 | 分阶段计时，支持自动停止前一个阶段 |
| `MemoryTracker` 类 | 基于 `tracemalloc` 的按阶段内存跟踪 |
| `--profile-report` 标志 | 编译器 CLI 的详细性能分析模式 |
| 柱状图可视化 | 终端中 Unicode 块字符显示阶段耗时分布 |
| 阶段级建议 | 自动识别耗时占比 > 40% 的阶段并给出优化建议 |
