## 4. 命名对照与口径建议

当前 `stdlib/` 根级模块命名中英并存，但实际英文名仅 9 个（均为行业惯用缩写），其余为中文名：

| 当前文件名 | 建议口径 | 备注 |
|---|---|---|
| `Base64.light/.py` | 保留 `Base64`（别名：Base64编码） | 行业惯用 |
| `CSV.light/.py`、`CSV读写器.light/.py` | 保留 `CSV`（别名：CSV读写） | 行业惯用 |
| `FFI.light/.py`、`FFI增强.light/.py` | 保留 `FFI`（别名：外部函数接口） | 行业惯用 |
| `HTTP.light/.py` | 保留 `HTTP` | 行业惯用 |
| `JSON.light/.py` | 保留 `JSON` | 行业惯用 |
| `XML.light/.py` | 保留 `XML` | 行业惯用 |
| `SSE.light/.py` | 保留 `SSE`（别名：服务端推送） | 行业惯用 |
| `中文NLP.light/.py`、`中文文本.light/.py` 等中文名 | 以中文名为主口径 | 已合规 |
| `列表工具`/`临时文件`/`加密`/`历法`/`参数解析` 等 | 以中文名为主口径 | 已合规 |

**建议口径（不改动文件名，仅作文档约定）**：
1. 通用协议/编码类（`Base64`/`CSV`/`FFI`/`HTTP`/`JSON`/`XML`/`SSE`）维持英文原名，文档中以中文别名标注，便于检索。
2. 其余模块统一以**中文名**为权威名，英文名仅在历史文档/导入兼容处保留为别名。
3. `lightpub/` 作为独立 Python 打包通道，其 56 个 `.py` 不与根级 `.light` 强求配对（打包形态不同）。
