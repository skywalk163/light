# 段言编译器架构解析：从中文到机器码的完整旅程

> **发布日期：** 2026-08-07
> **适用版本：** v5.5.0

---

## 引言

段言（Duan）作为一门中文编程语言，其编译器承担着将中文自然语言代码转换为可执行代码的重任。本文将深入解析段言编译器的架构设计，带你了解一段中文代码是如何一步步变成机器码的。

## 整体架构

段言编译器采用经典的**多阶段编译架构**，主要分为以下几个阶段：

```
源代码 (.duan)
    │
    ▼
┌──────────────┐
│  词法分析器   │  ←  lexer.py
│  （中文分词）  │
└──────┬───────┘
    │
    ▼
┌──────────────┐
│  Token 流    │
└──────┬───────┘
    │
    ▼
┌──────────────┐
│  语法分析器   │  ←  parser_core.py / parser_stmt.py / parser_expr.py
│  （递归下降）  │
└──────┬───────┘
    │
    ▼
┌──────────────┐
│  AST 抽象语法树│  ←  ast_nodes_v3.py / ast_unified.py
└──────┬───────┘
    │
    ▼
┌──────────────┐
│  语义分析器   │  ←  semantic_analyzer.py
│  （类型检查）  │
└──────┬───────┘
    │
    ▼
┌──────────────┐
│  代码生成器   │  ←  code_generator.py
│  （双后端）    │
└──┬────┬──────┘
   │    │
   ▼    ▼
Python  LLVM IR
代码    │
        ▼
    原生 EXE
```

## 第一阶段：词法分析（Lexer）

词法分析是编译器的第一个阶段，负责将源代码文本切分为**Token（词法单元）流**。

**文件：** `src/lexer.py`

段言词法分析器的特殊之处在于需要处理**中文关键字**。例如，对于这段代码：

```段言
设 年龄 为 25
如果 年龄 > 18：
    打印 "成年人"
```

词法分析器会生成以下 Token 序列：

```
KEYWORD(设) IDENTIFIER(年龄) KEYWORD(为) NUMBER(25) NEWLINE
KEYWORD(如果) IDENTIFIER(年龄) OPERATOR(>) NUMBER(18) COLON NEWLINE
INDENT KEYWORD(打印) STRING("成年人") NEWLINE
DEDENT EOF
```

### 关键技术点

- **中文关键字识别**：通过关键字表匹配中文 Token
- **缩进处理**：使用 `INDENT`/`DEDENT` Token 处理代码块（类似 Python）
- **中文运算符支持**：`加`/`减`/`乘`/`除` 等中文运算符映射到对应符号
- **中文数字字面量**：支持 `三`、`五` 等中文数字

## 第二阶段：语法分析（Parser）

语法分析器将 Token 流转换为**抽象语法树（AST）**。

**文件：** `src/parser_core.py`、`src/parser_stmt.py`、`src/parser_expr.py`

段言使用**递归下降解析器**（Recursive Descent Parser），这是一种手写的自顶向下解析方法。

### 解析策略

段言采用**双后端架构**：

| 后端 | 解析方式 | 适用场景 |
|------|----------|----------|
| **SRC**（默认） | 手写递归下降解析器 | 日常开发，无需额外依赖 |
| **ANTLR** | ANTLR 生成解析器 | 兼容旧语法，语法验证 |

### 解析示例

对于 `如果 分数 >= 90：`，解析器会构建以下 AST 节点：

```
IfStatement:
  condition: BinaryOp(Identifier("分数"), ">=", NumberLiteral(90))
  then_branch: Block([...])
  else_branch: Block([...])  # 可选
```

### 支持的语法结构

- 变量声明（`设 X 为 Y`）
- 段落定义（`段落 名 接收 参数:`）
- 条件语句（`如果`/`否则如果`/`否则`）
- 循环（`遍历`/`当`/`跳出`/`跳过`）
- 类定义（`类`/`继承`/`构造`/`己`）
- 异常处理（`尝试`/`捕获`/`抛出`/`最终`）
- 导入导出（`导入`/`从`/`导出`）
- 列表推导（`[表达式 遍历 变量 之 范围]`）

## 第三阶段：语义分析（Semantic Analysis）

语义分析器负责**类型检查**和**符号表管理**。

**文件：** `src/semantic_analyzer.py`

### 三级类型检查

段言提供三级类型检查，用户可以根据需要选择检查深度：

| 级别 | 说明 | 命令 |
|------|------|------|
| **签名级** | 检查函数签名和类型注解 | `duan check --type-check 签名` |
| **变量级** | 检查变量声明和赋值类型 | `duan type-check --level 变量` |
| **表达式级** | 完整表达式类型推导 | `duan type-check --level 表达式` |

### HM 类型推断

段言实现了**Hindley-Milner 类型推断系统**，支持：

- **自动类型推导**：无需显式类型注解
- **泛型函数**：`段落 恒等[T](x): 返回 x`
- **泛型类**：`类 栈[T]：`
- **多态类型**：同一函数在不同上下文中的类型多态

### 空安全系统

段言通过 `可空` 类型注解实现空安全：

```段言
设 可能为空 为 可空(字符串)("hello")
设 结果 为 unwrap(可能为空, "默认值")
```

## 第四阶段：代码生成（Code Generation）

段言支持**双后端代码生成**，灵活切换。

### Python 代码生成

**文件：** `src/code_generator.py`、`src/code_generator_unified.py`

将段言 AST 转换为等效的 Python 代码。这是默认的执行方式，无需任何额外依赖。

```段言
# 段言代码
段落 加法(甲, 乙):
    返回 甲 + 乙

打印 加法(3, 5)
```

转换为 Python：

```python
# Python 代码
def 加法(甲, 乙):
    return 甲 + 乙

print(加法(3, 5))
```

### LLVM 后端

**文件：** `src/llvm/codegen_typed.py`、`src/llvm/compiler.py`

LLVM 后端将段言编译为**原生机器码**，生成可独立运行的 EXE 文件。

```bash
duan compile hello.duan --backend llvm-typed -o hello.exe
```

LLVM 后端的编译流程：

```
段言 AST → 类型化 IR → LLVM IR → 优化 → 目标代码 → 链接 → EXE
```

LLVM 优化器在生成原生代码前会执行多个优化 Pass：

| 优化 Pass | 说明 |
|-----------|------|
| 常量折叠 | 编译时计算常量表达式 |
| 死代码消除 | 移除不会被执行的代码 |
| 循环不变式外提 | 将循环内不变的计算移到循环外 |
| 公共子表达式消除 | 消除重复计算 |
| 内联展开 | 小函数内联到调用点 |

## 第五阶段：AI 工具链集成

段言 v5.5.0 的 AI 工具链是编译器生态的重要组成部分。

### 核心思路

```
用户需求 → AI 生成 Python → 微调模型翻译为段言 → duan ai check 验证
```

### AI Copilot 命令

```bash
duan ai generate "写一个二分查找函数"  # AI 生成段言代码
duan ai fix hello.duan "第3行语法错误"  # 修复代码
duan ai card                           # 语法速查卡
duan ai check hello.duan               # 后端兼容性检测
```

### 微调训练

段言提供三套微调方案，覆盖从 0.3B 到 8B 的模型：

| 方案 | 模型 | 显存 | 训练时间 | 定位 |
|------|------|------|----------|------|
| ERNIE-4.5-0.3B | 0.3B | ~4 GB | 10-30 分钟 | 轻量级翻译 |
| Qwen3.5-2B | 2B | ~5 GB | ~10 分钟 | 开发调试首选 |
| Qwen3-8B | 8B | ~22 GB | ~30 分钟 | 生产部署 |

训练好的模型已上线 Ollama 官网：

```bash
ollama pull airoot/duan-translator
```

## 优化器（Optimizer）

**文件：** `src/optimizer/`

段言的优化器包含多个独立的优化 Pass：

| 文件 | 优化 Pass | 说明 |
|------|-----------|------|
| `constant_fold.py` | 常量折叠 | 编译时计算字面量表达式 |
| `dead_code.py` | 死代码消除 | 移除不可达代码 |
| `cse.py` | 公共子表达式消除 | 消除重复计算 |
| `inline.py` | 内联展开 | 小函数内联 |
| `loop_invariant.py` | 循环不变式外提 | 循环优化 |
| `peephole.py` | 窥孔优化 | 局部指令模式优化 |

## 增量编译

**文件：** `src/incremental_build.py`

段言支持增量编译，通过文件变更检测避免不必要的完全重编译：

- 记录文件的哈希值和修改时间
- 只重新编译变更的文件和依赖
- 缓存中间编译结果

## 包管理系统

**文件：** `src/package_manager.py`

段言的包管理器处理 `package.toml` 配置文件的解析和项目构建：

```bash
duan pkg init myproject    # 初始化项目
duan pkg -p myproject build # 编译项目
duan pkg -p myproject run   # 运行项目
```

## 总结

段言编译器从设计之初就遵循了经典编译原理的架构，同时针对中文自然语言做了专门的优化。其核心特点包括：

1. **全中文关键字**：从词法分析到语法分析都支持中文
2. **双后端架构**：Python 解释执行 + LLVM 原生编译
3. **HM 类型推断**：自动类型推导，无需显式注解
4. **三级类型检查**：灵活的检查粒度
5. **AI 工具链集成**：微调模型辅助代码生成
6. **增量编译**：加速开发迭代
7. **丰富的优化器**：多 Pass 代码优化
