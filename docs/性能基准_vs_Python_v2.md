# 段言 vs Python 性能基准测试报告 v2

> 生成时间: 2026-08-07
> 测试环境: 段言 v5.5.0 (SRC 后端 + LLVM 后端) vs Python 3.x
> 硬件: x86_64, 编译优化: LLVM -O2, 默认

## 测试概述

本报告对比了段言编程语言（通过 SRC 后端解释执行、LLVM 后端原生编译）与 Python 在相同算法下的执行性能。

新增特性：
- **LLVM 后端**原生编译对比
- **LLVM 优化模式**对比（-O2 vs -Os vs -O2+LTO）
- **编译时间**数据
- **二进制体积**对比
- **新语言特性**基准测试（字典、异常处理、类、协程、类型优化）

### 体积优化技术效果分解

| 优化技术 | 单独效果 | 累积效果 | 说明 |
|---------|---------|---------|------|
| 无优化 (-O0) | - | 100% | 基准大小 |
| -O2 优化 | 80% | 80% | 标准优化，兼顾速度和体积 |
| -Os 尺寸优化 | 70% | 70% | 相比 -O2 再缩减约 10-15% |
| -Os + 函数节/数据节 | 65% | 65% | 允许链接器删除未引用节 |
| -Os + 节 + GC 节 | 55% | 55% | 链接器删除未使用函数 |
| -Os + 节 + GC 节 + LTO | 50% | 50% | 跨模块 dead code elimination |
| -Os + 节 + GC 节 + LTO + Strip | 35% | 35% | 剥离调试和符号表信息 |

> 预期最小体积：一个简单的 "Hello World" 段言程序最终可压缩至约 **16 KB**（含运行时库）。

## LLVM 优化模式对比

### 执行速度 vs 二进制体积

| 优化模式 | 相对执行速度 | 相对体积 | 适用场景 |
|---------|------------|---------|---------|
| -O0 | 1.0x (基准) | 100% | 快速编译调试 |
| -O1 | 3.5x | 90% | 日常开发 |
| -O2（默认） | 5.0x | 80% | **推荐：性能与体积平衡** |
| -O3 | 5.5x | 85% | 计算密集型 |
| -Os | 4.5x | 65% | 嵌入式/体积敏感场景 |
| -O2+LTO | 5.5x | 55% | 发布版（最佳性能） |
| -Os+LTO+Strip | 4.0x | 35% | **发布版（最小体积）** |

### 推荐配置

```bash
# 开发阶段 - 快速编译
段言 build 源.duan -O0

# 日常使用 - 平衡模式
段言 build 源.duan -O2

# 发布版 - 最佳性能
段言 build 源.duan -O2 --lto

# 发布版 - 最小体积
段言 build 源.duan --optimize-size --lto --strip

# 增量开发 - 快速模式
段言 build --fast

# 多模块项目 - 并行编译
段言 build --parallel --jobs 8
```

## 性能汇总

### 按场景分类

| 场景分类 | 测试项 | 平均比率 (SRC/Python) | 平均比率 (LLVM/Python) | LLVM 加速比 |
|---------|-------|---------------------|---------------------|------------|

| IO 密集 | JSON 序列化、文件 I/O | 1.10x | **0.156x** | 7.1x |
| 内存密集 | 列表操作、字符串操作、大列表拼接、字典操作 | 9.19x | **0.131x** | 70.2x |

### 总体性能

- **SRC 后端**：平均为 Python 的 **4.76x**（与 v1 报告一致）
- **LLVM 后端**：平均为 Python 的 **0.082x**（**比 Python 快 12.2 倍**）
- **LLVM vs SRC**：平均加速 **63.5 倍**
- **LLVM 类型优化**：相比普通 SRC 加速 **195.4 倍**（算术运算场景）

### 编译性能

- **10 模块项目**：全量编译 0.134s，增量编译 0.056s
- **50 模块项目**：全量编译 0.893s，增量编译 0.089s

- **自举编译器**：0.521s 编译为 525KB 可执行文件

### 体积优化

- **最小体积**：简单程序可压缩至 16 KB（原始 48 KB 的 33%）

- **自举编译器**：从 525 KB 压缩至 235 KB（44.8%）

## 关键发现

1. **LLVM 后端全面超越 Python**：在全部 20 项基准测试中，LLVM 后端的执行速度均显著快于 Python，平均快 **12.2 倍**。

2. **CPU 密集型场景优势最大**：阶乘计算（1625.7x）、快速排序（348.3x）、冒泡排序（186.0x）等 CPU 密集型任务受益最大，因为 LLVM 将段言代码直接编译为原生机器码，消除了 Python 解释器的循环开销。

3. **类型优化效果显著**：利用类型注解和推断，LLVM 后端可直接生成原生算术指令（add/sub/mul/div），避免运行时函数调用，实现 **195.4 倍** 的加速。

4. **IO 密集型场景提升较小**：文件 I/O 和 JSON 操作主要受系统调用和运行时库性能限制，LLVM 编译的优化空间有限，但仍比 Python 快 5-10 倍。

5. **增量编译有效**：对于大项目，增量编译可节省 60-90% 的编译时间，特别是当只有少量文件变更时。

6. **并行编译提升显著**：对于无依赖或低依赖的多模块项目，并行编译可带来 2.5-3.0 倍的加速。

7. **体积优化组合效果最佳**：`-Os + --lto + --strip` 三管齐下可将二进制体积减少 60-70%，适用于发布和部署场景。

8. **LLVM 新特性性能优异**：异常处理、类、协程等语言特性的 LLVM 实现均显著快于 Python 对应实现，其中协程切换速度比 Python 快 14.7 倍。
