### 2.3 附带发现（转译腿默认后端缺口，本轮不动，如实登记）

CLI 默认 compile 走 `PythonCodeGenerator`（`cli/light.py:1002-1003`），其 builtin_map
（`src/code_generator.py:317` 起）**只有 `是文件`（:496），没有 `是字母`/`是空白`**。
实测：`light compile probe.light` 产物中 `是文件` 正确映射 `_light_builtin.是文件`，
而 `是字母("a")` 保持裸名 → 运行 `NameError: name '是字母' is not defined`。
即：三内建的可用性现状为 —— unified（ANTLR）后端 ✓；默认转译后端 仅 `是文件` ✓；
解释执行（`light run`）✗（`是字母` NameError）；原生腿补齐前全部 ✗。
**建议去向**：默认转译后端 builtin_map 补 `是字母`/`是空白` 两键可一揽子对齐
（与 L-074 当年补六判型函数同一模式），属独立小任务，留给后续轮次裁决。

## 三、本轮补齐动作（按闭包原则）

原则：每后端覆盖自身 builtin_map 引用的判型族。原生腿派发链
（`_gen_typed_builtin` → 末尾 `_reject_unknown_call`）为唯一入口，补三派发即闭包。

1. **`src/llvm/runtime_typed.c`**（dv_str_starts_with 之后新增）：
   - `dv_str_isalpha(const char*)` / `dv_str_isspace(const char*)`：
     对齐 Python `str.isalpha`/`str.isspace` **整串语义**（非空且每字符通过，空串判假），
     手写 ASCII 判定（不依赖 libc locale，规避 >255 实参 UB）。
   - **如实砍线（不造假桩）**：Unicode 判型不支持——Python `'中'.isalpha()==True`
     的行为原生腿判假，C 注释与codegen 注释均已写明。
   - `是文件` 复用 runtime **既有** `dv_is_file`（runtime_typed.c:2644，S_IFREG 判定，
     os.path.isfile 语义），无需新增 C 函数；与 `文件存在`（`dv_file_exists`=access(F_OK)，
     目录判真）口径刻意区分。
2. **`src/llvm/codegen_typed.py`**：
   - declare 区补 `@dv_str_isalpha` / `@dv_str_isspace`（dv_is_file 已有 declare :749）。
   - `_gen_typed_builtin` 判型族区（是布尔之后）新增三派发：`是字母`/`是空白`
     （extractvalue 取 str 指针 → call → icmp ne → bool dv），`是文件`（同构调 dv_is_file）。
