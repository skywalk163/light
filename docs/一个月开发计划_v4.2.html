技术债清单 (待解决)

单错误报告机制 P0

Parser 遇到第一个错误就抛出 ParseError 停止，初学者需要反复修改-重试才能发现所有错误。_generate_hint 只覆盖 13 个关键字和 6 个标点。

src/parser_core.py | src/duan_parser_v3.py

教程缺少进阶内容 P0

交互式教程仅 11 个练习（变量→FizzBuzz），缺少异常处理/文件IO/模块导入/duanpub 使用。完成度检查用子串匹配，脆弱不可靠。无进度保存。

cli/tutorial.py | cli/tutorial_30min.duan

stdlib 关键字膨胀 P1

VERB_ARITY 168 个条目中 126 个是 stdlib 函数名，被硬编码为关键字。导致词法膨胀、转译器冲突、每新增 stdlib 函数就要改 keywords.py。

src/keywords.py (VERB_ARITY) | src/lexer.py | src/parser_expr.py

duanpub P2 包未桥接 P0

109 个 duanpub 包中仅 4 个 P0 + 3 个 P1 有桥接，102 个 P2 包仅有索引无运行时加载机制，无法导入使用。

stdlib/duanpub/__init__.py | tools/gen_duanpub_index.py

包管理器功能不全 P1

duan pkg 仅有基础 build 命令，缺少 install/publish/search/依赖解析。用户无法从 duanpub 索引安装包。

cli/duan_unified.py | src/package_installer.py

结束关键字冗余 P1

每个块结构都需要结束. 关键字，对初学者不友好。Python 风格的纯缩进语法可以减少 30% 的代码行数。

src/lexer.py (INDENT/DEDENT) | src/duan_parser_v3.py

缺少类型注解 P1

段言目前没有类型注解语法，LLVM 后端的类型推断缺少源代码级信息。类型注解能提升代码可读性和工具支持。

src/ast_nodes_v3.py | src/duan_parser_v3.py | src/type_system.py

文档过时 P0

57 个 .md 文件中大量使用 v1.x 过时语法，部分文档使用 花括号/句号 等已被替代的语法。

docs/ 下全部文档

Compiler 阶段性能瓶颈 P1

性能基准显示 Parser 占 59-65% 总时间，Codegen 占 15-20%，Lexer 占 12-15%。需要针对性优化。

src/lexer.py | src/duan_parser_v3.py | src/code_generator.py

LLVM 后端类系统不完整 P2

LLVM 后端 typed 模式支持基础类系统，但继承链、super 调用、类型判断等需要更多测试和完善。

src/llvm/codegen_typed.py | src/llvm/runtime_typed.c

自举编译器未完全可用 P2

bootstrap/bootstrap_level5.duan 有 95 个函数，但自举编译生成的 EXE 功能有限，部分特性未覆盖。

Web Playground 功能有限 P1

Playground 有调试器但缺少分享链接、主题切换、自动补全、代码格式化等现代 IDE 基本功能。

风险分析与应急方案

R1: stdlib 关键字剥离导致大量测试失败 高

T03 需要从 VERB_ARITY 中移除 126 个 stdlib 函数名，大量测试直接使用这些函数关键字，迁移工作量可能超预期。
应急: 先写迁移工具批量处理测试文件；分阶段剥离（先剥离 50 个最不常用的）；保留向后兼容层避免 NameError。

R2: Level 6 无空格分词破坏现有分词 高

最长前缀匹配是最底层的词法变更，可能影响所有现有代码的分词结果。向后兼容性保障是关键挑战。
应急: 严格向后兼容：有空格时走旧路径，无空格时走新路径。先在小范围测试集验证，逐步扩大。W3 预留 2 天缓冲。

R3: duanpub P2 桥接接口不兼容 中

P2 包（60 个）的 Python 接口多样，部分包可能需要复杂的适配层，某些包可能依赖第三方库。
应急: 优先桥接 10 个最常用且无外部依赖的包；对于有第三方依赖的包，使用自动检测+友好提示安装。

R4: 纯缩进语法兼容性 中

同时支持"结束"和纯缩进两种语法需要解析器能智能识别，可能导致歧义或解析错误。
应急: 纯缩进模式下遇到结束关键字给出警告而非错误；解析器优先尝试缩进模式，失败时回退到结束模式。

R5: 文档更新工作量超预期 中

57 个 .md 文件逐一审查+更新可能超过 2 天预算。同时 Level 6 语法变更导致文档需要同步更新。
应急: 用脚本批量扫描过时语法；优先更新核心 15 个文档；剩余文档标记为"待更新"并记录版本号。

R6: 性能优化收益有限 低

Python 解释器本身的性能瓶颈难以通过纯代码优化解决，20% 的性能提升目标可能过于乐观。
应急: 优先优化 Parser 阶段（59% 瓶颈）；如果可以，考虑引入 PyPy 或 Cython 加速；性能数据仅作内部参考。

R7: 类型注解设计取舍 低

类型注解语法设计需要兼顾中文自然语言风格和 LLVM 后端的类型系统需求，可能会有设计争议。
应急: 参考现有设计文档（docs/superpowers/specs/）；先实现基础类型注解，复合类型和泛型留待下一版本。
