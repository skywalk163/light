# 编译器内部设计

> **版本：** v6.0
> **最后更新：** 2026-08-07

## 概述

段言编译器采用经典的编译器架构，包含词法分析、语法分析、语义分析、中间表示生成、代码优化和目标代码生成等阶段。编译器支持三种后端：SRC（自研解析器）、ANTLR（兼容旧语法）和 LLVM（原生编译）。

## 编译器管线架构

```
.duan 源文件
    │
    ▼
┌──────────────────────┐
│ 词法分析器 (Lexer)   │  输入 → Token 流
│ src/lexer.py         │  三层分词机制
└──────────┬───────────┘
           │
           ▼
┌──────────────────────┐
│ 语法分析器 (Parser)  │  Token 流 → AST
│ src/parser_stmt.py   │  支持缩进/花括号语法
│ src/parser_expr.py   │
│ src/parser_core.py   │
└──────────┬───────────┘
           │
           ▼
┌──────────────────────┐
│ 语义分析器           │  AST → 语义检查
│ src/semantic_analyzer│  类型检查、作用域
│ .py                  │
│ src/type_checker.py  │
└──────────┬───────────┘
           │
           ▼
┌──────────────────────┐
│ 代码生成器           │  语义检查 → 输出
│ ┌──────────────────┐ │
│ │ SRC 后端 (默认)  │ │  → Python 解释执行
│ │ code_generator.py│ │
│ ├──────────────────┤ │
│ │ ANTLR 后端       │ │  → ANTLR 解析 + 解释
│ │ duan_compiler.py │ │
│ ├──────────────────┤ │
│ │ LLVM 后端        │ │  → LLVM IR → 原生 EXE
│ │ llvm_codegen.py  │ │
│ └──────────────────┘ │
└──────────────────────┘
```

### 1. 词法分析（Lexer）

词法分析器位于 `src/lexer.py`，实现决策29的三层分词机制：

- **类型切换自动分词**：`甲加1` → `[甲] [加] [1]`
- **双字关键词优先匹配**：`定义甲` → `[定义] [甲]`
- **元数驱动参数收集**：`打印 甲`（元数=1）→ `[打印] [甲]`

核心特性：
- 支持中文符号（`。`、`，`、`：`等）自动转换为英文符号
- 保护复合词（如`四舍五入`、`二进制`不会被拆分为数字）
- 支持运算符动词识别（`加`、`减`、`乘`、`除`等）

### 2. 语法分析（Parser）

语法分析器位于 `src/parser_stmt.py`、`src/parser_expr.py` 和 `src/parser_core.py`。

支持两种语法风格：
- **缩进风格**：使用缩进表示代码块（推荐）
- **花括号风格**：使用 `{ }` 表示代码块（兼容旧语法）

解析的主要语句类型：
- 变量声明：`设 变量 为 值`
- 条件语句：`如果/否则如果/否则`
- 循环语句：`遍历/当/跳出/跳过`
- 函数定义：`段落/函数 名 接收 参数`
- 类定义：`类/继承/属性/构造`
- 异常处理：`尝试/捕获/抛出/最终`
- 模式匹配：`匹配/情况/默认`
- 导入导出：`导入/从/导出`
- 异步编程：`异步/等待`
- 上下文管理器：`使用`

### 3. 语义分析（Semantic Analyzer）

语义分析器位于 `src/semantic_analyzer.py`，负责：

- **类型检查**：验证表达式类型是否正确
- **作用域解析**：管理变量作用域和生命周期
- **名称绑定**：将标识符绑定到其声明
- **泛型实例化**：处理泛型类型参数
- **可空类型检查**：验证空安全约束

类型系统支持：
- 基础类型：`整数`、`小数`、`字符串`、`布尔`、`列表`、`字典`
- 泛型类型：`列表<整数>`、`字典<字符串, 小数>`
- 可空类型：`可空<整数>`
- 类型注解：`段落 加法 接收 a:整数, b:整数 返回 整数`

### 4. 中间表示（IR）

中间表示位于 `src/ir.py`，采用三地址码（Three-Address Code）形式：

```
# 示例：计算 3 + 5
t1 = 3
t2 = 5
t3 = t1 + t2
```

IR 优化器支持：
- 常量折叠（Constant Folding）
- 死代码消除（Dead Code Elimination）
- 公共子表达式消除（CSE）
- 循环不变式外提（Loop Invariant Code Motion）

## LLVM 后端设计

LLVM 后端位于 `src/llvm/` 目录，将段言代码编译为原生机器码。

### 编译流程

```
.duan 源文件 → Lexer → Parser(V3) → AST适配 → LLVM IR → 优化 → 目标文件 → 链接 → EXE
```

### 核心组件

| 组件 | 文件 | 功能 |
|------|------|------|
| TypedLLVMCodeGen | `src/llvm/codegen_typed.py` | 生成 LLVM IR |
| LLVMCompiler | `src/llvm/compiler.py` | 编译流程管理 |
| 运行时库 | `src/llvm/runtime_typed.c` | 运行时支持函数 |

### 类型映射

| 段言类型 | LLVM IR 类型 |
|---------|-------------|
| 整数 | `i64` |
| 小数 | `double` |
| 布尔 | `i1` |
| 字符串 | `i8*` (指针) |
| 列表 | 结构体指针 |
| 字典 | 结构体指针 |

### 支持的特性

- 基础类型：整数、小数、布尔、字符串
- 控制流：条件、循环、函数调用
- 内存管理：GC 自动内存管理
- 异常处理：setjmp/longjmp 实现
- FFI 调用：通过 LLVM 的 `extern` 机制

## 增量编译系统

增量编译系统位于 `src/incremental_build.py`，通过文件变更检测和缓存复用加速编译。

### 工作原理

1. 维护文件哈希表（`.duan_cache/` 目录）
2. 只重新编译发生变化的文件
3. 缓存编译后的 AST 和 IR
4. 依赖图追踪：只重新编译受影响的模块

### 缓存策略

```
源文件变更检测
    │
    ▼
哈希比较 → 未变更 → 复用缓存
    │
    变更
    ▼
重新编译 → 更新缓存 → 更新依赖图
```

### 缓存文件结构

```
项目目录/
├── .duan_cache/
│   ├── main.duan.ast       # 缓存的 AST
│   ├── main.duan.ir        # 缓存的 IR
│   ├── main.duan.hash      # 文件哈希值
│   ├── utils.duan.ast
│   ├── utils.duan.ir
│   └── utils.duan.hash
└── duan.lock               # 依赖锁定文件
```

## 缓存系统

缓存系统位于 `src/compiler.py` 中的 CompilerCache 类，提供多级缓存加速。

### 缓存层级

| 层级 | 存储位置 | 缓存内容 | 命中速度 |
|------|---------|---------|---------|
| L1 内存缓存 | 内存字典 | AST 节点 | 纳秒级 |
| L2 文件缓存 | `.duan_cache/` | AST / IR | 毫秒级 |
| L3 分布式缓存 | (预留) | 编译产物 | 网络级 |

### 缓存键设计

```
缓存键 = 哈希(源文件路径 + 文件内容哈希 + 编译器版本)
```

### 缓存失效策略

- 文件内容变化 → 自动失效
- 编译器版本更新 → 清空缓存
- 依赖模块变更 → 级联失效
- 手动清理：`duan clean --cache`

## 编译器命令行接口

段言编译器通过 `duan` 命令提供统一的 CLI 接口：

```bash
# 解释执行（SRC 后端）
duan run hello.duan

# 编译为 Python
duan compile hello.duan -o hello.py

# LLVM 原生编译
duan compile hello.duan --backend llvm-typed -o hello.exe

# 语法检查
duan check hello.duan

# 显示 AST
duan ast hello.duan

# 显示 Token 流
duan tokens hello.duan

# 交互式 REPL
duan repl

# 交互式教程
duan tutorial
```

## 编译器性能

| 阶段 | 操作 | 平均耗时 |
|------|------|---------|
| 词法分析 | 1000行代码 | < 5ms |
| 语法分析 | 1000行代码 | < 15ms |
| 语义分析 | 1000行代码 | < 10ms |
| 代码生成 | 1000行代码 (SRC) | < 20ms |
| LLVM 编译 | 1000行代码 (含优化) | ~500ms |

## 自举编译器

段言编译器本身也是用段言编写的，实现了自举（self-hosting）。自举编译器的源码位于 `bootstrap/` 目录：

- `bootstrap/lexer.duan` — 词法分析器
- `bootstrap/parser.duan` — 语法分析器
- `bootstrap/compiler.duan` — 编译器主流程
- `bootstrap/codegen.duan` — 代码生成器
- `bootstrap/bootstrap_merged.duan` — 合并后的自举编译器

自举过程：
1. 用 Python 实现第一版编译器
2. 用段言重写编译器（自举编译器）
3. 用自举编译器编译自己（自举验证）
4. 持续迭代优化
