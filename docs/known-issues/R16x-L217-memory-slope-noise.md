# KI-R166-01 · R16x L-217 的 MB 斜率判据在共享 mac/win runner 上无分辨力

**任务**：T-0252（R166-T2）
**平台**：macOS 26 arm64（GitHub `macos-26-arm64`）vs FreeBSD 15.1 x86_64（fb98）vs Intel macOS 12.7.6 x86_64
**结论**：`test_P4P5_相对改善有牙` 的 RSS 斜率在共享 mac/win runner 上信噪比 < 1，**判据限平台**；
`P1'/P3'/P2'` 的 10 倍信号判据仍然保留。**fail=0/skip 不代表 L-217 容器路径没问题**（见 §5）。

---

## 1. 现象：同码不同果（方向都会翻）

同一份代码、同一个探针，4 台 mac job 的 `增长MB` 互不相同，且**方向来回翻**：

| job | 用例 | 原始数字 |
|---|---|---|
| mac 3.10 | P5 | 修前 `(-1.0MB, 采样数 0)`（哨兵） vs 修后 1067.83MB |
| mac 3.11（pre-merge `807f5e0`） | P4 | 修前 978.1MB vs 修后 1210.1MB（**反向 -19.2%**） |
| mac 3.11（merge `12fac8c08` 后） | P4 + P3 | P4 修前 952.7 vs 修后 1246.3（**反向 -23.5%**）；P3 反跑 `-1.0MB`（哨兵） |
| mac 3.12 | P5 + P4 | P5 修后 1358.09（峰值 1607.05）；P4 修前 860.4 vs 修后 1420.8（**反向 -39.5%**） |
| mac 3.13 | P5 + P4 | P5 修后 1431.42（峰值 1734.19）；P4 修后 1062.11（峰值 1352.14） |

修前绝对值本身就横跨 860 / 952 / 1062 / 1358MB（±28%）。**方向**在 CI mac 上是
「修前 < 修后」，在本机/FreeBSD 上是「反跑 > 修后」（见 §3）——说明比较结果由 runner
的 CPU 配额/负载决定，不是机制决定的。

## 2. 哨兵：`采样数 < 2` 被当成「斜率没复原」

旧 `_跑` 在 `采样数 < 2` 时直接返回 `增长MB=-1.0`，并**丢弃 `rc` 与 stdout/stderr**，
于是「进程 2s 内退出（zc 崩溃 / 启动失败 / 被调度饿死）」与「反跑没牙（斜率 ≈ 0）」
在断言眼里是同一种红。最小复现（FreeBSD，旧口径）：

```sh
# 用一个立即退出的二进制喂给 _跑：等价于「探针秒退」
python3 - <<'PY'
import importlib.util, sys
repo='/tmp/t0252_wt'; sys.path[:0]=[repo, repo+'/src', repo+'/tests']
spec=importlib.util.spec_from_file_location('m', repo+'/tests/unit/test_R16x_L217_所有权收敛.py')
m=importlib.util.module_from_spec(spec); spec.loader.exec_module(m)
print(m._跑('/usr/bin/true', 'P5'))
PY
# 旧输出：{'增长MB': -1.0, '峰值MB': -1.0, '采样数': 0}
# stderr 为空——不是探针没输出，而是旧 _跑 根本没读管道
```

同理，`C_ROUNDS=2000` 让探针 2s 内跑完会得到同一哨兵；**CI 上的 `采样数: 0`
最可能就是这一类：探针在第一个 2s 采样点之前就退出了（崩溃/被 OOM/被调度）**。
旧实现没有 `rc` 佐证，无法进一步区分——这正是本卡要补的取证位。

**修复后**（同一份入口，三态已拆开）：

```
秒退-rc0  : {'增长MB': -1.0, '采样数': 1, 'rc': 0, '输出尾': '', '终止': '自行退出'}
  -> _断言测量有效 => Skipped「测量无效：采样数=1（窗口内进程提前退出…）」
崩溃-rc非0: {'增长MB': -1.0, '采样数': 1, 'rc': 7, '输出尾': 'boom-stderr\n'}
  -> _断言测量有效 => Failed「探针异常退出 rc=7（这不是噪声，是崩溃/ABI 问题）」
```

即：**秒退/采样不足 = 测量无效（重采一次后仍无效则 skip）；rc≠0 = 真崩溃（必须 fail）**。
`/tmp/crasher.sh`（`echo boom-stderr >&2; exit 7`）证明 stderr 已被捕获。

## 3. 三次重复实测：噪声 ≥ 机制信号

同一命令连跑三次（12s 窗口、6 个采样点，t≈0 的点只用于判断是否启动，斜率从 2s 起算）：

### FreeBSD 15.1 x86_64（fb98，clang 19.1.7）

| 种类 | 修后三次 (MB) | 修后中位 | 反跑三次 (MB) | 反跑中位 | 单侧最大极差 |
|---|---|---|---|---|---|
| P4 | 1249 / 1324 / 1269 | 1269 | 1292 / 1350 / 1420 | 1350 | 9.5% |
| P5 | 1189 / 1256 / 1277 | 1256 | 1441 / 1353 / 1307 | 1353 | 9.9% |

方向：反跑中位仅比修后高 **6.4%（P4）/ 7.7%（P5）**，而同一态三次极差已到 **9.5~9.9%**
⇒ **信噪比 < 1**。15% 容差只是把 `修前 >= 修后×0.85` 变成「不倒退哨兵」，
不是「机制有牙」的证明。

### Intel macOS 12.7.6 x86_64（本机，clang 19.1.7）

| 种类 | 修后三次 (MB) | 中位 | 反跑三次 (MB) | 中位 | 单侧最大极差 |
|---|---|---|---|---|---|
| P4 | 470.5 / 344.2 / 456.7 | 456.7 | 706.8 / 469.8 / 670.8 | 670.8 | 35.4% |
| P5 | 448.1 / 326.9 / 370.0 | 370.0 | 715.5 / 474.7 / 630.1 | 630.1 | 38.2% |

方向中位差 +46.9%（P4）/+70.3%（P5），但极差 35~38%；最差一组配对
（P4 反跑 469.8 vs 修后 470.5）只剩 **-0.1%**，15% 容差靠运气过。
再叠加 CI arm64 的反向 39.5%，**这条判据在 mac 上没有分辨力**。

## 4. 裁决（本卡选择「限平台」，卡面方案二）

- `P4'/P5'`：`darwin` / `win32` **skip**，skip 文本带本文件路径与实测数字；
  `Linux`/`FreeBSD` 保留 `修前 >= 修后×0.85`（容差 15% = FreeBSD 实测极差 9.9% 的 1.5 倍）。
- `P1'/P3'/P2'`：**不降级**。它们判的是「修后 ≤2MB vs 反跑 ≥20MB」（10 倍信号），
  在 mac/FreeBSD 上都稳定；只新增三态测量校验（崩溃 fail / 采样不足重采后 skip）。
- 哨兵不再等同于红：`采样数 < 2` 先重采一次（总时长仍受 pytest `--timeout` 约束），
  仍不足则 skip 并打印 `rc`/`输出尾`；`rc≠0` 一律 fail。
- 未删断言、未放宽 `P1/P3/P2` 阈值；`P4/P5` 的 mac skip 是**明确的平台能力边界**，
  不是把红藏起来。

## 5. 诚实披露：skip 不能读成「L-217 容器路径没问题」

- mac/win 上 `P4/P5` 为 skip ⇒ **该平台对「容器路径不倒退」零覆盖**；
  CI 绿只说明「没有在信号不足的地方继续抖红」，不说明 arm64 上机制正确。
- 机制是否有牙由 `P1'/P3'` 承担；容器所有权本身是设计 C5 浅拷契约，不在本卡 scope。
- 若后续要恢复 mac 覆盖，需要：固定 CPU/避免共享 runner 抖动（自建 arm64/专用机），
  或把判据改成**归一化斜率**（按完成轮数而非墙钟 12s 计 RSS/轮），二者都要另开卡。

## 6. arm64 到位后的复验步骤

1. 在 `macos-14`/`macos-26` arm64 runner（或自建 Apple Silicon）上跑：
   `python -m pytest -q tests/unit/test_R16x_L217_所有权收敛.py -k "P4P5" -s --timeout=600`
2. 连跑 3 次，记录修前/修后中位与极差；若极差 < 机制方向差，可把 `_P4P5噪声容差`
   按实测重标并恢复 `darwin` 判定（需要同步改 `docs/known_issues.md` 本节）。
3. 若 arm64 上稳定复现「修前 < 修后」，按卡面要求开**新卡**定位容器路径的代码层缺陷，
   不要在 `P4/P5` 里用更大容差把方向性错误吃掉。
