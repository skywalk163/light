## B-1（根治候选，优先）Job Object 成员查询

**现状**：`stdlib/进程树.light` 的 `[R92-A-LEAK]` 补杀走「全系统进程表 + PPID 链回溯」，
在 PID 复用压力下理论上存在误杀兄弟进程的风险（虽然 25,285 样本探针**未复现**）。

**方案要点**：
1. 杀树入口改为：先 `CreateJobObject` 把目标进程树纳入 Job，再 `TerminateJobObject`
   （Windows 原生保证整树终止，**不需要** PPID 回溯）。
2. 成员判定改用 `QueryInformationJobObject(JobObjectBasicProcessIdList)`
   或 `AssignProcessToJobObject` 的继承特性，杜绝 PID 复用误伤。
3. 需评估：Job 嵌套限制（Windows 8 前不支持嵌套 Job）、权限、与现有
   `Toolhelp32` 快照路径的共存/切换开关。

**验收**：
- 单层/多层进程树杀树用例 100 轮 0 漏杀；
- 人为极限 PID 复用压力（≥25k 短命树）下无关进程被杀数 = 0（本来已是 0，需保持）；
- 全量 `-n 4` 低负载 3 轮无 node down（若 KI-R94-01 因此消失，则一并销账）。

**风险**：新增 ctypes 面 + 新测试，属**功能改造**，必须独立轮次、独立门禁，禁止塞进冻结轮。

## B-2（兜底候选，优先级低于 B-1）创建时间闸门

**方案要点**：对「按 PID 判定是否为目标后代」的场合，额外比对进程**创建时间**
（`psutil.Process.create_time()`）与预期窗口，PID 复用但创建时间不符即跳过。

**为什么只是兜底**：
- 它只能防止「误杀」，**不能解释** worker 被谁杀（KI-R94-01 的机理仍未定性）；
- 引入新的时间窗口阈值 → 又是一个需要标定的魔数，有二次 flaky 风险。

**前置条件**：B-1 落地后若仍有漏杀/误杀，才启用 B-2；否则**不做**。
