# T-0211 交付摘要

## 问题
`解析时间` 默认格式只吃空格分隔（`%Y-%m-%d %H:%M:%S`），遇到 ISO-8601 的 T 分隔
（如 lighthive 租约时间戳 `2026-10-30T15:00:00`）静默返回 `空`；失败路径一律
`return None`，把「格式不对」伪装成「没有时间」，后续 `时间加减(空, …)` 也得空，
全程无一行报错。

## 改动（仅 paths 内文件）
- `stdlib/时间管理.py`：
  - 缺省格式（`格式=None`）同时尝试 `%Y-%m-%dT%H:%M:%S` 与 `%Y-%m-%d %H:%M:%S`；
  - 显式传入格式时仍只按该格式解析（不偷偷回退）；
  - 解析失败抛 `ValueError`，错误信息写明原始文本与候选格式；
  - 新增 `试解析时间(文本, 格式=None)`：失败返回 `空` 不抛，供「允许失败」的调用点显式使用；
  - `__all__` 登记 `试解析时间`。
- `stdlib/时间管理.light`：未改。该文件头注释明确列出 `解析时间` 属「原生腿无法完成」
  的 Python 独占族，本就不在 .light 安全子集内，无需同步。
- `tests/unit/test_LH37_解析时间.py`：新增，12 例覆盖验收 1–5。

## 验证（实跑）
`python -m pytest -q tests/unit/test_LH37_解析时间.py` → **12 passed**。

冒烟：ISO 解析 True / 空格解析 True / 试解析失败返回 None / 时间加减(ISO,+180分)=18:00:00。

## 边界遵守
- 未动 `时间戳` / `格式化时间` / `时间加减` / `时间差秒` 的行为；
- 未改 `stdlib/builtins.py`（不在 paths 内，测试直连 `时间管理` 模块导入）。
- 已知影响：存量 `tests/unit/test_LH01_时间算术.py` 中 `Test解析时间容错` 类断言的是
  旧「失败返回空不抛」行为，本任务即要改该 P0 行为，该类后续应由调用方迁移到
  `试解析时间`；不在本任务 paths 内，未改动。
