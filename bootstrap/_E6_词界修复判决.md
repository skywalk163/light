## 2. 词界修法

改 `bootstrap/level7_generated.py` 的 `扫()` 机制1（约 441–464 行）：
- 旧：关键字命中即发 KW；仅 `类` 且前一字符是 CJK 才跳过。
- 新：**行首（最后 token 为 NEWLINE/INDENT/DEDENT，或 toks 空）总是切关键字**（`段主函数`→KW段+ID主函数、`设己.x为x`→KW设）；**行中**，若前一字符是 `空格`/`(`/`[`（新词起点）且后随 CJK，则整串作标识符不切（`类型名到Python`、`返回类型`、`类型结果`）。
- 迭代过程：先做 `类`-only 保护 → STAGE1 绿但暴露 `返回类型` 被切；再扩到"行首切/行中不切" → 误伤无空格用例；最终加"行首检测"判据，20/20 复绿。

## 4. STAGE2 挂起根因（新，已 pin）

- faulthandler dump：`comp_if → compile_block → comp_if` 无限递归（栈深约 100），`p` 不前进。
- out1 的 parser 用 `find_matching_end` 找块尾，该函数期望 **`结束` token** 关闭 if/while 块（对应 level6.light:753–780）。但 `bootstrap_level6.light` 是**纯缩进方言**，源码里一个 `结束` 块关闭符都没有（`结束` 仅出现在字符串字面量与变量名 `找引用结束`/`找输出结束` 中，实测 out1 分词出 `KW结束=0`）。
- 找不到 `结束` → 块边界一路走到 token 尾 → 嵌套 `如果` 触发无限递归。
- **非本次修复引入**：原始 level7_generated.py 的 STAGE1 直接 SyntaxError，从没走到 STAGE2；词界修复让 STAGE1 转绿，才暴露这层既有的方言不匹配。
