**补内建后的真红（两层，与 v3 红因不同类）**：

## E.2 v3 红因复跑：仍复现，根因在 v3.light 自身分词器，src 无辜

**复跑调用（按体检报告③约定）**：src 后端 `LightParser` + `PythonCodeGenerator` 编 `bootstrap_v3.light` → 编译器 A（177524 字符，库式模块）；exec A 建 `_light_builtin` 命名空间 → `ns['compile_source'](bootstrap_v3.light)` → B（104679 字符）→ `compile(B,'<gen>','exec')`。

| 命令 | 退出码 | 结论 |
|---|---|---|
| `python .scratch\e2_probe.py` | **1** | compile(B) 抛 SyntaxError |

**S2 后是否仍复现：是。** B 第 521 行原文：
```
514: def 匹配():
516: 关键字 / 517: 接收 / 518: 文本 / 519: , / 520: 关键字列表
521: ：        ← SyntaxError: invalid character '：' (U+FF1A), lineno=521
```

**根因 pin 到的位置（关键反转：不在 src/）**：
- (a) **多字中文名被拆**：A 的内嵌分词器把 `匹配关键字` 切成 `匹配`(关键字) + `关键字`(标识符)。因为 light 关键字表含 **2 字关键字 `匹配`**（`bootstrap/bootstrap_v3.light:440`），而"单字关键字边界保护"只对长度==1 生效（light `bootstrap_v3.light:584` `如果 找到长度 等于 1 且…`，被 src 忠实译为 A:1239 `if ((找到长度 == 1) …)`）。`匹配` 是 2 字，保护不触发，被当关键字前缀吃掉。随后方法定义解析（light ~1552 / A:2918）期望 `接收` 却见到 `关键字`，跳过参数表，剩余签名逐行裸泄。
- (b) **全角冒号 U+FF1A**：不是独立转义缺陷。正常路径有翻译（light:452 `：`→`冒号`，正确解析时输出 ASCII `:`）；裸 `：` 是 (a) 错位后 `冒号` token 落入 A 的 `expr_stmt` 回退分支（A:4843-4849）原样回吐。

**反证 src 无辜**：同一行 light 被 src 后端编进 A 时完全正确——A:1130 `def 匹配关键字(文本, 关键字列表):`（4 字全名 + ASCII 冒号）。src 是忠实翻译器，对此无可改。

**处置：仅登记定位，未改 src**。修复点在 `bootstrap_v3.light:584`（把边界保护从"单字"泛化为"任意长度关键字后仍接合法标识符字符则整体作标识符"），但任务硬约束**不许改 bootstrap_v3.light 本身**，故不硬改。定位报告：`.scratch/E2_定位报告.md`。

> 含义修正：体检报告④.3"等 S2 落地后复跑，若仍红再按 codegen 分支修"的预设被推翻——S2 改的是 `src/` 翻译器，而 src 已被反证无辜；v3 的断裂点在 v3.light 自身的关键字/标识符歧义，不在 S2 域。
