## 1. 现役 parser 块边界机制 + out1 缺的那一段

### 现役绿链（level5 方言）怎么闭块
- `bootstrap_level5.light`（38860B）是 **`结束` 关键字 + `：` 冒号方言**：每个 段落/如果/当 块都以独立成行的 `结束` 收尾（全文 409 处 `结束`）。
- 现役宿主 `level6_generated.py` 编译 level5.light 时，词法层**丢弃换行/缩进**，parser 用 `find_matching_end(toks,p,level)` 数块开关键字(如果/当/遍历/段落…)推 level、靠命中 `结束`(level==1) 闭块。level5.light 有 `结束`，故收敛绿（44614B×3）。

### out1 为什么挂（根因）
- 真自举源 `bootstrap_level6.light`（改前 61961B）已被改写成**纯缩进方言**：无 `结束`、无 `：`。
- 但 out1 的词法层 `扫()`（改前 168–173 行）把**空格/`\n`/缩进全部直接丢弃**（不发 NEWLINE/INDENT/DEDENT），`：。，` 也丢弃——词法后是扁平 KW/ID/NUM/STR 流，parser 无从知道缩进层级。
- out1 的 `find_matching_end` 仍沿用 level5 的 `结束` 闭块逻辑 → level6.light 一个 `结束` 都没有 → 块边界一路走到 token 尾 → 嵌套 `如果` 触发 `comp_if→compile_block→comp_if` 无限递归爆栈（STAGE2 挂死）。

### out1 缺的整段（= level7_generated.py 手增强版已有、level6.light 描述里缺失）
1. **词法层缩进栈**：按行首空格数对比栈顶，发射 `INDENT`/`DEDENT`，行尾发射 `NEWLINE`，EOF 冲栈到缩进 0。
2. **`find_matching_end` 改 INDENT/DEDENT 深度计数**（depth==0 命中 DEDENT 即块尾），不再等 `结束`。
3. **comp_if/comp_while/comp_for**：条件表达式后先跳 `NEWLINE`、再跳 `INDENT`，再用深度版 find_matching_end 定块尾；否则子句同步跳 NEWLINE/INDENT。

> 实证：level6.light 源码**实际不含任何 类/尝试 块**（这些关键字只出现在关键词表与 parser 自身逻辑里），故 compile_class/comp_try 不会被触发，无需改动；表达式层天然在 NEWLINE 处停（运算符只认关键字、一元表达式对 NEWLINE/INDENT/DEDENT 类型不匹配即返回 None 不吞 token）；compile_stmts/compile_top 靠默认 `p+=1` 跳过结构 token、靠"下一函数关键字"收尾，亦无需改。
