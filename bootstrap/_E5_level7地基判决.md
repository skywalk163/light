## E.5b level7 自编译阶梯：红，根因已实证 pin 到行

**候选自身源证伪**：先用 level7 编译 `bootstrap/bootstrap_level6.light`（61961B）一次：

| 项 | 值 |
|---|---|
| out1 头注 | `# Generated by Light Level 7`（仅 2 行） |
| out1 大小 | 59434 B / 1364 行 |
| 磁盘 level7_generated.py | 88256 B（头注含调试外壳约 40 行） |
| out1 合法性 | **compile() 失败** |

→ out1 既不等于、量级也差 28KB，且非法。`bootstrap_level6.light` 不是磁盘那份 88KB `level7_generated.py` 的忠实自举源（后者应是手工补过调试外壳/或改过含保留子串的标识符）。即便如此，拿它当候选源跑阶梯，第一步就断。

**阶梯执行（每阶段 subprocess 隔离，60s 超时）**

| 阶段 | 结果 |
|---|---|
| STAGE1：level7_generated.py 编 bootstrap_level6.light → out1 | **rc=5，out1=59434B，COMPILE_OK=False** |
| STAGE2 / STAGE3 | 未执行（out1 非法 Python，无法 exec） |

**根因（用 level7 自带 `词法()` 实测，非推断）**
- 现场：`.scratch/level7_out1.py:42:5` → `def ():`（函数名缺失，offset 5 正是 `def ` 后该出名字处）；紧跟 L43 一个莫名其妙的 `class 型名到Python:`。
- 源 `bootstrap_level6.light:48` = `段落 类型名到Python 接收 tname`，分词实测：
  `KW 段落` → **`KW 类`** → `ID 型名到Python` → `KW 接收` → `ID tname`。
- 即无空格分词器把合法标识符 **`类型名到Python` 在保留字 `类` 处贪心切开**（源行明明有空格也照切）。解析器误读为 `段落 类 型名到Python`=类声明，吐出 `class 型名到Python:`，把 `段落` 的名字槽吃空 → `def ():`。调用点 `bootstrap_level6.light:73`（`设 type_str 为 类型名到Python(type_name)`）同样被切。
- 本质缺陷：**保留字匹配不尊重标识符词边界**。关键字表塞了大量单字短关键字（`类/段/返/过/若/否/遍/非/试/捕/抛/终/接/承/出/导/自…`），任何中文标识符只要**内含**这些字就被撕裂。这是 level7 分词器自身的词法歧义 bug，与宿主 ns/内建无关。

## 与 E.2（v3 红因）的关系：同一类病

E.2 的 v3 红因是 2 字关键字 `匹配` 贪吃标识符 `匹配关键字` 前缀；本轮 level7 红因是单字关键字 `类` 撕裂标识符 `类型名到Python`。**根因同构**：无空格分词器的关键字最长匹配/保留字判定不要求"匹配处不是合法标识符字符的内部"。修这一个词界规则，理论上同时解开 level7 自举闭环与 v3 合并版的死结（两处分词器是同源思路）。
