## ③ 红因定位：v3.light 链路缺哪个环节

红不在"文件缺失"，而在两处：

**红因 A（探针脚本缺陷，已在 bootstrap/ 内小修，见下）：**
1. `verify_all_components()` 路径双拼：`self.bootstrap_dir` 已指向 `bootstrap/`，字典里又写 `"bootstrap/lexer.light"` → 实际查 `bootstrap/bootstrap/lexer.light`，恒不存在 → 谎报 0/6。
2. 第 4 步假设"编译器 A 读 stdin"，把源码管道喂进去。实测生成的编译器 A 是**库式模块**：裸跑只定义函数即退出（无 argv、无 stdin 处理），对外暴露 `compile_source(source)` / `compile_file(filepath)` / `main(filepath)`（见生成产物尾部及 `main.light`）。stdin 必然"无输出"。

**红因 B（真实自举缺陷，超出 bootstrap/，只登记不修）：**
修正调用约定后，编译器 A 编 `bootstrap_v3.light` 产出 B（104679 字符），但 B **第 521 行起语法非法**：

```python
def 匹配():          # ← 函数名被截断
关键字               # ← 裸 token 泄漏到顶层
接收
文本
,
关键字列表
：                   # ← 全角冒号（U+FF1A）直接进了 Python 源码
```

对应源码 `bootstrap/bootstrap_v3.light:523`：`段落 匹配关键字 接收 文本, 关键字列表：`。
即：v3 自举编译器在编译**自身源码**里这条 `段落…接收…：` 语句时，codegen 把多字符中文名 `匹配关键字` 拆碎、裸 token 逐行泄漏、全角冒号未翻译——**src 后端生成的 A 编不动 v3 语法的这条语句**。
注意：A 本身（src 后端产物）里同一函数是 `def 匹配关键字(文本, 关键字列表):` 正确的，说明缺陷在"A 编自己"这条路上的 codegen，且 A 是今日由当前 `src/` 后端现编译的——S2 正在改 `src/code_generator*.py`，**是否 S2 在途改动引入的回归，需 S2 落地后复跑本探针确认**，本报告不替 src/ 下结论。

**附带观察（登记）：** `level6_self_compiled*.py` 这组输出文件名被 `test_bootstrap_level6.py`、`test_bootstrap_secondary.py/v2/v3.py`、`test_bootstrap_convergence.py` 至少 5 个脚本共用——今日 12:26 磁盘上该组文件为 54802 B（他脚本产物），本探针跑完变为 44614 B。收敛探针从 `level6_generated.py` 冷启动，结果不受污染，但文件名互踩是隐患。
