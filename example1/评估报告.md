## 三、六大高频问题

### 问题1: 函数定义 `段落` 关键字丢失 (6次)

**现象**: `def func():` 翻译时经常丢失 `段落` 关键字，只输出函数体。

**示例**:
```
Python: def fib(n):
光明(错误): 如果 n 小于等于 1：
光明(正确): 段落 fib 接收 n：
    如果 n 小于等于 1：
```

**影响用例**: func_01, func_02, func_03, algo_03, algo_04, (多个算法题)

**根因**: 0.5B 模型容量不足，面对多行函数时倾向于"跳过"函数头直接翻译函数体。训练数据中函数定义样本需要更强化。

### 问题2: 变量名/函数名翻译为中文 (8次)

**现象**: 明确要求"变量名保持英文原样"，但模型仍将英文变量名/函数名翻译为中文。

**示例**:
```
Python: def bubble_sort(arr):       → 段落 冒泡排序 接收 arr  (冒泡排序 应为 bubble_sort)
Python: def distance(self):         → 段落 距离：              (距离 应为 distance)
Python: class Animal:               → 类 动物：                (动物 应为 Animal)
Python: def factorial(n - 1)        → 裁定(n 减 1)             (裁定 应为 factorial)
Python: return -1                   → 返回 倒数                (倒数 应为 -1)
```

**影响用例**: func_03, oop_01, oop_02, algo_01, algo_02, complex_04

**根因**: 这是 0.5B 模型最顽固的问题。训练数据中虽有"变量名保持英文"的规则，但 0.5B 参数量无法充分学习这个约束。中文翻译是模型的"本能"。

### 问题3: `**` 幂运算翻译错误 (4次)

**现象**: `**` 应翻译为 `幂`，但模型输出 `乘方`、`乘 x 乘 x` 等。

**示例**:
```
Python: a ** b    → a 乘方 b        (应为 a 幂 b)
Python: x ** 2    → x 乘 x          (应为 x 幂 2)
Python: n ** 0.5  → n 乘 0.5        (应为 n 幂 0.5)
```

**影响用例**: ops_01, func_04, data_02, algo_04

**根因**: 0.5B 模型对 `**` 运算符的映射记忆不牢固，容易"退化"为乘法。SYSTEM_PROMPT 中 `** 翻译为 幂` 的规则虽已修复，但权重层面尚未用修复后数据重训。

### 问题4: `否则如果` 仍未修复 (1次)

**现象**: `elif` 应翻译为 `否则若`，但模型输出 `否则如果`。

**示例**:
```
Python: elif score >= 80:    → 否则如果 score 大于等于 80：  (应为 否则若)
```

**影响用例**: basic_02

**根因**: 模型权重中 `否则如果` 的记忆很强。虽然 Modelfile 的 SYSTEM_PROMPT 已修复为 `否则若`，但 0.5B 模型对 prompt 指令的遵从度有限，仍会输出权重中记忆的模式。**需要 GPU 重训**。

### 问题5: 负数处理错误 (1次)

**现象**: `-1` 应保持原样，但模型翻译为 `减 1` 或 `倒数`。

**示例**:
```
Python: return -1     → 返回 减 100      (应为 返回 -1)
Python: return -1     → 返回 倒数         (应为 返回 -1)
```

**影响用例**: ops_03, algo_02

**根因**: 与问题4类似，权重层面的记忆未通过重训修正。

### 问题6: `and` 翻译为 `和` 而非 `且` (1次)

**现象**: Python `and` 应翻译为光明 `且`，但模型输出 `和`。

**示例**:
```
Python: a and b    → a 和 b    (应为 a 且 b)
Python: not a      → not a     (应为 非 a)
```

**影响用例**: ops_04

**根因**: 训练数据中 `and` 的样本可能不足，模型退化为自然语言"和"。

## 六、提升建议

### 短期（无需重训）

1. **后处理修正**: 在 `local_infer.py` 中添加正则后处理，自动替换常见错误：
   - `否则如果` → `否则若`
   - `乘方` → `幂`
   - `返回 减` → `返回 -`
   - `返回 倒数` → `返回 -1`
   - `和` (在逻辑运算上下文) → `且`

2. **Few-shot prompting**: 在 prompt 中附加 2-3 个正确翻译示例，增强 0.5B 模型的上下文学习

3. **分步翻译**: 对复杂代码先拆分为函数签名 + 函数体，分别翻译后拼接

### 中期（需 GPU 重训）

4. **用 v6 数据集重训**: 当前数据集已 100% 干净率，但模型权重仍是旧的。在 Kaggle T4 上用 1168 条数据全量重训：
   ```bash
   python train_gpu_lora.py --preset qwen2.5-0.5b --qlora
   ```

5. **增加薄弱模式样本**: 针对6大高频问题增加专项训练样本：
   - 函数定义 + 多行函数体（至少 50 条）
   - 变量名保持英文（至少 30 条，覆盖常见命名模式）
   - `**` 幂运算（至少 20 条）
   - `elif` → `否则若`（至少 20 条）
   - 负数保持原样（至少 15 条）
   - `and/or/not` → `且/或/非`（至少 15 条）

6. **增加复杂度梯度样本**: 从单行→多行→嵌套→完整程序，渐进式训练

### 长期

7. **升级到 1.5B 或 2B 模型**: 0.5B 参数量是核心瓶颈，更大的模型能更好地遵循 prompt 指令
8. **RLHF / DPO**: 用偏好数据进一步优化翻译质量
9. **AST 级翻译**: 不依赖 seq2seq，而是基于 Python AST 做规则映射 + 神经网络补全
