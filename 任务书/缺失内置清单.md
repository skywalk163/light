## 0. 这批东西为什么落在 `.light` 里而不是内置里

`stdlib/路径护栏.light:355-366` 的「系统边界段」段头是官方落点声明：全模块的 `os` 调用只收在那一段里，一段一个原语。D9 没有自己补内置的原因写在 `任务书/交付报告_D9_S1.md:71`——两头堵：

1. `stdlib/builtins.py` 的写权在 C9 且**只许减**；
2. 新建一个专收 syscall 的边界模块也不行，`tools/ci/python_direct_calls.py:455-457` 规定新文件基线默认 0，任何新文件带直调即自动判红。

所以这 19 条只能登记、等 C9 落地。落地之后，边界段那 16 行是**机械替换**（一行换一行），上面的判定逻辑一行都不用动——`路径护栏` 的直调数就从 16 掉到 0，`≤3` 的护栏目标随之达成。

## 1. 施工顺序建议（按「阻断了什么 × 实现代价」排序）

### 批次 A —— 一行转发、零设计分歧、单条落地即生效（4 条）

先做这一批：每条都是一句 `return os.xxx(...)`，没有任何需要拍板的地方，而挡住的东西却是最要命的。

| 期望名 | Python 原语 | 挡住了什么 | 代价 |
|---|---|---|---|
| `真实路径(路径)` | `os.path.realpath` | 沙箱越界判定的**根基**。缺它就只能用 `绝对路径`（纯词法 abspath），`根/链接/../外面` 会被折成 `根/外面` 而放行 | 一行 |
| `随机字节(个数)` | `os.urandom` | 原子写临时文件名的不可预测性。缺它只能用 `时间戳`，同毫秒并发直接撞名 + 被 `独占` 打失败 | 一行 |
| `原子替换(源, 目标)` | `os.replace` | 原子写的最后一步。内置 `移动文件系统`(shutil.move) 在 Windows 上目标已存在会抛错，不是原子覆盖 | 一行 |
| `单调时钟()` | `time.monotonic` | 全部超时与限速逻辑的正确性前提（11 处调用点、5 个文件）。现有 `时间戳()` 是墙钟，会被 NTP/手动改时间**往回跳** | 一行 |

⚠️ `真实路径` 这条是本清单的头号护栏对象：**不许拿 `绝对路径` 顶替**。JSON 里每条都有「为什么现有内置不能替代」一栏，就是为了这件事。

### 批次 B —— `O_*` 常量转发（8 条，是批次 C 的前置依赖）

| 期望名 | Python 原语 | 备注 |
|---|---|---|
| `只读` | `os.O_RDONLY` | |
| `只写` | `os.O_WRONLY` | |
| `新建` | `os.O_CREAT` | |
| `截断` | `os.O_TRUNC` | 少它 = 覆盖写变成「覆写但留尾巴」 |
| `追加` | `os.O_APPEND` | **D9 报告 :79 的清单漏了这条**，但 `路径护栏.light:413` 真在用 |
| `独占` | `os.O_EXCL` | 防预置攻击的**唯一**手段；用「先 `文件存在()` 判一下」替代就是教科书级 TOCTOU |
| `二进制` | `os.O_BINARY`（仅 Windows） | **数据正确性必需件**，见下方 §2 |
| `不跟随符号链接` | `os.O_NOFOLLOW`（仅 POSIX） | 把 realpath→open 的窗口再收窄一格 |

### 批次 C —— fd 四件套（4 条）

`低级打开(路径, 标志位, 模式)` / `低级读(句柄, 字节数)` / `低级写(句柄, 字节)` / `低级关闭(句柄)`。

对应 `os.open` / `os.read` / `os.write` / `os.close`。落地后一次解锁三个模块的全部 IO：`路径护栏`（受核准读写 + 原子写）、`进程树`（输出溢出落盘）、`伪终端`（pty 主端读写）。

内置 `打开文件`(Python `open()`) 不能替代：拿不到 fd，于是既不能 fstat 复核身份，也不能传 `O_NOFOLLOW` / `O_EXCL`。

### 批次 D —— 状态两件（2 条，唯一需要设计拍板的）

`文件状态(路径)` / `句柄状态(句柄)`，对应 `os.stat` / `os.fstat`。状态对象至少要暴露 `硬链接数` / `设备号` / `节点号` / `大小` / `是目录`。取不到返回空、不抛。

需要拍板的是**状态对象怎么表达**：光明侧目前的消费写法是 `快照.st_ino` / `快照.st_dev`（`路径护栏.light:228-229`），也就是直接透传 Python 的 `os.stat_result`。若内置层要换成中文字段名的字典，`同一文件` / `疑似硬链接` 两个段落要同步改——请在动手前定下来并通知 D9 车道。

`句柄状态` 不是 `文件状态` 的重复：用路径再 stat 一次等于又开一个 TOCTOU 窗口，必须拿已经打开的那个句柄回查。

### 批次 E —— 环境枚举（1 条）

`环境枚举() -> [[键, 值], …]`，对应 `os.environ.items()`。内置 `环境变量(名)` 只能按名取值、**没有列出全部的入口**，而沙箱受控环境是「白名单前缀 + 黑名单覆盖」，前提就是先能枚举。

返回形态定成 `[[键, 值], …]` 而不是字典，是照抄 `路径护栏.light:467-472` 现有 `环境快照` 的产出，改成字典要同步改 `进程树.light` 的 `构建环境`。

## 2. 跨平台常量：不许硬编码数字

批次 B 全部 8 条都标了 `"跨平台常量": true`。**`O_*` 的数值在 Windows 与 POSIX 上不同**，写死数字就是在某一个平台上静默打开了错误的模式——不报错、不崩，只是数据坏掉。必须走 `os.O_*` 或平台等价常量。

两条特别的：

- **`二进制`（`os.O_BINARY`）只在 Windows 存在，POSIX 上没有也不需要 → 内置实现自己按平台返回 0**，不许让调用方去 try/except。
  这条是**数据正确性必需件**，不是优化项：Windows 上 `os.open` 默认走文本模式，读到 `0x1A`(Ctrl-Z) 就当 EOF 停下，写出时 `0x0A` 被翻成 `0x0D 0x0A`。`路径护栏.light:396-399` 记录了实测——**写 230400 字节二进制料、读回来只有 26 字节（截在第一个 `0x1A`），且不报任何错**。
- **`不跟随符号链接`（`os.O_NOFOLLOW`）只在 POSIX 存在，Windows 上返回 0**。
  ⚠️ `交付报告_D9_S1.md` 第 4 节第 2 条明写：护栏 fd 路径的 **POSIX 分支未实测**（Windows 上走的是另一支）。C9 落地后必须在 POSIX 上真跑一次，不许把 Windows 的绿当成两个平台都绿。

## 3. 命名注意事项

- `追加`：`src/code_generator.py:122` 的 `method_name_map` 里 `'追加' → 'append'`。那张表只作用于 `对象.追加(...)` 成员调用，不影响裸名常量，所以不冲突；但若 C9 认为风险太大，可改名 `追加位`——**名字可议，语义不可减**。
- `原子替换` 刻意不叫 `替换`：`method_name_map` 把定义侧 `段落 替换` 译成 `def replace`，而调用侧 `己.替换` 不译，编译期零报错、运行期 `AttributeError`（D9 移交清单 L2）。
- `单调时钟` 的 11 处调用点分布在 7 个段落里，其中 `协程收`、`等待令牌`、`收字节` 三个是 `异步 段落` —— 用 `grep "^\s*段落"` 找不到它们，验收脚本的段落匹配必须同时认 `异步 段落`。
