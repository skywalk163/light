## 2. B4-2：硬链接越界 —— 做真防护

现状：`路径护栏.light:31-32` 注释自认「硬链接是已知封不住的缺口：硬链接没有可解析的目标，
realpath 原样返回」。代码里 0 行 `st_nlink`/`st_ino`/设备号校验。
测试 `tests/test_path_guard_light.py:298-313` 是**反向钉住缺口存在**
（`assert 护栏.检查(str(链)) is True` + 断言真读到了根外数据），带 `skipif(win32)` + `xfail` 双重掩盖。

**做法（建议，不强制）**：`核准` 通过后、真正 open 之前（或 open 之后用 fd）检查
`st_nlink > 1` 的文件是否其 `st_dev`+`st_ino` 能在沙箱内被定位到；
更实用的近似是**拒绝 `st_nlink > 1` 的写入**，读取按策略决定。

**这里需要你做一次判断并在报告里写清楚**：完全封死硬链接在 POSIX 上要么靠
「同设备 + 遍历沙箱验证 inode 可达」（昂贵），要么靠「拒绝多链接文件」（可能误伤）。
选哪个都可以，但**必须写明代价与误伤面**，不许含糊说「已加固」。

**判据 B4-2**：
1. `test_path_guard_light.py:298-313` 的 xfail **去掉**，翻成正向断言：
   硬链接指向根外时 `检查` 返回 False（或 `核准` 抛 `路径护栏错误`），且**读不到根外数据**。
2. 正常单链接文件不受影响（不许为了封硬链接把普通文件也拒了）——要有对照用例。
3. **反跑**：去掉 st_nlink/inode 校验，用例必须变红。
4. Windows 上 `mklink /H` 需要权限时允许 skip，但 skip 理由必须写「掩盖的是 Windows 硬链接分支未实测」，
   **且 POSIX 分支必须真跑**（若你只有 Windows，明确写进未实测项）。

## 3. B4-3：TOCTOU —— 做真防护

现状：`路径护栏.light:139-143`（读）、`:152-153`、`:170-171`、`:184-185`（写/追加）的
`os.open` 标志只有 `O_RDONLY/O_WRONLY/O_CREAT/O_TRUNC/O_APPEND` + `二进制位()`（只是 `O_BINARY`）。
**无 `O_NOFOLLOW`、无 `dir_fd=`、打开后无 `fstat` 复核。**
头部注释 `:14-18` 与机读的 `安全声明`（`:85`）都声明放弃。
测试 `:320-337` 是反向钉住（核准后把目录换成 junction，`检查` 变 False，证明拦不住替换），
带 `skipif` + `xfail`。

**做法**：三件事按可行性做，能做几件写几件，但**每件都要说清做了没有**：

1. `O_NOFOLLOW`（POSIX 有，Windows 没有对应位——Windows 上要写明用什么替代或不做）
2. 打开后 `os.fstat(fd)` 复核 `st_dev`+`st_ino` 与核准时 `os.stat(路径)` 得到的一致，
   不一致则关 fd 并抛 `路径护栏错误`。**这条是跨平台都能做的，优先做这条。**
3. `dir_fd=` 相对打开（需要把路径拆成 dirfd + basename，Windows 不支持）

**判据 B4-3**：
1. `:320-337` 的 xfail 去掉，翻成正向断言。
   构造方式：核准之后、open 之前插一个替换动作（用 monkeypatch 在 `核准` 与 `os.open` 之间挂钩，
   或把护栏内部拆出一个可注入的时点）。**如果实现上无法插入这个时点，说明防护也无从验证——
   那就把「怎么让它可测」也算进本任务。**
2. 正常路径不受影响，读写性能不出现数量级退化（不用做基准，但别引入每次调用遍历目录树这种）。
3. **反跑**：去掉 fstat 复核，用例必须变红。
4. `安全声明`（`:85`）与头部注释 `:14-18` 必须同步更新——**不许代码修了、机读声明还说「存在 TOCTOU 窗口」**。

## 5. B4-5：`sh -c` 参数映射 bug

`代理工具集.light:550-556`：

```
如果 sys.platform 等于 "win32": 最终命令 为 ["cmd", "/c"] 加上 命令数组
否则: 最终命令 为 ["sh", "-c"] 加上 命令数组
```

`sh -c` 只接**一个**脚本串，后续 argv 会变成 `$0/$1…`。
`["ls","-la"]` → `sh -c ls -la` → 实际只执行 `ls`，`-la` 被当 `$0` **静默丢弃**。
Windows 侧 `cmd /c` 自行拼接，症状轻。

**全仓 grep `允许shell` 在测试里零命中**——这个分支从来没被测过。

**判据 B4-5**：
1. 修法二选一并说明：把命令数组按 shell 引用规则拼成单个脚本串（注意注入风险，
   要用 `shlex.quote` 等价的引用），或者干脆**拒绝 `允许shell` + 数组形态的组合**并报错。
2. 新用例覆盖 `允许shell=真` 分支：断言 `["echo","hello","world"]` 的**全部参数都生效**
   （输出含 `hello world`，不是只有 `hello`）。POSIX 无法本机跑就明确 xfail 并写掩盖了什么。
3. 注入面用例：命令数组里含 `;` / `$(...)` / 反引号时，行为必须是「按字面参数传递」或「明确拒绝」，
   **不许变成 shell 元字符被执行**。这条是安全判据，必须有。
