## 1. 逐缺陷：现象 → 根因 → 修复 → 验收

### 1.1 L-003（保持绿 + 确认加固）

**现象**：类内 `己.事件表 为 []` 曾被误编译成比较，`追加` 后 `事件表` 保持 None。

**根因定位**：缺陷账原错误形态在当前词法预扫描下已缓解（任务书 §4 注明「已缓解」），本任务无需新增代码改动。

**修复手法**：不改代码，做**加固确认**——用断言用例钉死「成员空列表赋值 = 真实赋值」语义：
- `_taskL2_L003_assert.light`：构造后 `追加` 两次，断言 `数量()==2` → 绿（rc=0）；
- `_taskL2_L003_rev.light`：断言 `数量()==3`（错值）→ 红（rc=1）。

**验收**：test_L003 保持绿（输出 `1\n--- 测试L003 结束 ---`）；assert/rev 双证通过。

### 1.2 L-005（非 self 成员下标按下标取值）

**现象**：`总线对象.监听器表["点击"]` 抛 `TypeError: 'dict' object is not callable`。

**根因定位**：解析期 `对象.表[键]` 的无括号「实参收集」循环把 `[` 当成列表字面量起点，`[键]` 被收集成**唯一实参**，产出 `MemberAccess(is_method_call=True, args=[ListLiteral([键])])`，代码生成层据此生成 `对象.表([键])` 调用。AST 层 `对象.表[键]` 与真实调用 `对象.方法([单元素])` **完全同构**，生成层无从区分——所以必须（也只能）在解析期切开。修复点：`src/parser_expr.py:2952`（`_parse_*_member_access` 无括号实参收集的阻断符判断）。

**修复手法**：把 `TokenType.LBRACKET` 加入无括号实参收集的阻断符集合（最小改动面：**一个枚举成员**）。`对象.表[键]` 的 `[` 由此走后续索引访问分支（IndexAccess），不再被吞成方法实参。

**验收**：AST 探针（`_taskL2_probe_ast.py`）确认 `总线对象.监听器表["点击"]` 解析为 IndexAccess；test_L005 红→绿（输出 `42`）；assert/rev 双证通过。

### 1.3 L-006（闭包内修改外层标量）

**现象**：`段落 处理器:` 内 `计数 = 计数 + 1` 抛 `UnboundLocalError: cannot access local variable '计数'`。

**根因定位**：`src/code_generator.py` 的段落/方法生成从不发射 `nonlocal`——内层 `def` 里对同名局部赋值被 Python 判为「新局部」，读取同名外层局部时报 UnboundLocalError。

**修复手法**（`src/code_generator.py`）：
- `__init__` 新增三个状态（`:114-122`）：`_function_locals_stack`（函数局部帧栈）、`_pending_nonlocal`（待发 nonlocal 名集合）、`_binding_params`（参数绑定阶段标志）；
- 新增 `_note_function_binding`（`:714`）：名字若已被**外层函数帧**绑定、且当前不在参数绑定阶段 → 判定为「改写外层局部」，记入 `_pending_nonlocal`；
- `_bind_local` 绑定局部时调用之；`_generate_paragraph`（`:1685` 记 def 行位置、`:1732-1739` 发射 `nonlocal`）与 `_generate_method`（`:2668`、`:2738-2745`）在 def 行后、首个语句前统一插入 nonlocal 声明；
- 参数遮蔽（`_binding_params=True`）只记入当前帧、不触发 nonlocal（参数遮蔽合法）。

**验收**：生成代码核验（`_taskL2_dump_compile.py`）确认：

```python
def 处理器():
    nonlocal 计数
    计数 = (计数 + 1)
```

test_L006 红→绿（输出 `1`）；assert/rev 双证通过。

### 1.5 L-014（语句级下标调用）

**现象**：`表["甲"](1)` 作语句（或 `表["甲"](1)` 的表达式链）抛 `CodeGenError: 未知语句类型 (节点类型: FunctionCallExpr)`。

**根因定位**：`FunctionCallExpr`（callee 为 IndexAccess 的链式调用）未纳入语句分发，落入「未知语句类型」分支。修复点：`src/code_generator.py` 语句分发（约 1320 行）。

### 1.6 L-016（`捕获 全部` → except BaseException）

**现象**：`尝试: 等待 任务` / `捕获:` 后，`asyncio.exceptions.CancelledError`（BaseException 子类）接不住，Traceback 冒泡，异步取消无法在光明层表达。

**根因定位**：`src/code_generator.py` 捕获生成段（约 1710 行）对 `捕获 X`/`捕获 X 为 e` 一律生成 `except Exception:`，覆盖不了 BaseException 子树。

**修复手法**：
- `src/code_generator.py` `_generate_catch_clause`（`:1766-1786`）：识别 `全部` 标记——三种写法归一为 `except BaseException`：
  - `捕获:`（裸，catch_type/catch_var 均 None）→ `except BaseException:`（与 Python 裸 `except:` 语义一致，即 test_L016 验收语义）；
  - `捕获 全部:`（parser 把「全部」当变量名，全 非大写）→ `except BaseException:`；
  - `捕获 全部 为 变量:`（parser 把「全部」当类型名）→ `except BaseException as 变量:`；
  - 既有 `捕获 X`/`捕获 X 为 e` **行为不变**（仍 `except X`/`except X as e`）。
- `src/code_generator_unified.py` `_generate_try_stmt`（`:832-866`）：同口径同步，并修掉裸 `捕获:` 因条件判错误发 `finally: pass` 的问题。

**验收**：
- 生成代码核验（`_taskL2_L016_forms_gen.txt`）：`捕获 全部:` → `except BaseException:`、裸 `捕获:` → `except BaseException:`、`捕获 值错误 为 错误` → `except ValueError as 错误:`、`捕获 异常 为 值错误` → `except Exception as 值错误:`；
- test_L016 红→绿（`等待 断言修复后()` 启用后，`接住==真` 成立）；assert/rev 双证通过。

## 2. L-016 新语法 `捕获 全部` 语法设计说明

**结论：词法、解析均无需改动，全部改动面在代码生成层。**

- **词法**：`全部` 是普通标识符，不是关键字，lexer 未特殊处理——无改动。
- **解析**：既有 `_parse_catch_clause`（`src/parser_stmt.py:2888`）靠「首字符大写」启发式天然覆盖三种形态：
  - `捕获:` → 无实参 → `(None, None)`；
  - `捕获 全部:` → 中文 `全` 的 `.isupper()` 为 False → 按「变量名」处理 → `(None, '全部')`；
  - `捕获 全部 为 变量:` → 命中 `为` 分支 → `('全部', '变量')`。
- **生成**：`_generate_catch_clause` 把 `'全部'` 识别为「捕获全部」标记 → `except BaseException`。这与既有 `捕获 X` 把类型名映射到 Python 异常类型是同一层设计。

**语义设计取舍（记入缺陷账认知）**：`全部` 在捕获位成为**保留标记**——`捕获 全部:` 不再绑定名为 `全部` 的异常变量（旧行为会是 `except Exception as 全部:`），而表示「接住一切（含 BaseException）」。若将来确需「接住一切且绑定到变量名 `全部`」，请用 `捕获 全部 为 变量` 形式，勿用 `捕获 全部:`。
