## 目标与验收（M13，行为判据 + 反跑）

| 需求 | 验收（跑产物断） | 反跑改坏点 |
|---|---|---|
| `异步信号量(初值)` | 并发 N 路里，实际同时通过的并发数**不超过初值**（用共享计数器/时序证明，不阻塞事件循环） | 去掉信号量→并发数超过初值→红 |
| `速率限制(每秒次数)` | 同样时间窗口内发起次数 ≤ 上限 | 关掉节流→超上限→红 |
| `重试(次数)` + 指数退避 | 可重试错误会重试到指定次数，重试间有退避（时序间接可证）；不可重试错误立刻失败不重试。**抖动按总纲 §4.3 默认不加** | 不重试→调用次数为 1→红 |

| `任务池(并发上限)` | 提交 M 个任务，最多 N 路并行，全部 await 收拢顺序正确 | 并发>上限→红 |
| `限时(秒)`/`先到先得` | 超时中断不卡死事件循环；竞速取首个完成 | 取消超时→饿死→红 |
| `读JSONL文件/写JSONL文件` | round-trip 数据一致；空行/坏行策略明确 | 改断行→丢数据→红 |
| `度量`：精确/多答案(集合)/正则打分 + 批量 pass-rate/统计 | 打分与手算一致；批量汇总与逐条相加一致 | 改计分→数字错→红 |
| 测试框架强化 | 用光明能写出断言失败会真红、通过真绿的简单测试 | 断言不生效→假绿→红 |

## 分块实现链路建议

1. 先写 `tests/test_concurrency_light.py`：每原语一条「并发上限 / 重试次数 / 超时」行为用例（红）。
2. 建 `并发.light`：`异步信号量`、`速率限制`（令牌桶）、`任务池`、`限时`、`先到先得`——
   内部组合语言层已有的 `异步 作用域`/`并发等待`/`创建任务`（若需要的原语语言层缺，记移交给 B5）。
3. 建 `重试.light`：可重试/不可重试分类 + 指数退避（抖动按总纲 §4.3 默认不加；文件头写明与
   `代理循环.light:435` 那份的关系）。
4. 建 `JSONL.light`：行流 round-trip + 坏行策略。**注意 `流式.light` 的 `按行读取` 是 `HTTP客户端`
   的方法、读 socket 不读文件**，不能直接拿来读评测集；文件行流要自己实现（或基于
   `文件系统` 的读块 + 增量切行），别指望现成的。
5. 建 `度量.light`：精确/集合/正则打分 + 批量汇总，复用 `统计.light`（它只有描述性统计，
   打分层要自己建）。
6. `测试.light`/`断言工具.py` 强化：补能真红的断言（`断言相等/断言真/断言命中`），给 D5 的 harness 用。
   注意 `测试.light` 现在是 12 行纯导出、实现在 `测试.py`；**若要往 `.light` 里写实现，
   小心遮蔽 `测试.py`**（同 JSONL 那条：纯光明实现是取代不是兜底）。
7. 全部绿 + 反跑证明。

- 判断用产物行为，禁止断字符串式判据；每一原语要么有反跑证明，要么写「未验证」并说明。

  新建 4 个文件会把自举率分母从 70 顶到 74，壳文件让分子不涨分母涨 → 25.71% 下降 →
  按总纲 §7「只许升」**直接判红**。（这也正是第二轮「不许再造只有壳的东西」。）

  本路做的正是「测试框架强化」，判据本身更不能是假绿。
- 新增测试必须能被收集（总纲 §5.7）：跨平台闸门专拦「整批没跑起来」。
