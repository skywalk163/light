## 一句话

用光明真正写一个 deepseek-harness MVP，端到端跑通（读 JSONL 评测集 → 异步并发跑 DeepSeek →
限流重试 → 打分 → 出报告），**报告数据与手算一致**。这是「光明达到能独立开发 deepseek-harness 类项目」
这一句话的最终判据本身；顺手把语言/stdlib 缺口反哺回移交清单。

## ⚠️ e2e 自动纳管与「真发网」风险（开工前必读）

`tests/e2e/test_e2e_chain.py` 对 `examples/` 下**每个**示例都跑两条参数化用例
（`run` 解释执行、`compile` 成 `.py` 再独立跑），**都断言 `rc == 0`**。当前：

- `E2E_EXCLUDED` 只排除了 `harness/主程序.light`（`:101-109`），注释写明理由：
  它缺 env 时按设计 `返回 2`，而本链路是「零环境跑一遍断 rc==0」，
  **「让它缺环境时返回 0 才是假绿（什么都没干却报成功）」**。
- `M2_流式对话.light` **没有被排除**，所以它现在就在被跑。
- `E2E_SUBPROC_ENV = {**os.environ, ...}`（`:28-32`）**会继承 `DEEPSEEK_API_KEY`** →
  本机或 runner 上有 key 时，e2e 会**真发网**到 api.deepseek.com。

**因此 D5 每新增一个 `examples/harness/*.light`，二选一并在交付报告里写明选了哪个**：
- (a) 无 key 时 rc=0 早退且**不发网**（适合纯本地/mock 路径）；
- (b) 加进 `E2E_EXCLUDED` 并把真覆盖放进自己的 mock 测试（照 `主程序.light` 的先例）。

不许出现第三种：既不排除、又在缺环境时 rc≠0（会把 e2e 打红），或既不排除、又在有 key 时真发网。


## 目标与验收（M14，唯一判据）

1. **端到端跑通**：`examples/harness/**` 用光明写成，入口一条命令能从 `评测集.jsonl` + 配置出发，
   驱动 `异步 段落 流式对话` 并发评测，最终产出报告。**跑 mock 即算达成，真实 key 可选。**
2. **并发真实**：配置一个并发上限，跑出来的实际重叠符合预期（可对照 `速率限制`/`任务池` 的时序，
   而非全串行）。**时序数字贴原始输出。**
3. **报告正确**：对一小组确定性评测集（如 mock server 固定回答 ABC，带期望答案），
   `度量` 打出的 pass-rate 与**手算结果逐项一致**——不是「看起来合理」，是数字对得上。
4. **反哺缺陷清单**：凡在写 harness 时用到一个缺口（缺原语/缺语法/别扭绕法），都记入移交清单给
   B5/A5/C5。**这份清单本身就是 M14 的副产物**，价值不低于 harness 本身。


### MVP 组件（光明实现）

- `评测集.jsonl`：每条含 prompt / 期望答案 / 可选打分器名称。
- 加载：`JSONL` 行流读（C5）。
- 编排：`异步 任务池` + `速率限制` + `重试` 驱动 `异步 段落 流式对话`（C5/A5），收集每路输出与耗时。
- 度量：`精确匹配`/`集合匹配`/`正则匹配` + 批量 pass-rate/统计（C5）。
- 报告：输出 Markdown + JSON（每条输出的输出、得分、耗时；总体 pass-rate、各子集统计）。
- 测试：`tests/test_harness_e2e_light.py` 用 mock server 跑确定性用例，断言报告数字正确 + 打红路径。

## 分块实现链路建议

1. 先写确定性 mock server 与最小评测集，定义报告 JSON 结构 == 「黄金输出」。
2. 骨架用**占位桩 + `TODO(移交:A5/C5)`** 先跑通形状（总纲 §3 的开工基线口径），
   等 A5/C5 合入后替换成真实现。
3. 接 `异步 段落 流式对话` + `任务池`/`速率限制`/`重试`。
4. 接 `度量` 打分，手算对账。
5. 出报告 + e2e 测试 + 缺陷清单反哺。
6. 视时间做 CLI 子命令与打包/分发打磨。

## 接口契约（消费 A5/C5，申报 B5/A5/C5）

- 用 `异步 段落 流式对话`（A5，§4.1，**带空格两段式，别写成 `异步流式对话`**）。
- 用 `异步信号量/速率限制/重试/任务池/限时`（C5，§4.3）、`度量`/`JSONL`（C5）。
- **并发模型边界**（总纲 §4.3 末尾契约）：评测编排在 loop 内；代理循环的工具并行是 threading，
  留在线程侧。**不许在 loop 里直接跑阻塞调用**（会把事件循环卡死），跨界只走「丢线程再 await」。
- 若某个原语不存在或别扭，**记入移交清单**，指明期望的语法/stdlib 能力，交给对应路去补。

## 硬约束

- 判据 = 端到端跑 + 报告数字与手算一致 + 并发时序。禁止用「能编过」当主判据。
- 不碰 `src/`、不碰他人 stdlib 独占文件。缺的东西外部组合或移交。
- **新增 `examples/harness/*.light` 必须按上面「e2e 自动纳管」那节二选一处置**，
  并在交付报告里写明每个新文件选了 (a) 还是 (b)。
- API key：只从环境变量读，绝不入源码、不入 git（`examples/harness/.env` 进 `.gitignore`）。
- **假测试门禁扫全仓**（总纲 §5.6）：新增断言不许出现 `assert len(x) > 0` / `>= N` /
  `assert x is not None` / `assertIn('字面量', py_code)`；举反面例子写在**多行**字符串里。
  报告数字要**逐项等值断言**，不许断「至少有几条」——那正是本轮门禁要拦的形态。
- 新增测试必须能被收集（总纲 §5.7）。
- 端口 `bind(("127.0.0.1", 0))`（mock 用）；临时文件前缀 `_taskD5_`，收尾删干净。
- 逐路径 `git add` 白名单，绝不用 `-A`/`commit -a`；commit message 用 `git commit -F <文件>`。
