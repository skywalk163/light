## 4. 验收标准（全部自动化 + 反跑判据）

1. **schema 校验通过**：合法参数（含嵌套 object/数组 item）执行成功。
2. **schema 校验失败**：缺 required 字段 → isError，error 含 `字段路径`（如 `["参数","秒"]`）与原因（missing/type/enum/pattern）。
   - **反跑判据**：把「校验失败 → isError」的断言改成相反 → 立红。
3. **类型校验**：数字给字符串 → type 错误；enum 外取值 → enum 错误；pattern 不符 → pattern 错误。
4. **prepare/finalize**：带 prepare 的工具在 execute 前调用 prepare（可改参数/拒绝），finalize 在 execute 后调用（可读结果/记录）；用共享计数器验证调用顺序。
   - **反跑判据**：把 prepare 计数器断言改反 → 立红。
5. **不回归**：`python 运行.py examples/test_工具.light` 与 `examples/test_并行.light` 仍绿（执行策略/并行不受影响）。

## 5. 光明缺陷避坑

- 命名规范：`校验参数`/`准备`/`收尾` 是安全前缀（`读`/`写`/`记`/`判` 系），但 **`模式`/`类型`/`工具`/`参数` 含危险词根**——校验器类成员名不要以 `模式`/`类型` 结尾开头（如「参数模式表」会炸，参考缺陷账 L-004/L-007：`注册表.工具模式表()` 被拆成 `注册表.工具`+`…`）。
- `校验参数` 返回的错误列表里字段路径用**列表**（`["参数","秒"]`）而非字符串拼接，避免歧义。
- 注释不写「导入 某模块」字样（L-009）。
