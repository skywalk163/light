## 0. 这一轮为什么这么排

第八轮之后的定位复盘，结论一句话：**光明今天能复刻 harness，但不能脱离 Python 交付，也不能横向扩展。**

三条硬事实：

1. **自举是假象的一半。** 文件维度自举率 31.58%（24/76），但 `stdlib/` 里 **53 个 `.light` 是同名 `.py` 的影子**，其中 **52 个是 decl 0 的纯 `导出` 清单**（典型：`stdlib/JSON.light:136-145` 六十多个 `导出` 名、零 `段落`）。更要紧的是 `stdlib/builtins.py`（1067 行、114 个函数）被 `src/code_generator.py:735-741` 注入进**每一份**生成产物 —— 连自称「零导入零引 Python」的 `stdlib/文件流.light:4` 都站在它的 `读取文件/写入文件/追加文件` 上。**它没有同名 `.light`，所以不在任何指标的分母里**：这是六轮来最大的度量盲区。
2. **原生腿能编能跑，但不是产品。** 第七轮 A7 已把 legacy pass 名从 `-mllvm` 摘掉（`src/llvm/compiler.py:198-212`），**O0–O3 四档现在全都真编译真跑**（`tests/test_native_cli.py` 24 passed，含 `[O0..O3] × [hello, socket, 协程]` 12 格矩阵）—— 凡是还在说「默认 O2 编译失败」的文档/记忆都是过期陈述，本轮起草时按此纠正。真缺口换成了三条：`--backend llvm`（非 typed）那条腿引用不存在的 `src/llvm/runtime.c`（`compiler.py:486`），**100% 不可用且零测试**；`ImportStatement` 在 `src/llvm/codegen_typed.py:2799-2800` 是 `pass`（no-op），单文件原生编译**根本看不见 stdlib**，多模块唯一出口是 `light pkg native`，而 `compile_light_project` 全仓零调用方；POSIX 侧 TLS 是 `dv_tls_unsupported` 桩。
3. **分布式是零，不是弱。** 逐关键词核过：无 gRPC、无 MQ 客户端（Redis/Kafka/RabbitMQ/NATS 全零）、无 RPC、无服务发现、无心跳、无选主。`contrib/分布式锁.py:49 内存分布式锁` 名不副实（进程内 `threading.Lock`）。`docs/lightpub/RPC框架.md` 是**文档先行、代码不存在**。并发上限就是单机单进程：`stdlib/并发.light` 95 行（asyncio）+ `stdlib/代理循环.light:672-691` 分批 join（threading）。并且 **`return_exceptions` 全仓零处理** —— `任务池` 一条异常炸全场且兄弟 Task 变孤儿。

→ 本轮按这三条排七条泳道，验收口径继续沿用第七轮的「对着清单勾完成度」，但**清单从一张扩到四张**（§4）。

## 5. 五条红线（违反即回退，不接受解释）

1. **不许建同名 `.py`。** 新增 stdlib 能力只建 `.light`；`stdlib/_light_import_hook.py` 让 `.py` 绝对优先，建了 `.py` 你的光明代码永远不会被执行。要「取代」同名 `.py` 必须在 `.light` **首两行**挂魔数「纯光明实现」（唯一活着的样板：`stdlib/列表工具.light`）。
2. **不许用 `引 Python：` 掩盖语言缺陷。** stdlib 内 `引 Python` 计数恒 0，`bootstrap_rate.py:578-580` 见 >0 即红。绕不过就写进移交清单交 A9。
3. **不许造只有壳的东西。** decl 0 的 `导出` 清单不算实现（52 个空壳就是这么攒出来的）；上界断言（`<=`、`>=` 单边）不算判据；没有反跑的测试不算判据。
4. **不许靠本机装第三方库转绿。** 尤其 F9：不许 `pip install redis/grpcio/pika` 之类，分布式层必须建在自家 socket / HTTP 上。POSIX TLS 若要引第三方 C 库，须先在 S1 提出并等主线裁决。
5. **不许在合并前刷基线。** 所有 `tools/ci/*_baseline.json` 的重建只在**合并点**由 G9/主线做；本机没收集 e2e 就报「已转绿」的，一律不许据此刷（第七/八轮各踩一次）。

## 8. 环境与协作（PowerShell 5.1，照抄不改）

- 每人一个 worktree：`git worktree add ../wt-X9 -b task-X9 main`，只在自己目录里作业。
- **只跑定向测试，不许跑全量**；定向测试超过 5 分钟先问主线。
- 端口一律 `bind(("127.0.0.1", 0))` + `getsockname()[1]` 取回，不写死端口（`pytest -n auto` 会让段划分自己撞自己）。**F9 的多节点测试尤其注意：三个节点也各自绑 0 端口。**
- 临时文件加任务前缀 `_taskX9_*`，收尾删干净。
- 杀进程只许按自己 spawn 的 PID，**绝对禁止按进程名杀**。
- 中文输出必须落盘再读；**落盘用 `cmd /c` 字节重定向**，`Out-File -Encoding utf8` 会真造出坏文件；不支持 `&&` 与 heredoc。
- 临时验证脚本不写盘，用 `python -c` 或落到临时目录，收尾删。
