## 0. 这一轮为什么这么排

第四轮把传输层换成了非阻塞 socket + selector（`stdlib/流式.light`、新建 `stdlib/选择器.light`），
给了「真异步」一块地基。**但拿到这个地基往上看，还差一个纵切的主干没通。**

第一件、也是本轮的第一性目标：**语言层的 `等待` 仍然驱动不了任何真实 I/O。**

- `异步 段落` / `异步 运行 主()` / `并发等待` 确实发射成 `asyncio.run` / `asyncio.gather`（真）。
- 但 `大模型客户端.light` 的 `流式对话` 仍是**同步生成器**，`遍历 块 之 己.客户端.read_body()` 同步收，
  全文件 grep 无一处 `异步/等待`（`stdlib/大模型客户端.light:137-171`）。
- 全仓**只有一个** `.light` 真在用异步关键字：`examples/harness/M2_流式对话.light:62/80`
  （`异步 段落 启动` + `异步 运行 启动(...)`），而它无 key 时早退，流式那段从未被验证。
- 结果：harness 要并发跑 N 条评测，现在唯一能做的还是线程 + 阻塞收，丑且散。


第二件：**语言能力的三个缺口挡住「重复代码写得省」这一步。**
- 光明**没有一等函数值**：函数不能当值传递/返回，`接收 …：…` lambda 只生成单表达式
  （`src/code_generator.py:2981-2985`），所以重试装饰器、工作池工厂、回调式 DSL 全部写不顺。
  **注意：变量捕获与改写不缺** —— A5 期已落地 `全局`→`global`、`外层`→`nonlocal`
  （`src/parser_stmt.py:713-717`、`src/code_generator.py:1173-1181`，真跑用例
  `tests/test_frontend_blockers_run.py:343-355`）。`大模型客户端.light:174`、
  `代理循环.light:411` 那两句「光明无闭包」是**过时注释**，本轮要订正（归属见 §3）。
- `推迟`（defer）**在主链路根本不存在**：`lexer.py`/`parser_stmt.py`/`code_generator.py` 全 0 命中，
  只有 `src/ast_nodes.py:537` + `src/code_generator_unified.py:908-923` 认它，且那份实现是
  try 体填 `pass`、finally 就地执行 = 等价内联。所以这是**新增关键字与语义**，不是「改内联为延迟」。
- `位与/位或` 等六个位运算不是二元运算符；`异步 遍历` 只认异步生成器不认普通可迭代。


第三件：**「并发编排」这块 stdlib 是空的，度量与测试框架偏薄。**
- 没有异步信号量/速率限制/重试退避/任务池这些**给一个并行评测 harness 用**的原语（codegen 只有
  `asyncio.gather`/`限时` 映射）。
- 评测数据集常用 JSONL，缺行流读写原语；打分指标（精确/多答案/正则匹配、批量统计）要靠手写。
- 语言内测试框架 `测试.light`/`断言工具` 覆盖浅，`assert '字符串' in code` 假绿门禁仍在扩。

一句话概括：**前三轮把「工具能干活」做成了，第四轮把「I/O 不阻塞」做成了，这一轮要把「语言能自己
写完一个并行评测类项目」做成——用光明自己写一个 deepseek-harness 当试金石。**

**本轮路线（四条工作流，A5/B5/C5/D5）：**
- **A5 异步 I/O 内核**：把 C4 的 selector 非阻塞机场真接到语言层 `await`，让网络/LLM 流式能被 `等待` 驱动。
- **B5 语言核心补齐**：一等函数值、defer 新增、`异步 遍历` 泛化、位运算。（**本路独占 `src/`**）

- **C5 并发编排 stdlib + 度量**：异步信号量/重试/任务池/超时取消 + JSONL + 打分指标 + 语言内测试框架强化。
- **D5 试金石 harness**：用光明真正写一个 deepseek-harness MVP 端到端跑通，反过来把缺口写回移交清单。

### 4.1 异步流式对话签名（A5 定义，C5/D5 消费）

**名字冻结为带空格的两段式**（`异步` 是修饰符、`流式对话` 是段落名），调用侧照下面这个写法：

```
异步 段落 流式对话 接收 消息列表:      # 定义
  ...
  生成 本次

异步 遍历 块 之 客户端.流式对话(消息列表):   # 消费（async for）
  ...
```

- ⚠️ **不许写成 `异步流式对话`（无空格）**：中文分词下那是**一个标识符**，与「修饰符 + 段落名」编出的
  产物完全不同，C5/D5 会直接调不上。总纲与四份任务书一律以本节写法为准。
- 新增名走 `异步 段落 流式对话`；**同步版 `流式对话` 签名与语义不变**（两者靠 `异步` 修饰符区分，
  若语言层不允许同名重载，A5 改用 `异步 段落 流式对话2` 之类并在本节回写实际定名，开工首日定完）。
- 增量块字段与同步版一致：`角色/内容增量/工具调用增量/累积内容/完成原因/结束`。
- 判据：A5 改完 `tests/test_llm_client_light.py` + `tests/test_tls_light.py` **一行都不许动**还能全绿
  （同步签名冻结的机读证明，沿用第四轮 §4.2）。
- ⚠️ **「selector 就绪怎么变成一个 `await` 点」是本轮实现风险最高的地方，且必须首日裁决**：
  codegen 没有 `add_reader`/`Future` 映射而 A5 不许碰 `src/`，`选择器.light` 的 `等待/等待就绪` 又是

### 4.3 C5 并发编排原语命名（C5 定义，D5 消费）

| 原语 | 语义 |
|---|---|
| `异步信号量(初值)` | 异步限流；`等待(信号量)`/`释放(信号量)`，不阻塞事件循环 |
| `速率限制(每秒次数)` | 令牌桶式节流，作用于 `异步 流式对话` 调用点 |
| `重试(次数 于 错误类型 …)` | 重试 + 指数退避；只在可重试错误上重试。**抖动 jitter 加不加见下面的口径裁决** |
| `任务池(并发上限)` | 提交一组任务，最多 N 路并行，全部 await 收拢 |
| `限时(秒)`/`先到先得` | 超时中断、竞速取首个完成（对应 asyncio.wait_for / FIRST_COMPLETED） |

- 这些原语**在语言层 `异步 作用域`/`异步 运行` 内真实可用**，且必须有行为级反跑判据。

**⚠️ 与既有实现的口径对齐（开工首日必须定，别写成第三套）**

- **重试退避已有旧实现**：`代理循环.light:435-438 退避秒` = `退避基数 * 2^(n-1)` 封顶 `退避上限`，
  参数 `退避基数 0.2 / 退避上限 8.0 / 重试次数 3`（`:280-283`），且 `:432` **明确写着「故意不加抖动」**
  （A3 裁决）。本节要求「+ 抖动」与它**直接冲突**。裁决口径（二选一，写进 C5 交付报告）：
  - (a) 维持 A3 裁决，`重试.light` 也不加抖动 → 本节删掉 jitter；
  - (b) 推翻 A3，两处都加抖动 → 但 `代理循环.light` 不属任何一路，本轮不许改它，
    于是会出现「新旧两套退避口径不一致」，必须在两处注释里互相指明差异与原因。
  **默认取 (a)**，除非 C5 给出「不加抖动会造成实际问题」的实测证据。
- **任务池已有两套**：`代理循环.light:612/:668` 的手写分批 join（`:608` 明写刻意不用
  `concurrent.futures`，理由「全 stdlib 对它零验证」）＋ `stdlib/线程.py` 的 `线程池`/`并发执行`。
  `并发.light` 会是第三套。C5 必须在文件头写明「本文件是 asyncio 语义，旧两套是 threading 语义，
  三者何时用哪个」，否则就是口径分裂。
- **两套并发模型共存契约（本轮新增，D5 集成阶段的头号风险）**：
  A4 的工具并行是 **threading + 手写分批 join**；C5 要做的是 **asyncio**。
  **在 asyncio 事件循环里直接 join 线程会把 loop 卡死。** 因此：
  - 评测编排（任务池/信号量/速率限制/重试）一律在 **loop 内**；
  - 代理循环的工具并行保持在 **线程侧**，不许被搬进 loop；
  - 跨界只走一个方向：loop 需要调用阻塞代码时用「丢线程再 await」的形式（`to_thread` 等价物），
    语言层若表达不出来，记移交清单，**不许在 loop 里直接跑阻塞调用**。


### 4.4 harness 规格（D5 定义，作为 M14 判据锚点）

⚠️ **测量全量 UTF-8 口径照第四轮 §7**：分家跑，A5/C5 家族可 `PYTHONUTF8=1`；进程树/伪终端不带。

## 8. 合并顺序

本轮有依赖，顺序比第四轮更严格：
1. **B5 先合**（语言核心：一等函数值/defer/异步遍历/位运算——C5 的原语实现、D5 的 harness 都可能依赖它）

2. **A5 次之**（`异步 流式对话` + event loop 接通，C5/D5 的并发驱动依赖它）
3. **C5 第三**（并发编排/度量/JSONL，D5 靠它调度）
4. **D5 最后**（试金石 harness：把前三路能力组装成端到端项目，并反哺缺陷清单）

每合一路，主线跑定向回归并出「红转绿 / 新增打红」两份名单；**每合一路都推一次远端等 CI**（第四轮教训）。

## 9. 交付格式（六项，沿用第四轮 §9）

1. 改了哪些文件（逐个列 + 一句改动意图）
2. 定向测试结果（跑了哪些、输出落盘、**汇总行直抄不许人工拼**）
3. **反跑证明**：每条核心判据，把实现改坏一处，贴用例变红的实测输出；「一次就绿」的判据必须补
4. **移交清单**：`光明写不出什么 → 你的临时绕法 → 期望的语言能力`
5. 已知未完成 / 未实测项（**POSIX 分支必须标注**）
6. skip / xfail 清单与掩盖分析
