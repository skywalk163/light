# 协作规程（四路并行强制约定）

> **适用对象**：任务 A / B / C / D 的执行 agent。
> **前提**：四个 agent 跑在**同一台机器**上（Win10 + PowerShell 5.1，同一套 Python 与 clang 环境），仓库 `g:\dswork\duan-light-merge\light-merge`，主分支 `main`。
> **这份规程优先于任务书里的任何冲突表述。** 有疑问停下来问，不要自行决定。

---

## 0. 为什么需要这份规程

四个 agent 同机同树作业会踩三个必然的坑，规程就是为了绕开它们：

1. **`git stash` 栈是仓库全局共享的**。如果每个 agent 都用「stash → 跑基线 → pop」的老办法，A 正处在 stash 状态时 B 一 pop，A 的改动就丢了或错位了，而且事后查不回来。
2. **同机跑多份全量 pytest 会造假红**。3400+ 用例本来就慢，多路抢 CPU 时所有 timing 敏感用例会集体假红——已知 `L1_baihua/10_引Python画笑脸.light` 就是靠 120s 子进程超时判死的，成败只看机器负载。任务 B 的 socket 用例、任务 D 的进程超时用例同样敏感。
3. **任务 D 要杀进程树**。若按进程名匹配，会把别的 agent 正在跑的 pytest 一起杀掉。

---

## 1. 工作树隔离（开工第一步）

**不许直接在 `g:\dswork\duan-light-merge\light-merge` 上改代码。** 每人一个独立 worktree + 独立分支：

```
git worktree add ../wt-A -b task-A main
git worktree add ../wt-B -b task-B main
git worktree add ../wt-C -b task-C main
git worktree add ../wt-D -b task-D main
```

你只在自己那个 `wt-X` 目录里作业。独立工作树 = 独立 stash 栈、独立 index，互不干扰。

**⚠️ 主工作树当前有 67 处未提交改动**（62 个 `docs/lightpub/*.md`、`src/code_generator.py`、`.gitea/workflows/ci.yml`、`tools/gen_lightpub_docs.py`，以及 2 个未跟踪的 lightpub importability 文件）。这些属于**另一个 agent 尚未收尾的工作**，正在等它提交。

- `git worktree add` 从 commit 检出，**不会带过来这些未提交改动**——所以你的起点是干净的 HEAD，这是好事
- **谁都不许去 commit / revert / stash 那 67 处改动**，那不是你的
- 等那个 agent 提交后，主线会通知你 `git rebase main` 同步
- **任务 A 特别注意**：`src/code_generator.py` 正是那 67 处里的一个，也是你的主战场文件。你 rebase 时**大概率冲突**。所以：先做不碰 `code_generator.py` 的部分（lexer / keywords / parser），把 codegen 侧的改动尽量集中在少数几个 hunk 里、并单独成 commit，降低冲突解决成本

## 2. 回归验证：全量串行，定向自跑

**旧协议（每人自己 `git stash push` 跑两遍全量）已作废，不要执行。** 新协议：

### 你要做的：只跑定向测试

在自己的 worktree 里，只跑与你改动相关的测试子集。快、无争抢、结论清晰。

- **任务 A**：`tests/test_async.py`、`tests/test_iterator_protocol.py`、前端相关 unit 测试，以及你自己新增的真跑测试。因为 A 的改动面广（尤其 `映射/筛选` 参数序变更），额外跑一遍 `tests/e2e/` 与积木库体检做粗筛
- **任务 B**：`tests/test_llvm_*.py`、`tests/unit/test_ir_verify.py`、`tests/e2e/test_llvm_pipeline.py`，以及你新建的 `tests/test_llvm_net.py`
- **任务 C**：你新建的 `tests/test_sse_light.py`、`tests/test_llm_client_light.py`、`tests/test_schema_light.py`，加 `tests/test_stdlib_complete.py`
- **任务 D**：你新建的 `tests/test_process_tree_light.py`、`tests/test_event_bus_light.py`、`tests/test_plugin_light.py`，加 `tests/test_cross_platform.py`

**不许跑全量**。也不许为了"确认没打破别的东西"而偷偷跑一次全量——那正是会互相干扰的行为。

### 主线要做的：合并点统一跑全量

每路交付后，主线（comate）在**独占机器**的条件下跑一次全量，并按既定口径出结论：

- 核对 `skipped / errors / collected` **三项全等**，再看 failed −N / passed +N
- 逐条 set-diff FAILED 清单，产出「红转绿」与「新增打红」**两份名单**（只看 failed 总数分不出「N 绿」和「N+1 绿 + 1 新红」）
- 基线权威在 `docs/v7_失败用例根因聚类工单.md` 首部，**同会话内自测取基线，不引用历史数字**
- 已知抖动源 `test_e2e_chain.py` 的 `L1_baihua/10_引Python画笑脸.light`（run + product 两例）不计入任何一张单

**所以：跑全量出结论不是你的活，别抢。** 你负责的是"我的定向测试全绿 + 我的改动范围说清楚"。

### 跑测试时的礼让

定向测试也可能撞车。开跑前在群里/日志里喊一声，或者约定时段。**如果你的定向测试超过 5 分钟，先问主线现在能不能跑。**

## 3. 同机资源不撞车

### 端口分配：一律 `bind(("127.0.0.1", 0))` 由内核分配

测试里的 fake server（echo / HTTP / SSE / TLS）**绑 0 端口，再用
`getsockname()[1]` 取回实际端口**，客户端 URL 由这个值拼出来。
不写死端口，也不需要探测可用性。

对应地，fixture 必须先起服务器、再拼 URL —— 别把 `服务器.port` 用在
`起服务器(...)` 之前。

~~原口径：任务 B 用 19100–19199 / 任务 C 用 19200–19299 / 任务 D 用 19300–19399，
绑定前先探测、占用则报错退出。~~ **已作废**（2026-08-22）：段划分解决的是
「不同任务的进程互不干扰」，而 CI 上 `pytest -n auto` 默认 `--dist=load`
会把同一个文件的用例散到不同 worker 去跑，**同一个段里自己撞自己**——
FreeBSD runner 上 8 条红就是这么来的，段划分对此结构性无解。
`SO_REUSEADDR` 也救不了：它只放行 TIME_WAIT 残留，不放行第二个活着的 listener。

（既有先例：`tests/test_lightpub_bridge.py` 一直是绑 0 端口的写法。）

### 临时文件命名

所有临时文件、spill 文件、落盘的输出捕获，一律加自己的任务前缀：`_taskA_*` / `_taskB_*` / `_taskC_*` / `_taskD_*`。**收尾必须删干净，工作树只留最终交付物。**

（这条沿用本项目既定口径：并行作业的探针名必须唯一。）

### 进程隔离（任务 D 重点）
- 杀进程**只许按自己 spawn 得到的 PID / 进程组**操作
- **绝对禁止**按进程名匹配去杀（`taskkill /IM python.exe` 之类），会连带杀掉别人正在跑的 pytest
- 测试里的超时清理也要走同一条规则

## 5. 两条不变的硬约束

1. **新增 stdlib 能力只建 `.light`，绝不建同名 `.py`**。`stdlib/_light_import_hook.py:140-142` 规定 `.py` 绝对优先，建了 `.py` 你的光明代码就永远不会被执行。（当前 stdlib 自举率 0/134，任务 C/D 是来破零的。）
2. **`引 Python` 计数恒为 0**。`导入 现有模块`（普通 import）可以；`引 Python：<裸 Python 代码>` 不行。绕不过就登记为语言缺陷交给任务 A——用逃逸口掩盖缺陷等于把整个项目的意义废掉。

另：**本机装第三方库导致的转绿不算修好**（任务 D 尤其注意别依赖 `psutil`）。

## 6. 环境约定（PowerShell 5.1）

- **中文输出必须落盘再读**，直接读会乱码（乱码只在显示层，文件内容是好的）
- **不支持 `&&`**，用 `;` 或分多次执行
- **不支持 heredoc**
- 命令输出被截断时，重跑同一条命令并 `| Out-File -Encoding utf8 <临时文件>`，读完即删

## 7. 交付格式

每路交付时提交一份自测报告，含四项：

1. **改了哪些文件**（逐个列，附一句改动意图）
2. **定向测试结果**（跑了哪些、全绿截图或输出落盘）
3. **移交清单**：格式 `光明写不出什么 → 你的临时绕法 → 期望的语言能力`。这份清单直接决定任务 A 下一批修什么，**是最有价值的产出之一，别偷懒**
4. **已知未完成 / 未实测项**（尤其跨平台：只在 Windows 实测过的 POSIX 分支必须标"未实测"，不许声称跨平台通过）

然后停下来等主线跑全量，不要自行合并到 `main`。

## 8. 合并顺序

1. 等主工作树那 67 处改动提交
2. **A 先合**（它是关键路径，B/C/D 的语言缺陷绕法都要靠它才能简化）
3. **B 次之**（零重叠，风险最低）
4. **C 和 D 错开合**（两者都在 `stdlib/` 下建新文件，虽不重名但会碰同一目录）

每合一路，主线跑一次全量并出「红转绿 / 新增打红」两份名单。
