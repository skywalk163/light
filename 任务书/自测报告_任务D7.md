## 附件 A：round-trip 样本清单 + 与 `JSON.py` 行为差异（§3.1 判据2）

### A.1 round-trip 样本清单（全部 `解析→序列化→解析` 与 `JSON.py.解析JSON` 逐字段相等）
- **评测集 6 条**：`examples/harness/评测集.jsonl`
- **构造样本 8 类**：深嵌套 / 中文 / 转义 / 大整数 / 浮点指数 / 空对象 / 空数组 / 混合
  - 深嵌套：`{a:1, b:[1,2,{c:[3,4,{d:"底"}]}], e:{f:{g:true}}}`
  - 中文：`{名字:张三, 城市:北京, 句子:"今天天气真好，适合写代码。"}`
  - 转义：`{s:"一行\n二行\t制表\"引号\\反斜杠", 尾:"结尾\r\n"}`
  - 大整数：`{big:123456789012345678901234567890, neg:-9876543210123456789}`（往返不丢精度）
  - 浮点指数：`{e1:1.5e10, e2:-3.14e-2, zero:0.0, one:1.0}`
  - 空对象 `{}` / 空数组 `[]`
  - 混合：`[null, true, false, "文本", 42, 3.14, {k:[1,"二",null]}]`

### A.2 与 `JSON.py` 行为差异（逐条登记，无静默不一致）
1. **`缩进=0` 形态差**：`序列化(值,0)` 产出「紧凑无换行」；`JSON.py.序列化JSON(值,0)` 因 `if 缩进 is not None` 判定产出「0 缩进换行」`{\n...\n}`。两者在 `缩进=2` / 无参紧凑时**逐字节一致**（`test_eval_set_serialize_matches_json_dumps` 以 `json.dumps(ensure_ascii=False, indent=2)` 对照全绿）。已在该测试注释登记。
2. **`<0x20` 控制符（除 `\n\r\t\b\f`）**：本实现原样输出、不转 `\u00XX`；`json.dumps(ensure_ascii=False)` 会转义。评测集与构造样本不含裸控制符，round-trip 不受影响；已在 `JSON核心.light` 文件头登记为已知差异（建议后续轮次补齐控制符转义以彻底消除差异）。
3. **非 ASCII（中文/é 等）**：两者均 `ensure_ascii=False` 原样保留 —— **一致**。
4. **数字**：整数任意精度 / 浮点指数 / 负数 —— 与 `json.loads` 一致（大整数往返不丢精度已验）。
5. **重复键**：后写覆盖前者 —— 与 `json.loads` 默认一致。
6. **NaN/Infinity**：标准 JSON 不允许；解析器遇之抛「非法字符」异常 —— 与 `json.loads` 默认 strict 一致。
