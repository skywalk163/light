### 8.2 FreeBSD runner 上的三层剥皮（run #63 → #65）

**这一节是 CI 侧（FreeBSD 14 + clang）的基线，跟 1.3 的本机（Windows）基线不是一回事，别混用。**
本机永远看不到下面这些红——它们全部只在 runner 的平台上成立。

逐轮实测（都是 push main，闸门时间几乎不动，因为运行时 `.o` 只编一次并被缓存）：

- **run #63**（`189e6aea`）：打红 71 / soft 59 / hard 12，`C Layer` 整条腿崩。
  根因是 `src/llvm/runtime_typed.c` 的 POSIX include 块缺 `<fcntl.h>`——
  glibc 会经别的头间接带出来，FreeBSD/clang 不会，`dv_socket_set_nonblocking`
  里的 `fcntl/F_GETFL/O_NONBLOCK` 直接 4 个 `use of undeclared identifier`。
- **run #64**（`2ecfa002`，补 `<fcntl.h>`）：数字与 #63 **完全一样**。
  编译 error 确实没了，但暴露出第二层——7 处测试侧 clang 链接命令各自硬编码
  Windows 的 `-lws2_32/-lsecur32/-lcrypt32`、且一律缺 `-lm`，在 FreeBSD 上链不上。
  之前这几条在 runner 上「绿」是因为被 skip 掉了，不是因为它们没问题。
- **run #65**（`5f02c570`，链接参数收成单点 `compiler.py::get_link_libs()`）：
  打红 **71 → 38**，soft **59 → 26**，hard 仍是 12（= 基线 12，新增打红 0），
  且第一次出现 `C Layer Results: 25/25 passed`。
  时间线 487 → 498 → 498 → 497.9 → 498.1s，clang 腿真跑起来了也没超预算。

**#65 之后新暴露出来的、已定性的三类**（口径变更见本节末，实现细节见各自测试文件里的注释）：

- 8 条端口撞车：`-n auto` 默认 `--dist=load` 把同文件用例散到不同 worker，
  几个 fake server 写死端口，两个 worker 同时 bind 同一个 `127.0.0.1:port`。
  `SO_REUSEADDR` 只挡 TIME_WAIT 残留，挡不住第二个活着的 listener。
- 1 条 `FD_SETSIZE` 判据空转：超容量用例写死 `want = 300`，只压得住 Windows 的
  `FD_SETSIZE=64`；FreeBSD/Linux 是 1024，一个都拒不掉。实现（`runtime_typed.c`
  的 `dv_poller_register`）本身是对的，红的是判据。
- 1 条 TLS 判据缺失 + 1 条平台表漂移（`解析库路径` 在 FreeBSD 上静默返回空串）。

**由此产生的两条口径变更（已裁决）**：

1. **端口一律 `bind(("127.0.0.1", 0))` 让内核分配，`协作规程.md` §3 的「端口段划分」作废。**
   段划分解决的是「不同任务的进程互不干扰」，而 xdist 是同一份用例在多 worker 里
   跑两遍——同一个段里自己撞自己，段划分对此无解。
2. **超容量判据按 `FD_SETSIZE + 64` 真压上限，不许写死常数。**
   代价是 POSIX 上要开 1088 个 socket，所以 `tests/test_llvm_c_runtime.c` 里
   自带 `setrlimit(RLIMIT_NOFILE)` 抬软上限；抬不动就让「开不满」这条判据明确失败，
   不把判据静默降级成「环境不够用」。

### 8.4 pty 那 3 条：一条从未真跑过的路径，缺陷是**叠层**的

结论先行：**不是「该 skip」，是真缺陷，而且一共四层，每修一层才露出下一层。**
run #66 → #69 四轮才收干净，最终 `collected=4396 failures=23`（soft 11 + hard 12
= 基线，新增打红 0，500.0s），三条 `TestPOSIXOpenPTY` 全绿。

逐层（都在 `stdlib/伪终端.light`）：

- **第一层 `TIOCSWINSZ` 请求号写死 21523。** 两处错：21523 = `0x5413` 是 Linux 的
  `TIOCGWINSZ`（**读**），不是 `TIOCSWINSZ`（`0x5414`，写）——**在 Linux 上也从没
  真改过窗口大小**；而 BSD 系走 `_IOW` 编码是 `0x80087467`，`0x5413` 在 FreeBSD 上
  根本不是合法请求号 → `ENOTTY(25)`。它由 `启动POSIX` 在构造期调用，所以三条全崩，
  连不碰窗口大小的那条也崩。改成问 `termios.TIOCSWINSZ` 要本平台真值。
- **第二层 `pty.fork()` 被当成返回裸 pid。** 它返回 `(pid, master_fd)` 元组，
  元组永远不等于 0，于是**子进程不进 `execvp` 分支、当成父进程继续跑**。
  在 `pytest -n auto` 下就是 worker 被 fork 成两份、同一 item 上报两次，
  xdist load 调度器 `list.remove` 炸掉 → 整场 `INTERNALERROR`、
  collected 从 4396 掉到 4064，闸门按「新增打红 `pytest::internal`」拦下（run #67）。
  连带：原先先 `openpty()` 再 `fork()` 出第二对 pty，`主fd` 指着前者、
  子进程的控制终端是后者，从主 fd 读永远是空。现在只用 `pty.fork()` 这一对。
- **第三层 `EAGAIN` 写死 11。** Linux 是 11，FreeBSD/macOS 是 **35**。
  读线程第一次非阻塞 `os.read` 拿到 35 就被当致命错误退出，缓冲区永远空 ——
  表现是 `test_启动命令读到带ANSI的输出` 等满 8s 拿到 `b''`（run #68）。
  旁证很硬：另两条不依赖读输出，所以**三条里恰好只红这一条**。
  改成取 `errno.EAGAIN` / `errno.EWOULDBLOCK`。
- 顺带把「`fcntl` 导入失败就静默 `返回`」改成抛错：公开接口什么都不做地返回
  就是静默假成功。并在 `execvp` 后补 `os._exit(127)` 兜底 —— 子进程绝不允许
  继续跑父进程代码，那正是第二层缺陷的形态。

**这四层 + 之前的 `fcntl.h` 缺 include、链接库写死 Windows 三件套缺 `-lm`、
`FD_SETSIZE` 判据写死 300，长的是同一张脸：把某个平台的取值当成通用取值，
且全部藏在从未在真机上执行过的路径里。**

由此定一条估工口径：**「一条从未在真机上跑过的实现」不许按「改一处就好了」
估工作量 —— 层数事先不可知，只能靠 CI 一层层剥。**（本轮我先说了「一个文件的事」，
低估了，四轮才收。）配套做法：修完一层后，先按同类判据把全仓扫一遍
（如 `errno` / 硬编码 ioctl 号 / 平台常量），避免为同一族缺陷反复排队等 CI。

**run #69 新出现一条与本次改动无关的红**：`test_http_client::test_concurrent_requests`
`assert 9 == 10`（10 个并发只回来 9 个 200）。它**不是**缺 aiohttp 那类环境欠账，
#66/#67/#68 都没红过、#69 才红，形态像 xdist 负载下的竞态/抖动。
soft 门没拦下，但它不该被算进「环境欠账」那一栏，需要单独定性（是判据太紧，
还是并发实现真丢请求）。
