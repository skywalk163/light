## 0. 一条贯穿全任务的口径

**静默错编是本项目最高优先级的缺陷类型**，高于"功能缺失"。理由：功能缺失用户会立刻发现并绕开；静默错编会让用户以为程序对了。第一轮的 `映射/筛选` 换序、`生成 从`、LLVM 语句丢弃全属此类。

所以本任务每一项的验收都包含一条：**错的写法必须炸，且报错文案要指向正确写法。** 不许只做"正路能跑"。

## A2-1 【P0】LLVM 后端语句分派没有 else 兜底 → 语句被无声吃掉

**证据**：`src/llvm/codegen_typed.py:2367-2409` 是一条 `if/elif` 链，链尾 `:2408-2409` 之后直接是下一个方法定义，**没有 else**。全 `src/llvm/` 目录 grep `ScopeDeclStmt|nonlocal` 零命中，`YieldStmt` 同样无分支。

**后果**：原生后端遇到 `全局 计数。`、`生成 X。` 这类语句，既不编译也不报错，**直接产出一个行为错误的二进制**。原生优先是北极星，这个洞不能留。

**要做的**
1. 链尾加 `else`，抛明确异常：`NotImplementedError`（或项目既有的 codegen 异常类型），文案必须含**语句类型名 + 源码行号 + 「原生后端暂不支持，请用转译后端（`python -m cli.light_unified run`）」**。
2. 用 `git grep` / AST 节点清单对照，列出**当前所有未被原生后端支持的语句类型**，写进移交清单（这份清单是"原生腿离承载 harness 还差多少"的量化答案，价值很高）。
3. 对 `ScopeDeclStmt`（`全局`/`外层`）：本轮**只要求明确报错**，不要求实现。原生后端没有闭包捕获的完整模型前，硬做会引入更深的错。

**测试**：`tests/unit/test_llvm_stmt_coverage.py`（新建）。至少覆盖：`全局`、`外层`、`生成`、以及你清单里任意 2 个未支持语句 → 断言抛异常且文案含语句名。**反跑护栏**：已支持的语句（`如果`/`遍历`/`返回`/赋值）必须仍然不抛。

## A2-2 【P0】`外层`/`全局` 的判据在分词被拆时静默失效

**证据**：`src/parser_stmt.py:579` 判的是**单个 token 的 `tok.value`**（`_SCOPE_DECL_WORDS = {'全局': 'global', '外层': 'nonlocal'}` 在 `:670`）。但光明的分词是上下文相关的——下面这段：

```
段落 外:
  设 计数 为 0
  段落 内:
    外层 计数。
```

因为 `外` 已是本文件的段落名，`外层` 被切成 `IDENTIFIER '外'` + `IDENTIFIER '层'`，`:579` 不命中，**静默编成 `外层(计数)`** —— 与修单前完全一样的「编译期零提示、运行期 NameError」。孤立写法能切成单 token，所以常规测试看不出来。

**要做的**
- 把判据从「单 token 值相等」改为**能容忍分词切分的序列判据**（多 token 拼接后比对，或在 lexer 侧对 `全局`/`外层` 做优先成词）。选哪条路你定，但**必须给出为什么这条路不会反过来打破"`外` 作段落名"的现有用例**。
- 这是本项目既定判据口径的应用：**单字/双字关键字类改动必须过全仓 A/B 对比**（第一轮口径），不能只跑定向测试就宣布好了。全量由主线跑，但你要提前用 AST 级扫描（不是文本 grep）给出影响面清单。

**测试**：真跑用例，必须包含**段落名叫 `外`/`全` 的场景**下 `外层 计数。` 仍然正确编成 `nonlocal 计数`。放进 `tests/test_frontend_blockers_run.py`（已有双腿真跑基建，`:36-68`）。

## A2-3 【P0】异步并发原语：agent 循环的刚需，现在一个都没有

**证据**：`src/lexer.py:234-239` 把 `异步睡眠`、`创建事件循环`、`事件循环运行`、`事件循环创建任务`、`异步任务等待` 列进词法名单，但 **Python 后端零映射、原样输出标识符**；真实定义只在 `stdlib/lightpub/异步运行时.py`（而 `stdlib/lightpub/__init__.py:45` 路由到**外部仓库** `C:\dumatework\lightpub`），`stdlib/builtins.py` 里没有。对应测试 `tests/test_async.py:581-658` 全是 `assert 'await 异步睡眠' in py_code` 这类字符串断言。

**结论：这批名字是"只在名单里"的假实现**，属第二轮总纲 §5 明令禁止的形态。

**要做的**——落地一组**真映射**的异步原语，沿用 `异步 运行` 已建立的 `_needs_asyncio` 机制（`src/code_generator.py:865-875` 按需插 `import asyncio`）：

| 光明写法 | 目标 Python | 用途（harness 里干什么） |
|---|---|---|
| `等待 异步睡眠(0.5)。` | `await asyncio.sleep(0.5)` | 重试退避 |
| `等待 并发等待(任务表)。` | `await asyncio.gather(*任务表)` | 并发发多个 tool call |
| `等待 限时(协程, 30)。` | `await asyncio.wait_for(协程, 30)` | 单次请求超时 |
| `创建任务(协程())。` | `asyncio.create_task(...)` | 后台任务 |
| `等待 首个完成(任务表)。` | `await asyncio.wait(..., return_when=FIRST_COMPLETED)` | 竞速/取消 |

命名可调整（跟现有中文风格一致优先），但**必须做到三件事**：
1. codegen 真映射，不是往名单里加名字；
2. **把 `src/lexer.py:234-239` 里那批做不到映射的死名字删掉**——留着就是继续误导用户；删除会不会打红现有用例，用 AST 扫描先查；
3. 每个原语都有真跑用例（断言 stdout 与时序），不是字符串断言。

**顺带**：`tests/test_async.py` 里那批字符串断言用例，**至少把涉及本任务原语的部分改造成真跑**。这个文件是"洞长期没被发现"的直接原因。全文改造工作量大，允许分批，但改到哪写清楚。

## A2-4 【P1】泛型参数发射时被丢弃

**证据**：泛型**已经解析进 AST**（`src/parser_stmt.py:4059-4073` 类、`:4449-4455` 段落、`:5973-5989` 类型别名 → `ClassDefinition.generic_params`，`src/ast_nodes_v3.py:505`），类型层也已消费（`src/type_inferencer.py:329-338`、`src/type_system.py:681`）。但 **`src/code_generator.py` 全文 grep `generic_params|TypeVar|Generic` 零命中** → `类 栈[T]:` 编成 `class 栈:`。

**测试**：真跑（构造一个泛型容器，实例化并断言行为）+ 生成码断言 `Generic[` 存在。

## A2-6 【P1】模块循环依赖：先核实"段落内延迟导入"是否真能用，再决定

**证据**：`src/module_resolver.py:746` / `:845` / `:872` 三处一律 `raise CircularDependencyError`，无 `allow_cycle` 之类开关。错误文案 `:54` 建议「在段落内部延迟导入」。

**要做的**（顺序不许颠倒）
1. **先实测**：`导入 X。` 写在段落体内，现在是否真能工作（解析允许吗？codegen 发射在函数体内吗？module_resolver 会不会仍把它计入依赖图从而照样报环）？
2. 如果延迟导入真能用 → **只改错误文案**，给出可复制的正确写法，不动拒绝策略。
3. 如果延迟导入也不能用 → 实现它。**默认仍然拒绝顶层循环依赖**，不要加"放行开关"。

理由：harness 的模块分层（`SSE → 流式 → 大模型客户端 → agent循环`）本来就该是 DAG，放行循环依赖是给坏设计开后门。但"官方建议的绕法其实不工作"是文档腐烂，必须修。
