## 3. S2：`伪终端`(98) 与 `进程树`(26)

### 3.1 `stdlib/伪终端.light` —— 最难的一个，ctypes 76

ctypes 直调 76 处是 Windows ConPTY API 的裸调用。**这不是「换个写法」能解决的，它需要 FFI 能力**。三条路：
- (a) 交给 B9 在 `runtime_typed.c` 里做 ConPTY 封装，光明侧调内置函数 → 直调归零，但依赖 B9 排期

- (c) 承认它是**平台边界**，在清单里登记豁免，只把 os(11)/time(2)/sys(1) 那 14 处搬走

**S1 末必须给出选型建议并等主线裁决。** 我的倾向是 (a)，因为原生腿本来就要有 ConPTY（M23 要跑 harness 全链，沙箱工具要开子进程）。但 (c) 也是诚实的选项 —— **登记豁免比假搬迁好**，前提是豁免要写进清单并说明为什么。

### 3.2 `stdlib/进程树.light`：26 → 目标 ≤8
