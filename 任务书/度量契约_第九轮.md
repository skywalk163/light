## 0. 为什么先写这份

总纲 §6 要求三份跨路契约「先写成文档 commit，再各自动手」。这一份是其中的度量侧：
清单结构不先冻结，C9 / B9 / F9 会各写一套字段名，G9 的门禁就得跟着改三次，
最后必然出现「指标能过但含义各不相同」——第二轮 0/134、8/63、16/68 三个自举率
口径打架就是这么来的。

**一句话原则：状态词不能当解释用。** 每个「做完了」都要指得出在哪，每个「做不到」
都要写清为什么。

## 1. 通用规约（三张清单都适用）

- 位置一律 `任务书/*.json`，**不许放 `docs/`**（`docs/` 会被
  `tests/unit/doc_block_scan.py` 扫，第五轮 `2595a6d0` 的既有裁决）。
- 编码 UTF-8、`indent=2`、`ensure_ascii=false`、结尾一个换行（`newline="\n"`）。
- **路径一律 POSIX `/`**，不许出现 `\`：基线键带 `os.sep` 会让本机绿 / CI 红
  （gitea run 71 的原样教训）。
- 证据形如 `相对路径:行号`。**行号是人读线索**，只有地板清单的落点会做窗口校验
  （见 §2），其余只校验文件存在 —— 行号会随任何编辑漂移，全面校验它只会造长红。
- 状态字段只许取值域内的词。写「基本完成」「大致可用」一律判红。
- 状态从 X 变成 Y，必须在交付报告第 5 项写明「哪几条从什么变成什么」。
- **基线只在合并点由 G9/主线重建**（总纲 §5 红线 5）。各路不许自己刷。

## 2. `自举地板清单.json`（C9 填内容，G9 守分母）

门禁：`tools/ci/floor_bootstrap.py`。指标：

    地板自举率 = 纯光明实现数 / (总数 − native_required 数)

条目字段：

- `名字`：`stdlib/builtins.py` 里的函数名。**集合必须与 `ast` 解析出的顶层函数名
  逐个相等**（双向咬合）。漂移了跑 `--sync-list` 补齐（只增不改）。
- `职责`：一句话。空着判红 —— 不写职责，后面没人判得出该不该搬。
- `当前实现语言`：`python` / `light`。**C9 的字段。**
- `native_required`：布尔。**G9 的字段，改它要走主线裁决。**
  为真必须在 `备注` 里写清是哪类边界。
- `计划落点`：自由文本，搬到哪个 `.light`。**C9 的字段。**
- `证据`：登记成 `light` 时必填，形如 `stdlib/内置核心.light:42`。
- `备注`：`native_required` 为真时必填。

**证据的判据（这条是本轮最严的一条，刻意如此）**：

1. 文件存在，且必须是 `.light`（指到 `.py` 等于没搬）；
2. **行号 ±2 窗口内存在一行「既是 `段落|类|函数` 定义行、又含该函数名」**；
3. 该 `.light` 不被同名 `.py` 遮蔽（有 `.py` 就必须首两行挂魔数「纯光明实现」，
   否则运行期跑的是那个 `.py`，写了也跑不到）。

为什么不是「行号在文件范围内」：那是**上界断言**，四千行文件里任何数字都过，
判据等于不存在（第七轮 B7 原稿踩过，`test_native_leg_capability.py:186` 已收紧）。
±2 是给正常编辑漂移的余量，不是给蒙数字的余量。

**分母三重锁**（防「挪进豁免涨点」）：`native_required` 名单新增即红、
`native_required` 条数只降不升、分母只升不降。真是边界的，先在交付报告里给理由
并请主线裁决，再随基线一起改。

G9 的初值裁决（32 条真边界，可争议但要走裁决）：文件 I/O 15 条、`绝对路径`（realpath）、
环境与进程 7 条、stdin/stdout/stderr 7 条、`时间戳`、`随机浮点`。
明确**不算**边界并已写进 `备注` 的：`连接路径`/`目录名`/`文件名`/`扩展名`/`分割路径`/
`分割扩展名`（纯字符串运算）、`格式化时间`（历法算术）、`随机整数`/`随机选择`
（可由 `随机浮点` 推出）、`解析JSON`/`序列化JSON`/`美化JSON`（纯文本处理）。

## 3. `原生腿产品清单.json`（B9 填内容，G9 守门禁）

门禁：`tools/ci/native_product.py`。三张表、三条指标。

### 3.1 `模块表`

字段 `模块` / `状态` / `阻断原因` / `证据` / `备注`。

- `状态` ∈ `可编译` / `不可编译` / `未实测`
- `模块` 集合必须与 `stdlib/` 下 `.light` 的实际集合逐个相等（`--sync-list` 补齐）
- `可编译` 必须有 `证据`，且证据里要含一条**可复跑的 `light` 命令** ——
  这就是总纲 §6「B9 → 全体的原生可编译判定命令」那份契约的落点
- `不可编译` 必须写 `阻断原因`
- 指标：可编译比例只升不降；`未实测` 数只降不升；总数不许缩

### 3.2 `CLI路径表`

字段 `路径` / `后端取值` / `状态` / `证据` / `备注`。

- `状态` ∈ `可用` / `坏` / `未实现` / `未实测`；`坏` 必须写 `备注`
- **`cli/light.py` 里 `--backend` 的每个 `choices` 取值都必须在 `后端取值` 里出现**，
  否则判红。这条同时堵住「删掉表里那条来消掉 `坏` 计数」
- 反向（表里有、源码已无）只**告警**不判红：摘掉死腿是本轮许可的处置
  （总纲 S1「修或删，二选一」），摘完 `坏` 计数下降是真进步
- 指标：`坏` 的条数只降不升
- 不是后端取值的路径（`light pkg native` / `light build --target native`）
  `后端取值` 填空串

### 3.3 `平台矩阵`

字段 `平台` / `能力` / `状态` / `证据` / `备注`，3 平台 × 4 能力 = 12 格。

- `状态` ∈ `已实测通过` / `已实测失败` / `未实测`
- `已实测通过` 必须写 `证据`（哪台机器、哪条命令、哪个测试）
- `已实测失败` 必须写 `备注`
- 指标：`未实测` 格数只降不升，`已实测通过` 格数只升不降。
  **这条专治「只在 Windows 测过就声称跨平台」**
- S1 初值：Windows 四格已实测通过（2026-08-24 本机实跑
  `pytest tests/test_llvm_net.py tests/test_llvm_tls.py tests/test_native_cli.py -q`
  → 37 passed / 3 skipped）；Linux 与 macOS 八格全 `未实测`

## 4. `分布式判据清单.json`（F9 填内容，G9 守门禁）

门禁：`tools/ci/dist_criteria.py`。九条能力：分发 / 心跳 / 重派 / 幂等 / 背压 /
限流 / 取消传播 / 结果汇聚 / 故障隔离。**可增不可删。**

字段 `能力` / `状态` / `判据` / `反跑` / `本阶段目标` / `备注`。

- `状态` ∈ `done` / `partial` / `none`
- `done` 必须**同时**满足：
  - `判据` 形如 `tests/xxx.py:123`，文件真存在、行号在文件范围内
  - `反跑` 非空、含动作词（改/删/取反/注释/换/调/去掉）、且指到一个真存在的文件
- `partial` / `none` 必须有 `备注` 写明差什么、本阶段做不做
- 指标：`done` 只升不降，已 `done` 不许退回

**为什么把反跑写成硬性字段**：从零起步的东西最容易攒出只有壳的判据 ——
一条 `assert 节点数 >= 1` 就能让「分发」看着有判据。反跑 = 一句可执行的话，说明
改哪一行会让这条判据立刻变红。写不出反跑的判据，通常意味着它没在验证它声称
验证的东西。**没有反跑就不算判据**（总纲 §5 红线 3）。

S2 / S3 两个合并点各跑一遍：

    python tools/ci/dist_criteria.py --root . --print-inspection

按输出逐条人工复跑，结果写进阶段合并报告。**反跑后仍绿的判据无效**，状态退回
`partial` 并留档。
