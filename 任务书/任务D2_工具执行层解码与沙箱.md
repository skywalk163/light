## D2-1 【P0】Windows 输出解码硬编码 UTF-8

**证据**：`stdlib/进程树.light:97-123` 的 `文本()` **硬编码 `decode("utf-8")`**。Windows 上子进程管道输出是 cp936/GBK，于是 `"目录甲"` 被解成 `'Ϳ¼\ufffd\ufffd'`。

**失败清单（5 条，同一根因）**：`test_正常退出取输出`、`test_非零退出码`、`test_stderr与stdout分离`、`test_未超界不建spill`（都是中文对不上）、`test_超界触发spill与省略标记`（尾部 `endswith("中国结束")` 不成立，同因）。
**通过的 3 条**恰好都不含中文：`test_命令不存在`、`test_超时杀整棵树含孙子进程`、`test_环境黑名单过滤`。
**skip 的 1 条**：`test_posix信号语义跳过占位`（`:116` 在 win32 上 skip）。

**要做的**
1. **字节接口与文本接口分开**：`字节()` 返回原始 bytes，`文本(编码=无, 错误="replace")` 做解码。**默认编码不许硬编码**——按平台探测（Windows 用 `locale.getpreferredencoding` / 控制台代码页；POSIX 用 UTF-8），且**允许调用方显式指定**。
2. **错误策略必须可控且默认不炸**：agent 工具执行遇到乱码字节不该让整轮循环挂掉。默认 `errors="replace"`，但**必须在结果里带一个"发生过解码替换"的标志位**，否则就成了静默数据损坏（本项目最高优先级缺陷类型）。
3. **spill 文件的截断点必须在字节层做，不是字符层**——现在尾部 N 字节窗口切割可能切断多字节字符，`.解码()` 会产生半个字符。检查现有实现有没有这个问题（`:97-123`），修法参照 C2 在 `stdlib/SSE.light:29` 用的增量解码器思路。
4. UTF-8 与 GBK 混合输出（一个子进程 stdout 是 UTF-8、另一个是 GBK）这种真实场景要能兜住，至少不崩。

**验收**：`tests/test_process_tree_light.py` 在 Windows 上 **0 failed**。新增用例：显式指定编码、编码探测、解码替换标志位、跨窗口边界的多字节字符。

## D2-3 【P1】PTY：交互式工具的前提

**证据**：全仓 `PTY`/`ConPTY`/`openpty` 彻底为零（仅 2 处 SFT 语料噪声）。

**为什么需要**：harness 的工具要执行 `git`、`npm`、交互式 CLI 时，管道模式下这些程序会关掉颜色、改变缓冲行为、甚至拒绝运行（检测到非 tty）。而且**行缓冲 vs 块缓冲的差异会让流式输出变成"跑完才一次吐出"**，agent 循环的实时性就没了。

**要做的**（范围克制）
- Windows：**ConPTY**（`CreatePseudoConsole`，Win10 1809+）；POSIX：`openpty`/`forkpty`。
- 新建 `stdlib/伪终端.light`（**不许建同名 `.py`**）。允许 `导入 pty` / `导入 ctypes`（普通 import 不算逃逸）；ConPTY 需要 ctypes 调 Win32 API。
- 接口与 `进程树.light` 对齐：能拿到 fd/句柄、能读流、能设窗口大小、能优雅关闭。
- **本轮只要求"能起一个 PTY、跑一条命令、读到带 ANSI 的输出、正常关闭"**。ANSI 转义序列的解析/剥离不在本轮范围（记为移交）。
- 平台缺失时**明确报错**（"本平台需 Win10 1809+"），不许静默退化成管道模式——静默退化会让上层以为拿到了 tty。

**测试**：`tests/test_pty_light.py`（新建）。Windows 与 POSIX 分别 skip 对方分支，但**每条 skip 都要写明掩盖了什么**。

## D2-4 【P1】工具执行沙箱：路径白名单

**要做的**（本轮只做最实用的一层）
- 工作目录限定 + **路径白名单**：工具只能读写指定目录树内的路径。校验必须在 **realpath/解析符号链接之后**做（否则 symlink 逃逸）。Windows 上注意 junction/短路径名（`PROGRA~1`）也能绕。
- 环境变量过滤沿用你已有的白/黑名单（`stdlib/进程树.light:303-332`）。
- **landlock / seccomp 本轮不做**（Linux only，且需要内核支持），记为移交并写清"没有内核级隔离意味着什么"——这个诚实的风险说明比半成品实现有价值。
- 明确声明这**不是安全沙箱**，只是防误操作的护栏。**不许在文档或报告里把它说成安全边界**——如果 harness 要跑不可信代码，需要容器/VM 级隔离。

**测试**：正负例都要——白名单内可读写、白名单外被拒、symlink 指向外部被拒、`..` 穿越被拒。
