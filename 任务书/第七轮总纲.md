## 0. 这一轮为什么这么排

第六轮之后有一次系统性复盘，结论是三条，本轮就是照这三条排的。

**第一，前六轮的验收判据与目标不在同一层。** 第五轮 M14 写的是「光明达到能独立开发
deepseek-harness 类项目的最终判据」，而 D5 任务书的落地判据是「**跑 mock 即算达成**」。
于是拿到的是：一条 202 行的单轮评测链（`examples/harness/评测驱动.light:81-91`，
只发一条 user 消息、请求体恒无 tools）+ 一条 728 行的多轮 agent 链
（`stdlib/代理循环.light:481`），**两条链互不相通**。原版 harness 的主体恰恰是
「评测集驱动 agent 多轮 + 工具调用」这个交叉点，它现在是空的。
→ 本轮把判据换成**对着功能对标清单勾完成度**（§4.1），并把两链合流做成唯一收口目标（M18）。

**第二，升级计划的 P0「U0-B 原生 socket + 事件循环」在第五轮被静默换掉了。**
第五轮四路实际做的是转译侧异步内核、语言核心四补、并发 stdlib、harness MVP，
五份任务书里没有一处写明「原生腿本轮不做，理由是 X」。
→ 本轮**正式立项 U0-B**（M16/M17），并且从此原生腿每轮必须在总纲里表态：做，或者写明不做的理由。

**第三，度量能升但不反映真相。**
- 自举率 22/74 = 29.73% 是**文件维度 + `decl ≥ 1` 即算有实现**，不含权重。harness 关键路径上
  `stdlib/JSON.light`（145 行、decl **0**）与 `stdlib/文件系统.light`（18 行、decl **0**）都被同名
  `.py` 占位，**评测集读取与报告写盘的底层实现仍然是 Python**。指标涨了，关键路径自举率还是 0。
- 「`引 Python` 逃逸 0」有口径漏洞：8 个 harness 文件里 `导入 os/sys/time/json` 后**直调 Python API
  的非注释行有 91 行**（`os.path.isabs`、`os.makedirs`、`sys.stdout.write`、`os.listdir`、
  `.encode("utf-8")`、`sys.exit`…）。逃逸走的是 `导入` 通道，不被任何门禁计数。
→ 本轮重建度量口径（M20），把「Python 直调行数」变成一条有基线的门禁。

**⚠️ 本轮开工前必须纠正一条流传了六轮的过期结论。**
`复刻deepseek-harness难点分析.md` 与多份记忆/报告写着「原生 runtime 一行网络代码都没有」、
「`epoll|kqueue|WSA|sys/socket` 全部零匹配」。**这是 B1/B2/B3/B2-4 合入前的旧话，现在是假的。**
实测（§2.1）：`src/llvm/runtime_typed.c` 5779 行里，`:4368-4525` 是 B1 socket、`:4547-4556` 是
B2 poller（Windows WSAPoll / 其他 poll）、`:4858-5074` 是 IO 等待队列 + 定时器 + **真事件循环
`dv_scheduler_run_event_loop`**、`:5076-5779` 是 B2-4 Windows Schannel TLS，
`tests/test_llvm_net.py` 13 例 + `tests/test_llvm_async.py` 11 例 + `tests/test_llvm_tls.py` 3 例
**全部真编译、真链接、真跑真 TCP，全过**。
**任何一路不许再在报告或注释里写「原生零网络」。** U0-B 的真实缺口不是「从零写 socket」，
而是四条：**产品路径不通**（`compile --backend llvm-typed` 默认档直接编译失败）、
**优化档与协程互斥**（O1+ 破坏 Duff's device）、**POSIX TLS 是桩**、**能力边界零登记**。

一句话概括本轮：**把「能写」推进到「能交付」——原生腿从实验室走上产品路径，
harness 从 mock 单轮走到评测驱动的多轮工具调用，度量从会涨的数字换成说真话的数字。**

## 1. 第七轮里程碑

- **M16（硬，A7）**：**原生腿走上产品路径。** `light compile --backend llvm-typed` 在**默认优化档**
  下能编译，产物能运行；`light run --backend llvm-typed` 存在并端到端可用。
  判据见 §1.1，**必须结构 + 实跑 + 反跑三连**。
- **M17（硬，B7）**：**原生腿跨平台与语言覆盖面对齐。** POSIX 侧 TLS 出裁决并落地（真实现或
  显式降级 + 文档登记）；`docs/原生腿能力边界.md` 补登 B1/B2/B3/TLS 与全部原生内置函数，
  并做成**机读清单 + 门禁守单点**（门禁脚本归 E7，清单数据归 B7）。
- **M18（硬，C7，本轮唯一收口）**：**评测集驱动多轮 agent + 工具调用端到端跑通，
  且单条失败不打死全场。** 这是「光明能开发 deepseek-harness 类项目」这句话在本轮的判据本身。
  判据见 §1.2。
- **M19（硬，D7）**：**关键路径自举 + 指标层。** harness 的 JSONL 读取与报告写盘不再落到
  Python 实现上；评测报告含 token 用量、成本估算、p50/p95 延迟。
- **M20（硬，E7）**：**度量口径重建。** 「`.light` 里 Python 直调行数」成为一条有基线、只降不升的
  门禁；功能对标清单（§4.1）机读化并做成完成度只升不降的门禁。
- **M21（可选，只升不降）**：pure-light 自举率。基线 **22/74 = 29.73%**，影子 **53**（只许降）。
  D7 会动分子分母，报告里必须分子分母各贴。

### 1.1 M16 的三连判据

1. **结构判据**：`cli/light.py` 的 `run` 子命令 `--backend` 可选值包含 `llvm-typed`
   （现值只有 `['antlr','src']`，`cli/light.py:1332`）；`compile` 的默认 `--optimize`
   档位（现为 `O2`，`cli/light.py:1361`）不再报 `Unknown command line argument`。
2. **实跑判据**：至少三档产物真跑——① hello world；② 一个用 socket 的 `.light`；
   ③ 一个用协程 + 事件循环的 `.light`。**每档都贴 `compile` 命令、`exe` 输出、`rc`**。
   O0/O1/O2/O3 四档全部实跑并列表（哪档过、哪档不过、不过的原因）。
3. **反跑判据**：把优化管线的修复变异掉，上面的用例必须变红。**贴前后实测输出。**

> ⚠️ 附加硬要求：新增的原生用例**必须走 `compile_light_typed` 这条生产路径**，
> 不许照现有测试那样绕过它自己发裸 `clang`（现状见 §2.3 假绿一条）。

### 1.2 M18 的三连判据

1. **功能判据**：一条命令，从 `examples/harness/评测集.jsonl` 出发，驱动**带工具的多轮 agent**
   跑完全部条目并出 JSON + Markdown 报告。评测集里**至少 2 条必须需要工具调用才能答对**
   （比如「读这个文件里的第 3 行」），mock 通道要能构造出 `finish_reason == "tool_calls"`。
   **跑 mock 即算达成**，真实通道另跑一次贴数字。
2. **韧性判据**：注入四类故障各至少一条——`TimeoutError`、`HTTP 401`、`OSError`、
   工具实现抛异常——**整场必须跑完、报告必须落盘**，失败条目在报告里带**错误分类**
   （不是现在 `编排.light:82` 那个被擦成常量的 `"可重试错误"`）。
3. **反跑判据**：把兜底 `捕获` 摘掉一处，韧性用例必须变红（现在是整场 rc=1 且零产出）。

6. **假测试门禁扫全仓 `--root .`**，469 条基线只许减。反面样例必须写在**多行**字符串里
