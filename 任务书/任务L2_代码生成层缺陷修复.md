## 0. 一句话目标

修复光明编译器**代码生成层**的 6 个语言缺陷：成员空列表赋值（L-003，保持绿）、非 self 下标调用（L-005）、闭包修改外层标量（L-006）、JSON 内置入口（L-008）、语句级下标调用（L-014）、`捕获 全部`（L-016，BaseException），使 `lightharness/examples/` 对应复现用例从「红」转「绿」（L-003 保持绿）。

## 1. 为什么必须做

lightharness 复刻 harness 主链路中，这些是**高频写法**：字典存函数后下标调用、闭包计数、JSON 序列化、捕获异步取消——全部在代码生成层卡住。L-016 尤其关键：光明 `捕获` 一律生成 `except Exception`，`asyncio.CancelledError`（BaseException 子类）接不住，异步取消语义无法在光明层表达。

## 2. 现有基础（只读）

- `src/code_generator.py`：SRC 后端（`light_parser_v3` + `code_generator`）的主生成器。
- L-008 修复点：`src/code_generator.py` 约 423 行内置映射表（`序列化JSON`/`解析JSON` 已有映射，缺 `序列化`/`解析JSON` 的直接可用入口）。
- L-016 修复点：`code_generator.py` 捕获生成段（约 1710 行，`捕获 X`/`捕获 异常 e` 均生成 `except Exception:`）。
- L-014 修复点：`code_generator.py` 语句分发（约 1320 行，「未知语句类型」分支），`FunctionCallExpr` 作语句未处理。

## 4. 缺陷明细

| 编号 | 现象一句话 | 期望能力 | 验收用例 | 当前 | 备注 |
|---|---|---|---|---|---|
| L-003 | 类内 `己.X 为 []` 被误编译成比较/拆分 | 成员空列表赋值稳定编译为赋值 | `test_L003.light` | 绿 | **保持绿 + 确认加固**（已缓解） |
| L-005 | `对象.表[键]`（非 self）被编译成 `对象.表([键])` 调用 | 非 self 成员下标按下标取值 | `test_L005.light` | 红 | 生成层 IndexAccess |
| L-006 | 闭包内 `X = X + 1` 改外层标量 → UnboundLocalError | 内层段落可更新外层同名局部标量 | `test_L006.light` | 红 | 生成层变量作用域/nonlocal |
| L-008 | `序列化(...)` 非全局内置（须 `从 JSON 导入 序列化JSON`） | `序列化`/`解析JSON` 直接可用（注册别名） | `test_L008.light` | 红 | 约 423 行内置映射表 |
| L-014 | 语句级 `字典["键"](参数)` → 「未知语句类型 FunctionCallExpr」 | `obj[k](args)` 作语句/表达式合法（与 JS/Python 一致） | `test_L014.light` | 红 | 语句分发约 1320 行 |

## 5. 验收标准

1. 在**你的独立编译器副本**上，`set LIGHT_MERGE=<副本>` 后逐个运行：
   `cd lightharness && set LIGHT_MERGE=G:\dswork\duan-light-merge\light-merge-task-L2 && python 运行.py examples/test_L0XX.light`
   L-005/L-006/L-008/L-014/L-016 **红→绿**；L-003 **保持绿**。
2. 每个用例修复后**启用「修复后断言段」**（L-016 的 `断言修复后` 是 `异步 段落`，修复后应能接住 CancelledError、`接住==真`）。
3. 反跑判据：改断言值或改回旧生成行为，用例立即转红。
4. L-016 额外验收：`捕获 全部:` 生成 `except BaseException:`（用 `python 工具集/校验编译.py` 核验生成代码），且不影响现有 `捕获:`/`捕获 异常 e`（仍 `except Exception`）。
5. 回归：lightharness 全量用例（`python 运行.py examples/test_*.light`，排除 test_L0*）不得出现新增红。
