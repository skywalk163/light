## 1. 本轮范围：定义清楚「产业级最小可信」

**不做**的（明确记账，别偷偷做）：gRPC / protobuf / 第三方 MQ 客户端 / 选主 / 分布式事务 / 一致性存储。理由：总纲红线 4 不许 pip 装第三方，自己实现 protobuf+HTTP2 会吃掉整轮工时，且 M24 不需要。

**要做**的（M24 的构成）：
1. **线协议**：JSON-RPC 风格，over HTTP/1.1（客户端已有，服务端你建）
2. **服务端**：纯光明 HTTP/1.1 服务端，能并发处理（建在 E9 的并发原语上）
3. **worker**：领任务 → 执行 → 回报结果，支持并发度配置
4. **调度器（master）**：任务分发 + 背压 + 结果汇聚
5. **健康检查**：心跳 + 超时判死
6. **容错**：worker 死了任务**自动重派**，且**幂等键**保证不重复计分
7. **可观测**：每个节点的进度/耗时/失败可汇总

**验收场景（M24）**：3 节点 × ≥1000 条评测，中途 `kill` 掉一个 worker，最终报告**条数完整、无重复计分、无静默丢条**。

### 3.2 纯光明 HTTP/1.1 服务端

这是整条链的地基，stdlib 主干为零。要求：

## 4. S2：master / worker 最小闭环

- **worker**：注册 → 循环领任务 → 执行（调 harness 的单条评测）→ 交结果 → 心跳。并发度可配（用 E9 的任务池 + 背压队列）。
- **master**：任务队列（有界，背压来自 E9）+ 分发 + 结果汇聚 + 心跳表 + 超时判死 + 重派。
- **幂等**：结果按幂等键去重；重派产生的重复结果必须被丢弃且**记账**（报告里能看到「重派 N 次、去重 M 条」）。
- **取消传播**：master 收到取消 → 所有 worker 停止领新任务并中断在跑的（依赖 E9 的 3.3）。

**判据（每条都要有反跑，登记进 `任务书/分布式判据清单.json`）**：
- 分发：3 worker × 30 任务，断言每个 worker 都真领到活（不是一个 worker 干完全部）
- 心跳：worker 停发心跳 → master 在时限内判死
- 重派：kill worker → 它没交的任务被重派并完成
- 幂等：**人为让同一任务被两个 worker 都执行完**（这条要能构造出来）→ 最终报告只计一次
- 背压：master 队列满 → 生产侧被真正挡住（不是内存无限涨）
- 故障隔离：一个 worker 抛异常 → 其余不受影响

**「没有反跑就不算判据」**（总纲红线 3）。清单里每条要写「改哪一行会让它立红」。

## 6. 安全提醒（不要跳过）

你在建的是**网络监听服务**。默认必须：
- 只绑 `127.0.0.1`，跨机监听要显式开关 + 显式声明风险
- **认证不是可选项**：worker 注册与领任务必须带共享密钥（最简可行：预共享 token + 常量时间比较）。无认证的任务分发服务等于「谁连上来都能塞任务/偷结果」
- 反序列化边界：所有入站 JSON 先过 `stdlib/模式校验.light`，不许直接信任字段
- 路径类参数一律过 D9 的 `路径护栏`，不许让远端指定落盘路径

若你决定 S1/S2 阶段先不做认证，**必须在交付报告里显式写「当前无认证，仅限本机回环」**，不许默默上线。
