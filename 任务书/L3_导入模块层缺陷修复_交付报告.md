## 1. 根因定位 → 修复手法 → 验收输出

### 1.1 根因（两段：编译期内联 + 运行期解析）

**编译期（内联失败）** — `cli/light.py` 的 `_resolve_local_imports`：

- 原实现（base `5cac82b6`）用 `Path(base_dir) / f"{mod_name}.light"` 解析依赖，只认**平铺**文件名。
- `从 _import_test.数据 导入 造值` 的 `mod_name = "_import_test.数据"` 含点号，拼出的路径是 `<base_dir>/_import_test.数据.light`（一个整文件），永不命中 `<base_dir>/_import_test/数据.light` → 该依赖编译产物缺失 → 主代码里 `from _import_test.数据 import 造值` 因模块未被内联而运行期 `No module named '_import_test.数据'`。
- 子导入也一律用入口目录 `base_dir` 解析，使包内再导入点号模块（如 `pkg/sub/内嵌.light` 里的 `从 pkg.sub.深层 导入 深层值`）落到错误目录 `pkg/sub/pkg/sub/深层.light`。

**运行期（普通 import 末段不绑定）** — `cli/light.py` 的 `_run_src`：

- `导入 子目录.模块`（普通 import，无 `符号`）生成 `import a.b.c`，Python 只把顶层包 `a` 绑进命名空间，**末段 `c` 不绑定**，导致 `c.符号()` 成员访问 `NameError`；且 `a.b.c.符号` 全路径访问也需顶层包 `a` 已绑定。

### 1.2 修复手法（仅 `cli/light.py`，编译器侧内联为主）

1. **新增 `_resolve_module_path(mod_name, base_dir)`（`cli/light.py:110-132`）**
   把 `a.b.c` 拆点号 → `<base_dir>/a/b/c.light`（优先）或 `.py`，支持平铺与点号分层目录，并回退 `.py`。

2. **重写 `_resolve_local_imports`（`cli/light.py:135-201`）**
   - 依赖查找由 `Path(base_dir)/f"{mod_name}.light"` 改为 `_resolve_module_path(mod_name, base_dir)`。
   - 递归子导入的解析目录规则（`cli/light.py:188-194`）：
     - **点号模块名**（`a.b.c`）视为「从项目根目录出发的绝对包路径」→ 基于入口搜索根 `source_dir` 解析；
     - **平铺模块名**（相对/兄弟模块）→ 基于被解析模块自身目录 `mod_path.parent` 解析。
   - 这样 `test_L001` 的 `_import_test.数据` 与包内再导入点号模块都能正确定位。

3. **`_run_src` 点号普通导入的模块对象绑定（`cli/light.py:237-251` 识别 + `291-331` 构造）**
   - 在主 AST 中收集「点号 + 普通 import」（`导入 a.b.c`，即 `ImportStmt.symbols is None` 且 `'.' in module_name`），放入 `_dotted_plain_list`。
   - 注释替换循环对点号普通 import **不注释**（原逻辑一律注释），改由下方构造真正的 `types.ModuleType`：
     - 把内联模块代码 `exec` 进独立 `ModuleType`，注册进 `sys.modules[_full]`；
     - 建立父包链 `a` / `a.b`，并 `setattr` 使包层级可访问；
     - 把末段名（或 `as` 别名）与顶层包名绑进执行命名空间，使 `c.符号()` 与 `a.b.c.符号` 两种成员访问都可用；
     - 最后把原 `import a.b.c` 行中性化为注释（模块对象已注册）。
