- A 若要删除被 `tests/**` 引用的模块（如 `incremental_compiler` 被 2 个测试引用），**不得单边删**，出「一行方案」给主线协调 B。

## 2. 共享协作规程（三包通用，冲突以本节约束为准）

1. **工作树隔离**：每人 `git worktree add ../wt-OptA -b task-opt-A main`（B/C 同理），只在自己 worktree 作业，不许直接在主工作树改代码。起点是干净 HEAD。
2. **只跑定向测试**：只跑与本次改动相关的测试子集；**不许跑全量**（多路并行会互相干扰、造假红，已知 120s 子进程超时用例 / socket 用例 / 进程超时用例对机器负载敏感）。
3. **基线先行**：开工第一动作是建立自己的基线（盘点清单 / 引用矩阵 / 耗时测量 / 文件清单），落盘存档；结论必须有「改动前 vs 改动后」同合同对比。
4. **单变量改动**：一次只做一个 delta；每个改动独立 commit，commit message 说明意图。
5. **反跑判据**：每个「删除 / 合并 / 改名 / 迁移」必须写明「改哪一行会让它立红 → 复位后绿」。
6. **红线（沿用既有规程）**：不许建同名 `.py`；不许靠本机装库转绿；不许造壳；不许在合并前刷基线；`known_issues.md` 已标「已解决」的条目不许再当新问题排查。
7. **环境约定**：端口一律 `bind(("127.0.0.1", 0))`；临时文件加 `_taskOptX_*` 前缀并收尾删除；中文输出落盘再读；临时验证脚本用 `python -c` 或临时目录，不写盘到仓库。
8. **不越界**：三包只动自己「写」列的文件；仓库外目录（`g:\dswork\duan-light-merge\` 下的 task-* 工作树、留档目录等）一律不碰。

## 3. 合并与验收流程

1. 每包交付后，各 agent 在自己分支 `git push` / 提供分支名；主线（用户或合并 agent）在**独占机器**上合入并按口径全量回归。
2. 回归口径：核对 `collected / skipped / errors` 三项与基线全等，再看 `failed −N / passed +N`；新增打红一律拒绝。
3. 每包交付说明必须回答：改了什么（逐个文件 + 意图）、定向测试结果、反跑判据、基线对比证据、已知未完成项。
4. 三包合入顺序建议：**B（测试基建）→ A（核心源码）→ C（内容生态）**，或三者按 B→A→C 逐个 merge，每次合并后全量回归一次。
