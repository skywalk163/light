## 4. 已知未完成 / 未实测项

- **`stdlib/JSON.py`、`stdlib/文件系统.py` 保留未删**：`stdlib/__init__.py:29/98` 用 `from .JSON import *` / `from .文件系统 import *` **包内相对导入**——它不走 `_light_import_hook`（该 hook 只处理顶层模块名，`'.' in fullname → return None`），删 `.py` 直接 AttributeError。代价是**影子数保持 53**（任务书明确「影子数不降不算失败」）。删除 `.py` 需先改 `__init__.py` 或让包级导入也让路，**归 G9 合并期裁决**。
- **门面与 `.py` 双实现共存**：顶层 `import JSON` 走 `.light`（hook 取代），`stdlib/__init__.py` 的相对导入走 `.py`——两份实现并存（sys.modules 里 `JSON` 与 `stdlib.JSON` 是不同条目）。API 层已对齐（定向测试覆盖），但行为差异（如异常消息措辞）未逐字节对齐，属已知可接受范围。
- **`JSONSchema验证` 的 `pattern` 分支未实现**（光明无 re，见 §3 #3）。
- **POSIX 分支未实测**：门面在 Windows 验证；`打开文件` 模式与 `_light_builtin` 转发的 POSIX 行为（路径分隔符、`创建目录` 的 exist_ok 语义）未在 Linux/macOS 跑过。
- **性能未测**（benchmark.py 前后对比）：门面转发开销在 S1 未量化，S2 搬迁时按任务书 §4 硬约束 1 补跑。
