  - `stdlib/路径护栏.light`(226 行，16 个段落/类)：**agent loop 零引用**

所以 B3 不是从零造轮子，主要是**接线 + 补文件类工具 + 把沙箱真正压上**。

## 2. 契约（照抄，不许改）

来自 `第三轮总纲.md` §4，A3 正在并行按同一份实现消费侧：

```
段落 注册全部 接收 循环, 根目录, 选项：
```

- `循环`：`代理循环` 实例，你**只许调它的 `注册工具`**，不许改它
- `根目录`：沙箱根，**所有文件类工具的路径一律经 `路径护栏` 归一 + 越界拒绝**
- `选项`：字典，至少支持 `["允许写": 真/假, "命令超时": 浮点, "输出上限": 整数]`

单个工具注册签名（沿用现状 `stdlib/代理循环.light:98-99`）：

```
循环.注册工具(名称, 描述, 参数模式, 实现)
```

- `名称`：**必须是 ASCII**（`[a-zA-Z0-9_]`）——它要送给模型，中文名不安全
- `参数模式`：JSON Schema 子集，**必须是 `stdlib/模式校验.light` 支持的形态**
  （它有 217 行、12 个段落，先读它支持什么再写 schema，别写它认不出的关键字）
- `实现`：签名 `实现(参数字典) -> 字符串`

**工具名冻结**（6 个，不许增删改名）：
`read_file` / `write_file` / `edit_file` / `list_dir` / `grep` / `run_command`

## 3. 要做的

### B3-1　新建 `stdlib/代理工具集.light`【P0】

**第一行/第二行必须写「纯光明实现」**——`stdlib/_light_import_hook.py:85-97` 的
`_is_pure_light()` **只读首两行**。且**绝不建同名 `.py`**。

六个工具的行为规格：

- **`read_file(path, offset?, limit?)`**
  返回带行号的内容（`N→内容` 形态，便于模型引用行号）。
  必须处理：文件不存在（明确报错文本）、二进制文件（拒绝并说明）、
  超大文件（按 `limit` 截断并标注 `...[还有 N 行]`）、**编码探测**
  （Windows 上 cp936 是常态——`stdlib/进程树.light` 已经踩过这个坑，
  它的编码探测逻辑可以借鉴）
- **`write_file(path, content)`**
  `选项["允许写"]` 为假时**直接拒绝并说明原因**（不许静默成功）。
  写入用「临时文件 + 原子替换」，避免半写坏文件。父目录不存在时明确报错，不许自动 mkdir -p
  （自动建目录会让模型的路径笔误变成一堆垃圾目录）
- **`edit_file(path, old_string, new_string)`**
  精确字符串替换。**`old_string` 未命中 → 报错；命中多次 → 报错并说明命中几次**
  （这是 harness 类工具的关键安全性质：不许猜）
- **`list_dir(path, depth?)`**
  目录树。必须有默认深度上限与条目数上限，超了截断并标注
- **`grep(pattern, path?, glob?)`**
  内容搜索。**用 `re`（`stdlib/模式校验.light:10` 与 `字符串工具轻量.light:13` 已在 `导入 re`，
  这是既定的「协议层自举、引擎层借 CPython」口径，不算违规）。**
  必须有匹配数上限；正则非法时返回明确错误而不是崩
- **`run_command(command, cwd?, timeout?)`**
  走 `stdlib/进程树.light`（它已有 493 行真实现：Windows `CREATE_NEW_PROCESS_GROUP`
  在 `:303`、POSIX `preexec_fn=os.setsid` 在 `:306`、杀树 `taskkill /T` 与 `os.killpg`
  在 `:421-439`、输出限尾 + 溢出落盘 + 编码探测）。
  返回**合并的 stdout/stderr + 退出码**，超时按 `选项["命令超时"]` 杀**整棵树**。
  `cwd` 必须经 `路径护栏` 校验在沙箱内

**通用规矩**：

- 每个工具的返回值都是**给模型看的字符串**。失败要返回**可行动的错误描述**
  （"文件不存在: X。当前目录下有: A, B, C" 比 "错误" 有用一百倍）
- **不许自己 `捕获 错误` 吞掉一切返回空串**（`第三轮总纲.md` §5 第 2 条）。
  预期内的失败返回错误文本；预期外的异常**让它抛出去**，由
  `stdlib/代理循环.light:225-229` 统一转成 `"工具调用失败: ..."`

### B3-2　沙箱真压上【P0】

**文件**：`stdlib/路径护栏.light`（可改）+ `stdlib/代理工具集.light`

`tests/test_path_guard_light.py`(392 行) 的注释自陈
**「掩盖：链接逃逸从未真机验证」**，且含多条 `skipif(platform != win32)`
与 3 处运行时 `pytest.skip`（`:135`、`:172`、`:309`、`:334`）。

- 每个文件类工具的**每一个路径参数**都必须过护栏，包括 `run_command` 的 `cwd`
- **必须真机验证逃逸**，至少这几类：
  - `..` 相对路径穿越
  - 绝对路径直接指向沙箱外
  - **符号链接/junction 指向沙箱外**（Windows 用 `mklink /J`，POSIX 用 `os.symlink`；
    Windows 上建符号链接可能需要权限，退化到 junction 或标注「需管理员，未实测」）
  - 大小写差异（Windows 不区分大小写：`C:\Sandbox` vs `c:\sandbox`）
  - 尾随空格/点（Windows 会静默剥掉 `foo. ` → `foo`）
  - UNC 路径 `\\?\` 与 `\\server\share`
- 归一化必须在**解析完符号链接之后**判边界（先 realpath 再比较），
  不然链接逃逸必然穿透
- **把那 3 处运行时 `pytest.skip` 逐条处理**：能真跑的改成真跑；
  确实平台不支持的改成 `xfail` 并在交付报告的 skip 清单里写明掩盖了什么

### B3-3　`run_command` 的安全边界【P0】

- **不许拼 shell 字符串**。用参数数组形态传给 `进程树`，
  避免命令注入（模型的输出是不可信输入，这一点必须当成外部输入对待）
- 如果确实需要 shell 语义（管道、重定向），**必须显式开关**
  （`选项["允许shell"]`，默认**假**），并在文档里写明风险
- 环境变量：`stdlib/进程树.light` 已有环境白/黑名单机制，用上它。
  **默认剔除 `*_API_KEY` / `*_TOKEN` / `*_SECRET` 之类**——
  否则模型让 harness 跑 `env` 就能把 key 打出来
- 输出上限按 `选项["输出上限"]`，超了截尾并标注

### B3-4　伪终端接线（可选，P2）

`stdlib/伪终端.light`(536 行) 有实现但零引用。`tests/test_pty_light.py`(193 行) 有
**8 条 `skipif`**（`:68,85,102,120,135,151,167,182`），平台条件全跳。

- 如果 `run_command` 需要跑交互式命令（带进度条、需要 tty 的工具），
  加一个 `run_command(..., tty=真)` 分支走伪终端
- **这条是 P2，做不完就明确写「未做」**，不要做一半留个壳
  （`第二轮总纲` §5 明令禁止「只有壳的东西」）
- CI 上 FreeBSD 容器里没有可用 pty（`openpty` 返回 `Errno 25`），
  3 条红是已归因的环境欠账，**不许为了让它绿而改判据**

### B3-5　真跑测试【P0】

**文件**：新建 `tests/test_agent_tools_light.py`

- 每个工具至少：一条正常路径 + 一条边界 + 一条错误路径
- **必须真跑真断言**（真建文件、真读回、真跑命令、真查退出码），
  参照 `tests/test_process_tree_light.py`（`:76` 断言 stdout 含特定内容、
  `:84` 断言退出码 == 3、`:167` 断言孙子进程随树被杀）的写法
- **不许用上界断言**（`assert len(x) <= N` 在 x 为空时恒真，是假绿的常见形态）。
  一律等值断言
- 临时目录用 pytest `tmp_path`，**不许在仓库里留文件**；
  必须落盘的中间文件加 `_taskB3_` 前缀，收尾删干净
- 端口一律 `bind(("127.0.0.1", 0))`
