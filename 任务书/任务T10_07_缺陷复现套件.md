把 `docs/功能对标/语言缺陷账.md` 里 L-001~L-011 每条的最小复现**固化为可独立运行的自动化用例**

让语言团队拿到就能跑：修复前红（复现缺陷）、修复后绿（缺陷消失）。

**只读**：全部 `src/`、`stdlib/`（用例只做语言能力复现，不依赖 lightharness 业务模块——除非缺陷恰好发生在业务模块，如 L-011 在 `外部命令`）。

## 4. 验收标准

1. 每个用例**用 `python 运行.py` 能独立运行**；当前运行结果与缺陷账描述一致（即：复现出缺陷现象）。
2. 每条用例头部有**三行注释**：`# 缺陷：<编号> <一句话>`、`# 当前：<预期红/报错现象>`、`# 修复后：<应绿的行为断言>`。
3. 用例文件**不引入 .py**（纯 .light），不依赖 lightharness src 业务模块（L-011 例外可用 stdlib 外部命令）。
4. `python 运行.py examples/test_L001.light` 等逐个可跑；把「修复后断言」写成 `断言` 段并用注释标明「当前刻意不调用（修复后启用）」。
5. **反跑判据即用例本身**：语言团队修好缺陷后，启用「修复后断言」段，用例应转绿；未修时保持红。

## 5. 边界与红线

- **不改任何 `src/`、`stdlib/` 源码**——本任务只产用例与文档，防止与 T1~T6 冲突。
- 用例要**最小**（尽量 <40 行），单文件可跑，不互相依赖。
- 不要为了「让用例跑绿」去绕缺陷；用例的目的就是**红着证明缺陷存在**。
- 注释不写「导入 某模块」字样（L-009 自身就是此坑，正好当反面教材）。

## 6. 交付格式（照总纲 §5）

1. 新建了哪些用例（逐个 + 触发哪个缺陷 + 当前运行结果）
2. 每条用例的定向运行输出（落盘 `_taskT10_07_*`，证明「当前红」）
3. 缺陷账.md 回写 diff 说明
4. 已知未完成（某些缺陷在当前语言版本下已部分缓解、无法复现的，标注并说明）

## 7. 参考：L-* 一句话对照（用于写用例头注释）

- L-001 跨目录点号导入不可用 → 用 `_import_test/` 子目录 + 点号导入复现

- L-004 关键字边界拆分中文标识符 → `导出X`/`生成Y` 方法名复现
- L-005 非 self 成员下标被编译成调用 → `总线.表[键]` 复现
- L-006 闭包改外层标量 → 内层段落 `X = X + 1` 复现

- L-008 JSON 序列化入口 → `序列化(...)` 未定义复现

- L-011 关键字根 `等待` 拆分成员访问 → `外部命令.等待进程(...)` 复现
