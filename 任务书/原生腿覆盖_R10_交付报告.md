# 追加：第二批（R10-9，2026-09-05）—— 变异函数属性写回 + dv_list_pop

## 成果：12 → 13（14.61%），解锁 数据结构轻量（编译 + 运行语义）

**落地修复**：
1. **runtime `dv_list_pop`**：index<0 弹末尾，复用 `dv_list_remove`；对应 declare。
2. **builtin `列表弹出`/`list_pop`**：返回移除元素后的新列表（数据结构轻量用法是「先取值、后弹、弃返回值」）。**刻意不注册 `弹出`/`pop`**——会劫持 `栈.弹出()` 类方法调用（已踩坑修正）。
3. **函数式变异调用写回**（`_gen_typed_function_call`）：`列表弹出(己.数据)` / `列表插入(己.数据, 0, x)` 等 mutating builtin 返回新列表后，写回第一参数（`_persist_to_receiver`，字段/变量均覆盖）。名单：追加/清空/设置/插入/删除/列表弹出 及别名。
4. **`_recv_is_field` 扩展**：放行无点局部变量接收者——此前方法调用 `栈.追加(元素)` 对局部变量接收者不写回（`_persist_to_receiver` 情况一明明支持变量但被门槛挡掉），跨调用累积丢失。

## 运行语义验证（真跑 exe，非仅编译）

|---|---|---|
| 栈 `s.压入(10)/s.压入(20)/s.弹出()/s.大小()` | `20 1 10 0` | PASS |
| 队列 `q.入队/q.出队`（`列表弹出(己.数据, 0)` 带索引） | `1 1 2 0` | PASS |
| 双端队列 `d.左入队/d.右入队/d.左出队/d.右出队` | `7 8` | PASS |
| 优先队列（`列表弹出(己.数据, 最小下标)` 变量索引 + 嵌套索引） | `甲 乙 丙` | PASS |

## 架构缺口（重要发现，需单独排期）

**原生腿段参数传值**，列表作为参数跨段变异传递不生效：
- 转译腿 = Python 引用（`入栈(s, 10)` 后 s 更新）；原生腿 = LightValue 值拷贝 + 共享底层数组，`dv_list_append`/`remove` 的 realloc 移动后调用方副本悬垂。
- 受影响：数据结构轻量的**辅助函数版本**（`创建栈/入栈/出栈/栈大小` 以列表为参数）——编译通过但运行受限（真跑抛「栈为空」）。
- **不受影响**：类版本（`己.数据` 字段 + self 对象共享，写回有效）——故 4 个类全部正确。
- 跨段引用语义是原生腿架构级缺口，影响所有「列表参数跨段变异」代码；需专项评估（REF 句柄 / 引用参数调用约定），非本批范围。

- 能力清单同步：builtin 293 / runtime 217（`列表弹出`/`list_pop`/`列表插入` + `dv_list_pop`；`弹出`/`pop` 因劫持类方法刻意未注册，已从 JSON 清除）。

# 追加：第三批（R10-10，2026-09-05）—— KeywordArg 展开 + 文件句柄链

## 成果：13 → 16（17.98%），解锁 JSON / JSON核心 / 内置核心列表（编译 + 运行语义）

**落地修复（codegen/compiler/runtime 三侧）**：

1. **KeywordArg 展开**：`ast_nodes` 新增 `KeywordArg`（ID=102）；`compiler._convert_keyword_arg`；codegen 函数/方法调用参数展开分离位置参数与关键字参数，`_merge_kwargs` 按 `_BUILTIN_KWARGS` 签名表（打开文件/排序 的 encoding/reverse）或光明段 `parameters` 参数名映射回位置——stdlib `打开文件(路径, "w", encoding=...)`、`表.sort(reverse=...)` 用。
2. **文件句柄链**：runtime 新增 `LV_TYPE_FILE`（type=22）：`dv_open_file`/`dv_file_write`/`dv_file_close`（fclose 后置 NULL 防双关）；codegen builtin `打开文件`/`write`/`close` 分支接线。
3. **try/catch IR 非法修复**：`catch` 体与 `finally` 体若已以 terminator 结束不再多发 `br`。
4. **dict 遍历 0 次根因**：`遍历 项 之 对象` 改用 `dv_len`（dict/list/str 统一取长）+ 新 runtime `dv_foreach_get`（开头 `v = dv_deref(v)` 处理 dict 内数组 REF）。
5. **段优先于 builtin**：`_gen_typed_function_call` 分派顺序调整为「本地段 > builtin > 导入段」，对齐转译腿 Python 语义（修复 JSON核心 `段落 连接` 被 `连接`(dv_concat) 劫持）。
6. **type 名对齐**：`dv_get_type_name` 返回英文名（NoneType/int/float/str/list/bool/dict），REF（type=8）解引用一层返回底层类型名。
7. **段默认参数丢失**：`compiler._convert_paragraph/_convert_parameter` 补 `default_value`（新增 `_convert_default_value` helper）；codegen 缺参分支应用默认值（stdlib `缩进 = 0`/`美化 = 假` 等）。
8. **dict 索引赋值**：`_gen_typed_assignment` 新增 IndexAccess 分支（`dv_dict_set` 原地设置 + 写回目标变量防 realloc 悬垂）；**并修复 `_convert_indexed_assignment`**——v3 的 `设 映射[键] 为 值` 在段落内 target 是已解析的 IndexAccess 节点，原实现 `Identifier(name=node.target)` 把节点塞进 name 导致 `'IndexAccess' object has no attribute 'encode'`（内置核心字典回归根因），现对非字符串 target 直接 `self.convert`。
9. **方法内调方法崩溃**：runtime 所有 `dv_call_method`/`dv_call_class_method`/`dv_call_static_method`/接口调用在 `method(result,...)` 前加 `dv_null(result)` 初始化结果槽。

## JSON 数组内 null：三处 REF 根因（本批关键调试成果）

| # | 根因 | 现象 | 修复 |
|---|---|---|---|
| ① | `dv_foreach_get` 不 deref REF | dict 内数组经 `dv_dict_get` 取值是 REF，`遍历 项 之 对象` 元素全 null（`{"b":[1,2,3]}` → `[null,null,null]`） | `dv_foreach_get` 开头 `v = dv_deref(v)` |

## T5C-POSIX：集合族「字典设置 句柄失效」缺陷修复（2026-09-06）

### 任务概述
- **起因**：T6B 收尾时在 **Ubuntu 24.04（clang 18.1.3）** 首次跑通全量原生腿回归，
  暴露 `test_集合_运算对拍_O0`（`移除元素`）抛 `值错误`；同一份代码在 Windows
  （clang 22.1.8）却全绿。
- **目标**：定位并修复该平台相关缺陷，关闭 T5C「未在 POSIX 实测」的缺口。
  能力清单按约定**留待合流时统一重建**，本轮不重建。
- **约束**：独立本地分支隔离；沿用 T5C 既定处置口径 —— 以 `.light` 层 workaround
  绕过，**不触碰 codegen 核心**（根因归 T7）。

### 根因：`字典设置` 使写回前的列表句柄失效
`字典设置(字典, 键, 值)` 会重绑/释放底层缓冲，使「**写回前**取到的列表句柄」
失效。事后对该句柄的**读**是未定义行为，**写**则落进已释放缓冲。

探针打印「写回后旧句柄长度」给出直接证据：

| 平台 | 写回后读旧句柄长度 | 后果 |
|---|---|---|
| Windows（clang 22.1.8） | `0` | `0 != 2` → 不抛错，**侥幸通过** |
| Linux / glibc（clang 18.1.3） | `2` | `2 == 2`（同新列表）→ **误判「没删掉」而抛错** |

同一份 UB 读出两种脏值，正是「Windows 绿、POSIX 红」的成因。

### 修复（两处，同一根因）

| 模块 | 原写法 | 症状 | 修法 |
|---|---|---|---|
| `集合.移除元素` | `字典设置` **之后**才比较 `长(列表)` | POSIX 上误抛 `值错误` | 写回**前**快照 `设 原长 为 长(列表)`，比较前置 |
| `集合操作.分组` | `字典设置` **之后**才 `追加(组, …)` | 每组恒少收 1 个元素（`分组([1,1,2])` 得 `{1:[1], 2:[]}`） | 新建组**先追加、后写回**；已有组走「字典读出句柄 + 追加」 |

两点附带收益：
1. `移除元素` 对不存在的元素不再产生半截写入 —— 与 Python `set.remove` 抛
   KeyError 且不改集合的语义一致。
2. `分组` 的缺陷**双平台均存在**，此前因测试只校验分组**键数**（恒为 2）而未暴露。

## T7A：float 类型推断/slot 管理根因修复（6 缺陷 + 移除 workaround）

**任务编号**：codegen-float-T7A  
**排期**：B10 S1  
**日期**：2026-09-06  
**Worktree**：`light-merge-codegen-float`

### 修复内容

#### 根因定位

T5A/T6A 过程中发现 6 个 O0 codegen 缺陷，同一根因族：**O0 下 int/int 除法
（`/`/`除`）返回的 dv 内部类型标记为 int 而非 float**，导致后续算术读取时
类型标记丢失，读到零初始化的 int slot。所有下游表现（跨段 float 返回值零
初始化、builtin 返回值零初始化、float 参数零初始化、整除结果零初始化）均由
此根因级联。

#### codegen 修复（`src/llvm/codegen_typed.py`，2 处）

1. **`_gen_typed_binary_op` INT 快路径**（约 L1099）：当 `op in ('/','除')` 且
   两侧均为 INT 时，改为 `fdiv` + `_create_float_dv_fast`（type=2），与
   `_infer_expr_type` 对 `/` 返回 FLOAT 的推断一致。`//`（整除）仍走
   `sdiv` + INT DV。

2. **`_gen_typed_binary_op` 通用路径**（约 L1172）：当 `op in ('/','除')` 时，
   先对两侧调 `dv_to_float` 再调 `dv_div`，确保双整数也走 float 分支返回
   FLOAT DV。`//` 仍直接调 `dv_div`。

#### builtin 路由补齐（`src/llvm/codegen_typed.py`，1 处）

在 `_gen_typed_builtin` 新增 `常用对数→dv_log10`、`对数2→dv_log2`、
`指数→dv_exp` 的 builtin 路由（声明已存在于约 L341-346），使 stdlib 可直接
调用这些 builtin 而无需内联 Taylor 展开。

### 修复方案选择与理由

采用**方案 2 变体**：`_safe_func_name` 按模块隔离 counter，段注册表 key 模块限定。

- **方案 1（段名收集加模块前缀）**：段名全局唯一，彻底解决冲突，但需改段引用解析全链路，

## T7C：控制流/变量存活根因修复（循环标量 + 模块级初始化 + 跨模块返回值污染）

**任务编号**：codegen-controlflow-T7C  
**排期**：B11 S1  
**日期**：2026-09-06  
**Worktree**：`light-merge-codegen-controlflow`

### 修复内容

#### 根因定位

T6A 过程中发现 3 个 O0 codegen 缺陷，涉及控制流变量存活与模块初始化。
经验证，3 个缺陷的根因分布不同：

1. **T6A-02**（循环嵌套分支标量赋值损坏）和 **T6A-10**（跨模块返回值污染）：
   在 T9A（段名模块隔离）+ T7A（float 类型推断）+ T7B（REF 参数写回）修复后
   的代码上已自然消除。任务书原分析的「PHI 节点管理错误」根因有误——codegen
   使用 **alloca 栈槽**（非 SSA 寄存器）存储局部变量，不存在 PHI 节点。实际根因
   是 T6A-09 的段名符号编号冲突（T9A 已修复）和 T5C-02/04 的参数写回污染
   （T7B 已修复）。

2. **T6A-03**（模块级字符串常量不可靠）：**真实根因在 `compiler.py` 的模块收集顺序**——
   `compile_modules_typed` 函数中 `all_module_list` 按 `modules.values()` 原始顺序
   收集，主模块可能排在被导入模块之前。这导致 `__light_init` 函数中主模块的顶层语句
   （可能调用导入段并读取导入模块的全局变量）先于被导入模块的全局初始化执行，
   读取到未初始化的空值。

#### 修复（`src/llvm/compiler.py`，1 处）

`compile_modules_typed`（约 L900）：将 `all_module_list` 从 `list(modules.values())`
改为 `[m for m in modules.values() if m is not main_mod] + [main_mod]`，使主模块
排在最后。`__light_init` 生成时按 `all_module_list` 顺序串联各模块的初始化代码，
从而保证被导入模块的全局初始化先于主模块顶层语句执行。

> **注**：任务书预设修改 `src/llvm/codegen_typed.py`，但实际根因（模块收集顺序）
> 在 `compiler.py` 的 `compile_modules_typed` 函数中。`codegen_typed.py` 不涉及
> 模块排序逻辑，无需修改。此偏差在交付报告中明确记录。

## T9B：re.light 回溯VM 根因修复（{n}多选分支回溯恢复 + 列表内存安全）

**任务编号**：relight-engine-T9B ｜ **排期**：B11 S3 ｜ **日期**：2026-09-06
**合并缺陷**：T6A-07（{n}重复体含多选分支时回溯恢复不完整）+ T6A-11（回溯VM列表操作内存安全）

### 修复内容

**根因族**：re.light 回溯 VM 的列表可变状态在回溯时未恢复。re.light 注释（原 L591）自称
"列表不可变语义天然支持回溯撤销"，但实际列表是引用传递+原地修改（`追加`/`设置`），
设计假设不成立。两个缺陷同根因：

1. **`支` 处理器**（T6A-07）：分支1递归调用可能通过 `保存` 指令修改 `组表`、
   通过嵌套 `循支` 修改 `回点`，分支1失败后分支2看到污染状态 → IPv4 `999.1.1.1` 误判通过。
2. **`循支` 处理器**（T6A-11）：body 失败后，body 内嵌套 `循支` 追加的 stale 回点条目
   未清理，影响出口路径 → 连续多次调用累积触发堆损坏 / valgrind Invalid read/write。

**修复**（`stdlib/re.light`，仅引擎内部，对外 API 不变）：

- 新增 `re_内部_列复制` 辅助段：列表浅复制，用于快照。
- `支` 处理器：尝试分支1前快照 `组表` 和 `回点`，分支1失败后恢复再试分支2。
- `循支` 处理器：追加 `[pc,pos]` 后快照 `组表` 和 `回点`（含刚追加的条目），
  body 失败后恢复（保留 `[pc,pos]` 防出口跳回死循环，清除 body 的 stale 条目）再试出口。

## 五、降级实现说明

### 5.1 高级文件.light

- **复制文件**：用 `_light_builtin.读取文件` + `_light_builtin.写入文件` 实现，
  不依赖 shutil.copy2。元数据（权限/时间戳）不保留（能力边界）。
- **目录大小**：基于 `_light_builtin.列出目录` + `_light_builtin.文件大小` 递归遍历，
  加深度限制 10 层防栈溢出，跳过 "."/".." 防无限递归。
  超大目录（如项目根目录）可能段错误（能力边界，测试用受控小目录）。
- **文件树**：递归生成文本树状结构，基于 `_light_builtin.列出目录` + `_light_builtin.目录存在`。
- **磁盘使用情况**：原生腿无磁盘统计符号，返回 `["能力边界": "原生腿无磁盘统计符号", "总空间": 0, "已用空间": 0, "可用空间": 0]`。
- **命令存在**：原生腿无 PATH 搜索，返回 假。

### 5.2 图像处理基础.light

- **纯数组像素表示**：图像对象为字典 `["宽": w, "高": h, "模式": "RGB"|"L", "像素": [...]]`，
  像素为扁平列表（RGB 模式每像素 3 元素，L 模式每像素 1 元素）。
- **灰度化**：公式 `gray = (299*r + 587*g + 114*b) / 1000`（整数近似，避免浮点），
  转换为 L 模式。
- **缩放**：最近邻插值，`源x = floor(x * 原宽 / 新宽)`，支持 RGB 和 L 模式。
- **字典值拷贝 workaround**：`设置像素` 中 `图像["像素"]` 返回列表拷贝，
  修改后需 `设 图像["像素"] 为 像素` 写回字典（详见 known_issues R11C §新发现限制 #2）。
- **未实现函数**：打开/保存/滤镜/旋转/翻转/亮度/对比度/文本绘制/合并图像
  均抛 `运行时错误("原生腿不支持...")`，明确声明不静默失败。

### 5.3 网络请求.light

- **基于 runtime socket 符号（B1）**：`socket_create`/`socket_connect`/`socket_send`/
  `socket_recv`/`socket_close`/`socket_last_error`（英文别名，避免与 `关闭` 关键字冲突）。
- **极简 HTTP/1.0 GET**：构造 `GET path HTTP/1.0\r\nHost: host\r\n\r\n` 请求，
  读取响应，解析状态行/头部/内容。
- **URL 解析**：手动解析协议/主机/端口/路径/查询字符串（不依赖 urllib）。
- **URL 编码/解码**：基础 ASCII 字符不编码，空格→`+`，`+`→空格；
  非 ASCII 字符用 `%3F` 占位（能力边界，不做真正的百分号编码）。
- **能力边界返回**：POST/HTTPS/重定向/chunked/超时均返回
  `["状态码": 0, "头部": 空, "内容": "", "错误": "..."]`，明确标注失败原因。

## 七、新发现的 codegen/runtime 限制

详见 `docs/known_issues.md` R11C 章节「新发现的 codegen/runtime 限制」，共 6 条：
1. O0 临时槽位池上限 2048（大型列表字面量溢出）→ 分段函数返回 workaround
2. 字典访问返回列表拷贝（跨段变异不生效）→ 取出-修改-写回 workaround
3. try/catch 块内不能用 `跳过`(continue) → 辅助函数+返回值 workaround
4. `列出目录` 可能返回 "."/".." → 递归遍历必须跳过
5. `输出("")` 不产生输出行 → 对拍用 `长()` 间接验证
6. 目录递归在超大目录可能段错误 → 深度限制+受控目录测试

以上均为纯光明 workaround 绕过，未触碰 codegen 核心（src/llvm/*.py）和
runtime_typed.c。
