## 3. 移交清单（光明写不出什么 → 临时绕法 → 期望的语言能力）

| # | 光明写不出 / A9 有已知 bug | 本轮临时绕法 | 期望语言能力（交 A9，S2 起可清理） |
|---|---|---|---|
| 1 | **`尝试/最终`（无显式 `捕获`）** A9 codegen 会偷插一个空 `except Exception: pass` → 把所有 Exception 吞掉，`return await 函()` 抛的 RuntimeError 变 None 返回。证据：`_taskE9_probe4.py` 输出 行 296 `except Exception: pass`（A9 catch 折叠在无捕获分支上的变种）。 | `带限流`、`并行槽体`、`带限流收集异常` **一律写成 尝试/捕获 异常 e / 抛出 e / 最终 三段式**：显式 `捕获 异常 e: 抛出 e` 让 codegen 生成 `except Exception as e: raise e` 正确路径，保住异常传播正确性；`最终` 仍只写归还信号量/写槽位。 | 修复 A9 codegen：当 `尝试/最终` 没有 `捕获` 块时，**不要**生成 `except Exception: pass`（只生成 `try: ... finally:`）。修复后 `带限流`、`并行槽体` 的 `捕获/抛出 e` 两行可删除。 |
| 2 | `捕获:`（裸）或「双层捕获」语法 **仍然只生成 `except Exception:`**，无法捕获 Python 3.11+ 下是 `BaseException` 子类的 `asyncio.CancelledError` → 全或无模式下取消兄弟任务后 `吞异常等待()` 抓不到它，导致 CancelledError 逃出清理阶段并覆盖原始首异常。 | **双层 尝试/最终 绕法**：`全或无等待` 把清理 await（`并发等待(清理列表)`）再包一层 `尝试 / 最终: 抛出 首异常`——无论 CancelledError 还是 Exception 从清理里逃出，`最终` 块总会先执行并抛回「用户任务的首个 Exception」，调用方永远拿到业务异常而不是 CancelledError。 | 在 `捕获` 语法里支持「裸 except」或「捕获 BaseException」语义，让 `吞异常等待` 能真正吞下所有异常类型，消除对外层 `最终` 兜底的依赖。 |
| 3 | 光明语言层目前 **没有 `!=` 运算符**（会被 parser 判成语法错误：「无法识别的语法元素 ':'」）。 | 所有不等判断改写成「两重 `==` + 逻辑与」：`合法模式 = 假；若 模式 == "全或无": 合法=真；若 模式 == "逐条收集": 合法=真；若非 合法: …`，等价于 `!=` 但可编译。 | 语言层补 `!=` 二元运算符，并在 code_generator 分派为 Python `!=`（`not_equal` AST 节点）。 |
| 4 | `"" 加上 None` / 字符串拼接 `失败模式` 入参是 None 时，直接抛 `TypeError: can only concatenate str (not "NoneType")` —— 无法在 `值错误` 捕获到，导致非法模式断言本该立红却 TypeError 逃逸。 | 非法模式报错统一走 `转字符串(失败模式)`（stdlib 已有 `转字符串` 导出），`str(None) = "None"` 正确进入 ValueError 的消息文本。 | 光明语言层的 `字符串 + X` 做**隐式 str() 兜底**（像 Python `f"{x}"` 语义），或者在 Type Lattice 层把 str concat 的非 str  operand 先转字符串。 |
