- master：`stdlib/分布式/master.light`（纯光明，298 行，零 Python 直调）
- worker：`stdlib/分布式/worker.light`（纯光明，117 行，零 Python 直调）

## 4. 本轮根因与修复（S2 维护期新增）

### 4.1 真根因：光明 `遍历 键 之 字典` = 直接 dict 迭代，循环内 pop 必炸

`kill+重派` 测试（`test_重派与心跳`）在修复前**必现** 90s 超时，非偶发竞态：

- 监控循环（`master.light` 旧版 172-187）在 `遍历 节点ID 之 己.工人` 的循环体内，
  对失联节点执行 `己.工人.pop(节点ID, 空)`；
- 光明编译器把 `遍历 X 之 字典` 原样编成 `for X in 字典`（已用最小复现验证：
  `RuntimeError: dictionary changed size during iteration`）；
- 于是「失联检测触发」的**同一个 tick** 里，pop 之后 for 循环取下一个键即抛 RuntimeError，
  监控循环协程死亡，**本 tick 的 `写文本(state.json)` 永远执行不到**；
- 症状链：state.json 冻结在失联检测前一 tick（`失联=[]`、孤儿任务还在 `在跑`）→
  `完成事件` 永不被设置 → master 永不写报告 → 测试 90s 超时。诊断轨迹里
  「已汇聚冻结 + 失联恒为[] + 在跑恒为1」正是这个形态。

### 4.2 修复：两阶段监控循环

```
第一遍（只读）：遍历 己.工人，收集 过期 节点ID 列表
第二遍（可写）：遍历 过期，逐节点 失联.追加 → 重派在跑任务（换新幂等键入队）
              → 在跑.pop → 己.工人.pop
```

**绝不在遍历 `己.工人` / `己.在跑` 的同时改它们。** 修复后 kill 场景 26s 内完整汇聚 1200、
失联正确标记。`处理注销`（152-166）的写法本就是两阶段，监控循环照此对齐。

### 4.3 连带修复（本轮排错中发现并已收）

- `worker.light`：实例属性 `运行`(bool) 与方法 `运行` 撞名 → 方法改名 `运转`；
- `节点网络.py`/`worker.light`/测试：光明词法器把 `设令牌` 切成 `设`+`令牌` → 改名 `带令牌`；
- `worker.light` 空队列守卫：master 返回的是 `{"任务": 空}` 字典不是 `空` →
  `如果 结果 == 空 或 结果["任务"] == 空:`；
- `test_distributed_eval_light.py _跑集群` finally：子进程 terminate+join 回收，
  防孤儿进程占管道导致 `| tail` 挂死。

## 7. 残留欠账与合并注意

### 7.1 残留欠账（S2 → partial / none 的理由）

- **背压 partial**：有界队列「满=等」已实现且有反跑；但 master 派发速率是无条件全速出队，
  「队列满」未作为反压信号回传 master 限速；队列深度/阻塞时长未暴露成监控指标。
  跨节点全局水位/反压信令属 S3。
- **限流 partial**：滑动窗口已实现且有反跑（区别于分批）；但阈值(3)/窗口(1.0s) 是写死常量，
  未做成可配置、未接入 master 跨节点聚合配额；且只在单元级反跑验证过，
  未在 3 进程集群里与分发/重派联调。
- **取消传播 none**：`取消` 协议消息未实现；代理循环的取消令牌在上游也没有赋值入口。
  S3 要断「取消后 worker 侧真停了」，不是「master 侧标记了取消」。
- **故障隔离 partial**：连接级已修（F9 S2）；节点级（一个 worker 炸不影响其余）尚不存在，S3。
- **worker 优雅退出**：注销 协议已实现但 worker 未调用；猝死场景（kill/断电）走心跳超时重派，
  优雅退出路径留 S3 与取消传播一起收。

### 7.2 合并注意

1. **`stdlib/HTTP服务端.light` 上移**：由 `stdlib/分布式/` 移到 `stdlib/` 根目录——
   光明编译器对 `HTTP服务端` 硬编码 `stdlib.lightpub.HTTP服务端`，而 lightpub 那份是旧的
   http.server 桥接、没有 `HTTP服务端` 类；上移触发编译器「根目录同名模块优先」，
   被导入钩子正确解析到纯光明实现（与 F9 S2 交付报告 §3 同因）。
2. **门禁数字会变**：`dist_criteria.py` done 0 → 5（无文件基线，若门禁配置要求刷新基线，
   以 done_count=5 为准）；新增 5 个 .light（master/worker/主控/节点）+ 2 个 .py（节点网络/队列）
   会影响 `python_direct_calls.py` / `bootstrap_rate.py` / `spec_coverage.py` 的计数，
   需在合并点重建相应基线（见下方自查命令输出）。
3. **CancelledError 注意**：光明 `捕获 异常` 不兜 `BaseException`（含 CancelledError），
   master 优雅退出用 `己.运行 = 假` + `服务端.停止()` 让循环自然退出，不靠 cancel 注入
   取消异常——S3 实现取消传播时不能照抄 cancel 模式。
4. **判据/反跑行号已按最终文件校正**：master.light（114/142/178/191/195）、
