## 1. 架构与协议贴合说明

### 1.1 角色与拓扑

```
                 ┌─────────────────────────────┐
                 │  master（调度器）             │
                 │  stdlib/分布式/调度核心.light  │
                 │  任务表 → 有界队列 → 派发      │
                 │  结果表 / 每节点 / 失联 / 去重  │
                 │  监控循环（0.1s 心跳超时扫描） │
                 └──────────┬──────────────────┘
                            │ JSON-RPC over HTTP/1.1 (keep-alive)
              ┌─────────────┼─────────────┐
              ▼             ▼             ▼
        worker#0        worker#1       worker#2
        stdlib/分布式/节点核心.light（纯光明，确定性执行桩）
```

- master：`stdlib/分布式/调度核心.light`（纯光明，零 Python 直调）——S2 返工 §3-4 按仓库
  惯例（stdlib 全中文名）由 `master.light` 改名而来；`主控.light` 是可手动执行的环境变量入口
  （`异步 运行 主环境()` 是光明主脚本入口语义，不可作为库 import——入口脚本预期行为）。
- worker：`stdlib/分布式/节点核心.light`（纯光明，零 Python 直调），同上由 `worker.light`
  改名；`节点.light` 是环境变量入口。
- 传输层：复用 `stdlib/HTTP服务端.light`（F9 S2 修好的纯光明 HTTP/1.1 服务端，
  本轮由 `stdlib/分布式/` 上移到 `stdlib/` 根目录——编译器硬编码 `stdlib.lightpub.HTTP服务端`
  的权宜，真缺陷已立项，见 §7.3）。
- 系统边界：`stdlib/分布式/节点网络.py`（socket/JSON/事件/时钟/令牌）、
  `stdlib/分布式/队列.py`（有界异步队列 + 滑动窗口限流）—— 均为 .py，被门禁当作光明模块、
  不计入 python_direct_calls；每个边界原语的「为什么是真边界 + 期望中文内置名」已按任务书
  §4.5 格式逐项写进两个文件头注释（返工 §2.5），**`客户端类` 已从「边界」摘出**（见 §1.2 偏离）。
- 执行桩：worker 的 `执行` 是确定性桩（输入回显 + 得分 1，支持 `DUAN_SLOW_SECS` 慢速开关
  模拟秒级耗时）。S2 判据考验**分发/心跳/重派/幂等/结果汇聚这条链路**；上线时把 `执行`
  换成 harness 驱动即可，链路不动。
- **心跳 = 独立协程**（返工 §1.1）：`节点核心.light 心跳循环` 按 `心跳间隔` 周期发心跳，
  与 `领任务/交结果/执行` 完全解耦——真 harness 单条任务秒级耗时也不会被 master 判死。
  客户端 keep-alive 单连接由 `asyncio.Lock` 串行化，防两协程并发写帧错乱。

### 1.2 线协议贴合（`任务书/分布式线协议.json`，冻结稿 v1.0）+ 偏离登记

| 消息 | 方向 | 使用位置 | 偏离 |
|---|---|---|---|
| 注册 | worker→master | `节点核心.light 注册`；`调度核心.light 处理注册` | 无。带 `协议版本` 校验（非 "1.0" → 码 100）；`X-Auth-Token` 强制 |
| 领任务 | worker→master | `节点核心.light` 主循环；`调度核心.light 处理领任务` | 无。队列空时返回 `{"任务": 空, "全部完成": bool}` |
| 交结果 | worker→master | `节点核心.light` 主循环；`调度核心.light 处理交结果` | 无。幂等去重按 `任务ID`，首报校验 `幂等键` 匹配当前派发 |
| 心跳 | worker→master | `节点核心.light 心跳循环`（独立协程）；`调度核心.light 处理心跳` | 无。仅刷新 `最后心跳` |
| 注销 | worker→master | master 侧已实现；worker 本轮未调用（猝死走心跳超时重派，优雅退出留 S3） | 无偏离，属未用到的协议面 |
| 取消 | master→worker | 未实现 | 协议冻结稿里有该消息；`取消传播` = none，S3 实现 |

**传输层偏离登记（返工 §2.4，如实记账）：** 裁决 3 原话「不许引第二套传输（不许 socket 自己再糊
一层）」。`stdlib/分布式/节点网络.py 客户端类` 是**手写的完整 HTTP/1.1 + JSON-RPC 客户端**
（`asyncio.open_connection` 建连、手拼请求行/头、手解析 `Content-Length`）——**这是第二套传输
实现（客户端侧）**。S2 的现实取舍：`HTTP服务端.light` 只有服务端、全仓没有光明 HTTP 客户端。
已登记为**一条偏离 + 一条欠账「客户端侧待光明化」**（§7.1 欠账②），S3 消除；`客户端类`
不再挂在「系统边界原语」名下（返工 §2.5 已从边界清单摘出）。

**认证如实说明（返工 §3-7）：** `注册` 签发会话令牌，后续请求 `取工人` 校验 `X-Auth-Token`
（`常量比较` 常量时间比较，防时序侧信道）。**但注册环节无准入**——任何节点都能注册并领到令牌，
`注册` 只校验 `节点ID` 格式与协议版本。节点身份不可信，属 S3（准入/证书）。

### 1.3 背压裁决口径（§7.2）

「背压 full = wait/block producer」：`队列.py 有界队列类.入队` = `await asyncio.Queue.put`，
满时挂起生产者，**不抛、不偷偷多进**。与并发.light 无关（F9 不许改它，改需求走 E9 移交）。

### 1.4 三个裁决立场（沿用）

1. 传输层复用 `HTTP服务端.light`（F9 S2 修好的版本），不新造服务端——客户端侧例外已登记（§1.2）；
2. 背压 full = 等（阻塞生产者），用有界异步队列，不碰 `并发.light`；
3. "3 节点" = 同机 multiprocessing.spawn 的 3 个 worker 进程，端口 0 内核分配后读回。

## 4. 本轮根因与修复（两轮合并）

### 4.1 根因一：光明 `遍历 键 之 字典` = 直接 dict 迭代，循环内 pop 必炸（首提已修）

`kill+重派` 测试修复前**必现** 90s 超时：监控循环在 `遍历 节点ID 之 己.工人` 循环体内
`己.工人.pop(节点ID, 空)` → 光明把 `遍历 X 之 字典` 原样编成 `for X in 字典` → 下一次取键
抛 `RuntimeError: dictionary changed size during iteration` → 监控循环协程死亡 → `完成事件`
永不设置 → master 永不写报告。**修复：两阶段监控循环**（第一遍只读收集过期节点，第二遍才
重派/pop）。

### 4.2 根因二：心跳搭任务完成便车，真 harness 上 livelock（返工 §1.1 已修）

首提版 `节点核心.light` 只在「交完一条结果之后」才发心跳，空队列 idle 分支不发心跳 →
心跳周期 ≈ 单条任务耗时。桩执行微秒级测不出来；真 harness 秒级执行 + `心跳超时` 1.5s →
worker 正常干活期间被判死踢出、交结果被 103 拒收、**交结果路径不看 `错误` 字段而静默丢条** →
接手 worker 同样超时 → 整链 livelock。**修复（三条都做了）**：

1. **心跳挪进独立协程**（`心跳循环`，周期 = `心跳间隔`，与 `执行` 耗时无关），
   keep-alive 连接加 `asyncio.Lock` 串行化防帧错乱；
2. **新增判据测试** `test_心跳独立于执行_长任务期间不被标失联`（执行桩 `DUAN_SLOW_SECS`
   拉慢到 3s/条 > 心跳超时 1.5s，断言失联为空、结果全被接受）；反跑 = 停掉独立心跳协程
   → 74.22s 超时红（已实跑，见 §3 反跑 8）；
3. **交结果/领任务路径检查 `错误` 字段**：码 103 → 重新注册 → 重投，不许静默丢结果
   （M24「无静默丢条」）；其它错误码无法自愈才退出。

### 4.3 连带修复

- 实例属性 `运行`(bool) 遮蔽方法 → 方法改名 `运转`；
- 光明词法器把 `设令牌` 切成 `设`+`令牌` → 改名 `带令牌`；
- 空队列守卫：master 返回 `{"任务": 空}` 字典不是 `空` → `结果 == 空 或 结果["任务"] == 空`；
- `_跑集群` finally 回收子进程，防孤儿占管道挂死；
- 薄包装 `主控.light`/`节点.light` 的 `异步 运行 主环境().` 半角句点 → 全角 `。`（语法 bug，
  首提时薄包装从未被 import 过未暴露，返工改名验证时发现并修）。

## 7. 残留欠账与合并注意

### 7.1 残留欠账（S2 → partial / none 的理由）

- **背压 partial**：有界队列「满=等」已实现且有反跑，但实现落在 `.py` 边界
  （`队列.py 有界队列类` 底层 `asyncio.Queue`），光明侧只有转发；master 派发速率无条件全速
  出队，「队列满」未作为反压信号回传 master 限速；队列深度/阻塞时长未暴露成监控指标。
  跨节点全局水位/反压信令属 S3。
- **限流 partial**：滑动窗口已实现且有反跑，但实现同样落在 `.py` 边界
  （`队列.py 滑动窗口类` 纯 Python list+pop）；阈值(3)/窗口(1.0s) 写死常量、未接入 master
  跨节点聚合配额；未在 3 进程集群里与分发/重派联调。
- **取消传播 none**：`取消` 协议消息未实现；代理循环的取消令牌在上游也没有赋值入口。
  S3 要断「取消后 worker 侧真停了」。
- **故障隔离 partial**：连接级已修（F9 S2）；节点级（一个 worker 炸不影响其余）尚不存在，S3。
- **worker 优雅退出**：注销协议已实现但 worker 未调用；猝死走心跳超时重派，优雅退出留 S3。
- **注册无准入（返工 §3-7）**：任何节点都能注册领令牌，节点身份不可信，S3 加准入。
- **任务级超时（返工 §3-2）**：S2 不做任务级超时重派，`任务超时/截止时间` 字段已删——
  任务级超时是 M24 harness 层语义（执行超时在 worker 侧掐），不在调度侧。
- **单 worker 并发（返工 §3-2）**：S2 单 worker 串行执行一条；`并发度` 仅作协议字段上报，
  master 未据此调度，S3 实现单节点并行。

### 7.2 E9 移交条目（返工 §2.6 正式立项）

  文件 = `stdlib/并发.light`，欠账清单 = `任务书/缺失内置清单.json`（期望内置
  「异步有界队列类」）+ 本报告 §7.1 背压条目。目标：背压语义用光明原语表达，
