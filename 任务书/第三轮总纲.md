## 0. 这一轮为什么这么排

第二轮把**传输栈**打通了（TLS 真握手、SSE 真解析、流式真逐 token、原生 socket 真跑），
也确实产出了一个 263 行的纯光明 agent loop。但用只读复核（不采信自测报告）实测出一件事：

> **`stdlib/大模型客户端.light` 的请求体里没有 `tools` 字段**
> （`stdlib/大模型客户端.light:63`、`:74` 载荷只有 `messages` / `model` / `stream`）。

工具注册表只活在本地，**从来没告诉过模型**。所以对真实 DeepSeek，模型永远不会返回
`tool_calls`——整条工具链只能靠离线伪造的 SSE 帧走通。
`自测报告_任务C2.md:16` 声称的「M2 真连 DeepSeek 完成 tool_call 往返」**在协议层就不可能成立**。

这是第三轮的第一性问题：**我们造了一条能说话的电话线，但从没告诉对方我们有哪些手脚。**

第二类问题是同一个毛病换了个位置。第二轮给 LLVM **语句层**加了 else 兜底
（`src/llvm/codegen_typed.py:2644-2646`，`全局`/`外层`/`生成` 现在会响亮报错），
但**表达式层还在静默降级成整数 0**：

- `src/llvm/codegen_typed.py:885` —— `_gen_expression` 链尾 `return self._create_int_dv('0'), 'dv'`
- `src/llvm/codegen_typed.py:861` —— 未知 `ParagraphCall` 同样返回 0

字典字面量、Lambda、字符串插值、推导式、切片、`RangeExpr`、`Pipeline` 在原生腿
**编译成功但产物行为错误**。洞搬家了，没堵完。

第三类是**假测试仍在生产假绿**。已抓到一条活的：
`tests/test_agent_loop_light.py` 的 `TestMaxRounds`（`:231-247`）订阅了一个只收 1 个参数的
`lambda payload:`，而 `stdlib/事件总线.light:143` 用 `处理器(事件名, 载荷)` **两参**调用，
TypeError 被 `:152 捕获 错误` 吞掉 → `events` 恒为空 → `assert len(events) <= 3` **空转通过**。
这正是第二轮明令禁止的第二种形态，禁令没兜住。

## 1. 第三轮里程碑

- **M4（本轮主目标，硬）**：`.light` 源码带 `tools` 声明真连 `https://api.deepseek.com`，
  完成**一次真实的 tool_call 往返**（模型自己决定调工具 → 我们执行 → 回填 → 模型给最终答复）
  + 流式逐 token，`引 Python` 计数 0。
- **M5（本轮主目标，硬）**：harness 能**真做一件事**——给定一个目录，
  它能读文件、写文件、列目录、搜索、执行命令，并在沙箱边界内完成一个可验证的小任务。
- **M6（本轮铺路）**：原生腿表达式层**零静默降级**，能力边界从「猜」变成「查表 + 报错」。

### 1.1 M4 的验收必须双轨（这条是硬规矩）

本机 `DEEPSEEK_API_KEY` **未设置**（已实测），`light-merge/.env` **不存在**。
第二轮就是因为「无 key 则 skip」把 HTTPS 不通这个洞盖了整轮。所以：

- **离线轨（判绿点，不许 skip）**：本地起一个**协议等价的 mock DeepSeek server**——
  真 HTTP/1.1 + 真 SSE 分帧，**必须解析并断言收到的请求体里 `tools` 字段结构正确**，
  再按 OpenAI 兼容格式回 `tool_calls` 分片。这条在任何机器上都必须绿。
- **在线轨（可选，但产物要留档）**：有 key 时真连 DeepSeek，把
  **请求体 + 响应帧原文**落盘到 `第三轮留档/M4_在线往返实录.txt`（**API key 必须打码**）。
  无 key 时这条 skip，但 skip 理由必须写成
  「掩盖的是：真实模型对我们的 tools 声明的接受度」，不许写「掩盖了 tool_call 功能」——
  功能由离线轨守。

### 2.3 自举率的可复现口径（第三轮起用这一套）

- 代码行维度：2838/3308 ≈ 85.8% ← **虚高，不许用**（分母那 470 行几乎全是导出清单本身）

## 4. 接口契约（开工前冻结，A3 与 B3 各自照此实现，不许协商变更）

这一节是四路能真并行的前提。**A3 负责消费侧，B3 负责生产侧，两边都按这份写就必然对得上。**

### 4.1 工具注册（沿用现状，A3 不许改签名）

```
己.注册工具(名称, 描述, 参数模式, 实现)
```

- `名称`：字符串，OpenAI 函数名规范（`[a-zA-Z0-9_]`，不许中文，**因为要送给模型**）
- `描述`：字符串，给模型看的自然语言说明
- `参数模式`：字典，JSON Schema 子集，**必须是 `stdlib/模式校验.light` 支持的形态**
- `实现`：可调用，签名 `实现(参数字典) -> 字符串`

**约定**：`实现` 只返回字符串。抛异常由 `代理循环` 捕获并转成
`"工具调用失败: <原因>"` 的 tool 消息（现状 `stdlib/代理循环.light:225-229` 已如此）。
B3 的工具**不许自己捕获全部异常返回空串**——那会把失败伪装成成功。

### 4.2 A3 必须发出的载荷形状（M4 的判绿依据）

```json
"tools": [{"type": "function",
           "function": {"name": ..., "description": ..., "parameters": <参数模式>}}]
"tool_choice": "auto"
```

`工具表` 为空时 **`tools` 字段整体不出现**（不许发 `"tools": []`，部分服务端会 400）。

### 4.3 B3 必须导出的注册入口（A3 与示例程序照此调用）

```
段落 注册全部 接收 循环, 根目录, 选项：
```

- `循环`：`代理循环` 实例，B3 只调它的 `注册工具`
- `根目录`：沙箱根，**所有文件类工具的路径一律经 `路径护栏` 归一 + 越界拒绝**
- `选项`：字典，至少支持 `["允许写": 真/假, "命令超时": 浮点, "输出上限": 整数]`

工具名冻结为这 6 个：`read_file` / `write_file` / `edit_file` / `list_dir` / `grep` / `run_command`。

### 4.4 事件名冻结（A3 发布，B3 与示例订阅）

`请求开始` / `增量`(流式 token) / `请求结束` / `工具开始` / `工具结束` / `工具失败` / `轮次结束`。
**处理器签名一律 `处理器(事件名, 载荷)` 两参**——这是 `stdlib/事件总线.light:143` 的既有形态，
A3 的活是让签名不匹配时**响亮报错**而不是被吞掉，不是改成一参。

## 5. 本轮新增的三条硬约束

1. **不许再造「协议上不可能成立」的东西。** 凡涉及与外部服务对接，
   验收必须有一条**解析并断言请求体**的离线用例。第二轮的教训：
   我们测了「我们能收」，从没测过「我们发对了」。
2. **不许让 `捕获` 吞掉签名/类型错误。** `捕获 错误`（宽泛捕获）只许用在
   「已知外部不可控」的边界（网络、子进程、文件系统）。
   业务内部的 TypeError/AttributeError 必须让它炸出来。
   已知的一处（`事件总线.light:152`）由 A3 修，其余由 D3 普查登记。
3. **不许用「本机能跑」当验收。** 沿用既有口径并加一条：
   任何只在 Windows 实测过的分支，交付报告必须写「POSIX 未实测」，
   **且不许在 CI 里靠 skip 让它显示为绿**——要么真跑，要么明确 xfail 并写明掩盖了什么。

## 10. 环境约定（PowerShell 5.1，血泪版）

- **中文输出必须落盘再读**，直接读会乱码（乱码只在显示层，文件内容是好的）
- **不支持 `&&`**，用 `;` 或分多次执行；**不支持 heredoc**
- 输出被截断时重跑同一条命令 `| Out-File -Encoding utf8 <临时文件>`，读完即删
- **测量全量门禁时必须 UTF-8**：捕获流被 reconfigure 成 strict + 子进程 GBK 字节会造成
  整场级联假红（曾报出 3565 errors 的幻影），`PYTHONUTF8` 挡不住，
  必须 `errors='replace'`（`tests/conftest.py` 已修，别再改回去）
