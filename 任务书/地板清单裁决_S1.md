# 自举地板清单 · C9 版 vs G9 版 差异裁决表（S1 合并点前）

两路各自建了 `任务书/自举地板清单.json`（C9 `12c4095e`、G9 `edb53caa`），同路径撞车，且都改了 `.gitignore`。
本文件是可裁决的差异表：每条给**实测证据**与**建议裁决**，主线定完再改文件。

**归属前提**：清单的所有权在 C9（任务书 C9 §3「新建 `任务书/自举地板清单.json`」），
G9 只建门禁（任务书 G9 §2.1「清单由 C9 产出。你要：写 `tools/ci/floor_bootstrap.py`」）。
所以**结构与字段以 C9 版为准**，G9 那份骨架作废、门禁改读 C9 的字段名。

---

## 1. 名单本身：无差异

- 两版都是 114 条，名字集合**完全相等**，与 `stdlib/builtins.py` 的 ast 顶层函数逐个咬合。
- 这一层不用裁决。

## 2. 字段名撞车（必须裁一个）

- C9 版：`名字 / 职责 / 当前实现语言 / 分类 / 目标落点 / 证据行`，`分类` 是五值枚举
  （`native_required` / `movable` / `has_light_impl` / `duplicate` / `unused`）。
- G9 版：`名字 / 职责 / 当前实现语言 / native_required(bool) / 计划落点 / 证据 / 备注`。

**建议裁决：用 C9 版字段。** 任务书 C9 §3 明文要求「分五类」，布尔字段表达不了 `duplicate` / `unused`，
而这两类是 S3 删码的输入。G9 的 `备注`（豁免理由）作为**新增字段**并进 C9 结构保留 —— 豁免理由是分母口径的证据，
不能只剩一个 `native_required` 字样。

**连带改动**：`tools/ci/floor_bootstrap.py` 现在读 `条目[].native_required`，要改成读 `函数[].分类 == "native_required"`；
证据字段从 `证据` 改读 `证据行`，落点从 `计划落点` 改读 `目标落点`。

## 3. 分母（native_required）差 2 条 —— 逐条实测

C9 标 34 条，G9 标 32 条。差异只有 4 个名字：

- **`随机整数`（`builtins.py:792`）** —— C9 标边界，G9 标可搬。
  实测：函数体 `random.randint(...)`，是真熵源。**裁 C9 对，改判为 native_required。**
- **`随机选择`（`builtins.py:816`）** —— 同上，体内 `random.choice(...)`。**裁 C9 对。**
- **`绝对路径`（`builtins.py:201-203`）** —— C9 标可搬，G9 标边界。
  实测：`return os.path.abspath(path)`，abspath 要读进程 cwd（`getcwd` 系统调用），
  光明层拿不到 cwd。**裁 G9 对，保持 native_required。**
- **`格式化时间`（`builtins.py:756-785`）** —— C9 标边界，G9 标可搬。
  实测：**不读当前时间**，入参是时间戳或时间字符串，体内只有 `fromtimestamp` / `strptime` / `strftime`。
  这是纯计算（外加本地时区），不是「时间戳读取」这个边界。**裁 G9 对，保持 movable**，
  但备注要写明「`fromtimestamp` 依赖本机时区，搬迁时需显式传时区或接受 UTC」。

**裁决后**：native_required = G9 的 32 条 + `随机整数` + `随机选择` = **34 条**，
分母 = 114 − 34 = **80**。数字与 C9 的 80 相同，但成分差两个名字（`绝对路径` 在内、`格式化时间` 在外）。

## 4. 分子：12 还是 0 —— 这是真分歧

C9 记 `has_light_impl` = 12，直接当分子，得 12/80 = 15%。逐条查过，两件事都成立：

**(a) 那 12 个光明实现是真的，不是空壳。**
- `stdlib/JSON.light`（170 行，首两行挂魔数「纯光明实现」，同名 `JSON.py` 存在但被遮蔽规则让 `.light` 赢）：
  `段落 解析JSON`(13)、`段落 序列化JSON`(17)、`段落 美化JSON`(23)。
- `stdlib/列表工具.light`（129 行，挂魔数，同名 `.py` 被取代）：`段落 求和`(15)。
- `stdlib/字符串工具轻量.light`（187 行，挂魔数，**无**同名 `.py`）：
  `段落 转大写`(21)、`转小写`(24)、`分割字符串`(50)、`连接字符串`(56)、`替换字符串`(67)、
  `去除左侧空白`(73)、`去除右侧空白`(76)、`字符串长度`(114)。

**(b) 但 `builtins.py` 一个都没接过去。** 实测函数体：
- `builtins.py:482 分割字符串` → `return text.split(separator)`
- `builtins.py:502 转大写` → `return text.upper()`
- `builtins.py:380 解析JSON` → `return _light_json_module.loads(text)`（`import json`）
- `:388 序列化JSON` → `json.dumps`；`:398 美化JSON` → 转发给上一个 Python 实现

也就是说：**运行期每一份产物执行的仍然是这 12 个 Python 实现**，光明替身在旁边平行存在、无人调用。
任务书 C9 §4 自己写的 S2 做法正是「改 `builtins.py` 让它**转发**到光明实现」——**转发这一步 S1 没做**。

**建议裁决：分子 = 0，S1 基线 = 0/80 = 0%。** 那 12 条保留 `分类=has_light_impl`
（含义是「替身已就位、待接线」），但**不计入分子**。理由：这个指标量的是「地板本身是不是光明的」，
`builtins.py` 的函数体还在跑 Python 就不算搬迁 —— 否则「有个同名光明文件」就能刷率，与第七轮
「只有壳的东西不算落地」同一类假绿。

**顺带**：C9 那 12 条的 `证据行` 全部填的是 `stdlib/builtins.py:<行号>`，即 **Python 定义行**，
不是光明 `段落` 定义行。这个字段本意是证明光明实现存在，填 builtins.py 等于证明「Python 版存在」，
自我否证。裁决后应改成如 `stdlib/字符串工具轻量.light:50`（门禁按 ±2 行窗口 + 行内含函数名判定）。

## 5. 需要主线拍的四件事

1. 字段结构用 C9 版（+ 保留 `备注`），G9 门禁改读 C9 字段名。
2. `随机整数` / `随机选择` 改判 native_required；`绝对路径` 保持 native_required；`格式化时间` 保持 movable。分母 = 80。
3. S1 基线分子 = 0（12 条替身不计入，等 S2 接转发）。若主线裁「替身就位即算」，
   则必须同时改指标名（不能再叫「地板自举率」）并在门禁里明确记录这条口径。
4. `.gitignore`：两版都补了对 `任务书/*.json` 的放行，合并时留一份即可（`*.json` 在第 46 行会吞掉这些清单）。

## 6. 复跑方式

本表的每条数字都可复跑：

```
python tools/ci/floor_bootstrap.py --root <worktree> --baseline <路径>
```

字段/分类差异与分子核查用的临时脚本已删；结论依据全部落在上文的 `文件:行号` 上，可直接 `read` 复核。
反跑：把上面任一 `段落` 定义行的函数名改掉再跑门禁，对应条目必须打红；
把 `builtins.py:482` 的函数体改成真转发，分子必须从 0 变 1。
