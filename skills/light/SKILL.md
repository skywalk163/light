# 光明（Light）代码工作流

以下路径都相对仓库根。装在 PATH 里的 `light` 与 `python cli/light.py` 等价，本文用短写法。

## 三步闭环

1. **读卡**：`light ai card` 拿精简速查卡（`--full` 出全量）；需要模板就 `light ai snippets`。事实以 `spec/light.spec.json` 为准，别凭记忆。
2. **写码**：套模板，守六条硬规则——中文关键字、块首行带冒号、`print` 写 `打印`、`读取(x)` 是读 stdin、读文件用 `读取文件`、块靠 4 空格缩进。
3. **自查**：`light ai check --json 目标.light`。退出码 0 = 无 error，1 = 有 error，2 = 用法/文件错误。stdout 只有一个 JSON，读 `diagnostics[].fixes` 按提示改，再跑一遍直到 0 或只剩 warning。
4. **跑一遍**：`light 运行 目标.light`；需要脚本参数就用 `--` 分隔，`--` 之后原样交给脚本。

## 完整可跑示例

```光明
从 文件系统 导入 读取文件, 写入文件

段落 统计行数 接收 路径：
    设 文本 为 读取文件(路径)
    设 行 为 分割(文本, "\n")
    返回 长(行)

段落 主：
    打印(统计行数("README.md"))
    写入文件("out.txt", "完成")
```

## 常见失败模式

| 现象 | 真正原因 | 改法 |
|------|----------|------|
| `语法错误`：期望 冒号「:」 | 块首行漏了冒号 | 段落/如果/遍历/当 行末补 `：` |
| 程序停住等输入 | 用了 `读取(x)`，它读的是 stdin | 读文件改 `读取文件(路径)` |
| `导入错误`：cannot import name | 函数名猜错（文件系统里是 `遍历目录`，不是 `列出目录`） | 以 `docs/STDLIB_REFERENCE.md` 的导出名为准 |
| 追加元素写法不统一 | 函数式与方法式混用 | 统一 `列表.追加(项)` |

## 边界

- 只在允许的路径里改；不新增依赖，不为过检查而放宽判据。
- 需要深入时读 `docs/AI编程指南.md`（§六 避坑）与 `docs/STDLIB_REFERENCE.md`（函数名权威表），标准库实现看 `stdlib/文件系统.light`，回归测试在 `tests/unit`。
