1. **`.github/workflows/ci.yml` lint 步的 rc 捕获不可达（P0）**。原写法
   `flake8 ... > flake8_report.txt 2>&1` 换行再 `rc=$?`：GitHub Actions 的 `run:`
   默认 shell 是 `bash -e -o pipefail`，flake8 一有违规就 exit 1，`set -e` 当场中止，
   `rc=$?` 永远执行不到——D4 自己写的注释「1=有违规（不阻塞）」被反转成「有违规就判红」。
   本机 bash 两向实测：`(exit 1); rc=$?; echo reached-$rc` → 整步 exit 1 且 reached 从未打印；
   改成 `|| rc=$?` → 打印 reached-1 且整步 exit 0。已改为 `rc=0; flake8 ... || rc=$?`。
   （`.gitea/workflows/ci.yml` 无 flake8 步，所以 run #77 全绿掩盖了这个洞。）
2. **下界形态漏 `> N` 拼法（P0）**：见 `docs/known_issues.md` 14.4(b)，
   基线 358 → **424**（lower-bound 26 → 92）。
3. **`built_from_commit` 指向孤儿提交（P0）**：本报告 §六 与下表原写 `b498142c`，
   实测两份基线里都是 `8c7d6292b066`——不在任何分支上。已重新生成，戳指向可达提交，
