# 段言积木组合（积木库）

把「AI 生成代码」替换为「预置积木的组合装配」——给定一句话需求，系统在**零 token、全离线**的情况下选出合适的段言积木、按契约接线、内联粘合成一个可运行的 `.duan` 文件。只有当需求真的超出当前积木能力时，才把 LLM 当作「兜底生成器」补一块新积木并永久沉淀。

核心思路：用**组合式软件生成**（compositional generation）替代**生成式软件生成**。本仓库对标隔壁 jikuai，但底层用段言的真·模块系统 + 成语式宏 + 字节码，组合更稳、更可控。

---

## 30 秒上手

```bash
# 自动组合（默认 embedding 选块，零 token）
python 积木库/组合.py "对一批数字求和再算平均" --输入 "[1,2,3,4,5]" --top 2

# 语义选块（同义改写也能命中）
python 积木库/语义选块.py "把金额写成人民币大写" --top 3

# 契约级链式接线：前一步结果自动喂后一步
python 积木库/组合.py "求和然后分页" --链式 --输入 "[1..25]" --top 2

# LLM 兜底：库内没有的能力自动生成新积木并运行
python 积木库/组合.py "计算斐波那契数列第10项" --输入 "10" --top 1
```

> 运行需经段言解释器：`python cli/duan.py run <文件>.duan`。上面的 `组合.py` 会自己调起解释器。

## 架构（一条零 token 链路）

| 模块 | 文件 | 职责 |
|---|---|---|
| 契约索引 | `索引.json` | 每块的名称/领域/层级/输入输出/稳定性/路径/导出名 |
| 关键词选块 | `选块.py` | v0 字符重叠打分（零 token） |
| 语义选块 | `语义选块.py` | TF-IDF(字符 n-gram)+同义词+领域先验（零 token） |
| **embedding 选块** | `embedding选块.py` | 概念图向量（默认，0.1ms）；真·句向量为 `--real` 实验选项（基准显示反而更差，见 `评估/README.md`） |
| **五把尺子** | `评估/跑分.py`、`评估/接线跑分.py`、`评估/体检.py`、`评估/冒烟.py`、`评估/扰动跑分.py` | 分别量选块（89 条）、接线（26 条）、契约自洽性、可运行率（92/92）、泛化（扰动集 40 条刻意避开块名用字的迂回说法），防止改动回退 |
| **LLM/本地校验器** | `校验器.py` | 运行前第二道闸：本地概念交集 + 可接真实 LLM 判定组合是否满足需求 |
| **类型系统** | `类型.py` | 结构化类型（`列表[T]`/`字典[K,V]`/`可选`/`联合`）+ 0~1 匹配度 |
| 契约级接线 | `接线.py` | 结构化类型匹配 + 参数名相似 + 上游优先的数据流规划；接不上上游时显式告警 |
| 内联粘合 | `粘合.py` | 把选中积木源码拼进单一 `.duan`（对应成语式宏展开） |
| 组合总入口 | `组合.py` | 需求 + 输入 → 选块 → 校验 → 接线 → 粘合 → 运行 |
| 层级生成 | `层级生成.py` | 成语式宏：把 L0+ 组合固化成 L1/L2 高级积木并注册进索引 |
| 兜底生成器 | `兜底生成器.py` | LLM 按契约生成新积木；无 key 时降级本地规则 |

数据流：`需求 → 选块(召回) → 校验(判定) → 接线(数据流) → 粘合(代码) → 运行`。

## 设计原则：零 token 优先

- **常态零 token**：选块、校验、接线、层级、粘合全本地。
- **LLM 只是兜底**：仅在「无候选 / 分数低于阈值 / 校验 MISMATCH / 接线不可接」且本地规则也覆盖不了时才调一次模型；生成的新积木写入 `生成/` 并注册进索引，**下次同需求零 token 复用**。
- **可解释可复现**：每个组合都能还原成一份方案 JSON（`方案` 结构见 `协议.md`），不依赖概率生成。

## 如何新增一块积木（L0）

1. 在对应领域目录新建 `积木库/<领域>/<名称>.duan`，格式：

   ```duan
   # 注释：一句话说明 + 契约
   导出 求和
   段落 求和 接收 序列：
       设 和 为 0
       设 i 为 0
       当 i 小于 长度(序列)：
           设 和 为 和 加 序列[i]
           设 i 为 i 加 1
       返回 和
   ```

2. 在 `索引.json` 的 `块` 数组追加一条契约（名称/领域/层级=0/描述/输入/输出/稳定性/路径/导出名）。
   **类型必须写结构化形式**：`列表[数]` / `列表[文本]` / `字典[文本,数]` / `可选[数]` / `联合[数,文本]`，
   元素类型确实任意时写 `列表[任意]`；裸 `列表` 虽向后兼容，但体检器会报 W4 警告。
3. `python 积木库/评估/体检.py` 必须 0 错误（段落名==导出名、导出名互不互为前缀、签名数一致）。
4. （可选）`python 积木库/组合.py "你的需求" --输入 "..." --top 1` 验证能被选中运行。

> 铁律一：`段落` 名必须与 `导出` 名（即「导出名」）一致，否则调用方按导出名调用会 `NameError`。
> 铁律二：导出名之间**不得互为前缀**（如 `中位` 与 `中位数`）——段言词法器全文件预扫描 +
> 最长匹配，前缀重叠会把标识符切碎。体检器 W1 专门盯这个。

## 如何新增一个 L1+（成语式宏）

写一个配方 JSON（见 `范围跨度配方.json` / `统计双指标配方.json`），运行：

```bash
python 积木库/层级生成.py 积木库/范围跨度配方.json --写索引
# 或自动发现可组合模式并织成 L1：
python 积木库/层级生成.py --自动
```

生成的 L1/L2 会进入索引，后续可像普通积木一样被选中或继续向上组合。

## 接入真实大模型

复制 `llm_config.example.json` 为 `llm_config.json`，填入 `api_key` / `base_url` / `model`（OpenAI 兼容端点）。此时：
- 选块低置信或能力缺失时，由真实 LLM 生成缺失积木；
- 校验器用真实 LLM 判定「组合是否真的满足需求」，能拦下词法/语义的细微错配。

无 key 时全部降级为本地规则，系统仍完整可用。

完整协议与方案 JSON 结构见 [`协议.md`](./协议.md)。
