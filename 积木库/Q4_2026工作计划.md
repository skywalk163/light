## 一、v1.0 收官回顾（一句话，详述见 `3个月提升计划.md` 九）

质量底座、工程化、产品化、真实覆盖四条线全部闭合；北星指标（真实留出语料零 token 覆盖率）**1.0**，超额完成原定 ≥ 0.95 目标。
但收官后仍有三处"看似做了、实际没真跑起来"的收尾欠账，构成本季度主线：

| 欠账 | 现状（事实） | 季度内目标 |
|---|---|---|
| **自动防回归** | CI（`ci.yml`）只跑段言语言本体 `tests/`，**五把尺子零覆盖**；积木库回归 100% 靠人工手动跑 | 五把尺子 + 真实语料接入 CI，`留出段<0.99` 或 `主基准<1.0` 的 PR 自动失败 |
| **真实 LLM 兜底** | `llm_config.json` 的 `api_key` 为空，降级本地规则；"真模型生成新块并沉淀"链路**从未在真实模型上验证** | 配真实 key，跑通 20 条库外意图的端到端兜底闭环，沉淀成功率 ≥ 90% |
| **可观测 / 产品化** | `运行日志.jsonl` 仅 363 字节；积木平台无独立使用文档/示例集（mkdocs 是段言本体的） | 全量运行日志 + 周看板；积木平台独立文档站与示例集 |

## 二、下一季度北星指标（新）

| 指标 | 定义 | 季度目标 |
|---|---|---|
| **回归零容忍门禁** | CI 在每次 push/PR 跑五把尺子 + 真实语料，设硬门槛 | 留出段 Hit@1 ≥ 0.99、主基准链路正确率 = 1.0、冒烟 = 151/151；任一不达标 PR 自动 fail |
| **真实 LLM 兜底闭环跑通率** | 库外需求经真实模型生成新块并注册沉淀的比例 | ≥ 90%（20 条样本），且生成块 100% 过 体检+冒烟 才入库 |
| **真实语料压力测试规模** | 多来源、独立于作者的真实需求语料 | 扩至 **500+** 条，留出段 Hit@1 仍 ≥ 0.97 |
| **产品化采纳** | 可独立上手的使用文档 + 真实端到端录屏 | v1.1 发布（文档站 + 录屏 + 示例集 + 面向使用者的 README） |

辅助：单次兜底 token 成本可控（gpt-4o-mini 量级，均值 ≤ 800 token）；计划缓存命中率维持（库内需求近乎 0 选块开销）。

## 四、第 1 月（10月）：防回归 + 真实 LLM 兜底首跑

**目标**：把"人工手动跑尺子"变成"推送即防回归"，并把 v1.0 演示的本地规则兜底升级为真实模型兜底。

- **1.1 五把尺子接入 CI（最高优先级）**
  - 新增 `积木库/评估/ci_eval.py`（或 workflow step）：在 push/PR 时依次跑 `真实跑分.py` / `扰动跑分.py` / `跑分.py` / `冒烟.py` / `体检.py`，解析各报告 JSON，对关键指标设硬门槛：
    - 真实语料留出段 concept Hit@1 **≥ 0.99**
    - 主基准链路正确率 = **1.0**、失败条目 = 0
    - 冒烟 = **151/151**
    - 任一不达标 → 非零退出码 → PR 检查失败。
  - 新增 `.github/workflows/eval.yml`（积木库专用）；解决 runner 可达性：当前本机对 github.com 网络不可达、代码实际推在 gitcode——优先给 **gitcode 配 CI runner**，或本机网络恢复后推 github 启用 `actions`。在 CI 说明里写清「代码需同步到可运行 CI 的远端」。
- **1.2 真实 LLM 兜底首跑**
  - 把真实 `api_key` 写入 `llm_config.json`（OpenAI 兼容端点，gpt-4o-mini）；构造 **20 条库外意图**（覆盖本地规则已覆盖的 7 类 + 新领域如 进制转换/单位换算/日期推算/文本风格改写）。
  - 跑通「选不准 → 真模型生成新块源码 → 写 `生成/` → 注册 `索引.json` → 下次零 token 复用」全链路；记录每条的 token 成本、生成质量（人工抽检 代码可运行性 + 结果正确性）、沉淀成功率。
- **1.3 兜底质量护栏**
  - 生成块须经 `体检` + `冒烟` 才允许正式入库；不合格块进 `积木库/生成/待审/` 而非污染 `索引.json`，避免坏块拉低选块质量。
  - `组合.py` 结构化回传补充「兜底来源（LLM/本地规则）/ 生成块名 / token 成本」字段，写 `运行日志.jsonl`。

**月底验收**：`eval.yml` 首次绿（门槛生效）；真实 LLM 兜底 ≥ 15/20 成功沉淀；产出 token 成本报告与质量抽检表。

## 五、第 2 月（11月）：规模压力测试 + 端到端可观测

**目标**：用更大、更真实的语料压测零 token 覆盖率，并把可观测日志变成可复盘资产。

- **2.1 真实语料扩至 500+（治同源过拟合）**
  - 从产品/社区/内部多渠道收集真实用户需求，强制划分**调参段 / 留出段**（留出段严格只测不调，来源独立于代码作者）。
  - 目标：留出段 Hit@1 **≥ 0.97**（比 200 条时更诚实的泛化数字）；对掉点项用「补长触发词 / 局部遮蔽别名」同法消歧，流程已固化在 v0.26。
- **2.2 真实录屏演示（对外素材）**
  - 录 3–5 条从「自然语言需求 → 零 token 方案 → 运行结果」的真实端到端录屏；其中至少 1 条展示「真实 LLM 兜底生成新块并沉淀」全过程，作为 v1.1 发布素材。
- **2.3 可观测性补全**
  - `运行日志.jsonl` 全量采集每次组合的「选中块 / 分数 / 是否兜底 / 兜底来源 / token 成本 / 耗时 / 缓存命中」；做周维度聚合脚本，输出掉点/兜底频次看板，反哺语料挖掘与别名补丁。
- **2.4 兜底跑分纳入门禁**
  - 新增 `积木库/评估/兜底跑分.py`，把库外意图命中率/沉淀成功率纳入 `eval.yml` 门禁，防止真实 LLM 兜底链路回退。

**月底验收**：500+ 语料、留出段 ≥ 0.97；录屏产出；日志看板可用；兜底跑分入 CI。

## 六、第 3 月（12月）：产品化深化 + v1.1 发布

**目标**：从"开发者能跑"变成"使用者能上手、能扩展、能信赖"。

- **3.1 积木平台独立文档站 / 示例集**
  - 基于 mkdocs 新建积木平台专属文档（与段言本体文档分离）：`安装` / `一行需求出结果` / `如何扩一块` / `看指标与防回归` / `真实 LLM 兜底`；配套可复制示例集（覆盖 12 领域各 1–2 例）。
- **3.2 Web/API 产品化**
  - 演示页加**示例画廊 + 指标实时展示**（选中块、分数、是否兜底、耗时）；如对外，API 加鉴权/限流。
- **3.3 协议 v1.1 兼容章节**
  - 随真实反馈修订契约，补 v1.1 破坏性变更与兼容策略；`索引.json` 顶层 `协议版本` 递增；消费方（选块/粘合/校验）按版本分支。
- **3.4 发布 v1.1**
  - PyPI `duan-blocks 1.1.0` + 文档站 + 录屏 + 示例集 + 面向使用者的 README 重写；演示海报/视频重发。
- **3.5 社区 / 采纳**
  - 开放示例投稿入口；收集前 N 个真实用户需求验证零 token 覆盖率，作为 v1.1 北星佐证。

**月底验收**：v1.1 发布；文档站上线；真实 LLM 兜底闭环常态化（CI 门禁看护）；北星指标稳定。

## 七、风险与依赖

| 风险 | 缓解 |
|---|---|
| github 网络不可达，CI 跑不起来 | 优先给 **gitcode 配 runner**；或在可达网络环境推 github 启用 `actions`；CI 说明写清远端同步要求 |
| LLM `api_key` 合规/成本 | OpenAI 兼容端点 + 预算上限；本地规则仍作兜底；token 成本报告周度盯控 |
| 真实语料获取成本 / 又写又测过拟合 | 多来源 + 留出段只测不调 + 来源独立于作者 |
| 真实 LLM 生成块质量不稳 | 护栏（体检/冒烟/待审）+ 人工抽检 + 沉淀成功率门禁 |
| 文档站与段言本体文档混淆 | 新建积木平台专属 mkdocs 站点，物理分离 |
| 协议 v1.1 破坏性变更 | 契约带版本号、向后兼容；消费方按 `协议版本` 分支 |
