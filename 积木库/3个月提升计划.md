# 段言积木平台 · 3 个月提升计划（v0.23 → v1.0）

> 定位：把「零 token 组合式代码生成」从「仓库里能跑的实验室原型」推进到「一行命令能装、能演示、能发布」的产品。
> 制定日期：2026-08-10 ｜ 基准现状：主基准 89 条 Hit@1=MRR=库外召回=链路正确率=1.0；冒烟 92/92；体检 0 错 0 警；扰动集留出段 concept 1.0 / hybrid 0.975。

## 二、北星指标

**零 token 覆盖率**（真实用户需求留出语料口径）= 库内需求被正确组合 **且未误兜底** 的比例。
- 现状（自测）：≈ 1.0（但语料同源，虚高）
- 3 个月目标：真实留出语料 ≥ **0.95**

辅助指标：库规模（150+ 可见块）、pip 可装可用、v1.0 发布、压测报告（库 200 块下选块延迟/缓存命中）。

## 四、第 1 月：底座固化 + 工程化破冰

**目标**：从「仓库里能跑」变成「一行命令能装能用」。

- **1.1 协议 v1.0 定稿（冻结）**
  - 锁定契约格式、方案 JSON 结构、五段式数据流、失败信号约定（`rc==0 且 非空 stdout`）、版本兼容策略（契约加 `协议版本` 字段，旧块可标注兼容范围）。
  - 产出：把 `协议.md` 升为 `协议_v1.md`（或原地升 v1.0），并补「破坏性变更」章节。
- **1.2 工程化：pip 可装 + CLI 包装**
  - `pyproject.toml` + `console_scripts`：`duan-combo "需求" --input "..."` 直接出结果；把 `组合.py` 包成正式入口。
  - 段言运行时依赖以文档化方式声明（或打包进 wheel），避免用户手动配 `cli/duan.py`。
  - 依赖隔离遵循仓库约定（受管 venv / 隔离目录）。
- **1.3 落地库外 5 项能力（清历史欠账）**
  - 正则（re import，已确认可用）、base64（base64 import）、文件IO（读 CSV/读文本，os/io import）——**直接落地，零第三方包**。
  - 拼音（pypinyin）、繁简（opencc）——需第三方包，确认离线安装与词典体积；若体积过大则做懒加载/可选依赖。
  - 每块过 体检 + 冒烟，并把 X01/X02/X05/X06/X09 从「应兜底」转为「库内」，主基准同步扩标。
- **1.4 失败可诊断**
  - 组合.py 在执行闭环里结构化回传「为何兜底 / 选了谁 / 分数多少 / 是否命中缓存」，不再静默吞错。

**月底验收**：`pip install .` 成功；库外 5 项 100% 命中；主基准 + 冒烟零回归。

## 五、第 2 月：扩库 + 泛化 + 真实语料

**目标**：从「自造基准满分」走向「真实措辞也接得住」。

- **2.1 扩库 92 → 150（新增方向）**
  - 集合与关系（并/交/差/笛卡尔/去重计数）、概率统计（分位数/偏度/峰度/相关系数）、几何（距离/面积/向量运算）、金融进阶（IRR/NPV/夏普比率）、Web/HTTP（抓标题/解析 query 参数）、加解密（MD5/SHA/哈希）、批量文件（列目录/多 CSV 合并）、日期高级（时区/季度/财年）。
- **2.2 真实语料采集（治过拟合）**
  - 从产品/社区/内部收集真实用户需求 **200+** 条，强制划分调参段 / 留出段（留出段只测不调）。
  - 目标：留出段 Hit@1 ≥ **0.95**（诚实泛化数字）。
- **2.3 泛化加固**
  - `auto_alias` 扩到新领域；复合意图门控覆盖更多「同时/都」场景；具体度决胜覆盖更多并列群。
- **2.4 真实 LLM 校验器验证**
  - 配置 key，跑通 few-shot 拦截「中文转拼音 vs 数字转中文」等细微错配的真实案例；记录本地 vs LLM 校验的 FP/FN。

**月底验收**：库 150 块、留出段 ≥ 0.95、冒烟 100%、LLM 校验跑通且有 FP/FN 记录。

---

## 六、第 3 月：产品化 + 发布 + 可观测

**目标**：从「开发者工具」变成「可演示、可发布、可扩展」的产品。

- **3.1 Web/API 服务**
  - FastAPI 包装 `组合.py`：`POST /combo {需求, 输入}` → 返回方案 JSON + 运行结果 + 诊断；附带极简前端演示页（实时输入需求看组合）。
- **3.2 兜底生成端到端 demo**
  - 真实跑通「库外需求 → LLM 生成新块 → 写入 生成/ → 注册索引 → 下次零 token 复用」，录一条端到端演示。
- **3.3 可观测性**
  - 每次组合输出结构化日志（选中块 / 分数 / 是否兜底 / 耗时 / 缓存命中），存档便于复盘与语料挖掘。
- **3.4 性能 / 规模压测**
  - 库 150 / 200 块下选块延迟、内存占用、计划缓存命中率，产出压测报告（验证 150→200 规模下的延迟上限）。
- **3.5 发布 v1.0**
  - PyPI 包 + 文档站（mkdocs 已有脚手架）+ 示例集 + 5 分钟演示视频 + 面向使用者的 README 重写。

**月底验收**：v1.0 发布；API 可用；零 token 覆盖率（留出段）≥ 0.95；压测报告产出。

## 七、风险与依赖

| 风险 | 缓解 |
|---|---|
| 拼音/繁简第三方包体积大、离线安装难 | 确认 pypinyin/opencc 词典离线可用；做可选依赖 + 懒加载，缺失时优雅降级为「应兜底」 |
| 段言运行时强耦合 `cli/duan.py` | 发布时在 wheel 内捆绑运行时或文档化一键安装；CLI 入口自动探测 |
| 真实语料获取成本 / 又写又测导致过拟合 | 留出段严格只测不调；语料来源独立于代码作者 |
| 协议冻结后契约改动成本高 | v1.0 前充分评审；契约带版本号，向后兼容 |
| 继续在算法上内卷而忽略工程化 | 本计划明确把第 1 月重心放在工程化，质量指标已达标不再过度优化 |
