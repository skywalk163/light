段言积木库 · 使用文档

面向积木使用者：用一行自然语言需求拼出可运行的段言程序，常态零 AI token。本页为独立静态文档站，与段言语言本体的 mkdocs 物理分离。

1. 安装

积木库已发布到 PyPI（包名 duan-blocks，当前版本 1.0.1）。段言语言本体与积木平台分开安装：

# 段言语言本体
pip install duan
# 积木组合平台（已发 1.0.1）
pip install duan-blocks
# 可选：拼音 / 繁简 / 农历等中文能力
pip install duan-blocks[zh]

安装后可用命令行 duan-combo 直接跑需求；也可起 Web 演示服务：

# 交互式演示页 + JSON API（端口可改）
uvicorn duan_blocks.api:app --port 8123
#   GET  /       演示页
#   POST /combo  {"requirement":"半径5的圆有多大","input":"5"}
本地仓库运行：在本仓库内调试脚本时，使用受管 Python 解释器（已随 WorkBuddy 安装） C:/Users/skywalk/.workbuddy/binaries/python/versions/3.13.12/python.exe。 例如运行生成脚本：该python 积木库/docs_site/build_docs.py。 仓库内脚本会优先用 cli/duan.py 作为运行时；pip 安装后回退到 duan 命令（见 组合.py 的 _定位运行时）。
已知边界（诚实声明）：拼音/繁简/历法依赖可选第三方包（pypinyin/opencc/lunardate），缺失时对应块运行期才报错；真实 LLM 兜底需配置 llm_config.json 的 api_key（未配时本地规则覆盖 7 类常见库外意图）。

2. 一行需求出结果

核心用法只有两步：先用 组合.py 把自然语言需求拼成段言源码，再用段言运行时执行。

# ① 选块 → 校验 → 契约级接线 → 内联粘合 → 运行，写出 组合结果.duan
python 积木库/组合.py "对一批数字求和再算平均"

# ② 用段言运行时执行生成的 .duan（rc==0 且非空输出即成功）
python cli/duan.py run 组合结果.duan

组合器默认共享输入为 [1, 2, 3, 4, 5]，可用 --输入 覆盖；--json 输出结构化诊断；--无兜底 可关闭 LLM 兜底。

python 积木库/组合.py "半径5的圆面积" --输入 5 --json
常态零 token。选块（概念图向量，零依赖毫秒级）、校验、接线、粘合全部本地运行； 仅当「选不准」时才调用一次 LLM 兜底生成新积木，且生成结果永久沉淀，下次同需求零 token 复用。

3. 如何扩一块

积木库是一张契约索引。每个块在 索引.json 的 块 数组里是一条记录。以「求和」为例，真实字段如下：

{
  "名称": "求和",
  "领域": "数据",
  "层级": 0,
  "描述": "对数值列表求和，返回所有元素之和",
  "输入": [{"名": "列表", "类型": "列表[数]"}],
  "输出": {"类型": "数"},
  "稳定性": "stable",
  "路径": "数据/求和.duan",
  "导出名": "汇总"
}

各字段含义（来自 协议.md 冻结的契约格式）：

  • 名称：块的中文名（使用者可见）。
  • 领域：所属领域，如 数据/文本/中文/财务/工具/网络/生成/日期/校验/格式/集合/几何。
  • 层级：L0 原子块 / L1+ 聚合块（由 层级生成.py 织出）。
  • 描述：选块器据此匹配需求，写清「具体能力概念」，避开旧概念触发词以免余弦平局被旧块抢答。
  • 输入 / 输出：结构化类型（列表[数]/字典[文本,数]/可选[T]/联合[A,B]），供契约级类型闸门接线。
  • 稳定性：stable（手写 .duan 为准）或 generated（兜底生成、源码内联存 索引.json）。
  • 路径：源码相对库根位置，缺省时粘合器按 领域/块.duan 回退。
  • 导出名：粘合进单一 .duan 后的段落导出名，词法器最长匹配消费。

两条铁律（评估/体检.py 强制）

铁律一：段落名 == 导出名。 源码里的 段落 必须与索引的 导出名 完全一致（体检 E4）。
铁律二：导出名之间不得互为前缀。 否则词法器最长匹配会把一个名切碎成另一个（体检 W1；曾真实发生过 均值 导出名误写成 中位 与 中位数 互为前缀）。

新增一块的最小步骤

  1. 在对应领域目录新建 <名称>.duan，段落名 == 导出名，且导出名不与任何现有导出名互为前缀。
  2. 在 索引.json 的 块 数组追加一条（必填：名称/领域/层级/描述/输入/输出/稳定性/路径/导出名）。
  3. 跑 python 积木库/评估/体检.py --严格 确认铁律与契约一致通过。
  4. 跑 python 积木库/评估/冒烟.py --只跑 <领域> 真跑该块，确认输出符合预期。
逐块真实字段见 块清单（由 build_docs.py 从 索引.json 实时生成，不手抄）。

4. 指标与防回归

质量靠「尺子」量化，任何优化都要能回答「被哪把尺子量到」。使用者侧最相关的五把：

  • 选块（评估/跑分.py）：候选块对不对（Hit@1 / 链路正确率）。
  • 校验（评估/校验器.py 思路）：运行前第二道闸，需求能力概念与所选块无交集即判误选。
  • 体检（评估/体检.py）：索引与 .duan 源文件一致性，守卫两条铁律。
  • 冒烟（评估/冒烟.py）：真跑每一块比对期望输出，统计可运行率。
  • 扰动（评估/扰动跑分.py）：用刻意避开块名用字的迂回说法，测对外泛化召回。
此外还有真实语料尺子（评估/真实跑分.py，按调参/留出分段防自欺）与接线尺子（评估/接线跑分.py，契约级类型闸门），二者也是 CI 门禁的一部分。

兜底跑分门禁（评估/ci_eval.py + 评估/门槛.json）

ci_eval.py 进程内串起上述各尺子，按 门槛.json 数据驱动判 22 项闸门；任一不达标即非零退出码、CI 标红。门槛可随库演进调整（改 门槛.json，不改代码）。关键门槛（来自真实 门槛.json）：

组指标门槛
主基准Hit@1= 1.0
主基准链路正确率= 1.0
主基准失败条目数 / 库外召回0 / = 1.0
扰动集留出段 concept / hybrid Hit@1≥ 0.95
扰动集全部 concept Hit@3 / 空候选≥ 0.99 / ≤ 0
体检错误数 / 警告数≤ 0
冒烟可运行率 / 问题块数= 1.0 / ≤ 0
兜底（条件）触发率≥ 1.0
兜底（条件）沉淀成功率≥ 0.7
兜底两闸为条件门禁：仅当 兜底首跑.py 产出 ≥ 10 条兜底样本时激活；未真跑则跳过，避免拿「没测过」当回归。
# 全量（含并发冒烟，约 50s）
python 积木库/评估/ci_eval.py --并发 8
# 快模式（跳过冒烟，秒级）：提交前本地快速回归
python 积木库/评估/ci_eval.py --快

5. 真实 LLM 兜底

当组合器对某个需求「选不准」，触发 兜底生成器.py 按契约生成一块新积木：

  • 触发信号：① 无候选（概念图余弦≈0，需求库内无对应概念）；② top 分数低于阈值，或契约级接线不可接；③ 校验器判 MISMATCH（本地概念无交集 / LLM 认为组合不满足需求）。
  • 本地规则先行：未配 API key 时，本地规则覆盖 方差/标准差/中位数/绝对值/斐波那契/阶乘/素数/累加和 等常见库外意图，仍零 token。
  • 真实 LLM：本地规则也覆盖不了、且配置了 key 时，才调用一次 OpenAI 兼容的 chat/completions 生成新积木。
沉淀与护栏。生成的块写入 生成/<名称>.duan 并注册进 索引.json，下次同需求零 token 复用。 若未过护栏（如臆造了不存在的内建名），则由 入待审 写入 生成/待审/ 并记入 待审清单.jsonl，不污染 索引.json； 护栏回滚时只注销 生成/ 下的生成块，不影响原库条目。 
# 兜底配置优先级（任选其一）
#   1) 积木库/.env          OPENAI_API_KEY / OPENAI_BASE_URL / OPENAI_MODEL
#   2) 环境变量              OPENAI_API_KEY / OPENAI_BASE_URL / OPENAI_MODEL
#   3) 积木库/llm_config.json   {"api_key":"...","base_url":"...","model":"..."}
