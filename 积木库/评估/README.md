# 评估 —— 段言积木组合系统的尺子

> 没有尺子，任何「优化」都只是感觉。这个目录把选块、校验、兜底判定的质量变成可回归的数字。

## 目录

| 文件 | 作用 |
| --- | --- |
| `基准.json` | 89 条真实需求（全部库内，标注可接受的正确块；库外 5 项已于 v0.24 清零转入库内），含 S01–S08 句法系列 |
| `跑分.py` | 跑「选块 → 校验 → 兜底判定」，回答**选对块了吗** |
| `真实语料.json` | 80 条口语/场景化需求（调参/留出各 40），`真实跑分.py` 按段统计 concept/hybrid |
| `真实跑分.py` | 在真实语料上量化选块与兜底判定质量（区分调参段/留出段，防自欺） |
| `扰动集.json` | 40 条刻意避开块名用字的迂回说法（R01–R20 调参 / R21–R40 留出），照妖镜 |
| `扰动跑分.py` | 在扰动集上量化泛化召回（留出段只测不调，对外泛化数字） |
| `接线基准.json` | 26 条接线用例：17 条链式接线 + 9 条类型闸门 |
| `接线跑分.py` | 跑「契约级接线 + 类型闸门」，回答**接对线了吗** |
| `体检.py` | 索引与 `.duan` 源文件的一致性检查（铁律守卫）；对外接口 `收集()` 供 CI 进程内调用 |
| `冒烟.py` | 第四把尺子：真跑每一块比对 `期望`；v0.27 缺依赖单列 + 并发 + stderr 诊断（见下） |
| `迁移_类型v2.py` | 一次性迁移：把粗类型标注升级为类型系统 v2，并检出漏标 |
| `ci_eval.py` | **总闸门**：进程内调用上述六把尺子，按 `门槛.json` 判 22 项闸门，非零退出码触发 CI 失败 |
| `门槛.json` | CI 闸门的数据驱动门槛配置（基线日期 2026-08-11，可随库演进调整） |
| `报告/` | 历次跑分结果（json），含 `ci_eval.json` / `ci_daily.json` / `ci_history.jsonl`，用于纵向对比 |

三个脚本**只做判定、不做生成**：绝不调用 `注册()`，因此不会向 `索引.json` 或 `生成/` 写入任何东西。

## 用法

```bash
# ① 选块质量（概念图向量，零依赖毫秒级）
python 积木库/评估/跑分.py --策略 概念图

# 真·句向量（需 sentence_transformers；首次需 HF_ENDPOINT=https://hf-mirror.com）
python 积木库/评估/跑分.py --策略 embedding --标签 真向量

# 与历史报告逐指标对比
python 积木库/评估/跑分.py --策略 概念图 --对比 积木库/评估/报告/report_概念图_baseline.json

# ② 接线质量（类型系统 v2 的收益就体现在这里）
python 积木库/评估/接线跑分.py --详细
python 积木库/评估/接线跑分.py --粗类型     # 对照：用 v0.17 粗类型跑，量化收益

# ③ 契约体检（扩库前后必跑）
python 积木库/评估/体检.py --严格
```

可选策略：`embedding`（默认=概念图）、`概念图`、`语义`（TF-IDF）、`关键词`（v0 字符重叠）。

## CI 防回归门禁（ci_eval.py）

把六把尺子串成一道**非零退出码**闸门，推送即防回归。进程内 `import` 各尺子模块调函数
（不解析 stdout，规避管道吞输出误判），按 `门槛.json` 数据驱动判定 22 项闸门。

```bash
# 全量（含并发冒烟，约 50s）：六把尺子全跑，写 报告/ci_eval.json
python 积木库/评估/ci_eval.py --并发 8

# 快模式（跳过冒烟，秒级）：提交前本地快速回归
python 积木库/评估/ci_eval.py --快

# 每日巡检：写 ci_daily.json + 追加 ci_history.jsonl，并与昨日对比防回退
python 积木库/评估/ci_eval.py --并发 8 --每日 --对比 积木库/评估/报告/ci_daily.json

# 详细 + 对比历史报告
python 积木库/评估/ci_eval.py --详细 --对比 积木库/评估/报告/ci_eval.json
```

**22（+2 条件）项闸门**（门槛见 `门槛.json`，基线 2026-08-11）：

| 组 | 关键闸门 | 门槛 |
| --- | --- | --- |
| 真实语料 | 留出段 concept/hybrid Hit@1 | ≥ 0.99 / ≥ 0.97 |
| 真实语料 | 调参段 concept Hit@1、全部 concept 空候选 | = 1.0 / ≤ 0 |
| 扰动集 | 留出段 concept/hybrid Hit@1 | ≥ 0.95 |
| 扰动集 | 全部 concept Hit@3、空候选 | ≥ 0.99 / ≤ 0 |
| 主基准 | Hit@1、链路正确率、失败条目、库外召回 | = 1.0 / ≤ 0 / = 1.0 |
| 主基准 | 库内误兜底率、校验 FN/FP 误拦误放 | ≤ 0.0 / ≤ 0 |
| 接线 | 链式接线 / 类型闸门 / 总正确率 | ≥ 1.0 |
| 体检 | 错误数、警告数 | ≤ 0 |
| 冒烟 | 可运行率、问题块数 | = 1.0 / ≤ 0 |
| 兜底（条件） | 触发率、沉淀成功率 | = 1.0 / ≥ 0.7（仅当 `兜底首跑.py` 产出 ≥ 10 条兜底样本时激活，未真跑则跳过，避免拿「没测过」当回归） |

**双端部署**：`.github/workflows/eval.yml`（GitHub，路径过滤 `积木库/**`）与
`.gitcode/workflows/eval.yml`（GitCode，EulerOS runner）都跑 `ci_eval.py --并发 8`，上传报告 artifact。
runner 就绪前由本机每日 09:00 自动化任务跑 `--每日 --对比` 兜底（结果存 `报告/ci_daily.json`）。

> **反向验证**：①收紧任一门槛立刻标红并指出掉点；②摘掉 `概念别名补充.json` 模拟真实回归，
> 6 项闸门立刻红（主基准 Hit@1 0.9663 等）——证明闸门能拦真实回退，不是摆设。

## 冒烟 v0.27（第四把尺子升级）

- **缺依赖单列**：`缺哪些依赖(块)` 按索引 `依赖` 字段预检第三方包（如 `pypinyin`/`lunardate`）；
  环境未装时单列「缺依赖」，从「可运行率」分母剔除——避免可选依赖块（转拼音/公历转农历/农历转公历）
  把 148/151 错拉成非 1.0。装了可选依赖后 **151/151**。
- **stderr 诊断**：段言运行期错误写 stderr，新增 `_stderr摘要()` 回退取 stderr，修复「问题块详情长期为空」。
- **并发**：`跑(..., 并发=N)` 槽位队列（每线程独占工位文件），2m53s → 22s；工位文件 `_冒烟工位_*.duan` 已忽略。
- **结构化返回**：`跑()` 返回含 `统计/可运行率/问题块/缺依赖块` 的 dict，供 CI 与脚本消费。

```bash
python 积木库/评估/冒烟.py --并发 8          # 并发全量
python 积木库/评估/冒烟.py --只跑 日期 --并发 4   # 局部验证
```

## 两把尺子的分工

选块跑分只回答「候选集合对不对」，**它对接线错误完全无感**——类型系统 v2 上线时选块指标
一动不动（0.9839 → 0.9839），收益全在接线跑分上（0.7692 → 1.0000）。任何改动都要问一句：
**它该被哪把尺子量到？如果两把都量不到，就先去补尺子。**

## 指标含义

| 指标 | 定义 | 关注点 |
| --- | --- | --- |
| `Hit@1` / `Hit@3` | 库内条目中，top1 / top3 命中期望块的比例 | 选块精度 |
| `MRR` | 首个正确块位次的倒数均值 | 排序质量 |
| `库外召回` | 该兜底的需求中，被正确判定为兜底的比例 | 能力边界意识 |
| `库内误兜底率` | 库内需求被错误判为兜底的比例（会白白触发生成） | 成本浪费 |
| `校验器 FN / FP` | FN=把对的组合拦下；FP=把错的组合放行 | 第二道闸的可靠性 |
| `链路正确率` | 库内 top1 正确且不误兜底 + 库外正确兜底，占全部条目 | **系统总分** |

## 基准编写约定

- `期望块` 是**可接受集合**：命中任一即算正确（如「同时给出均值和极差」既可选 `统计双指标` 也可选 `描述统计`）。
- `应兜底: true` 表示该能力库内确实不存在，正确行为是空候选/校验拦截 → 兜底生成。
- `标签` 用于分组统计；`难` 标记已知短板，用来长期跟踪而不是掩盖。
- 新增积木后，若它覆盖了某条库外条目的能力，需把该条从「应兜底」改为库内并填写期望块。

## 结果存档

### 纵向：概念拆分前后（同为概念图策略）

| 报告 | 阶段 | Hit@1 | Hit@3 | MRR | 库外召回 | 链路正确率 |
| --- | --- | --- | --- | --- | --- | --- |
| `report_概念图_baseline.json` | 概念拆分前（v0.16） | 0.362 | 0.702 | 0.514 | 0.467 | 0.387 |
| `report_概念图_拆分后.json` | 概念拆分 + 最长匹配（v0.17） | **0.979** | **1.000** | **0.989** | **1.000** | **0.984** |

### 横向：四种选块策略（v0.17 概念词典下）

| 策略 | Hit@1 | 库外召回 | 库内误兜底率 | 链路正确率 | 平均耗时 |
| --- | --- | --- | --- | --- | --- |
| **概念图向量（默认）** | **0.979** | 1.000 | 0.000 | **0.984** | **0.1 ms** |
| 语义 TF-IDF | 0.915 | 1.000 | 0.085 | 0.903 | 11.7 ms |
| 真·句向量 text2vec | 0.766 | 1.000 | 0.149 | 0.823 | 3733 ms |
| 关键词字符重叠（v0） | 0.745 | 1.000 | 0.106 | 0.807 | 1.7 ms |

**关键结论（推翻了 v0.16 的默认设定）**：真·句向量在本库规模下**反而最差且慢 3 万倍**。
中文短查询与长块描述的句向量相似度高度趋同（各向异性），「把这组数加起来」会被
`样本方差 0.716 / 中位数 0.707 / 方差 0.694` 这类统计块吃掉。因此 v0.17 起真向量
**降级为显式实验选项**（`--real` 或 `DUAN_EMBED_REAL=1`），默认走概念图。

四种策略的库外召回都是 1.000，这恰恰证明**校验器作为第二道闸的价值**：即使选块召回全错，
基于概念图的校验器仍能拦下并转入兜底。

### 接线：类型系统 v2 前后（v0.18）

| 契约类型 | 链式接线 | 类型闸门 | 总正确率 |
| --- | --- | --- | --- |
| v0.17 粗类型（列表/字典 不带元素类型） | 0.765 | 0.778 | 0.769 |
| **v0.18 类型 v2（列表[T]/可选/联合/字典[K,V]）** | **1.000** | **1.000** | **1.000** |

粗类型下失败的 6 条**全都是会生成崩溃代码的场景**：`切分文本 → 求和`、`切分文本 → 均值`、
`切分文本 → 取偶数`、`中文数字 → 求和`，以及文本列表输入时 `求和/方差/中位数` 没被闸门滤掉。
旧系统里它们都叫「列表」，类型检查形同虚设。

复现对照：`python 积木库/评估/接线跑分.py --粗类型`

### 选块：从属子句降权前后（v0.18）

| 阶段 | 条目 | Hit@1 | Hit@3 | MRR | 库外召回 | 链路正确率 |
| --- | --- | --- | --- | --- | --- | --- |
| v0.17 概念拆分 | 62 | 0.979 | 1.000 | 0.989 | 1.000 | 0.984 |
| v0.18 从属降权 + 校验器 R2 | **70** | **1.000** | **1.000** | **1.000** | **1.000** | **1.000** |

D13 的根因不是词典缺词，是**句法**：`排序` 是定语从句（怎么求中位数），`中位数` 才是目标，
但概念袋把两者同权，余弦精确打平在 0.686。修法见 `协议.md` v0.18 第 6 节：

- 概念命中紧跟 `后/之后/然后/再/完/以后` 或被 `先/首先` 引导 ⇒ 权重 ×0.6；
- 余弦对整体缩放不敏感 ⇒ **单概念查询分数完全不变**，只有多概念查询被重排；
- 校验器新增 R2「目标能力覆盖」：只盖住从属概念、目标层全空 ⇒ 判误选。

同时新增 S01–S08 八条句法用例防过拟合——它们当场又抓出两个真缺口
（「还剩几个」未映射到 `计数长度`、「拼起来」未映射到 `文本拼接`），补词典后 70/70 满分。

### 已知短板（长期跟踪）

- 概念词典仍需随库扩充维护：口语化长句若用词典外的说法（如「按字母顺序排好」）仍会无候选
  → 误触发兜底。属于覆盖度问题，不是架构问题。
- 从属降权是**词表级句法启发式**，不是真句法分析；遇到「排序后的列表再排一次」这类嵌套
  结构仍可能判偏。当前 8 条句法用例是它的回归护栏。

### 基准暴露并已修复的真 bug

1. **模型重复加载**：`_真向量检索` 每次调用都 `SentenceTransformer(model)`（约 5 秒/次），
   批量场景放大成分钟级 → 改为进程内实例缓存。
2. **兜底重复生成**：能力缺失预检只检查「不在候选中」，库内已有同名块时会再生成一次并
   污染 `索引.json` → 改为「库内已有则纠正选块，绝不重复生成」。
3. **并行装配类型错误**：top-k 步骤共用同一输入，`保留分`（吃「数」）被塞进列表输入的
   方案里，合成出 `留分([1,2,3,4,5])` → 新增**类型闸门**，过滤签名接不上的块。
4. `组合.py` 的 `_cli` 中 `无兜底` 未定义（应为 `args.无兜底`），运行失败时才触发。
5. **导出名前缀冲突（体检器首跑即抓到）**：`均值` 的导出名竟是 `中位`，与 `中位数` 互为前缀。
   `描述统计.duan` 里两者同处一个合成文件，全靠词法器最长匹配侥幸没炸 → 已改名为 `平均`。
6. **多共享输入时主数据被抢**：接线器「最近上游优先」对共享输入也生效，导致第 1 个参数接到
   了最后一个共享变量 → 改为「上游产物按最近优先、共享输入按声明序」，并加「同一步骤内不重复
   占用同一变量」。
7. **`--链式` 静默退化成并行**：某步接不上任何上游产物时会悄悄退回共享输入，用户以为是串联
   → 新增 `_回退` 标记与 `回退步()`，`组合.py` 显式打印告警。
