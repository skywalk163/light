# 《段言积木组合协议 v1.0》（定稿）

> **v1.0 定稿声明（2026-08-10）**：自本版起，下列接口冻结为稳定契约，v1.0 之后的改动
> 必须走「破坏性变更流程」（见下），不得静默修改：
>
> - **契约格式**（`索引.json` 块条目字段）：
>   - 必填：`名称/领域/层级/描述/输入/输出/稳定性/路径/导出名`。
>   - 可选：`样例/选块可见/期望/依赖/源码/兼容`。
>     - `样例`：冒烟/验收用输入列表（与 `期望` 一一对应，可缺）。
>     - `选块可见`：缺省 `true`；自动织聚合块置 `false` 退出候选池。
>     - `期望`：该 `样例` 对应的期望输出文本（字符串或 JSON 串），供冒烟做「输出 == 期望」比对。
>     - `依赖`：可选第三方 Python 包名列表（如 `pypinyin`），环境缺装时冒烟单列「缺依赖」、不污染可运行率分母。
>     - `源码`：仅 `稳定性=generated` 的块内联存源码（可直接内联粘合）；`stable` 块源码以 `.duan` 文件为准、不在此冗余。
>     - `兼容`：可选，声明本条目可被哪些协议版本消费（缺省视为仅本版）；当前全库未填充，消费方跳过逻辑为预留能力。
>   - 类型一律结构化写法（`列表[数]`/`字典[文本,数]`/`可选[T]`/`联合[A,B]`），裸 `列表` 向后兼容但体检器报 W4。
> - **方案 JSON**（粘合器输入）：`需求/共享/步骤/打印` 四字段。
>   - 共享项：`名/值/类型`（`类型` 供接线器做类型匹配，`粘合.py` 仅消费 `名/值`）。
>   - 步骤项：`块/领域/导出名/路径/参数`，另有可选 `说明`（仅作内联注释）；
>     `路径` 缺省时粘合器按 `领域/块.duan` 回退定位。
>   - 打印：结果变量列表（`赵果N` 约定，`N` 从 1 计数）。
> - **五段式数据流**：选块 → 校验 → 契约级接线 → 内联粘合 → 运行（`cli/duan.py run`）。
> - **失败信号约定**：组合运行成功的可靠信号是 **`rc==0 且 有非空 stdout`**。`cli/duan.py run`
>   在运行期出错（越界/除零/NameError…）会显式 `sys.exit(1)` 返回非零 rc，并把错误打到 stderr；
>   解析错误同样非零 rc；正常方案必含 `打印` 步骤故必有输出。组合器 `_成功(rc, out)` 据此判定：
>   `rc!=0` 或 输出为空 一律判失败并走兜底。可选地传 `期望` 时额外做语义校验（见下「成功信号的可选语义校验」），
>   但生产/CI 主链路只用 `rc==0 且 非空 stdout`。
> - **两条铁律**：`段落` 名 == `导出` 名；导出名之间不得互为前缀（词法器最长匹配会切碎）。
>   由 `评估/体检.py` 强制（E2 导出名重复 / E4 段落名 == 导出名 / E5 缺 `导出` / W1 前缀风险）；
>   `粘合.py` 不另行校验，直接信任索引里的 `导出名`。
>
> **版本兼容策略**：`索引.json` 顶层 **`协议版本`** 字段标明契约版本（当前 `"1.0.0"`）；
> 顶层另有个 legacy `版本` 字段（当前 `"0.1.0"`，早期 jikuai 移植遗留），**不表示契约版本**，以 `协议版本` 为准。
> 块条目允许带 `兼容` 数组声明可被哪些协议版本消费（缺省视为仅本版）。消费方（选块/粘合/校验）
> 遇不兼容条目应显式告警并跳过，不得静默退化。
>
> **破坏性变更流程**：① 改动者在本文件「变更记录」追加条目（影响面/理由/迁移路径）；
> ② 递增 `索引.json` 顶层 `协议版本`；③ 跑五把尺子（体检/冒烟/选块/接线/扰动）确认
> 无回归后方可合入；④ 旧条目按 `兼容` 声明标注迁移状态，不得直接删除。

把「用户自然语言需求」映射为「一组积木的选择 + 契约级参数接线」，再由粘合器内联合成为
可运行的段言 `.duan` 源码，最后用 `cli/duan.py run` 执行。**常态零 AI token**；仅在
「选不准」时调用 LLM 兜底生成新积木，且生成结果沉淀为永久积木，下次零 token 复用。

本方案移植自 jikuai 的《块选择协议》，关键差异见文末「与 jikuai 的差异」。

## 五段式数据流（v0.15）

```
用户需求（字符串）
      │
      ▼
[选块]  embedding选块.py（默认；概念图向量零依赖，装了 sentence_transformers 自动升级真·句向量更细召回）
        选块.py（--关键词，字符重叠）/ 语义选块.py（--语义，TF-IDF）
      │     库外概念 → 概念图余弦≈0 → 返回空候选 → 直接走兜底
      ▼
[校验]  校验器.py（运行前第二道闸，零 token 本地 / 配置 key 后 LLM）
      │     需求具体能力概念 与 所选块 无交集 → MISMATCH → 兜底
      ▼
[契约级接线]  接线.py：按「配置常量优先 > 类型匹配 > 参数名相似 > 最近上游」接线
      │            （不可接则触发兜底）
      ▼
[粘合]  粘合.py：把选中积木源码「内联」进单一 .duan（成语式宏展开）
      │
      ▼
可运行段言代码 → python cli/duan.py run 组合结果.duan
      │
      ▼ （仅「选不准」时）
[兜底]  兜底生成器.py：按契约生成新积木写入 生成/ 并注册进 索引.json
      │
      ▼ （可选 --自动层级）
[层级织]  层级生成.py：把 生成/ + 全库积木自动织成 L1+（成语式宏升级）
```

## v0.15 新增能力

### 1. embedding 概念图选块（解决词法盲区）
- 每个块与查询都映射到「受控概念空间」的稠密向量（概念词典见 `embedding选块.py`）。
- **关键约束**：刻意不把过宽通用字（数/列/值）映射到具体概念，避免「数」把数列需求
  误引到统计块。
- 若查询命中库内某概念 → 对应块高相似，正常选中；若命中「库内无对应块」的概念
  （如 斐波那契/阶乘/素数）→ 向量与所有块余弦≈0 → 返回**空候选** → 上层直接兜底。
- 可选升级：环境装了 `sentence_transformers` 时自动改用真·句向量（仍零 token）。
- **这从根本上修复了 v0.14 的盲区**：旧关键词选块曾因共享「数」字把「斐波那契」误中
  「统计双指标」(7.8 分)，根本不触发兜底；现在概念图直接判为空候选。

### 2. LLM / 本地校验器（第二道闸）
- 即使选块召回了块，仍可能语义错配。校验器在「运行前」做最后一次判定。
- **本地校验（零 token）**：用概念图看「需求具体能力概念」与「所选块具体能力概念」
  是否有交集；仅共享通用领域词（如「中文」）不算通过。无交集 ⇒ 误选 ⇒ MISMATCH。
  （例：`斐波那契` vs `统计双指标` → 具体概念 {数列生成} 无交集 → MISMATCH）
- **LLM 校验（有 key）**：把「需求 + 所选块名/描述 + 接线方案」发给大模型判定。
- 判定失败才触发兜底生成，保证零 token 为常态。

### 3. 生成块自动织入 L1+（层级生成 v0.15）
- `层级生成.py --自动`：扫描全库（含 `生成/`）自动织成 L1 积木，幂等注册进索引。
- 两类织法：①按输入类型聚类的「聚合」L1（同输入多块并行，返回列表）；
  ②策划的高价值组合（如 `描述统计` = 均值+最大+最小+计数+**方差**+**中位数**，
  `中文数字` = 人民币大写+数字转中文）。
- `组合.py --自动层级` 可在组合时顺带触发自动织。
- **已验证**：`描述统计([1..6]) = [3.5,6,1,6,2.9167,3.5]`，其中方差/中位数来自 `生成/`。

## v0.16 新增能力

### 1. 真·句向量检索（更细语义召回）
- `embedding选块.py` 接入 sentence_transformers：把「块名 + 领域 + 描述」与「查询」编码成句向量，
  按余弦召回。能捕捉「金额写大写 ↔ 转大写」这类字符不重叠但语义相近的细粒度关系，召回比
  概念图向量更准。
- 块向量首次编码后缓存到 `积木库/.embed_cache/`（按模型名索引），后续调用秒级；可通过
  `DUAN_EMBED_MODEL` 指定模型、`DUAN_EMBED_FLOOR` 调阈值、`embedding选块.py --real` 强制走真向量。
- 概念图向量仍为零依赖默认路径；真向量不可用或失败时自动降级，零 token 为常态。

### 2. 真实 LLM 校验器（细微错配拦截）
- 校验器系统提示内置 few-shot，专门覆盖「斐波那契 vs 统计」「中文转拼音 vs 数字转中文」
  等细微错配；传给 LLM 的候选已富化含输入/输出类型与描述，判定更精准。
- 本地校验器新增「拼音转换」概念：即使无 key，「中文转拼音」与「数字转中文」因具体能力概念
  无交集被判 MISMATCH，不再被共享的「中文」通用词误导。
- 提供 `校验器.py --dry-run` 展示将发给 LLM 的完整请求体（含已选块输入/输出类型），便于在
  不配置 key 时验证接线正确。

## v0.17 新增能力（评测驱动）

### 1. 基准套件：先造尺子，再谈优化
- `评估/基准.json`：62 条真实需求（47 库内标注期望块 + 15 库外标注应兜底），
  `评估/跑分.py` 产出 Hit@1 / Hit@3 / MRR / 库外召回 / 库内误兜底率 / 校验器 FP·FN / 链路正确率。
- 跑分**只判定不生成**（绝不调用 `注册()`），因此可随时回归而不污染 `索引.json`。

### 2. 概念拆分 + 最长别名优先匹配
- 粗概念（`数列生成` / `数值运算` / `列表集合` / `文本清洗` / `极值跨度`）拆成 40+ 细概念，
  每个概念对应一种**具体能力**而非一个领域。
- `概念向量()` 从「任意子串命中」升级为**最长别名优先**：`人民币大写` 压过 `大写`、
  `前缀和` 压过 `累加`，短别名不再把语义完全不同的需求引到错误概念。
- 权重分层：名称命中 1.0 > 描述命中 0.5 > 领域标签 0.25，通用领域概念整体降权 0.25，
  修掉「同域块被拉平成同分」的问题。
- **能力边界约束**：查询与块只共享通用领域概念（如都带「文本」）时相似度直接置 0 →
  空候选 → 正确兜底。库外概念（拼音/繁简/标准差/base64/UUID…）刻意注册但无对应块，
  让系统「知道自己不知道」。
- **效果**：链路正确率 0.387 → **0.984**，Hit@1 0.362 → **0.979**，库外召回 0.467 → **1.000**。

### 3. 真向量降级为实验选项（数据推翻了 v0.16 的默认）
同一把尺子下，text2vec 真·句向量 **0.823 / 3733ms**，反而不如概念图 **0.984 / 0.1ms**——
中文短查询与长块描述的句向量高度趋同，把「求和/最大/计数」冲散到统计块上。
v0.17 起默认走概念图，真向量需 `--real` 或 `DUAN_EMBED_REAL=1` 显式开启。

### 4. 类型闸门 + 纠正优先于生成
- **类型闸门**：非链式并行装配时，所有步骤共用同一输入，故过滤掉「签名接不上」的块
  （如列表输入下的 `保留分`），避免合成出 `留分([1,2,3])` 这类必然崩溃的代码。
- **纠正优先**：能力缺失预检发现本地规则块**已存在于索引**时，改为把它提到候选首位
  （纠正选块），而不是重复生成同名块污染索引。

## v0.18 新增能力（类型系统 v2）

### 1. 结构化类型：从「列表」到「列表[数]」
`类型.py` 提供一套可组合的类型表达式，取代 v0.17 的裸标签：

| 形态 | 例子 | 含义 |
|---|---|---|
| 基础 | `数` `文本` `逻辑` `任意` `空` | 标量 |
| 列表 | `列表[数]` `列表[文本]` `列表[任意]` | 元素类型协变 |
| 字典 | `字典[文本,数]` | 键/值各自匹配 |
| 可选 | `可选[数]` | 等价于 `联合[数,空]` |
| 联合 | `联合[数,文本]` | 归一化：展平嵌套、去重、含 `任意` 则退化 `任意` |

裸标签（`列表`）向后兼容，等价于 `列表[任意]`。全库 42 块已由
`评估/迁移_类型v2.py` 一次性迁移完毕（35 处标注升级，零漏标零非法）。

### 2. 匹配度取代布尔兼容
`类型.匹配度(need, have)` 返回 0.0~1.0 的实数，而不是「兼容/不兼容」：

| 情形 | 分值 |
|---|---|
| 精确同构（`列表[数]` ← `列表[数]`） | **1.00** |
| 联合分支命中（`联合[数,文本]` ← `数`） | **0.95** |
| 渐进匹配（任一侧含 `任意`，含裸 `列表`） | **0.60** |
| 不兼容（`列表[数]` ← `列表[文本]`） | **0.00** |

有了实数分值，接线器才能在「都能接」的多个候选里挑**最贴切**的那个，
而不是撞上第一个「不报错」的。

### 3. 接线器 v2：类型优先的排序键
排序键从 v0.17 的「常量 > 类型全等 > 名相似 > 最近上游」改为：

```
(类型匹配度↓, 本步未重复占用, 上游产物优先(组=0), 名相似度↓, 位置序)
```

- **共享输入按声明序**（组=1），**步骤产物按最近上游优先**（组=0）——修掉
  「多个共享输入时主数据被最后一个变量抢走」的老 bug。
- **本步已用集合**：同一步骤内不重复占用同一个变量。
- **回退标记**：某步接不上任何上游产物、只能退回共享输入时打 `_回退`，
  由 `回退步()` 暴露给 `组合.py` 打印告警——`--链式` 不再**静默**退化成并行。

### 4. 类型闸门升级
`组合._可单参调用` 从「输入类型字符串全等」改为 `匹配度(块入参, 共享类型) > 0`，
既拦得住 `列表[文本]` 喂给 `求和`，又不误伤 `列表[任意]` 这类渐进标注。

### 5. 契约体检器（第三把尺子）
`评估/体检.py` 守两条铁律：**段落名 == 导出名**、**导出名互不互为前缀**
（段言词法器全文件预扫描 + 最长匹配，前缀重叠会把标识符切碎）。
检查项：E1 名称重复 / E2 导出名重复 / E3 路径缺失 / E4 段落缺失 / E5 导出缺失 /
E6 类型非法 / E7 签名数不符，警告 W1 前缀风险 / W2 描述过短 / W4 裸类型。

> 首跑即抓到真雷：`均值` 的导出名竟是 `中位`，与 `中位数` 互为前缀，且两者同在
> `描述统计.duan` 内——靠最长匹配侥幸没炸。已改名 `中位` → `平均`。

### 6. 从属子句降权（句法特征）+ 校验器 R2
中文需求习惯把「怎么做」写在前、「要什么」写在后：

| 需求 | 前置步骤 | 目标 |
|---|---|---|
| 排序**后**处在中间位置的那个值 | 排序 | 中位数 |
| 求和**再**算平均 | 求和汇总 | 均值平均 |
| **先**排序**再**取最大的那个数 | 排序 | 最大值 |

v0.17 之前两层概念同权，`排序列表` 与 `中位数` 余弦完全打平（0.686/0.686），
top1 随索引顺序抖动——这就是基准里最后一条失败项 **D13**。

- **选块侧**：命中片段紧跟从属标记（后/之后/然后/再/完/以后）或被「先/首先」引导时，
  该概念权重 ×0.6。余弦对整体缩放不敏感，因此**单概念查询完全不受影响**，
  只有多概念查询才被重排——最小扰动。
- **校验器侧（R2 目标能力覆盖）**：把需求概念分成「目标」与「从属」两层，
  若所选块只盖住从属概念、目标层一个都没盖上 ⇒ 判定误选。
  即便选块偶然排错，这道闸也会指出「目标能力『中位数』无块覆盖」。

基准同步扩到 **70 条**（新增 S01–S08 句法系列），结果：
`Hit@1 0.9793 → 1.0000`、`链路正确率 0.9839 → 1.0000`。

已补进概念词典——**这正是基准的价值：新尺子刻度更细，就量得出旧问题**。

## 与 jikuai 的差异
- jikuai 块是扁平目录 + 顺次 glue；段言用**内联成语式宏**展开，单文件即跑。
- 选块：jikuai 用 embeddings 检索（bench_retrieval 在 vector_index=None 时退化为
  TF-IDF+同义词）；段言 v0.15 用**概念图向量**做零 token 召回 + **校验器**做第二道闸，
  比 jikuai 多一层「判定」。
- 层级：jikuai 有 blocks→pipelines→scenarios 三层目录；段言用 `层级生成.py` 把任意
  低级积木组合固化成高级积木并注册，可层层向上（L1→L2→…），且 `生成/` 块也参与编织。
- 兜底：jikuai 未内置；段言有 `兜底生成器.py`（LLM + 本地规则降级），生成块永久沉淀。

## v0.21 混合选块与计划缓存

### 基准满分 ≠ 泛化：扰动集是照妖镜
基准 89 条 Hit@1=1.0 会让人误判系统已经很强。造 `评估/扰动集.json`（40 条**刻意避开块名
用字**的迂回说法，如「这组数据波动有多大」对应 `标准差`、「头一个字母变大写」对应 `词首大写`）
一测，概念图 Hit@1 只有 **0.375**，且 **18/40 完全空候选**。
结论：**瓶颈在召回不在排序**。基准里的说法早被写进概念词典，等于自己考自己。

### 两级选块（混合选块.py）
1. **主召回** 走概念图（受控概念空间、0.4ms、库外硬约束保兜底能力）。
2. **补召回**：主召回为空或 top1 弱于 `DUAN_HYBRID_FLOOR` 时，用 TF-IDF 字符 n-gram 补一批，
   打上 `补召回` 标记（分数做压制，不与概念分直接可比）。
3. **重排**：top1 与后续差距小于 `DUAN_HYBRID_DELTA`（默认 0.03）视为「并列群」，
   群内按 `ALPHA * 概念分 + (1-ALPHA) * 语义分` 重排；群外顺序不动。

代价是耗时 0.4ms → 3.6ms，仍远低于真向量的 3733ms。真向量在 Windows 批量调用下会硬崩
（单条正常），保持 `--real` 实验选项不作默认。

### 防自欺：调参段 / 留出段
扰动集 R01–R20 为**调参段**（允许照着它补概念词典别名），R21–R40 为**留出段**（只测不调）。
补完词典后：调参段 1.00（含过拟合，不可信），**留出段 hybrid 0.70 vs concept 0.50** —— 这才是
可以对外说的泛化数字。

### 计划缓存（计划缓存.py）
键 = `规范需求 + 库指纹 + 策略指纹`。
- **库指纹**覆盖每块的 名称/路径/导出名/输入类型/输出类型/选块可见。兜底生成了新块、
  或谁改了契约，指纹立刻变化 → 旧缓存**整体作废**，不会拿过期方案硬套。
- **输入类型**单独比对：接线是按类型规划的，`列表[数]` 的计划不能给 `文本` 用。
- 只缓存「计划」不缓存「结果」：换一组输入值照样命中，重新执行即可。
- 规划耗时 13.2ms → 2.5ms（**5.3x**）；真正的大头是配了 LLM key 时省下的校验/兜底调用。

**踩过的坑**：`阈值` 参数在选块后会被就地填成策略默认值（None → 0.06），
读缓存在填充前、写缓存在填充后，两头算出的键永远不同 —— 写得进去、读不出来，
表现为「条目数 1、累计命中 0」。修法是函数入口先存 `阈值原`，读写都用它。

## 成功信号的可选语义校验（v1.0）

失败信号（`rc==0 且 非空 stdout`）只能证明「跑通了」，证明不了「算对了」。`组合.py` 的
`_成功(rc, out, 期望)` 在传入 `期望` 时叠加一层**语义校验**：

- 先过 `rc==0 且 非空 stdout`（与生产/CI 主链路一致）；
- 再比 `_语义匹配(实际, 期望)`：优先 JSON 语义等价（容错空格/键序，`[3, 6, 9]` ≡ `[3,6,9]`），
  JSON 不可解析退化为精确字符串相等；数值带 1% 相对容差，吸收 LLM 对浮点常做的 `四舍五入(值,2)`。
  `期望` 为空时直接放行（退化为纯 rc+非空判定）。

该能力用于**验收测试集**（`组合.py --期望`、`库外意图20.json` 的 `期望` 字段），定位
「有输出但语义错」的假阳性（如倍数列表把列表当单参做重复仍有输出）。**生产主链路与 CI 主闸
不传 `期望`**，只验 `rc==0 且 非空 stdout`，行为与契约冻结声明一致。

## v1.1 兼容规划（2026-08-14）

> **v1.1 版本意图**：本协议从 `"1.0.0"` 升到 `"1.1.0"`，属于**向后兼容**的版本递增（不改动任何
> v1.0 已冻结的契约字段），目的为月3 产品化 / v1.1 发布做兼容铺垫。消费方须按 `索引.json` 顶层
> `协议版本` 做契约解析分支，详见文首 v1.0 定稿声明的「版本兼容策略」与本小节。

### 1. 消费方按 `协议版本` 分支
- 选块 / 粘合 / 校验 等消费方在加载 `索引.json` 时，**先读取顶层 `协议版本`**，再决定契约解析分支：
  - `协议版本 >= "1.1.0"`：支持并解析块条目可选 `兼容` 数组语义（见下）。
  - 旧版消费方或精确匹配分支：按 `兼容` 缺省逻辑（仅本版）处理，不假设存在 `兼容` 字段。
- 版本判定建议用**语义化版本顺序**做 `>=` 比较，避免字符串字典序误判（如 `"1.10.0"` 不应小于 `"1.9.0"`）。

### 2. 块条目 `兼容` 数组语义（固化）
- `兼容` 为**可选**数组，元素是本协议版本号字符串，声明**本条目可被哪些协议版本消费**。
- 缺省（不填 `兼容`）：视为仅能被 `协议版本` 所示的本版本消费（当前 `"1.1.0"`）。
- 例：`"兼容": ["1.1.0", "1.2.0"]` 表示它从 v1.1.0 起可被消费、且兼容到 v1.2.0；消费方的
  `协议版本` 落在数组内（或满足 `>=` 最低声明版本，按消费方约定）才纳入候选。
- 当前全库未填充 `兼容`，消费方跳过逻辑为预留能力；v1.1 仅**固化语义**，不强制回填。

### 3. 不兼容条目处理（不得静默退化）
- 消费方解析某条目时，若其 `兼容` 声明与自身 `协议版本` **不匹配**，应**显式告警并跳过**该条目，
  不得静默退化（不得假装兼容、不得吞错继续合成）。
- 告警须携带：条目名 / 条目 `兼容` 声明 / 消费方 `协议版本`，便于定位。
- 旧条目迁移按破坏性变更流程④：如需跨版本复用，补 `兼容` 声明标注迁移状态，**不得直接删除**条目。
