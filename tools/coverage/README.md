# 光明 (LightLang) 代码覆盖率工具

> 状态：**P3 基础原型**（单文件行覆盖率）。设计文档 + 可运行原型，未接入主 `light` CLI。

## 1. 目标

为光明（`.light`）源码提供**行级代码覆盖率**统计，回答：
- 这个文件里有多少行可执行代码？
- 跑完这段测试/运行后，哪些行被执行到了？哪些没跑到？
- 按 `段落`（函数）拆分，每个函数的覆盖情况如何？

支持命令（任务要求）：
- `light coverage run <file>` —— 编译并执行，产出覆盖率数据
- `light coverage report` —— 展示每个函数的覆盖行数

## 2. 设计

### 2.1 关键洞察：编译器自带的源映射

光明编译器把 `.light` 翻译为 Python 时，会在**每条语句前**插入标记：

```python
# LIGHT_SRC:17
for i in range(1, (10) + 1):
    # LIGHT_SRC:18
    和 = (和 + i)
```

其中 `LIGHT_SRC:<n>` 的 `<n>` 就是原始 `.light` 文件的行号。这个标记就是天然的
「目标行 → 源行」映射表，使覆盖率可以精确回溯到**光明源码行**，而不是停留在 Python 层。

### 2.2 流程

```
.light ──compile──▶ <tmp>.py (带 # LIGHT_SRC 标记)
                         │
                         ├─ 扫描标记 → 建立 py行 → 光明行 映射
                         │            → 可执行光明行集合（有标记的行）
                         │
                         └─ tracer 下执行 .py → 记录被执行的 光明行
                                  │
                                  ▼
                         按 段落(函数) 边界分组统计
                                  │
                                  ▼
                         覆盖率 JSON (run) → 报告 (report)
```

### 2.3 可执行行的定义

本原型把「编译器为某条光明语句生成了 `# LIGHT_SRC` 标记」的源行视为**可执行行**
（注释、空行、纯 `导入/导出/段落` 定义行不计数）。这是行覆盖率的合理近似。

### 2.4 函数边界识别

用正则 `^\s*段落\s+<名>\s*接收` 扫描源码，得到每个 `段落` 的起始行；函数区间 =
[本函数起始行, 下一函数起始行-1]。区间内属于「可执行行集合」的行参与统计。

## 3. 用法（原型）

当前以独立脚本提供（**不改动核心编译器 / stdlib**）：

```bash
# 1) 运行并生成覆盖率数据（默认写 coverage.lightcov）
python tools/coverage/coverage.py run examples/hello.light

# 2) 查看报告（含每个函数的覆盖行数）
python tools/coverage/coverage.py report

# 3) 列出未覆盖的光明源码行号
python tools/coverage/coverage.py report --show-missing
```

### 3.1 接入 `light coverage` 子命令（后续小改动）

在 `cli/light.py` 的 argparse 中增加子命令 `coverage`，其 `run`/`report` 子动作直接
调用本目录的 `coverage.py` 逻辑即可（约 10 行 glue 代码）。本原型刻意放在
`tools/coverage/` 下，待主 CLI 合并时再接线，符合「勿动核心编译器」的隔离要求。

## 4. 输出示例

```
覆盖率报告：examples/hello.light
总览：可执行行 12 / 已覆盖 12 = 100.0%

函数                 可执行    已覆盖    覆盖率
--------------------------------------------
阶乘                    5        5      100.0%
(顶层)                 7        7      100.0%
--------------------------------------------

未覆盖行（光明源码行号）:
  （无）
```

## 5. 已知限制 / 后续迭代

| 项 | 说明 | 后续 |
|----|------|------|
| 仅行覆盖 | 不含分支覆盖（if/否则两边是否都跑） | 解析 AST 分支节点，统计真假两路 |
| 单文件 | 一次只统计一个入口文件 | 支持 `light pkg` 多模块聚合 |
| 交互程序 | 被测程序含 `输入(...)` 会阻塞 | 注入 stdin 桩 / 非交互模式 |
| 函数识别窄 | 仅识别 `段落 ... 接收` 形态 | 覆盖 `函数/类方法` 等定义形态 |
| 标记依赖 | 依赖编译器输出 `# LIGHT_SRC` 格式 | 锁定该格式或改为 AST 插桩 |
| 无 HTML 报告 | 仅终端文本 | 生成 `coverage.html`（类似 coverage.py） |

## 6. 验证

定向测试：`python tools/coverage/coverage.py run examples/hello.light` 能产出覆盖率
JSON；`report` 能输出每个函数的覆盖行数（见上方示例结构）。
