# MiniLog 规格说明书（v1.0，语言无关）

> 本文件是给**参赛实现者（AI Agent）**的唯一任务依据。
> 全文不含任何编程语言的代码片段，不含任何语言特定的库名、语法或构建说明。
> 所有语言实现同一份规格，测试以黑盒方式调用可执行文件 `minilog`。

**版本**：1.0
**适用**：Track A（v1 / v2）
**可执行文件**：工作目录下的 `./minilog`（无参数后缀、无扩展名）

---

## 0. 术语与数据模型

### 0.1 NDJSON 输入

输入是**换行分隔的 JSON**（NDJSON）：每一行是一条独立记录，每条记录是一个 JSON 对象。

- 编码：**UTF-8**，不含 BOM。
- 行分隔符：`\n`（LF）。若行尾出现 `\r`（CRLF 输入），实现必须将其去除后再处理。
- **记录单位**：先去掉行尾的 `\r`，再判断该行是否为「空行」——把行文本去掉首尾 ASCII 空白（空格、TAB、CR、LF）后长度为 0 即为空行。**空行被忽略，不参与任何编号与统计**。
- **记录索引**：忽略空行之后，按出现顺序从 **1** 开始编号（1-based）。索引是「第几条记录」，不是物理行号。
- **原样输出**：凡规格要求「输出记录」时，必须输出该记录的**原始行文本**（已去除行尾 `\r`），不得重新序列化 JSON、不得增删字段、不得改变字段顺序、不得改变空格、不得添加引号或前缀。
- 输出编码 UTF-8，行尾统一为 `\n`，**输出的最后一行之后必须有一个 `\n`**。若结果为空，则 stdout 为 0 字节。

### 0.2 记录字段

一条合法日志记录是含以下四个键的 JSON 对象：

| 键 | 含义 | 合法值 |
|----|------|--------|
| `timestamp` | 时间戳 | JSON 字符串，格式 `YYYY-MM-DDTHH:MM:SSZ`（ISO 8601 UTC，固定 20 字符） |
| `level` | 级别 | JSON 字符串 |
| `service` | 服务名 | JSON 字符串 |
| `message` | 消息 | JSON 字符串 |

- 允许出现额外键；实现不得因额外键而判为非法。
- 允许字段值为空字符串 `""`。
- **必需性判定**：某字段「合法」当且仅当该键存在、且对应的值是 **JSON 字符串类型**。值为 `null` / 数字 / 布尔 / 数组 / 对象 / 键缺失，均视为该字段缺失。
- `timestamp` 的**时间先后**一律按 **20 字符字符串的字典序**比较，不得做时区换算、不得做日期解析。字典序较大者即「更新」。（此规定用于消除各语言日期库差异带来的不公平。）

### 0.3 非法 JSON 行

不能解析为 JSON 对象（语法错误、或解析结果不是对象而是数组/标量）的非空行，称为「非法 JSON 行」。

统一处理规则（适用于所有子命令）：

- 该行**不参与**输出与聚合；
- 向 **stderr** 写一行警告，格式严格为：`WARN invalid_json index=<记录索引>`，行尾 `\n`；
- 处理继续，**不因非法 JSON 行而改变退出码**（仍按该子命令的正常规则）。

> 设计理由：若把「非法 JSON」定义为致命错误，则手写 JSON 解析器与成熟 JSON 库的实现难度差异会被放大，污染语言对比。统一降级为警告可使对比聚焦于规格实现而非解析器工程。

### 0.4 行长

实现**不得**设置人为的行长上限。隐藏测试包含单行约 1 MiB（1,048,576 字节）的记录。不得截断、不得因行长报错。

## 1. 命令行通用约定

```
./minilog <子命令> [选项...]
```

- 选项一律写成 `--key=value` 形式（等号，无空格）。**不要求**支持 `--key value` 形式。
- 选项可以出现在子命令之后的任意顺序。
- 未识别的选项 → 用法错误（见 §1.2）。

### 1.1 I/O 来源

| 场景 | 默认行为 |
|------|----------|
| 未指定 `--input` | 从 **标准输入（stdin）** 读取全部内容直到 EOF |
| `--input=-` | 显式表示从标准输入读取，与默认等价 |
| `--input=<路径>` | 从该路径的文件读取；路径为相对路径时相对当前工作目录 |
| 未指定 `--output` | 结果写到 **标准输出（stdout）** |
| `--output=<路径>` | 结果写到该文件（**覆盖写**，若文件已存在则截断；父目录视为已存在）；此时 stdout 必须为 0 字节 |

> **v1 只需支持 stdin/stdout 与 `--input=<路径>`；`--output` 与 `--input=-` 在 v2 才纳入考核**，但 v1 实现提前支持不会扣分。

### 1.2 退出码

| 码 | 含义 | 触发条件 |
|----|------|----------|
| `0` | 成功 | 正常完成（即使输入为空、即使有非法 JSON 行、即使无任何输出） |
| `2` | 用法错误 | 未知子命令；缺必需选项；选项值不合法；同一选项重复给出 |
| `1` | I/O 错误 | `--input` 指向的文件无法打开/读取；`--output` 指向的文件无法创建/写入 |

用法错误与 I/O 错误时，必须向 stderr 写一行人类可读的说明（内容不限，但不为空），stdout 必须为 0 字节。

## 2. v1 子命令

### 2.1 `filter --level=<值>`

输出所有 `level` 字段**等于**给定值且记录为合法 JSON 对象的记录。

- `--level` 为必需选项，缺失 → 退出码 `2`。
- 比较为**区分大小写的精确字符串相等**。
- 缺 `level` 字段、或 `level` 非字符串类型的记录：**不输出**（也不视为非法 JSON 行，不写警告）。
- 输出顺序与输入顺序一致，逐行原样输出。
- `level` 值可以含空格、等号等字符（以 `--level=` 之后的整体为准）。

**示例**

输入：
```
{"timestamp":"2026-11-01T10:00:00Z","level":"error","service":"auth","message":"login failed"}
{"timestamp":"2026-11-01T10:01:00Z","level":"info","service":"auth","message":"login ok"}
{"timestamp":"2026-11-01T10:02:00Z","level":"error","service":"api","message":"timeout"}
```

命令：`./minilog filter --level=error`

stdout（两行，顺序保持，原样）：
```
{"timestamp":"2026-11-01T10:00:00Z","level":"error","service":"auth","message":"login failed"}
{"timestamp":"2026-11-01T10:02:00Z","level":"error","service":"api","message":"timeout"}
```

### 2.2 `tail --n=<正整数>`

输出**最后 N 条记录**。

- `--n` 为必需选项，值必须是十进制正整数（`>= 1`，无前导 `+`、无小数点）；否则退出码 `2`。
- 记录单位按 §0.1（空行忽略后编号）。
- **非法 JSON 行也算一条记录**（按 §0.3 写警告，但计数仍包含它，且 tail 原样输出它）。
- 若记录总数 `M < N`，输出全部 `M` 条。
- 输出顺序与输入顺序一致，逐行原样输出。
- 输入为空 → stdout 为 0 字节，退出码 `0`。

**示例**：对 §2.1 的输入执行 `./minilog tail --n=2`，输出第 2、3 条记录（原样）。

### 2.3 `validate`

检查每条记录是否具备全部四个必需字段（§0.2），输出**不合法**记录的诊断。

- 对每条记录（按索引升序）依次检查 `timestamp`、`level`、`service`、`message` 四个键。
- 对每个缺失/类型不符的字段输出一行，格式严格为：

```
<记录索引>\t<原因码>
```

其中 `\t` 是单个 TAB（ASCII 0x09）。**原因码**为以下固定英文枚举之一：

| 原因码 | 含义 |
|--------|------|
| `missing_timestamp` | 缺 `timestamp` 或值非 JSON 字符串 |
| `missing_level` | 缺 `level` 或值非 JSON 字符串 |
| `missing_service` | 缺 `service` 或值非 JSON 字符串 |
| `missing_message` | 缺 `message` 或值非 JSON 字符串 |
| `invalid_json` | 该行不是合法 JSON 对象 |

- 一行输出的**顺序规则**：先按记录索引升序；同一记录内按 `timestamp` → `level` → `service` → `message` 的固定顺序。
- 非法 JSON 行只输出一行 `<索引>\tinvalid_json`（同时按 §0.3 向 stderr 写警告）。
- 全部记录合法 → stdout 为 0 字节，退出码 `0`。

**示例**

输入：
```
{"timestamp":"2026-11-01T10:00:00Z","level":"info","service":"auth","message":"ok"}
{"level":"info","service":"auth","message":"no timestamp"}
not json
{"timestamp":123,"level":"error","message":"bad types"}
```

stdout：
```
2missing_timestamp
3invalid_json
4missing_timestamp
4missing_service
```

stderr：
```
WARN invalid_json index=3
```

## 3. v2 增量要求

v2 在 v1 的**全部**行为之上，新增以下三点。**v1 的行为在 v2 中必须保持不变**（回归测试会复跑 v1 全量用例）。

### 3.1 `--input=-` 与 `--output=<路径>`

按 §1.1 生效。要点：

- `--input=-` 与不写 `--input` 完全等价。
- 指定 `--output` 时，结果只写入文件，stdout 必须为 **0 字节**；退出码规则不变。
- 结果文件内容与「不指定 `--output` 时的 stdout 内容」**逐字节相同**。
- 输出为空时，仍须创建（或截断）目标文件为 0 字节。
- `--output` 可与任意子命令组合，包括 `validate`、`stats`。

### 3.2 `stats --group-by=service`

按 `service` 字段分组，输出每组的记录数与最新时间戳。

- `--group-by` 为必需选项；本规格只定义取值 `service`；取其他值 → 退出码 `2`。
- 参与统计的记录：**合法 JSON 对象**且 `service` 是 JSON 字符串且 `timestamp` 是 JSON 字符串。缺任一者**跳过该记录**（不写警告、不报错、不计入任何组）。
- 非法 JSON 行按 §0.3 处理（警告、跳过）。
- 每组的「记录数」= 该组参与统计的记录条数。
- 每组的「最新时间戳」= 该组所有 `timestamp` 字符串中的**字典序最大者**（§0.2）。重复时间戳不影响结果。
- 输出每行一组，格式严格为：

```
<service>\t<记录数>\t<最新时间戳>
```

- **排序**：按 `service` 字符串的**字节序（UTF-8 字节逐字节比较）升序**输出。此规定用于消除哈希表遍历顺序的语言差异。
- `service` 值含 TAB 或换行时：本规格保证测试数据不含此类值，实现无需转义。
- 无任何组 → stdout 为 0 字节，退出码 `0`。

**示例**：对 §2.1 的输入执行 `./minilog stats --group-by=service`：

```
api12026-11-01T10:02:00Z
auth22026-11-01T10:01:00Z
```

> 注意 `auth` 组有 2 条，最新时间戳是 `10:01:00Z` 而非 `10:00:00Z`（字典序比较）。

### 3.3 流式处理约束

规格**不强制**实现必须逐行流式读取（允许整体读入内存），因此隐藏测试不设超出可用内存的数据量。但「1 MiB 单行」用例（§0.4）意味着实现不能依赖固定长度的读行缓冲区。

## 4. 边界情况汇总（实现者自查表）

| # | 情况 | 期望 |
|---|------|------|
| 1 | 输入为 0 字节 | 所有子命令 stdout 0 字节，退出码 0 |
| 2 | 输入只有空行 / 空白行 | 同上（空行忽略） |
| 3 | 文件末尾无换行符 | 最后一行仍算一条记录 |
| 4 | CRLF 行尾 | 输出中不含 `\r` |
| 5 | 缺失一个或多个必需字段 | `validate` 按固定顺序输出对应原因码 |
| 6 | 必需字段值为 `null` / 数字 / 布尔 / 对象 | 视为该字段缺失 |
| 7 | 非法 JSON 行 | stderr 警告 + 跳过；不影响退出码；`tail` 仍计入并原样输出 |
| 8 | 单行约 1 MiB | 不截断、不报错 |
| 9 | 重复时间戳 | `stats` 取字典序最大者，其余不受影响 |
| 10 | 额外字段 / 字段顺序打乱 | `filter`、`tail` 原样输出；`validate` 判为合法 |
| 11 | `--n` 大于记录总数 | `tail` 输出全部记录 |
| 12 | 未知子命令 / 缺必需选项 / `--n=0` / `--n=-1` / `--n=abc` | 退出码 2，stdout 0 字节，stderr 非空 |
| 13 | `--input` 文件不存在 | 退出码 1，stdout 0 字节，stderr 非空 |
| 14 | `--output` 指向不可写位置 | 退出码 1，stderr 非空 |
| 15 | 同一选项重复给出 | 退出码 2 |

## 5. 明确不在考核范围

为避免歧义，以下内容**不要求**实现，做了也不加分：

- `--key value` 空格形式的选项、`-l error` 短选项。
- `--level` 的多值 / 正则 / 大小写不敏感 / 级别层级（如 `error` 包含 `warn`）。
- 输出到 stdout 时的彩色、进度条、日志、欢迎语等任何额外文本。
- 并发、多线程、性能优化、内存上限控制。
- 支持 `--group-by` 取 `service` 以外的值。
- 时区解析、日期格式化、时间戳合法性校验（只要存在且为字符串即可，不校验是否为合法日期）。
- JSON 中的 Unicode 转义 `\uXXXX` 的高级处理（测试数据只使用 `\n`、`\"`、`\\` 三种转义及直接 UTF-8 中文）。

## 6. 公平性声明（给评测组织者，不给实现者）

1. 规格刻意把「输出格式」精确到字节，是为了让黑盒测试不依赖任何语言的内部结构。
2. 时间比较退化为字符串字典序、分组排序退化为字节序，是为了剥离日期库与哈希表实现差异。
3. 「原样输出」避免了 JSON 重新序列化时各语言在空格、键序、Unicode 转义上的分歧。
4. 非法 JSON 降级为警告，避免「从零写解析器」的语言被过度惩罚。
5. 隐藏测试只在本文件已声明的语义空间内取值，不引入规格未定义的行为。
