## Triage

- **Symptom**：
  - 类方法内单行 for：`复制追加(["a","b"])` 只返回 `['a']`（截断）——`返回 副本` 被吞进循环体首轮。
  - 模块级函数内单行 for：吞掉函数剩余语句乃至模块级 `主()` 调用（程序零输出、rc=0）。
- **Expected**：单行循环体在行尾 NEWLINE 处立即闭合，等价 Python `for x in y: stmt`；后续语句/类/主调用不被吞。
- **Repro 起点**：`python 运行.py examples/test_L013语义.light`（修复前零输出；修复后 `数量=3`）。
- **Environment**：Windows / CPython 3.14 / 光明语言 SRC 后端（parser_stmt.py）。
- **First seen**：语言缺陷账 L-013 登记，账上标「已缓解」不成立——test_L013.light 的语义断言段 `断言修复后()` 被刻意禁用，「绿」只证明不级联吞类。
- **Severity**：影响功能（编译器级）。

修复前（stash parser_stmt.py 至 HEAD）：零输出、rc=0 → `主()` 被吞。RED 成立。

## Hypothesis

- **H1（确认）**：`_parse_foreach_stmt` / `_parse_while_stmt` 调用 `_parse_body()` 时未传 `allow_single_line=True`，导致单行体不被行尾 NEWLINE 立即闭合，而是继续把后续语句/缩进块并入循环体 → 级联吞语句、错位嵌套。置信度 H。
- **H2（排除）**：词法层 NEWLINE 缺失——冒号后确实有 NEWLINE token（if 语句同场景可正常闭合），排除。
- **H3（排除）**：循环语义/求值问题——多行 for 行为正确，仅单行路径异常，排除。

## Diagnose（backward trace）

从症状反向追：`返回 副本` 被吞 → `_parse_body` 把后续语句并入了循环体 → `_parse_body(allow_single_line=False)`（默认）遇到行尾 NEWLINE 不闭合 → foreach/while 解析未按冒号后是否有换行选择 `allow_single_line`。

对照 if 语句正确写法（parser_stmt.py 2332-2333）：

```python
then_body = self._parse_body(allow_single_line=not has_newline, stop_on_else=True)
```

foreach/while 缺了同样的 `not has_newline` 判定。根因确认 = H1。

## Fix（外科手术式，仅 root cause 路径）

`src/parser_stmt.py`：

- **foreach**（2715-2730）：冒号后循环消耗连续 NEWLINE（`has_newline` 置位）、处理 INDENT，再 `_parse_body(allow_single_line=not has_newline)`。
- **while**（2760-2778）：同上，额外在多行条件场景先消耗多余 DEDENT，再传 `allow_single_line=not has_newline`。

保留原有 NEWLINE/DEDENT/INDENT 消耗逻辑，多行体行为不变。

## Defense-in-depth / 备注

- 单行 while 与单行 for 共用同一 `allow_single_line=not has_newline` 机制，防止 `当 ...: 语句` 同样级联吞语句。
- 语义与 Python `for x in y: stmt` / `while c: stmt` 一致：单行体在行尾 NEWLINE 处立即闭合。
- 后续若再出现「循环吞后续语句」类缺陷，test_L013语义.light 为回归哨兵立红。
