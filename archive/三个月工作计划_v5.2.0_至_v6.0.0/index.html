    9.2 质量保障红线¶

    1. 每次变更必须跑全量测试 — 0 failures 是硬性门槛
    2. 新增功能必须附带测试 — 无测试的代码不合并
    3. 不允许改测试期望值来「修 bug」 — 必须修复底层逻辑
    4. 不允许用 SkipTest 跳过失败 — 必须修复或标注为环境依赖
    5. 每次提交前 git status 检查 — 不引入新的未跟踪临时文件
    6. CHANGELOG 必须同步更新 — 每个功能变更都有记录
