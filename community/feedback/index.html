    用户反馈收集¶

    最后更新： 2026-08-07 适用版本： v6.2.1

    感谢您使用光明（Light）编程语言！您的反馈是我们改进产品的重要依据。本指南说明了如何提交有价值的反馈，并介绍了所有可用的反馈渠道。

    为什么需要您的反馈？¶

    光明还是一个年轻的语言，您的每一条反馈都直接影响着它的发展方向。通过反馈，我们可以：

    • 发现 Bug：及时修复问题，提升稳定性
    • 了解需求：知道用户最需要什么功能，合理规划开发优先级
    • 改进体验：优化文档、错误信息和用户界面
    • 建设社区：让用户参与到语言的设计和演进中来

    反馈渠道总览¶

    渠道 适用场景 响应速度 公开性
    GitHub Issues Bug 报告、功能请求、任务跟踪 ⭐⭐⭐ 最快 公开
    GitHub Discussions 技术讨论、问题求助、作品展示 ⭐⭐ 较快 公开
    文档站评论区 文档反馈、内容建议 ⭐⭐ 较快 公开
    微信群 实时交流、快速问答 ⭐⭐⭐ 最快 半公开
    QQ 群 实时交流、新手求助 ⭐⭐⭐ 最快 半公开
    邮件 安全敏感反馈、商务合作 ⭐ 较慢 私密

    各渠道详细说明¶

    🐛 GitHub Issues¶

    适用场景：Bug 报告、功能请求、任务跟踪

    地址：https://github.com/skywalk163/light/issues

    提交方式： - Bug 报告模板 - 功能请求模板

    好的 Bug 报告包含：

    1. 清晰的问题描述：用一句话说明发生了什么问题
    2. 完整的复现步骤：从创建文件到运行命令的完整过程
    3. 最小可复现代码：尽可能精简的代码片段
    4. 环境信息：操作系统、Python 版本、光明版本
    5. 完整的错误信息：复制完整的错误输出，不要截取片段

    示例：

    ## 描述
使用 `light run` 运行包含中文注释的文件时，词法分析器报错。

## 复现步骤
1. 创建文件 test.light，内容为：
   ```光明
   # 这是一条中文注释
   打印 "你好"
   ```
2. 运行：`light run test.light`
3. 看到错误：
   ```
   SyntaxError: 第 1 行：意外的字符 '#'
   ```

## 环境信息
- 操作系统：Windows 11
- Python 版本：3.12.0
- 光明版本：v6.2.1
- 安装方式：pip install light

    📖 文档反馈¶

    适用场景：发现文档中的错误、遗漏或不清楚的地方

    提交方式： - 直接在文档页面的 GitHub 源码 上提交 PR - 在 GitHub Discussions 中发起讨论 - 提交 Issue 并标注为 docs

    好的文档反馈包含：

    1. 文档位置：文档的路径或 URL
    2. 问题描述：是错误、遗漏还是不清楚？
    3. 建议的修改：你期望的正确内容是什么？
    4. 参考信息：相关的代码示例或其他参考资料

    💬 微信群¶

    适用场景：实时交流、快速问答、社区互动

    群规： - 禁止广告和无关内容 - 提问前请先搜索已有讨论 - 保持友善和尊重的交流氛围

    💬 QQ 群¶

    适用场景：实时交流、新手求助

    群号：请关注项目 README.md 中的 QQ 群号码。

    适用场景：安全敏感反馈、商务合作、隐私相关问题

    邮箱：请在项目主页查看维护者联系邮箱。

    反馈处理流程¶

    我们按照以下流程处理每一份反馈：

    提交反馈 → 分类 → 确认 → 评估 → 排期 → 实施 → 发布

    各阶段说明¶

    阶段 说明 预计时间
    提交 用户通过 Issue 或 Discussion 提交反馈 -
    分类 维护者将反馈分类（Bug/功能/文档/其他） 1-2 个工作日
    确认 确认 Bug 可复现或功能建议合理 1-3 个工作日
    评估 评估影响范围、实现难度和优先级 1-2 周
    排期 纳入开发计划，分配里程碑 视优先级而定
    实施 开发、测试、代码审查 视复杂度而定
    发布 随下一个版本发布 随版本节奏

    优先级说明¶

    优先级 标签 说明 响应时间
    🔴 紧急 critical 严重 Bug，影响核心功能 24 小时内
    🟠 高 high 重要功能或影响较大的 Bug 3 天内
    🟡 中 medium 常规功能或易修复的 Bug 1 周内
    🟢 低 low 小改进或非关键问题 2 周内

    反馈质量指南¶

    好的反馈示例¶

    ## 问题描述
在使用 `light compile` 命令编译包含类型注解的文件时，LLVM 后端
报错 "TypeError: unsupported type"。这个问题在 v6.2.1 中仍然存在。

## 复现步骤
1. 创建文件 test.light：
   ```光明
   段落 加法 接收 甲: 整数, 乙: 整数 -> 整数:
       返回 甲 + 乙

   设 结果 为 加法(3, 5)
   打印 结果
   ```
2. 运行：`light compile test.light --backend llvm-typed`
3. 错误信息：
   ```
   TypeError: unsupported type: 整数
   File "test.light", line 1, in 加法
   ```

## 环境信息
- 操作系统：macOS 14.5
- Python 版本：3.12.3
- 光明版本：v6.2.1
- 安装方式：pip install light

## 期望行为
应该能成功编译并生成可执行文件。

    不够好的反馈示例¶

    光明有问题，JSON 解析不了，快点修一下。

    问题：信息不完整，无法定位问题。

    如何改进¶

    1. 提供完整的错误信息
    2. 提供可复现的代码
    3. 说明你的环境配置
    4. 描述你期望的行为

    社区反馈积分制度¶

    为鼓励高质量的反馈和社区参与，我们试行积分制度：

    行为 积分
    提交有效 Bug 报告 +5
    提交被采纳的功能建议 +10
    在 Discussions 中帮助他人 +3
    提交文档改进 PR +5
    提交代码 PR（已合并） +20

    积分可用于： - 优先处理你提交的 Issue - 参与功能投票决策 - 获得社区贡献者徽章
