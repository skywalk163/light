    光明磊落系统验证报告¶

    光明积木组合系统——组合式软件生成引擎 验证日期：2026-08-10

    概述¶

    光明磊落系统（Light Block Library System）是光明语言（Light）的积木组合引擎。它将「AI 生成代码」替换为「预置积木的组合装配」——给定一句话需求，系统在零 token、全离线的情况下选出合适的光明积木、按契约接线、内联粘合成一个可运行的 .light 文件。只有当需求真的超出当前积木能力时，才把 LLM 当作「兜底生成器」补一块新积木并永久沉淀。

    核心思路：组合式软件生成（compositional generation）替代生成式软件生成。

    一、系统架构¶

    五段式数据流¶

    用户需求（字符串）
      │
      ▼
[选块]  embedding选块.py（默认；概念图向量零依赖）
        选块.py（--关键词，字符重叠）
        语义选块.py（--语义，TF-IDF+同义词）
      │     库外概念 → 概念图余弦≈0 → 返回空候选 → 直接走兜底
      ▼
[校验]  校验器.py（运行前第二道闸，零 token 本地 / 配置 key 后 LLM）
      │     需求具体能力概念 与 所选块 无交集 → MISMATCH → 兜底
      ▼
[契约级接线]  接线.py：按类型匹配 + 参数名相似度接线
      │            （不可接则触发兜底）
      ▼
[粘合]  粘合.py：把选中积木源码「内联」进单一 .light（成语式宏展开）
      │
      ▼
可运行光明代码 → python cli/light.py run 组合结果.light
      │
      ▼ （仅「选不准」时）
[兜底]  兜底生成器.py：按契约生成新积木写入 生成/ 并注册进 索引.json
      │
      ▼ （可选 --自动层级）
[层级织]  层级生成.py：把 生成/ + 全库积木自动织成 L1+（成语式宏升级）

    积木分层体系¶

    层级 说明 示例
    L0 原子积木，手工编写的单一功能 .light 源文件 求和.light、均值.light、人民币大写.light
    L1 组合积木，由 L0 积木按配方组合而成 范围跨度.light、描述统计.light
    L2 高级组合，由 L1+ 积木进一步组合 统计双指标.light

    二、积木库目录结构¶

    积木库/
├── 工具/          # 10 块积木
├── 数据/          # 8 块积木
├── 文本/          # 11 块积木
├── 中文/          # 4 块积木
├── 网络/          # 1 块积木
├── 财务/          # 2 块积木
├── 生成/          # 6 块积木（兜底生成）
├── README.md        # 项目说明文档
├── 协议.md          # 积木组合协议 v0.16
├── 索引.json        # 契约索引（30 块积木）
├── 选块.py          # 关键词选块器
├── 语义选块.py      # 语义选块器（TF-IDF+同义词）
├── embedding选块.py # 概念图向量选块器
├── 接线.py          # 契约级接线器
├── 粘合.py          # 内联粘合器
├── 校验器.py        # 运行前校验器
├── 兜底生成器.py    # LLM 兜底生成器
├── 层级生成.py      # 高级积木生成器
├── 组合.py          # 组合总入口
├── 范围跨度配方.json   # L1 配方
├── 统计双指标配方.json # L2 配方
├── 个税方案.json       # 方案示例
└── 分页方案.json       # 方案示例

    总计：42 块积木（.light 源码）+ 9 个 Python 工具链脚本 + 4 个配方/方案 JSON + 2 份文档 + 1 个契约索引

  2. 取余数（工具）  分数=1.3
  3. 均值（数据）    分数=1.3

    结论：关键词字符重叠打分正确，「求和」以显著优势排在首位。

    V2：语义选块 —— 通过 ✅¶

    需求: "把金额写成人民币大写"
模式: TF-IDF+同义词
候选:
  1. 人民币大写（中文）  分数=0.4388  ← 命中
  2. 中文数字（中文）    分数=0.2860
  3. 转大写（文本）      分数=0.2691

    结论：语义选块正确识别「金额/大写」语义，将「人民币大写」排至首位，且「中文数字」作为相关组合积木也排在第二。

    V3：Embedding 组合（求和+均值）—— 通过 ✅¶

    选块候选（embedding）：

    验证：输入 [1,2,3,4,5]，均值 = (1+2+3+4+5)/5 = 3.0 ✅，求和 = 15 ✅

    V4：链式组合（求和→分页）—— 通过 ✅¶

    选块候选（embedding）：

  分页: [0, 10, 20, 30, 40, 50]

    V5：兜底生成（斐波那契）—— 通过 ✅¶

    六、系统特性总结¶

    设计原则：零 token 优先¶

    模块 实现方式 Token 消耗
    选块（关键词） 字符重叠打分 0
    选块（语义） TF-IDF + 同义词 0
    选块（embedding） 概念图向量 / 句向量 0（本地推理）
    校验 本地概念交集 0
    接线 类型匹配 + 参数名相似度 0
    粘合 内联拼接 0
    层级生成 聚类 + 幂等注册 0
    兜底生成 LLM 按契约生成 有 key 时消耗，生成块永久沉淀

    关键开关¶

    开关 作用
    --关键词 使用字符重叠选块替代默认 embedding
    --语义 使用 TF-IDF+同义词选块
    --链式 契约级精确接线（前步结果自动喂后步）
    --无校验 跳过运行前校验器
    --无兜底 关闭 LLM 兜底
    --自动层级 把生成积木自动织成 L1+
    --阈值 触发兜底的分数阈值

    30 秒上手¶

    # 自动组合（默认 embedding 选块，零 token）
python 积木库/组合.py "对一批数字求和再算平均" --输入 "[1,2,3,4,5]" --top 2

# 语义选块（同义改写也能命中）
python 积木库/语义选块.py "把金额写成人民币大写" --top 3

# 契约级链式接线：前一步结果自动喂后一步
python 积木库/组合.py "求和然后分页" --链式 --输入 "[1..25]" --top 2

# 层级生成：自动织入 L1 高级积木
python 积木库/层级生成.py --自动
